## Context

PLAN.md's one-line thesis ends with a command: *"`messq trace <id>` replays the whole story."* #19
made that possible by writing an event row in the same transaction as every state change, so the
journal structurally cannot disagree with reality. **Nobody can read it yet.** The `events` table is
a set of rows with three indexes and no query path, no HTTP surface, and no renderer. This issue
turns the journal into the product feature the whole project is positioned on:

- `GET /v1/messages/{id}/trace` — the life story of one message, assembled across consumers, DLQ
  hops and redrives.
- `GET /v1/events` — the filtered journal, with `follow=1` for a live NDJSON tail.
- `messq trace` — the flagship rendering (PLAN §8), golden-tested byte-for-byte, because **this
  screenshot is the product**.
- `messq events [--follow]` — the live/historical journal at the terminal.

This is the M5 exit criterion in one issue: *"`messq trace` renders the §8 timeline for a
timed-out/naked/acked message."*

Governing PLAN.md material:

- **§8 CLI design** — the flagship `messq trace` transcript, frozen here; the rules that govern it
  (human on a TTY / machine otherwise, data to stdout, *every inspect command ends with the next
  useful command*, exit codes as a contract).
- **§9.1 / D11** — three surfaces, one vocabulary: *"the durable events table is the source of
  truth; logs and metrics are projections."* This issue is the read side of that decision and the
  reason the events table is **never sampled** — `trace` is always complete where retention allows.
- **§9.2 event vocabulary** (closed set) and §9.3's rule that problem events are never sampleable.
- **§7 API / protocol** — the two endpoints, the shared error envelope, `Accept:
  application/x-ndjson` as D2's kept-open door (the framing this issue uses for `follow`).
- **§4.2 schema** — `events` and its three indexes (`events_msg`, `events_trace`, `events_ts`).
  Those indexes decide every query shape below.
- **§4.5** — `--event-retention` (72 h) / `--event-max-rows`: the journal is finite, so `trace` must
  be able to say *"history before T was trimmed"* instead of quietly showing half a story.
- **§5.2 I9** — *every duplicate has a named cause.* The `duplicates: 2 — all accounted for` line is
  I9 evaluated live, at render time, in front of the operator.
- **§5.2 I11** — no unbounded collection: follower rings, follower count, result limits and scan
  budgets are all capped here.
- **§3.2** — the event fan-out goroutine feeds `/v1/events` followers from **committed** events, on
  a bounded ring per follower, and **overflow drops loudly**. A follower must never be able to slow
  the writer down.

Three properties this issue owns, because the product's credibility rests on them:

1. **The story is continuous.** Timeout → nak → dead → DLQ → redrive is one history, not five
   disconnected lookups. The DLQ copy preserves `id` and `trace_id` (D3/#12) precisely so this works.
2. **The story is honest about its gaps.** Trimmed events, truncated results, dropped follower
   lines and unexplained duplicates are *printed*, never silently absorbed.
3. **Reading is free.** Everything here runs on the read-only pool or on already-committed events;
   no query enqueues writer work, and a stalled `--follow` client costs the daemon a bounded buffer
   and nothing else.

## Design proposal

> A proposed starting point, not a mandate — except the four items marked **_decision_**, which are
> cheap now and expensive after #18 freezes the wire, #26 freezes the goldens and #42 reuses the
> framing. Two items are additions to PLAN.md §7 and need a matching line in `docs/PROTOCOL.md`;
> both are called out.

### 1. The read layer: one anchor, then residual predicates

```go
package store

type Order uint8 // OrderAsc (default) | OrderDesc

type EventFilter struct {
	MsgID    string   // anchors on events_msg
	TraceID  string   // anchors on events_trace
	Stream   string   // residual
	Consumer string   // residual
	Events   []string // residual; exact ("msg.dead") or one-level glob ("msg.*")
	Since    int64    // ms, inclusive; anchors on events_ts when no id anchor
	Until    int64    // ms, exclusive
	AfterID  int64    // exclusive cursor; also the follow handoff point
	Limit    int      // clamped to --event-query-max-limit
	Order    Order
}

type EventPage struct {
	Events      []obs.Event
	Complete    bool  // false ⇒ the scan budget ran out before the range was exhausted
	ScannedToID int64 // how far the scan actually got
	NextAfterID int64 // 0 when exhausted
	HorizonTS   int64 // ts of the oldest retained event row (for "history was trimmed")
}

func (r *Reader) Events(ctx context.Context, f EventFilter) (EventPage, error)
func (r *Reader) MaxEventID(ctx context.Context) (int64, error)
```

**_Decision 1: every query is anchored on an index, and residual predicates are budgeted._** PLAN
§4.2 gives `events` exactly three indexes and no `stream`/`consumer`/`event` index. So:

| Filter given | Anchor | Plan |
|---|---|---|
| `msg_id` | `events_msg(msg_id, id)` | exact, always cheap |
| `trace_id` | `events_trace(trace_id, id)` | exact, always cheap |
| `since`/`until` only | `events_ts(ts)` | range scan, budgeted |
| `after_id` only, or nothing | `events` PK (`id`) | tail walk (`ORDER BY id DESC`), budgeted |

`stream`, `consumer` and `event` are **residual filters applied to anchored rows**, bounded by
`--event-scan-budget` (200 000 rows). When the budget runs out, the response is `complete:false`
with `scanned_to_id`, exactly like #7's partial-answer convention for message listings — a silently
truncated audit answer is worse than a short one. A test asserts the plan with
`EXPLAIN QUERY PLAN`, so a lost index becomes a failing test, not a mystery outage.

*Deferred with a trigger:* a `CREATE INDEX events_stream ON events(stream, id)` migration if
`BenchmarkEventQuery/tail_filtered` at 10 M rows exceeds ~50 ms, or if `--follow --stream` with a
long `--since` routinely exhausts the budget. Every index costs write amplification on the hot
commit path, which is why it is not free.

### 2. Trace assembly is a pure function

```go
package trace // internal/obs/trace — no I/O, no time.Now (Clock seam per §3.3)

type Trace struct {
	Query     Query           // ByMsgID | ByTraceID, plus the filters applied
	Messages  []MessageStory  // ordered by first event; >1 for a trace id or a lineage chain
	Summary   Summary
	Horizon   int64           // oldest retained event ts
	Complete  bool            // false ⇒ events older than Horizon were trimmed
	Truncated bool            // false ⇒ hit --trace-max-events / --trace-max-hops
	Next      []string        // next-command hints, derived from Outcome
}

type MessageStory struct {
	ID, Stream, Subject string
	Seq                 int64
	Size                int64
	PublishedAt         int64
	TraceID             string
	Headers             map[string]string
	DLQ                 bool
	Copies              []store.MsgRef // #12's lineage-aware LookupID
	Lines               []Line         // merged chronological timeline across all consumers
	Consumers           []ConsumerRoll // per-consumer roll-up
	Link                *Link          // → DLQ copy, → redriven-as, ← redrive-of
}

type Line struct {
	ID       int64  // events.id — the ordering key
	TS       int64
	Verb     string // display verb (§4)
	Consumer string
	Attempt, MaxDeliver int
	Cause    string // "timeout" | "nak" | "broker_restart" | "seek" | "redrive" | ""
	Reason   string
	Detail   map[string]any
	Anomaly  string // "clock_jump" | "unexplained" | ""
}

type ConsumerRoll struct {
	Consumer   string
	Attempts   int
	Outcome    Outcome // Acked | Termed | Dead | InFlight | Ready | Scheduled | Unknown
	ResolvedMS int64
	Duplicates int
	Causes     map[string]int // {"timeout":1,"nak":1}
	Unexplained int
}

func Assemble(msgs []store.Message, evs []obs.Event, opt Options) Trace
func Render(w io.Writer, t Trace, opt RenderOptions) error
```

Purity is what makes the byte-for-byte golden cheap: fixtures in, bytes out, no daemon, no clock, no
database. `Assemble` is also the natural home for the rapid property tests in §11.

**Ordering:** by `events.id`, never by `ts`. `id` is the commit order and is monotonic by
construction; `ts` is wall clock and can go backwards (PLAN §11's clock-jump fault family). When
`ts` decreases between consecutive ids, the line renders with a `⟲ clock jump` annotation and a
`+0.000s` delta instead of a negative duration.

**Cause attribution (I9 at render time).** `msg.deliver.detail.cause` is authoritative — #11 already
emits `cause=timeout`, #12 `cause=max_deliver`. The assembler cross-checks it against the preceding
event for the same `(msg, consumer)` pair:

| Preceding event for the pair | Expected `cause` |
|---|---|
| none (first delivery) | `first` |
| `msg.nak` | `nak` |
| `msg.timeout` | `timeout` |
| a `recovery.reclaimed` (aggregate, no `msg_id`) between the two deliveries | `broker_restart` |
| `consumer.seek` / `dlq.redrive` | `seek` / `redrive` |

A mismatch, or an `attempt > 1` with no admissible cause, sets `Anomaly: "unexplained"` and is
counted in `Summary.Unexplained`. **_Decision 2: `trace` prints unexplained duplicates instead of
hiding them._** I9 says every duplicate has a named cause *or it is a bug*; a renderer that quietly
prints an unattributed redelivery would hide exactly the bug the product exists to expose.
`recovery.reclaimed` carries no `msg_id` (it is one aggregate row per restart, PLAN §4.4), which is
why the per-delivery `cause` field is required and why the fallback is a time-window match.

**Lineage traversal.** Bounded, cycle-safe, breadth-first from the queried id:

1. `store.LookupID(id)` (#12) → the origin row plus every DLQ copy, which **share the id** — so
   `events_msg` already returns both sides of the DLQ hop in one indexed query.
2. `msg.dead.detail.dlq = {"stream":"orders.dlq","seq":7}` renders the `→` hop line.
3. `dlq.redrive.detail = {"new_id":…, "new_stream":…, "new_seq":…}` (contract requested of #29;
   T11 mints a *new* id linked by `Messq-Redrive-Of`) is followed forward to the redriven message,
   whose `trace_id` is preserved — so the chain also holds when the detail link is missing.
4. Visited set + `--trace-max-hops` (8). Redrive loops are real: a redriven message can die and be
   redriven again, and nothing forbids an operator redriving in a cycle.

### 3. Display verbs and exhaustiveness

Display verb = event name with a leading `msg.` stripped and `_` replaced by `.`; every other event
renders its full dotted name. `msg.ack_stale` → `ack.stale`, `msg.publish` → `publish`,
`recovery.reclaimed` → `recovery.reclaimed`. The verb column is padded to the widest verb in the
rendered set, minimum 9.

**_Decision 3: the renderer is exhaustive over the closed vocabulary._** `TestEveryEventRenders`
iterates `obs.AllEvents()` (#19) and fails if any event has no rendering case. Without it, adding an
event to the vocabulary silently produces a blank line in the flagship output — the failure mode
nobody notices until an incident.

### 5. HTTP surface

```
GET /v1/messages/{id}/trace ?consumer=&limit=&hops=&include_events=1
GET /v1/traces/{trace_id}   ?limit=&hops=              (§7 addition — one line in PROTOCOL.md)
GET /v1/events ?msg_id=&trace_id=&stream=&consumer=&event=&since=&until=&after_id=&limit=&order=&follow=1
```

`/v1/events?trace_id=T` and then one `/v1/messages/{id}` per distinct id — an N+1 on the fan-out
case (`--trace-id` is exactly the "one upstream request became six messages" story). If reviewers
prefer §7 as printed, the fallback is that N+1 and the CLI pays for it.

### 6. `follow=1`: the live tail

**_Decision 4: subscribe first, snapshot second, deduplicate by id._**

```go
func (s *Server) followEvents(w http.ResponseWriter, r *http.Request, f store.EventFilter) error {
	sub, err := s.events.Subscribe(f, s.cfg.EventFollowBuffer) // #19's committed-event bus
	if err != nil {                                            // --max-event-followers
		return errs.E(errTooManyFollowers, "api.events", "…")   // 429 + Retry-After
	}
	defer sub.Close()

	cutoff := sub.StartID()          // max(events.id) observed at subscribe time
	rc := http.NewResponseController(w)
	w.Header().Set("Content-Type", "application/x-ndjson")

	for page := range s.history(f, cutoff) {   // read pool, chunked, id-ordered
		if err := writeLines(w, rc, page); err != nil { return nil } // client gone
	}
	for {
		select {
		case batch := <-sub.C():                 // live; ids <= cutoff already sent → skip
			writeLines(w, rc, batch.After(cutoff))
			if n, from, to := batch.Dropped(); n > 0 {
				writeLine(w, rc, lostMarker(n, from, to))
			}
		case <-s.clock.After(s.cfg.EventFollowHeartbeat):
			writeLine(w, rc, heartbeat(sub.LastID()))
		case <-r.Context().Done():
			return nil
		}
	}
}
```

Subscribing *before* the history query is the same lost-wakeup discipline as #14's fetch: an event
committed between the snapshot and the subscribe would otherwise vanish. Monotonic `id` makes the
handoff exact — no time window, no heuristic, no duplicate.

**The line framing.** Every NDJSON line carries `type`, with the frozen event fields inline at the
top level of `type:"event"` lines:

```console
$ curl -sN --unix-socket /run/messq/messq.sock \
    'http://x/v1/events?follow=1&event=msg.nak,msg.timeout,msg.dead&consumer=worker'
{"type":"event","id":91002,"ts":1755767948190,"event":"msg.timeout","stream":"orders",…}
{"type":"event","id":91004,"ts":1755767949771,"event":"msg.nak","stream":"orders",…}
{"type":"lost","lost":842,"from_id":91005,"to_id":91846,"ts":1755767950004,
 "hint":"follower buffer overflow; messq events --since … replays the gap"}
{"type":"heartbeat","ts":1755767965004,"last_id":92710}
{"type":"end","reason":"shutting_down","last_id":92710}
```

Keeping the event fields at the top level means `jq 'select(.event=="msg.dead")'` works unchanged on
history pages, follow streams and #42's exports. The `type` frame exists so a stream can *say*
something went wrong mid-stream — which is precisely what a truncated audit export must also be able
to do, so #42 inherits this framing rather than inventing a second one.

**Overflow drops loudly (PLAN §3.2).** Each follower gets a ring of `--event-follow-buffer` (1024)
events. The fan-out's `Publish` is non-blocking (#19/#14's registry rule): on a full ring it drops
the **oldest**, records `{count, from_id, to_id}` and continues. The next flush emits the `lost`
marker. **The writer is never blocked by a follower, ever** — that is the whole point of the ring,
and there is a benchmark for it.

**Deadlines and flushing.** No global `WriteTimeout` (#14). A rolling
`rc.SetWriteDeadline(now + 2×heartbeat)` is reset after every successful flush, so a dead peer is
reaped within one heartbeat while a healthy idle follower lives forever. Lines are flushed when the
ready batch is drained, so wake latency matches the < 5 ms target rather than a fixed tick.

### 7. Flags

| Flag | Env | Default | Meaning |
|---|---|---|---|
| `--event-follow-buffer` | `MESSQ_EVENT_FOLLOW_BUFFER` | `1024` | Per-follower ring size; overflow → `lost` marker |
| `--max-event-followers` | `MESSQ_MAX_EVENT_FOLLOWERS` | `32` | Cap; beyond it `429 too_many_followers` + `Retry-After` (I11) |
| `--event-follow-heartbeat` | `MESSQ_EVENT_FOLLOW_HEARTBEAT` | `15s` | Idle heartbeat line; also drives the write deadline |
| `--event-query-max-limit` | `MESSQ_EVENT_QUERY_MAX_LIMIT` | `1000` | Clamp on `limit`; effective value echoed |
| `--event-scan-budget` | `MESSQ_EVENT_SCAN_BUDGET` | `200000` | Rows examined before an honest `complete:false` |
| `--trace-max-events` | `MESSQ_TRACE_MAX_EVENTS` | `10000` | Events per trace before `truncated:true` |
| `--trace-max-messages` | `MESSQ_TRACE_MAX_MESSAGES` | `100` | Messages per trace id |
| `--trace-max-hops` | `MESSQ_TRACE_MAX_HOPS` | `8` | Lineage hops (DLQ copies, redrives) |

### 8. CLI (minimal form; #23/#24 re-home it)

Following #08's precedent for `messq verify`: exactly these flags and these exit codes now, so the
cobra chassis inherits rather than corrects them. The renderer is framework-agnostic
(`func Trace(ctx, src Source, args []string, out, errw io.Writer) int`), and `Source` has two
implementations — the read pool (tests, goldens) and a ~60-line HTTP transport that #22's
`pkg/client` later replaces without touching the renderer.

```
messq trace <msg-id> | --trace-id <hex>
      [--consumer C] [--relative] [--full-ids] [--no-lineage] [--max-hops N]
      [--output table|json] [--addr ADDR]

messq events [--follow] [--verb msg.dead,msg.nak,msg.*] [--stream S] [--consumer C]
      [--msg-id ID] [--trace-id T] [--since -1h|RFC3339] [--until …] [--limit N]
      [--output table|json|ndjson] [--addr ADDR]
```

```console
$ messq events --follow --verb nak,timeout,dead --consumer billing
09:14:32.191  timeout    orders.created  01J8Z…D1E  seq=10493  worker  attempt=1/5  held=30.001s
09:14:44.771  nak        orders.created  01J8Z…D1E  seq=10493  worker  attempt=2/5  reason="upstream 503"
^C
```

**`messq events` in table mode renders each line through #19's human slog formatter**
(`obs.FormatLine`), not a second layout. One renderer means the live tail and the daemon's own log
are byte-identical for the same event — asserted by `TestEventsTailMatchesServerLog`. Two formats
that drift is how "the log says one thing, the tail says another" incidents start.

`--verb` accepts the PLAN §9.2 names, the `msg.`-stripped short forms (`dead`, `nak`) and one-level
globs (`msg.*`); an unknown verb is a usage error that **lists the closed vocabulary** rather than
returning zero rows for a typo.

Exit codes (PLAN §8 contract): `0` ok · `2` usage · `3` not found (no message and no events for the
id) · `5` empty (a filter matched nothing) · `6` daemon unreachable · `7` permission. `--follow`
interrupted by SIGINT exits `0` after flushing the current line; SIGPIPE (`| head -5`) exits `0`
silently.

### 9. Authorization

Both routes declare `Role` in #15's route registry; #16 enforces. `GET /v1/events` unfiltered
requires `admin`; with `stream=` a token holding `consume` on that stream suffices, and its results
are filtered to that stream regardless of what was requested. Trace endpoints require `consume` on
the stream that owns the message, or `admin`.

Events are **not** less sensitive than payloads: `msg.nak.detail.reason` is the worker's stderr
(first 4 KiB, per PLAN §8's `--exec` contract) and routinely contains fragments of the data being
processed. Bodies never enter events (#19's redaction + the canary test), but reasons do, so the
default posture is closed.

### 10. Edge cases, decided

| Case | Handling |
|---|---|
| Message exists, events trimmed by retention | `200`, `complete:false`, `horizon_ts` set; renderer prints the "trimmed" warning to stderr and starts mid-story. **Never** a 404 |
| Events exist, message purged/expired | `200`; the story renders from events alone, header marked `(message no longer stored)`; `peek` hints suppressed |
| Neither exists | `404 not_found`; CLI exit `3`; `next` suggests `messq events --since -24h --verb dead` |
| Malformed ULID | `400 bad_request` (fails #3's parser) — a typo and an absent message are different incidents |
| Same id in origin **and** DLQ (by design, D3) | One story; the DLQ copy is a `→` hop, not a second message block. `#12`'s `LookupID` returns both, oldest first |
| Same `(consumer, seq)` dead twice after a seek | Two DLQ copies, distinguished by `Messq-Origin-Generation` (#12); rendered as two hops with the generation shown |
| Two consumers, interleaved lifecycles | One chronological list with a consumer column; per-consumer roll-ups in the summary. Not two separate blocks |
| `--consumer C` given | Timeline filtered to that pair plus message-level events (`publish`, `dup`, `retention.expire`) |
| Redrive chain / cycle | Visited set + `--trace-max-hops`; on the cap, `truncated:true` and a line naming the next unfollowed id |
| `dlq.redrive` detail link absent (pre-#29 data) | Fall back to `trace_id` grouping; the `→ redriven as` line is omitted rather than guessed |
| `ts` goes backwards between consecutive ids (clock jump) | Ordered by `id` regardless; delta rendered `+0.000s` with a `⟲ clock jump` annotation |
| Trace spans midnight | `── 2026-08-22 ──` separator line at the rollover; the header keeps the full RFC3339 publish time |
| `attempt > 1` with no admissible cause | `unexplained` annotation + stderr warning naming I9 and `messq verify --deep`; exit stays `0` (a report, not a failure) |
| Follower client stalls (`| less`, then coffee) | Ring fills, oldest dropped, `lost` marker on resume; writer unaffected; the connection is reaped only if a *write* blocks past the deadline |
| More than `--max-event-followers` | `429 too_many_followers` + `Retry-After: 5`; existing followers unaffected |
| `follow=1` with `until` in the past | `400 bad_request` — a bounded range cannot be followed |
| `follow=1` with `msg_id` | Legal and useful: tail one message's remaining lifecycle. History then live |
| Daemon draining (#17) | `{"type":"end","reason":"shutting_down"}` then a clean close; CLI exits `0` and says the daemon is shutting down |
| Store latched read-only (#6, EIO) | Queries keep answering from the read pool (the journal is the incident evidence); the fan-out stops, and the last line is `{"type":"end","reason":"read_only"}` |
| `limit` above the cap / `after_id` past the end | Clamped with the effective value echoed / empty `events[]`, `next_after_id:null`, not an error |
| Event `detail` contains an unexpected key | Rendered as `key=value` in the trailing detail; unknown keys never break the layout (forward compatibility for #37–#41) |
| Terminal is not a TTY | JSON, per §8's two-mode rule. `NO_COLOR`/`TERM=dumb` disable colour but never change the layout, so goldens are stable |
| Non-UTF-8 or control characters in a nak reason | Escaped with `strconv.Quote` semantics before rendering; a fuzz target asserts no control character ever reaches the terminal |

### Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| Gapless follow via SQLite catch-up on ring overflow (refill the missing id range, emit `lagged` instead of `lost`) | PLAN §3.2 mandates "overflow drops loudly"; the durable, gapless path is #42's export | A user needs a gapless live tail and #42's export is not enough |
| Server-Sent Events instead of NDJSON (plan-03) | NDJSON is `curl`-able, `jq`-able and identical to the export format; SSE adds a framing nobody asked for | A browser client appears (which would also mean a web UI — a §1.4 non-goal) |
| `messq trace --watch` (live-updating trace) | `messq events --follow --msg-id …` already answers it with no new renderer | Operators ask for it during incident review |
| OTLP span export of the events table | §13 explicitly refuses the OTel SDK; we emit W3C trace ids and correlate | A bridge is written outside core and demand is demonstrated |
| Rendering payload previews in `trace` | §10: payloads never enter logs; `peek --raw` is one keystroke away and is separately authorized | Never |
| `events_stream` index | Write amplification on the hot commit path | `BenchmarkEventQuery/tail_filtered` > 50 ms at 10 M rows |

## Acceptance criteria

- [ ] `messq trace <id>` renders the PLAN §8 timeline **byte-for-byte** for the committed
      `publish → deliver → timeout → deliver → ack.stale → nak → deliver → ack` fixture from
      #10/#11, including the `duplicates: 2 — all accounted for (1× timeout, 1× nak)` line.
- [ ] A message that timed out, was naked, dead-lettered and was redriven renders as **one
      continuous history**: origin block, `→ orders.dlq seq N` hop, `dlq.redrive` line, and the
      redriven message's block under the same `trace_id`.
- [ ] `messq trace --trace-id <hex>` renders every message sharing the trace, ordered by first
      event, with one shared header and one combined summary.
- [ ] `TestEveryEventRenders`: every name in `obs.AllEvents()` has a rendering case; adding an event
      to the vocabulary without a case fails the build.
- [ ] Display-verb mapping is exactly "strip `msg.`, `_`→`.`": `msg.ack_stale` renders `ack.stale`.
- [ ] A duplicate with no admissible cause is annotated `unexplained`, counted in the summary, and
      warned about on stderr naming I9 — and a synthetic event stream with a forged unattributed
      redelivery makes the test fail loudly rather than render cleanly.
- [ ] `trace.Assemble` is pure: no I/O, no `time.Now()` (Clock seam), deterministic across 1 000
      shuffles of the input event slice, and ordered by `events.id` even when `ts` moves backwards.
- [ ] Trimmed history is reported, never faked: a message whose `msg.publish` predates the retention
      horizon returns `complete:false` with `horizon_ts` and prints the trimming warning; it is a
      `200`, not a `404`.
- [ ] `GET /v1/events` supports every filter in PLAN §7, clamps `limit` while echoing the effective
      value, paginates via `after_id` with no gaps or repeats, and reports `complete:false` +
      `scanned_to_id` when `--event-scan-budget` is exhausted.
- [ ] `EXPLAIN QUERY PLAN` asserts the anchor index for each query class (`msg_id`→`events_msg`,
      `trace_id`→`events_trace`, time range→`events_ts`, tail→PK); no query class falls back to a
      full table scan.
- [ ] `follow=1` emits no gap and no duplicate across the history→live handoff: under concurrent
      publish load, the ids received are exactly the ids committed after the request, in order.
- [ ] A follower whose ring overflows receives a `lost` marker with exact `from_id`/`to_id`, and
      `received + Σ lost == produced` over the follow window.
- [ ] A stalled follower does not slow the writer: publish throughput with 32 stalled followers is
      within benchmark noise of 0 followers, and `cmdCh` depth is unchanged.
- [ ] Every NDJSON line carries `type`; `type:"event"` lines carry the frozen #19 fields at the top
      level so one `jq` filter works on history, follow and (later) #42 exports.
- [ ] Heartbeats arrive at `--event-follow-heartbeat` on an idle stream; a peer that stops reading is
      reaped within two heartbeats; no global `WriteTimeout` exists.
- [ ] `--max-event-followers` is enforced with `429 too_many_followers` + `Retry-After`; follower
      count returns to zero after every client disconnect (I11 — asserted by a registry gauge, not
      by timing).
- [ ] Client disconnect mid-stream frees the subscription and its ring within one select loop, with
      no goroutine leak (`goleak`-style assertion at test end).
- [ ] Neither endpoint enqueues a writer command: a counter on `cmdCh` is zero across a scripted
      query/trace/follow workload, and both keep answering while the store is latched read-only.
- [ ] Exit codes match PLAN §8: `3` for an unknown id, `5` for an empty filter result, `6` for an
      unreachable daemon, `0` for SIGINT during `--follow` and for SIGPIPE.
- [ ] `messq events` table output is produced by #19's `obs.FormatLine`, byte-identical to the
      daemon's own human log line for the same event.
- [ ] `--output json` emits no hint or warning text on stdout; hints are the `next[]` array and
      warnings go to stderr.
- [ ] `--verb` accepts full names, short forms and one-level globs; an unknown verb is exit `2` and
      prints the closed vocabulary.
- [ ] Every `detail` key the renderer depends on (`cause`, `held_ms`, `delay_ms`, `dlq`, `new_id`)
      is documented in `docs/log-schema.md` and covered by a golden.
- [ ] Both routes are in #15's route registry with a declared `Role`; `PROTOCOL.md` documents
      `GET /v1/traces/{trace_id}` and the NDJSON framing.
- [ ] Coverage floors from #2 pass; no `time.Sleep` in tests; no `time.Now()` outside the Clock seam.

## Test plan

Per PLAN §11 / D13: `-race` everywhere, real SQLite files in `t.TempDir()` (never `:memory:`), no
`time.Sleep`, all timing via `testing/synctest` and the Clock seam, every fixed bug landing with a
committed reproduction artifact.

**Unit — `internal/obs/trace` (pure, fixture-driven)**
- Golden renderings: the PLAN §8 fixture; the DLQ+redrive chain; multi-consumer interleaving;
  `--relative`; `--full-ids`; `NO_COLOR`; a 40-column terminal; the day-rollover separator; the
  clock-jump annotation; an empty (fully trimmed) history.
- Cause attribution table: one case per row of the §2 table, plus the mismatch and the
  no-admissible-cause cases.
- Duplicate accounting: `duplicates == Σ(attempts−1)` over randomised consumer counts; the
  `unexplained` path.
- Lineage: DLQ hop, redrive hop, missing `dlq.redrive` detail, hop cap, and a deliberate cycle.
- Determinism: shuffled input order, duplicate event ids, out-of-order `ts`.
- `TestEveryEventRenders` over `obs.AllEvents()`.

**Unit — `internal/store` (real files)**
- `Events` against seeded journals: each anchor class, residual filters, `after_id` pagination,
  `order`, budget exhaustion, empty results, `horizon_ts`.
- `EXPLAIN QUERY PLAN` assertions per query class (the objective form of "no accidental scan").
- The `since` parser: RFC3339, unix-ms, `-15m`, `0`, garbage, overflow.

**Unit — `internal/api`**
- Query-parameter boundaries: negative/overflow `limit`, repeated keys, `follow=1` with `until`,
  unknown `event` names, `msg_id` + `trace_id` together.
- Line framing: every marker type serialises to exactly one line, sorted keys, no embedded newline
  even when a nak reason contains one.

**Property (`pgregory.net/rapid`)**
- **Follow completeness** (the key property): random publish/fetch/nak/timeout/ack sequences with a
  follower attached at a random point; assert the received id set equals the committed id set over
  the window, in order, with `Σ lost` accounting for exactly the missing ids.
- **Trace ≡ fold**: rendering the assembled trace's per-consumer roll-up equals folding the same
  events through the #13 reference model — I10 applied to one message, and the strongest available
  check that the renderer is not inventing history.
- **Pagination totality**: for any filter and page size, walking `after_id` yields every matching
  row exactly once and terminates.
- Failfiles committed to `testdata/regressions/`.

**Deterministic timing (`testing/synctest`)**
- Heartbeat cadence, write-deadline reap, follow handoff under a simulated slow reader, an hour of
  idle follow in microseconds of wall clock.

**Integration — real listener, `httptest` over a Unix socket**
- End-to-end: publish → fetch → timeout → nak → ack over HTTP, then `GET /…/trace` and assert the
  rendered bytes match the golden with ULIDs and timestamps normalised.
- Overflow: a reader that reads one line then stalls, with a publisher at rate → exactly one `lost`
  marker with correct bounds, then a clean resume.
- Disconnect mid-stream, `--max-event-followers` rejection, drain (`type:"end"`), read-only latch.
- Zero-writer-work assertion (`cmdCh` counter) and read-only-pool-only assertion.
- The `curl` transcripts in this issue's design section execute in CI (#18 owns the harness; the
  transcripts land here).

**Crash (extends #8's harness)**
- A message whose lifecycle spans a SIGKILL: after restart, `trace` shows the `recovery.reclaimed`
  attribution and reports the duplicate as accounted for (I9 visible in the flagship output). This
  is the test that proves the audit trail survives the thing it exists to explain.
- SIGKILL while a follower is attached: no partial line is ever emitted as valid NDJSON (the last
  line is either complete or the stream simply ends).

**Fuzz** (60 s/target in CI, corpus committed)
- The `since`/`until`/`--verb` filter parsers.
- The renderer against arbitrary `detail` JSON and arbitrary reason bytes: never panics, never emits
  a control character or ANSI escape from data, never breaks column alignment invariants.
- The NDJSON framer: output is always exactly one line per record.

**Golden**
- `docs/log-schema.md` binding test: every `detail` key the renderer reads is documented, and every
  documented key has a renderer or an explicit "rendered as raw detail" note.
- `TestEventsTailMatchesServerLog`.

**Benchmarks**
- `BenchmarkEventQuery/{by_msg,by_trace,tail,tail_filtered}` at 1 M and 10 M events — the numbers
  that decide the deferred `events_stream` index.
- `BenchmarkTraceAssemble/{10,1000,10000}` events and `BenchmarkTraceRender`.
- `BenchmarkFanoutWithFollowers/{0,1,32,32-stalled}` — the writer-isolation gate; a regression here
  means a `curl` on `/v1/events` can slow down publishes, which is a correctness-adjacent bug.

**Not tested here:** the event write path, vocabulary and sampling (#19); metric names (#21); the
cobra chassis and shared renderer (#23/#24); the testscript suite (#26); the frozen wire contract
(#18); redrive mechanics (#29); export and the audit sink (#42).
