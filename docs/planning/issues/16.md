## Context

#14 stood up the HTTP data plane and #15 completed the control plane. Both left one named,
no-op link in the middleware chain called `authz`, and both declared a `Role` field on every
route in `api.Routes()` that nothing reads. **This issue makes those declarations load-bearing.**

Until it lands, `messq serve` may only bind a Unix socket or a loopback TCP address: #14 makes a
non-loopback bind a fatal startup error whose message names `--auth-file`, a flag that does not
yet exist. This issue is what that error is waiting for, and it is the last piece of M4's
"auth + listener policy" scope.

Governing PLAN.md material:

- **D12 — Security model: secure-by-default minimalism.** Unix socket (0660) plus filesystem
  permissions is the default *and the whole story for local use*. TCP requires a bearer token
  file (SHA-256-hashed secrets, constant-time compare, never logged — `slog.LogValuer`
  redaction). **Three roles (`publish`/`consume`/`admin`) scoped per stream — ~100 lines, no
  RBAC engine.** Explicitly rejected for v1: hash-chained audit trails, Ed25519 checkpoints, the
  grant-coverage decision procedure, SLSA ceremony. *"The in-transaction events table is the
  audit trail."*
- **§10 Security model.** Data dir 0700, DB 0600, *"verified at startup, refuse to run
  otherwise"*. Tokens in a 0600 file, reloaded on SIGHUP; token **ids** (not secrets) appear in
  logs; *"a non-loopback bind without auth is a fatal startup error"*; no TLS in core at 1.0 —
  terminate it in nginx/caddy/Envoy *into the Unix socket*; a `gitleaks` rule for the token prefix.
- **§4.2 Schema.** `events.actor TEXT — token id / uid for admin actions`. That column is the
  reason peer credentials are read at all: it lets `messq trace` answer *"who did this?"*.
- **§9.2/§9.3/§9.4.** `auth.denied` and `admin.action` are already in the closed vocabulary; as
  problem events they join the never-sampled allow-list; and the cardinality rule means
  `messq_auth_denied_total` carries a closed `reason` label and **never** a token id.
- **D8 — flags + `MESSQ_*` env only.** Every knob below is a flag; the token file is data, not
  configuration, which is why it reloads on SIGHUP while flags do not.
- **§13 dependency budget.** `crypto/sha256`, `crypto/subtle`, `crypto/rand` and
  `golang.org/x/sys/unix` (already a direct dep) carry all of it. **No new module.**

What it unlocks: **#18** (the auth-denial and listener-policy contract cases it must run) and
**#40** (native TLS tightens the same listener-policy function and reuses this principal plumbing
for mTLS identities), plus non-blocking consumers — **#17** wires SIGHUP to the reload function
defined here, **#19** inherits the secret-redaction denylist entries, **#21** binds the counter,
**#22**/**#23** send the credential, **#30**'s `doctor` prints what this preflight computes.

The bar is not "auth exists". It is: **an endpoint cannot be added without an authorization
decision**, and **a secret cannot reach an output stream**. Both are enforced by tests, not by
review discipline.

## Scope

### In scope

- **`internal/auth`** (~400 lines incl. comments): `Role`/`RoleSet`, `Principal`, the `Secret`
  redaction type, the token-file parser, the token `Registry` with atomic reload, credential
  verification, and stream-pattern matching.
- **The token file format**: line-oriented `id  sha256(token)  roles  stream-patterns`, comments,
  strict parsing, duplicate detection, permission and ownership checks.
- **The wire credential**: `Authorization: Bearer msq1_<id>_<secret>` — a fixed greppable prefix
  (the `gitleaks`/secret-scanning rule of §10), an id that survives into logs, and a secret the
  server only ever sees as a SHA-256 digest.
- **Authentication middleware**: resolves a `Principal` from the credential, or from
  `SO_PEERCRED` on the Unix socket, or anonymous. Installed into #14's chain.
- **Authorization middleware** over #15's route registry: `Route.Any RoleSet` + `Route.Scope`,
  deny-by-default, the **fail-closed tripwire** (a 2xx response that recorded no authorization
  decision is a `500` and a loud bug event).
- **The generated permission matrix**: `Routes()` × a fixed principal cast → an
  allow/deny golden regenerated with `-update` and committed, so an authz change is a reviewable
  diff. A route with no matrix entry, or a mutating route with `RoleNone`, fails the build.
- **Listener policy and startup preflight**: address classification (unix / loopback /
  non-loopback, incl. IPv6, `0.0.0.0`, `::`, hostnames resolving to a mix), the fatal/warn table,
  the startup banner, and the filesystem audit (data dir 0700, DB 0600, auth file 0600 +
  ownership, socket mode not world-accessible, root warning) that refuses to start on a fatal row.
- **Denials as observable facts**: `auth.denied` events (with the durable-write coalescing rule),
  `messq_auth_denied_total{reason}` through a small interface, `WWW-Authenticate` on 401, and the
  `unauthorized`/`forbidden` envelopes #14 reserved.
- **`actor` attribution** (`tok:<id>` / `uid:<n>`) on `admin.action` and every mutating event, and
  **atomic fail-safe reload**: `Registry.Reload()` returns a diff; on any error the previous set
  stays live (#17 calls it from SIGHUP).
- **`messq auth add|hash|ls|check`** on #1's placeholder dispatcher (secrets never in argv; `add`
  prints the secret exactly once), plus the pure-shell minting recipe.
- **Docs**: the `SECURITY.md` section (threat posture, why SHA-256 and not argon2, TLS
  termination, known limitations), the `docs/PROTOCOL.md` auth section, the `gitleaks` rule.

### Out of scope

- Native TLS, mTLS client identities, certificate hot reload → **#40**. This issue leaves
  `Principal.Kind` open for `KindCert` and keeps listener classification in one function so #40
  edits one table.
- The SIGHUP signal handler, the reload registry and the hardened systemd unit → **#17**. This

- The slog handlers, `ReplaceAttr`, the event fan-out and the payload-redaction type → **#19**.
  This issue supplies the security entries for the key denylist (`authorization`, `token`,
  `secret`, `password`) and the *token* canary test; the *payload* canary test is #19's.
- Prometheus registration → **#21**: the counter is defined and incremented through a one-method

- Client-side credential handling: `pkg/client` → **#22**; `--token-file`, `MESSQ_TOKEN_FILE` and

- `messq doctor`'s prose findings → **#30**, which calls `auth.Preflight()`. Contract/golden

- Per-consumer (rather than per-stream) grants, token expiry, revocation lists, quotas, subject-

- A separate metrics listener with its own auth setting → deferred; `--metrics-auth` on the main

## Design proposal

> Proposal and starting point, not mandate — **except** the four **_decisions_** below (cheap now,
> expensive after #18 freezes the wire) and the token-file format, which becomes an
> operator-visible compatibility surface the moment anyone writes one.

### 1. Package layout and where it plugs in

```
internal/auth/
  role.go       Role, RoleSet, parsing, String()
  principal.go  Principal, Actor(), Allows(), FilterStreams()
  secret.go     Secret — LogValuer/Stringer/GoStringer/TextMarshaler/json.Marshaler
  file.go       token-file grammar, parser, strict errors with line numbers
  registry.go   Registry: atomic set swap, Verify(), the authfile Reloader (#17)
  pattern.go    stream-pattern grammar and matcher (NOT the subject matcher)
  peer.go       SO_PEERCRED via x/sys/unix, ConnContext hook  (peer_linux.go + stub)
  listener.go   address classification + the policy table
  preflight.go  filesystem permission audit; shared with doctor (#30)
internal/api/
  authn.go      middleware: credential → Principal → context
  authz.go      middleware: Route.Any × Route.Scope → allow/deny; the tripwire
internal/cli/
  auth.go       messq auth add|hash|ls|check   (re-parented under cobra by #23)
```

`internal/auth` imports `internal/errs`, `internal/clock` and `x/sys/unix` only — never
`internal/api`, `internal/store` or `net/http`. Authorization is a pure decision over
`(Principal, Role, streams)`, which is what makes the matrix test exhaustive and instant.

The chain, amending #14's `middleware.go`:
`recover → request id → conn limit → authn → body limit → authz → handler → tripwire check`.
`authn` runs before the body limit so a `413` still logs *who* sent it; `authz` runs after,
because two routes (settle, stream create) resolve their scope from the body.

### 2. Types

```go
package auth

type Role uint8
const (RolePublish Role = iota; RoleConsume; RoleAdmin; numRoles)

type RoleSet uint8   // bitmask; RoleSet(0) is the empty set, never "all"
type Kind uint8
const (KindAnonymous Kind = iota; KindToken; KindLocal /* KindCert: #40 */)

type Peer struct{ UID, GID, PID int32 }             // SO_PEERCRED, set at connect(2)
type Grant struct{ Roles RoleSet; Pattern Pattern } // Pattern is a compiled stream pattern

type Principal struct {
    ID     string     // "ci-publisher" | "uid:1000" | ""
    Kind   Kind
    grants []Grant    // unexported: a Principal is immutable once built
    Peer   *Peer      // set when Kind == KindLocal
}

// Allows is the whole authorization engine. No hierarchy, no implication table,
// no deny rules: a principal holds a role on a stream, or it does not.
func (p Principal) Allows(r Role, stream string) bool
func (p Principal) AllowsAny(rs RoleSet, stream string) bool     // any role in the set
func (p Principal) AllowsGlobal(r Role) bool                     // held on EVERY stream, i.e. via "*"
func (p Principal) FilterStreams(rs RoleSet, names []string) []string  // narrow a listing
func (p Principal) Actor() string  // events.actor: "tok:ci-publisher" | "uid:1000" | "anonymous"
```

**_Decision 1: roles are a set, not a hierarchy._** `admin` does **not** imply `consume` or
`publish`. This is *less* code than a hierarchy (no implication table, no "does admin cover
peek?" review argument) and it makes "the administrator read the payloads" a separately granted,
separately auditable act. A token that needs both gets `admin,consume`, and the 403 teaching
error says exactly that — **without naming the token**, which belongs in the log line and the
event row, not in a response body that may be pasted into a ticket (#18 pins this):

```json
{"error":{"code":"forbidden",
  "message":"this token holds [admin] on stream \"orders\"; this route requires consume",
  "next":["messq auth add <id> --role admin,consume --streams 'orders*' --auth-file /etc/messq/tokens"],
  "trace_id":"…"}}
```

### 3. The token file

```
# /etc/messq/tokens   mode 0600, owned by the messq user
# id             sha256(full presented credential)                                roles          streams
ci-publisher     3f786850e387550fdab836ed7e6dc881de23001b19b2d1b0b3d1a37f7cbbd3ae  publish        orders,payments
orders-worker    7d793037a0760186574b0282f2f435e7b6d1a3c0b6b0b3e3a6b1f5b3b8a3d4c1  consume        orders*
ops-admin        9c56cc51b374c3ba189210d5b6d4bf57790d351c96c47c02190ecf1e430635ab  admin,consume  *
```

Grammar: blank lines and `#`-prefixed lines are ignored; every other line is **exactly four**
whitespace-separated fields; a fifth field is an error (not a comment — inline comments would
make a stray `#` in a pattern silently truncate a grant).

| Field | Rule | Failure |
|---|---|---|
| id | `[a-z0-9][a-z0-9._-]{1,63}` | `tokens:12: token id "CI_Pub" must match [a-z0-9][a-z0-9._-]{1,63}` |
| hash | 64 hex chars, case-insensitive, stored lowercased | `tokens:12: expected 64 hex characters, got 43 — is this the secret rather than its SHA-256?` |
| roles | comma-separated, non-empty, subset of `publish,consume,admin`, no duplicates | `tokens:12: unknown role "peek" (valid: publish, consume, admin)` |
| streams | comma-separated, non-empty stream patterns | `tokens:12: invalid stream pattern "or*ers": "*" is only allowed as a whole pattern or a trailing character` |

Duplicate ids and duplicate hashes are both fatal (a duplicate hash is a copy-paste accident that
would otherwise give two ids the same credential and make the audit trail ambiguous).

**Stream patterns** (`pattern.go`) — deliberately *not* the subject matcher from #3:

| Pattern | Matches |
|---|---|
| `*` | every stream |
| `orders*` | `orders`, `orders.dlq`, `orders2` — prefix match |
| `orders` | exactly `orders` |

A pattern containing `>` or an interior `*` is a parse error naming the difference: *"stream
patterns are not subject patterns; `>` matches subject tokens, not stream names"*. A test asserts
the two matchers share no code and no test fixtures.

**The DLQ trap, decided:** a grant on `orders` does **not** cover `orders.dlq` — DLQ streams are
real streams (D3) with real names. `messq auth check` prints a hint for every consume/admin grant
that names a stream literally while a `<name>.dlq` stream exists, and the `dlq` routes' 403
message names the missing pattern.

### 4. Credential format and verification

```
Authorization: Bearer msq1_ci-publisher_9J8XQ2ZK4M7N0P3R5T6V8W1Y2A4C6E8G0J2L4N6Q8S0U2W
                      └──┬─┘└─────┬─────┘ └────────────────── 256 bits ──────────────┘
                       prefix     id (public, appears in logs)
```

- The prefix `msq1_` is fixed and greppable — that is the entire point (§10's `gitleaks` rule,
  GitHub secret scanning, and `grep -r msq1_ .` before a commit).
- **_Decision 2: the stored hash covers the whole presented string_**, prefix and id included.
  There is then no second parse in the security-critical path (parse for logging, hash for
  deciding); renaming an id invalidates its credential, which is the correct blast radius; and
  the hash column is reproducible with `sha256sum` from any shell.
- The server **never** validates the secret's alphabet. `messq auth add` mints 256 bits from
  `crypto/rand` in Crockford base32 (D10's alphabet: no ambiguous characters when read off a
  screen), but any opaque string works — which is what makes shell minting real.

```go
// Verify is the hot path: one regex-free split, one map lookup, one SHA-256, one
// constant-time compare. ~1 µs, dominated by SHA-256 of ~70 bytes.
func (r *Registry) Verify(credential string) (Principal, error) {
    set := r.set.Load()                       // atomic.Pointer[tokenSet]; reload is a swap
    id, ok := splitCredential(credential)     // prefix + shape check, no secrets logged
    if !ok {
        return Principal{}, errs.E(errs.ErrUnauthorized, "auth.verify", "malformed credential")
    }
    sum := sha256.Sum256([]byte(credential))
    ent, found := set.byID[id]
    if !found {
        ent = set.decoy                       // fixed dummy digest: same work, same shape
    }
    if subtle.ConstantTimeCompare(sum[:], ent.hash) != 1 || !found {
        return Principal{}, errs.E(errs.ErrUnauthorized, "auth.verify", "unknown token or bad secret")
    }
    return ent.principal, nil
}
```

Shape check before hashing: `msq1_` prefix, a valid id, a secret of 16–512 characters from
`[A-Za-z0-9._~-]`. This rejects garbage without hashing it and bounds the work per request.
Header edge cases: scheme compared case-insensitively (`bearer` is legal per RFC 7235); more than
one `Authorization` header → `malformed`; empty credential → `malformed`; the whole header is
already bounded by #14's `MaxHeaderBytes` (16 KiB).

**Why SHA-256 and not argon2/bcrypt** (written into `SECURITY.md` so a well-meaning contributor
does not "fix" it): password KDFs exist to make *low-entropy* secrets expensive to guess. A
256-bit random value is not guessable, and a deliberately slow KDF on the hot path is a DoS
vector an unauthenticated client controls. There is no lockout and no artificial delay for the
same reason — `messq_auth_denied_total` plus the shipped alert is the control.

### 5. The local principal (Unix socket)

D12 says filesystem permissions are the ACL for local use; the kernel still tells us *who*
connected, and §4.2's `actor` column wants that answer. Installed on #14's `http.Server`, once
per connection rather than per request:

```go
srv.ConnContext = func(ctx context.Context, c net.Conn) context.Context {
    if uc, ok := c.(*net.UnixConn); ok {
        if p, err := auth.PeerCred(uc); err == nil {   // SO_PEERCRED at connect(2) time
            return context.WithValue(ctx, auth.PeerKey{}, p)
        }
    }
    return ctx
}
```

| `--unix-auth` | Behaviour on the Unix socket |
|---|---|
| `trusted` (default) | No credential needed. Principal = `KindLocal`, all roles on `*`, `Actor() == "uid:1000"`. An `Authorization` header, if present, is still honoured and wins (so the same client code works on both listeners). |
| `required` | A bearer token is required exactly as on TCP; the peer uid is still recorded as `peer_uid` on the log line and in `auth.denied` detail. |

Honest limitation, documented: peer credentials authenticate a **uid, not an application** — any
process running as that uid has the same access, which is exactly what `0660` already meant.

**Reverse-proxy warning (operationally important):** nginx/caddy/Envoy terminating TLS *into* the
Unix socket (§10's recommended deployment) connect as their own uid and therefore inherit full
local authority. If per-client roles must survive the proxy, run `--unix-auth=required` and have
the proxy forward `Authorization` unchanged. `X-Forwarded-For` is never read, for anything.

### 6. Route registry, scopes and the permission matrix

#15's `Route` grows two fields (`Role Role` becomes `Any RoleSet`; `Scope` is new):

```go
type Route struct {
    Method, Pattern string
    Handler http.HandlerFunc
    Any     RoleSet     // satisfied by ANY role in the set; 0 only for PublicRoutes
    Scope   Scope       // which streams this request touches
    Mutates, DryRun bool
    Confirm, Summary string
}

type Scope func(*http.Request) ([]string, error)  // nil slice ⇒ global (requires role on "*")

var (
    scopePath      = func(key string) Scope { … }  // {stream} path value
    scopePathAndDLQ = func(key string) Scope { … } // {stream} and "<stream>.dlq"
    scopeGlobal    Scope                            // nil streams
    scopeDeferred  Scope                            // handler decides; tripwire enforces
)
```

| Route | Roles (any of) | Scope |
|---|---|---|
| `GET /healthz`, `GET /readyz` | *public* | — |
| `GET /metrics` | `admin` (see `--metrics-auth`) | global |
| `GET /v1/info` | `admin` | global |
| `POST /v1/streams` | `admin` | deferred — name comes from the body |
| `GET /v1/streams` | `admin` | deferred — **filtered**, not denied |
| `GET|PATCH|DELETE /v1/streams/{s}` | `admin` | path |
| `POST /v1/streams/{s}/purge` | `admin` | path |
| `POST /v1/streams/{s}/messages`, `:batch` | `publish` | path |
| `GET /v1/streams/{s}/messages…`, `…/{seq}`, `…/{seq}/data` | `consume` | path |
| `POST /v1/streams/{s}/consumers`, `PATCH|DELETE`, `pause`, `resume`, `seek` | `admin` | path |
| `GET /v1/streams/{s}/consumers[/{c}]` | `consume`, `admin` | path |
| `GET …/consumers/{c}/pending` | `consume`, `admin` | path |
| `POST …/consumers/{c}/fetch` | `consume` | path |
| `POST /v1/ack|nak|term|extend` | `consume` | deferred — streams come from the ack tokens |
| `GET /v1/messages/{id}`, `…/trace` | `consume`, `admin` | deferred — after lookup |
| `GET /v1/events` | `admin` | deferred — filtered; unfiltered needs `admin` on `*` |
| `POST /v1/dlq/{s}/redrive` | `admin` | `{s}` **and** `{s}.dlq` |
| `POST /v1/admin/log-level` | `admin` | global |

Rules that fall out of the table, each one a test:

1. **Global routes require the role on `*`.** A token scoped to `orders` cannot change the
   process log level or read cross-stream events. `AllowsGlobal` is that one line.
2. **Listings filter; they do not deny.** `GET /v1/streams`, `GET /v1/events` and (via #24)
   `messq lag` return the in-scope subset. A principal with zero relevant grants gets `200` and
   an empty list — not a 403, because "you may see nothing" is a legitimate answer and a 403
   would be an existence oracle.
3. **Authorize before lookup, except when the id *is* the lookup.** Stream-scoped routes decide
   from the path, so a denied caller gets `403` whether or not the stream exists — no oracle.
   `GET /v1/messages/{id}` must resolve the ULID first; therefore an unauthorized hit returns
   **`404 not_found`, byte-identical to a genuine miss** (decided, tested).
4. **Settle batches fail closed as a unit.** If any ack token in the body names a stream the
   principal may not consume, the whole request is `403` with
   `detail.denied_streams` — per-item results are for *fencing* outcomes (`ok|stale|unknown`),
   never for authorization. No store command is submitted.
5. **Public probe bodies carry no detail.** `/healthz` and `/readyz` answer anonymous callers with
   status and reason only; #15's `degraded[].detail` is included only for `admin` on `*`.
   Golden-tested: no version, no stream name, no path.

**_Decision 3: the fail-closed tripwire._** The authz middleware puts a small recorder in the
request context. `scopeDeferred` handlers must call `api.Authorize(ctx, role, streams...)`, which
stamps it. After the handler returns, the middleware checks: **a 2xx response with no recorded
authorization decision is converted to `500 internal`** and emits an ERROR event
(`api.error`, `detail.bug="unauthorized_response"`). In tests it is a hard failure. Thirty lines,
and "someone added an endpoint and forgot the check" becomes impossible rather than unlikely —
the one idea worth taking from plan-08 at this tax bracket.

**The generated matrix.** `TestPermissionMatrix` walks `Routes()` × a fixed cast of principals
(anonymous · local-uid · publish@`orders` · consume@`orders` · consume@`orders*` · admin@`orders`
· admin@`*` · admin+consume@`*`) and writes `testdata/authz_matrix.md` under `-update`:

```
route                                        anon local pub@o con@o con@o* adm@o adm@* adm+con@*
POST   /v1/streams/orders/messages           ✗    ✓     ✓     ✗     ✗      ✗     ✗     ✗
POST   /v1/streams/orders/consumers/w/fetch  ✗    ✓     ✗     ✓     ✓      ✗     ✗     ✓
GET    /v1/streams/orders.dlq/messages/1     ✗    ✓     ✗     ✗     ✓      ✗     ✗     ✓
POST   /v1/dlq/orders/redrive                ✗    ✓     ✗     ✗     ✗      ✗     ✓     ✓
POST   /v1/admin/log-level                   ✗    ✓     ✗     ✗     ✗      ✗     ✓     ✓
```

The file is committed and listed in `CODEOWNERS`: every authorization change arrives as a
reviewable diff in one place. Adding a route without a matrix row, or a `Mutates` route with
`Any == 0` that is not in the written `PublicRoutes` allow-list (with a reason string), fails the
test.

### 7. Listener policy and startup preflight

```go
type Class uint8
const (ClassUnix Class = iota; ClassLoopback; ClassPublic)

// Classify resolves a --listen address. A hostname resolving to any non-loopback
// address is ClassPublic — the safe direction.
func Classify(addr string) (Class, error)
```

| Listener | `--auth-file` | Result |
|---|---|---|
| `unix://…` | absent | ✅ default. `--unix-auth=trusted`. |
| `unix://…` | present | ✅ tokens honoured; `--unix-auth=required` enforces them. |
| `tcp://127.0.0.1`, `tcp://[::1]` | absent | ⚠️ allowed. **WARN banner** at startup, repeated every 10 min, flagged by `doctor`. |
| `tcp://127.0.0.1` | present | ✅ |
| non-loopback (incl. `0.0.0.0`, `::`) | absent | ❌ **fatal at startup**, exit 1, message names `--auth-file` and prints the two commands that fix it. |
| non-loopback | present | ✅ with a **WARN banner**: bearer tokens travel in cleartext — terminate TLS in front of the Unix socket, or use WireGuard/Tailscale (§10); native TLS is #40. |

There is no flag that disables authentication on a public listener. `--dev` (PLAN §8) may collapse
the loopback warning into a single dev banner; it may **never** permit a public plaintext bind,
and a test asserts that.

Filesystem preflight, run before listeners open, shared verbatim with `doctor` (#30):

| Check | Fatal? |
|---|---|
| data dir mode ⊄ 0700 | fatal — `chmod 700 /var/lib/messq` |
| `messq.db` (and `-wal`, `-shm`) mode ⊄ 0600 | fatal |
| auth file mode ⊄ 0600 | fatal — `chmod 600 /etc/messq/tokens` |
| auth file not owned by the process euid or root | fatal |
| auth file unparseable | fatal at startup; **kept-old at reload** (§9) |
| auth file parses to zero tokens while any listener requires auth | fatal — a daemon nobody can talk to is a misconfiguration, not a state |
| `--socket-mode` grants other-read or other-write (`0666`, `0777`) | fatal — that is an unauthenticated local path |
| running as uid 0 | WARN (containers do it legitimately); names the systemd unit's `User=messq` |

Every fatal row — here and in the listener table — exits **78 (`EX_CONFIG`)**, the code #17's
systemd unit lists in `RestartPreventExitStatus`: a misconfiguration will never succeed on retry,
so it must fail loudly and stay failed. Each prints one sentence of what/why/what-to-type and
emits `server.start outcome=refused` before exiting — a refusal must be as greppable as a start.

### 8. Flags (D8: flags + `MESSQ_*` env only)

| Flag | Env | Default | Meaning |
|---|---|---|---|
| `--auth-file` | `MESSQ_AUTH_FILE` | *(none)* | Bearer token file. Required for any non-loopback listener. |
| `--unix-auth` | `MESSQ_UNIX_AUTH` | `trusted` | `trusted` \| `required` — whether the Unix socket also demands a token. |
| `--metrics-auth` | `MESSQ_METRICS_AUTH` | `admin` | `admin` \| `none`. `none` is refused at startup if any listener is `ClassPublic`. |
| `--auth-event-window` | `MESSQ_AUTH_EVENT_WINDOW` | `10s` | Coalescing window for durable `auth.denied` rows from 401 floods (§9). |

`--metrics-auth=admin` is scrapeable — Prometheus supports bearer auth natively, and the
`scrape_configs` snippet (`authorization: {type: Bearer, credentials_file: …}`) ships in
`contrib/prometheus/` next to #21's alert rules.

### 9. Denials, events, metrics, reload

```console
$ curl -si http://messq-1:4390/v1/info
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="messq"
Messq-Request-Id: 01J8ZQ4K2N7T3W1P8Q9R0S2V4X
{"error":{"code":"unauthorized","message":"this listener requires a bearer token",
 "next":["messq auth add my-tool --role admin --streams '*' --auth-file /etc/messq/tokens"],
 "trace_id":"…"}}
```

**Every 401 body is byte-identical** — no credential, a `Basic` header, a malformed token, an
unknown id and a wrong secret all produce exactly the response above, and the `next` line always
names `--auth-file`. The *reason* lives in the log line, the event row and the metric, where the
operator can see it and the caller cannot (#18 pins the identical bodies).

Log line (INFO for 401, WARN for 403 — a valid credential doing something it may not is the
interesting case):

```
WARN auth.denied  reason=insufficient_role token=orders-worker route=POST /v1/streams/{stream}/purge
                  stream=orders required=admin held=consume remote=10.2.0.9:52310 request_id=01J8…
```

**_Decision 4: 401s coalesce in the events table; 403s do not._** An unauthenticated flood must
not drive fsyncs through the writer (an amplification an attacker controls). So:

- Every denial → log + `messq_auth_denied_total{reason}` increment, always, unsampled.
- `403` (valid principal, insufficient role) → one durable `auth.denied` row per occurrence; rare
  by construction, since you need a real token to produce one.
- `401` (no/unknown/malformed credential) → coalesced: a bounded map keyed by
  `(reason, remote-host)` emits **one** durable row per key per `--auth-event-window` (default
  10 s) with `detail.suppressed=N`, capped at 1024 keys (LRU — I11 applies to security
  bookkeeping too), written on the janitor's tick, never on the request path.

`reason` is a closed enum: `no_credential`, `malformed`, `unknown_token`, `bad_secret`,
`insufficient_role`, `listener_policy`. It is a metric label because it is small and closed
(precedent: `messq_redelivered_total{…,cause}`). **The token id is deliberately not a label** —
it is an identity, it belongs in logs and events, and §9.4's cardinality rule is not negotiable.

`admin.action` and every mutating event carry `actor` from `Principal.Actor()`, threaded through
the store command envelope so `messq trace` can answer "who purged this stream".

**Reload** — this issue supplies the `authfile` reloader that #17 registers in its SIGHUP registry,
implementing #17's two-phase interface exactly:

```go
// authReloader satisfies lifecycle.Reloader (#17 §7): Validate does all the fallible work,
// Apply is an atomic.Pointer.Store that cannot fail.
func (a *authReloader) Name() string                 { return "authfile" }
func (a *authReloader) Validate() (lifecycle.Change, error)  // re-read, re-check perms, build set
func (a *authReloader) Apply()                               // swap; existing connections unaffected

type Diff struct{ Added, Removed, RolesChanged []string; Total int }  // ids only, never secrets
```

`Validate` parses the whole file into a new set and re-runs the permission and ownership checks;
`Apply` swaps the pointer. **On any validation error nothing is applied and the previous set stays
live** — a typo in a token file at 3 a.m. must not lock every worker out of a working broker (#17's
all-or-nothing rule). Success renders as `reload.diff reloader=authfile tokens=7→8
added=[ci-runner] removed=[] roles_changed=[deploy]`. In-flight requests are unaffected;
authorization is decided once, at request start.

### 10. `messq auth` (secrets never touch argv)

Landed on #1's placeholder dispatcher; #23 re-parents it under the cobra root with identical
flags and output.

```console
$ sudo -u messq messq auth add ci-publisher --role publish --streams 'orders,payments' \
      --auth-file /etc/messq/tokens
id ci-publisher   roles publish   streams orders, payments

secret (shown once — store it now):
  msq1_ci-publisher_9J8XQ2ZK4M7N0P3R5T6V8W1Y2A4C6E8G0J2L4N6Q8S0U2W

appended to /etc/messq/tokens (mode 0600)
next: systemctl reload messq        # or: kill -HUP $(pidof messq)

$ messq auth check --auth-file /etc/messq/tokens
ok    3 tokens, file mode 0600, owner messq
warn  orders-worker: consume on "orders" does not cover "orders.dlq" (a stream that exists)
      fix: messq auth add orders-worker --role consume --streams 'orders*' …
```

- `add` writes atomically (temp file in the same directory, `fsync`, `rename`, mode 0600
  preserved) and refuses to clobber an existing id; `ls` prints ids, roles and patterns — never
  hashes, never secrets.
- `hash` reads the credential **from stdin only** (`messq auth hash < token.txt`) — a secret in
  `argv` is visible in `ps` to every user on the box.
- `check` exits 0 with warnings, 1 with errors; #30's `doctor` calls the same function.
- Fully shell-mintable for the air-gapped case, documented in `SECURITY.md`:
  `secret="msq1_${id}_$(head -c32 /dev/urandom | base32 | tr -d = | tr A-Z a-z)"` then
  `printf '%s' "$secret" | sha256sum` — **`printf`, not `echo`**: a trailing newline changes the
  hash, and that footgun costs an hour if it is not written down.

### 11. Redaction, and the contract for #22/#23

```go
// Secret never prints itself. Reveal() is the single, greppable exit.
type Secret string

func (Secret) String() string                 { return "msq1_…redacted…" }
func (Secret) GoString() string                { return `auth.Secret("REDACTED")` }
func (Secret) LogValue() slog.Value            { return slog.StringValue("REDACTED") }
func (Secret) MarshalText() ([]byte, error)    { return []byte("REDACTED"), nil }
func (Secret) MarshalJSON() ([]byte, error)    { return []byte(`"REDACTED"`), nil }
func (s Secret) Reveal() string                { return string(s) }
```

All five interfaces, because a secret leaks through whichever one the caller happens to use:
`%v`, `%s`, `%#v`, `slog.Any`, `json.Marshal`. A `forbidigo` rule (#2) forbids `.Reveal()` outside
`internal/auth` and `pkg/client`. The security entries for #19's `ReplaceAttr` key denylist
(`authorization`, `token`, `secret`, `password`) are contributed here.

Client-side contract, frozen here and implemented by #22/#23: `--token-file` /
`MESSQ_TOKEN_FILE` names a 0600 file whose **entire trimmed content is one credential** — *not*
the server's `--auth-file`, a confusion both `messq auth check` and the client detect (a file with
four whitespace-separated fields is a server file, and the error says so). `MESSQ_TOKEN` is
accepted for containers and CI with its cost documented (readable via `/proc/<pid>/environ` by the
same uid). `401`/`403` maps to CLI exit code **7 (permission)** with the envelope's `next` lines
printed verbatim. The credential never rides a redirect.

### 12. Edge cases, decided

| Case | Handling |
|---|---|
| Two `Authorization` headers | `401`. No "first one wins" ambiguity. |
| `Bearer` with correct id, wrong secret | Same body and same timing as an unknown id (decoy digest). The log names the id; the response never distinguishes. |
| Credential in a query parameter (`?token=`) | Never supported — URLs land in proxy access logs and browser history. Permanent refusal, documented. |
| Token revoked while a long poll is parked | The parked request completes; authorization is evaluated at request start and bounded by `--max-fetch-wait` (5 m). In `SECURITY.md`; cancellation-on-reload is deferred (§13). |
| Ack token names `orders`, principal has consume on `orders*` | Allowed — prefix match. The stream inside the ack token is authoritative for scope; a forged stream name fails #10's fencing anyway. |
| Settle batch mixing `orders` (allowed) and `payments` (denied) | Whole request `403`, `detail.denied_streams:["payments"]`, **zero store commands submitted**. |
| `GET /v1/messages/{id}` in a stream the caller cannot consume | `404 not_found`, byte-identical to a genuine miss. |
| `GET /v1/streams` with no grants | `200 {"streams":[]}` — not 403. |
| `GET /v1/events` without `admin` on `*` | Filtered to in-scope streams; rows with a NULL stream (`server.start`, `storage.fatal`) are omitted. `follow=1` applies the same filter live. |
| `POST /v1/streams` creating `orders` with `admin` on `payments*` | `403`, scope resolved from the body before any store call. |
| Auth file emptied or `chmod 644`, then SIGHUP | Validation fails, old set stays live, WARN names the file and the fix. |
| `--auth-file` on a Unix-socket-only daemon | Legal and useful; tokens are accepted, `--unix-auth=trusted` still lets local clients in without one. |
| `SO_PEERCRED` unavailable (non-Linux build, socketpair oddity) | `KindLocal` with `Peer == nil`, `Actor() == "uid:unknown"`; access unchanged — filesystem permissions were always the ACL. Linux is the supported platform (§1.2). |
| Very long credential (1 MiB header) | Rejected by `MaxHeaderBytes` (16 KiB) before our code runs; the shape check caps the credential at 512 bytes regardless. |
| Clock jump during the 401 coalescing window | Window uses the monotonic `Clock` seam (#3); a wall-clock jump cannot suppress or duplicate rows. |
| Principal holding `admin` but not `consume` calls `peek` | `403` — Decision 1, with `messq auth add <id> --role admin,consume …` in `next`. |

### 13. Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| Subject-level grants + the `Covers` decision procedure (plan-08 §5.4) | D12 rejected it by name: a correct coverage procedure needs a differential oracle and a fuzz target of its own, and streams are already the tenancy boundary for the ICP | A user runs multi-tenant subjects inside one stream and says so |
| mTLS / client-certificate principals | Requires TLS, which is #40 | #40 |
| Token expiry, revocation lists, per-token quotas | Each is a new field, a new clock dependency and a new failure mode; deleting a line plus SIGHUP is the v1 revocation story | Someone operates > 20 tokens |
| Per-consumer (not per-stream) grants | Anyone with `consume` on a stream can settle any of its deliveries today. Honest limitation, in `SECURITY.md` | Two teams share one stream |
| Cancelling parked long polls on revocation | Bounded by `--max-fetch-wait`; costs a reload-versioned waiter registry | Revocation latency shows up in an incident |
| Failed-auth rate limiting / lockout | A 256-bit secret is not brute-forceable; a lockout is a DoS vector against a legitimate token | Never, absent a change to the secret model |
| Hash-chained audit trail, Ed25519 checkpoints (plan-08) | D12: *"the in-transaction events table is the audit trail"* | A compliance requirement with a name |

## Acceptance criteria

- [ ] `messq serve --listen tcp://0.0.0.0:4390` **without** `--auth-file` exits **78** before
      binding, prints one sentence naming `--auth-file` plus the two commands that fix it, and
      emits `server.start outcome=refused`; the same address **with** `--auth-file` starts and
      prints the cleartext-transport WARN banner.
- [ ] `messq serve --listen tcp://127.0.0.1:4390` without auth starts, serves, and prints a WARN
      banner naming the risk; `--dev` does not change the public-bind refusal (asserted).
- [ ] Address classification is table-tested over `unix://`, `127.0.0.1`, `[::1]`, `0.0.0.0`,
      `::`, a private IPv4, a hostname resolving to loopback, and a hostname resolving to both
      loopback and a public address (the mixed case classifies as public).
- [ ] Startup refuses with exit **78** and an exact `chmod`/`chown` fix in the message when the
      data dir is not 0700, `messq.db` is wider than 0600, the auth file is wider than 0600 or
      foreign-owned, the auth file parses to zero tokens while a listener requires auth, or
      `--socket-mode` grants other-access. Running as uid 0 warns and continues.
- [ ] **`TestPermissionMatrix` passes**: every route in `api.Routes()` × the fixed principal cast
      matches the committed `testdata/authz_matrix.md`, regenerable with `-update`.
- [ ] A route added without a matrix entry fails the test; a `Mutates` route with an empty
      `RoleSet` that is not in the written `PublicRoutes` allow-list (with a reason) fails the
      test; a route with a `{stream}` pattern and a global scope fails the test.
- [ ] The tripwire holds: a deliberately broken `scopeDeferred` handler that skips
      `api.Authorize` returns `500 internal` with `detail.bug="unauthorized_response"` instead of
      the data, and the test that proves it is committed.
- [ ] Anonymous requests to every non-public route return `401` with `WWW-Authenticate: Bearer
      realm="messq"` and the `unauthorized` envelope; missing, malformed, unknown-id and
      wrong-secret credentials produce **byte-identical** bodies; `/healthz` and `/readyz` answer
      `200` anonymously with no version, path, stream name or `degraded[].detail` in the body.
- [ ] A valid token lacking the required role returns `403 forbidden` whose message names the
      roles held, the stream and the required role with an actionable `next` line, and which
      contains **no token id and no secret** — the id appears only in the log line and the event
      row (#18 pins this body).
- [ ] A denied request performs **zero** store mutations: the writer-submission counter is
      unchanged across denied publish, fetch, settle, purge, seek and redrive attempts.
- [ ] `GET /v1/messages/{id}` returns a byte-identical `404` for "does not exist" and "exists but
      not authorized"; `GET /v1/streams` and `GET /v1/events` filter rather than deny; a settle
      batch containing one unauthorized stream returns `403` with `detail.denied_streams` and
      settles nothing.
- [ ] `Verify` rejects — with the correct `reason` and no panic — a wrong secret for a valid id, a
      valid secret under the wrong id, a missing `msq1_` prefix, an empty credential, a duplicate
      `Authorization` header and a 100 KiB credential; comparison uses
      `crypto/subtle.ConstantTimeCompare` against a decoy digest for unknown ids, and a benchmark
      shows the unknown-id and wrong-secret paths within noise of each other.
- [ ] Stream-pattern matching is exact/prefix/`*` only (`orders` does not match `orders.dlq`,
      `orders*` does; `or*ers` and `orders.>` are parse errors naming the subject-matcher
      distinction), and roles are a set: `admin` alone is denied on `fetch` and `peek`,
      `admin,consume` is allowed, global routes require the role via a `*` pattern.
- [ ] The `authfile` reloader satisfies #17's two-phase `Reloader`: `Validate` is side-effect-free
      and `Apply` cannot fail; the returned diff carries ids only, never hashes or secrets; a
      malformed, empty, wrongly-permed or deleted file fails validation, leaves the previous set
      live and keeps the daemon serving (asserted with a request before and after).
- [ ] `auth.denied` is emitted on all three surfaces: WARN/INFO log, `messq_auth_denied_total`
      increment with a closed `reason` label and **no** id label, and a durable event row —
      per-occurrence for 403, coalesced with `detail.suppressed=N` for 401 floods, capped at 1024
      tracked keys.
- [ ] `events.actor` is `tok:<id>` for token principals and `uid:<n>` for local ones on every
      mutating and `admin.action` event, verified end to end through a purge over both listeners.
- [ ] **The canary test passes**: a run that mints and uses a token containing
      `CANARY-<random>` and also sends garbage credentials produces no occurrence of any canary
      in captured stdout, stderr, `/metrics`, any error envelope, or the `events` table
      (`detail`, `actor` and all columns) — asserted by grepping the raw bytes.
- [ ] `messq auth add` prints the secret exactly once, appends atomically at mode 0600, refuses a
      duplicate id, and never accepts a secret in `argv`; `messq auth hash` reads stdin only;
      `messq auth check` exits 0/1 and reports the `<stream>.dlq` coverage hint.
- [ ] `SECURITY.md` documents the threat posture, the SHA-256-not-argon2 reasoning, TLS
      termination, revocation via file-edit + SIGHUP and the three named limitations
      (uid-not-application, proxy inherits local authority, per-stream not per-consumer);
      `docs/PROTOCOL.md` gains the auth section; a `gitleaks` rule for `msq1_` is in CI, proven
      by a fixture.

## Test plan

Consistent with PLAN §11: `-race` everywhere, no `time.Sleep` (the coalescing window uses #3's
Clock seam under `testing/synctest`), every fixed bug lands with its reproduction artifact.

**Unit — `internal/auth` (pure, fast, the coverage centre of this issue)**
- Token-file parser table: valid file; every field-level error above with its exact line number;
  3 vs 4 vs 5 fields; tabs vs spaces vs mixed runs; CRLF; missing trailing newline; UTF-8 BOM;
  comment-only; blank; duplicate id; duplicate hash; uppercase hash; 8 KiB line.
- `Pattern` table: `*`, `orders`, `orders*`, empty, `or*ers`, `orders.>`, `*orders`, `**`, case
  sensitivity, and the `orders` vs `orders.dlq` pair. `Principal.Allows`/`AllowsAny`/
  `AllowsGlobal`/`FilterStreams` truth table over all role/pattern combinations, the empty
  `RoleSet` and multi-grant principals.
- `Verify`: the six denial reasons; success; decoy-path behaviour for unknown ids. `Classify`:
  the address table from the acceptance criteria, with a stubbed resolver. `Preflight`: a
  `t.TempDir()` matrix of modes and owners (owner cases skipped when not root), asserting
  fatal/warn classification and the exact fix strings.
- `Secret`: assert `%v`, `%s`, `%+v`, `%#v`, `slog` (JSON and text handlers), `json.Marshal` and
  `fmt.Sprint` of a *struct containing* a `Secret` all yield no secret bytes — the unit-level half
  of the canary test.
- `Reload`: success diff; each failure mode leaves the old set live; concurrent `Verify` during a
  reload under `-race` never observes a torn set (1 000 iterations).

**Property (`pgregory.net/rapid`)**
- Round trip: generate random principals (ids, role sets, pattern sets) → render a token file →
  parse it → assert the parsed principals are `cmp.Diff`-equal, and that a randomly generated
  credential verifies iff it is the minted one.
- Authorization oracle: generate a random grant set and random `(role, stream)` queries; compare
  `Allows` against a ~15-line naive reference (expand nothing, string-compare with an explicit
  prefix rule). Failfiles committed to `testdata/regressions/`.

**Fuzz (`go test -fuzz`, 60 s per target in PR CI, 30 min nightly; corpus committed — #33 adopts)**
- `FuzzParseAuthFile`: never panics; any file that parses re-renders and re-parses identically.
- `FuzzParseCredential`: never panics; **no input other than a minted credential ever verifies**
  against a fixed one-token registry (the forgery property, mirroring the ack-token fuzz of #10).
- `FuzzAuthorizationHeader`: raw header bytes through the middleware; asserts a response is always
  produced and is always an envelope.

**Golden**
- `testdata/authz_matrix.md` (the security artifact reviewers read); the 401 and 403 envelopes
  with ids normalised; `auth.denied` JSON log lines and the `messq_auth_denied_total` label set;
  public `/healthz` + `/readyz` bodies for an anonymous caller vs an `admin@*` caller.

**Integration — real listeners, real files, `httptest` + real `net.Listen`**
- One test per row of the §6 route table over three transports — Unix socket (`trusted`), Unix
  socket (`required`), loopback TCP — each with the eight-principal cast, asserting the status
  code and, on denial, that the store saw nothing.
- Public-bind refusal: a real `messq serve` subprocess bound to `0.0.0.0` without `--auth-file`;
  assert exit **78**, stderr text, and that nothing ever listened (connect refused).
- Reload: drive `Validate`/`Apply` directly (the signal is #17's), asserting a revoked token's
  next request is `401` while a request already in flight completes.
- Peer credentials: purge over a Unix socket, assert `events.actor == "uid:<os.Getuid()>"`.
- End-to-end worker: PLAN §7's five-line curl worker over loopback TCP with a `consume`-scoped
  token — fetch, ack, and a `403` when the same token tries to publish.

**Security-specific**
- **Canary leak test** (the flagship): a scenario mints `msq1_canary-tok_CANARY-<rand>`, uses it,
  then sends five malformed/wrong credentials carrying a second canary. All captured stdout/stderr
  (both handlers, level DEBUG), the `/metrics` body, every response body and a dump of the
  `events` table are grepped for either canary; any hit fails the build. PR lane, not nightly.
- Lint proof: a fixture calling `Secret.Reveal()` outside the allowed packages fails `forbidigo`;
  a fixture containing `msq1_…` fails the `gitleaks` rule.

**Bench** — `BenchmarkVerify` (hit / unknown-id / wrong-secret) and `BenchmarkAuthorize` (path and
settle scopes), plus an end-to-end publish bench with and without `--auth-file` on loopback TCP.
Reported, not gated: auth should be invisible against the group-commit fsync of PLAN §12, and a
number in the PR is how we know.

**Not tested here:** TLS conformance (#40), the SIGHUP signal path and drain (#17), the full
contract/executable-doc harness (#18), payload redaction (#19), metric registration (#21).
