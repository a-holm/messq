## Context

Every promise messq makes — "a 2xx publish survived the power cut", "an ack is a durability
promise", "the audit trail cannot disagree with reality", "`kill -9` is always safe" — bottoms
out in one SQLite file and the code that opens it. This issue builds that code: `internal/store`,
the package that owns `<data-dir>/messq.db`.

It is the first issue of **M2: Durable store & publish** and the root of the M2/M3/M5 dependency
tree. Nothing above it can be written until the schema exists, the pragmas are provably in
effect, and a dirty data directory can be brought back to a known-good state.

Governing PLAN.md material:

- **§2 / D1 — SQLite via `modernc.org/sqlite`.** One transactional boundary collapses the crash
  matrix; inspectability (`sqlite3 messq.db` works with the daemon down) is the product; there is
  deliberately **zero bespoke recovery code**. D1 also mandates the `//go:build cgosqlite` escape
  hatch, wired from day one and exercised in CI.
- **§4.1 — Engine and connections.** The DSNs, the `rw` (MaxOpenConns=1) / `ro` (NumCPU) split,
  and the **connection hook that re-asserts and reads back the durability pragmas on every pooled
  connection** — D1's answer to "durability lives in a DSN string" being a trap.
- **§4.2 — Schema (v1).** Seven `STRICT` tables, Unix-millisecond integer timestamps, numbered
  forward-only migrations embedded with `go:embed`, applied in one transaction, tracked in `meta`.
- **§4.4 — Crash recovery.** The startup procedure that runs *before listeners open*.
- **§2 / D6 — Attempt counting.** Recovery reclaims in-flight leases **without touching
  `attempts`**: the delivery already counted. That is transition **T9** in §5.1 and is what makes
  invariant **I4** (`attempts ≤ max_deliver` across restarts) hold.
- **§10 / §3.1 — Security & process model.** Data dir `0700`, DB `0600`, verified at startup and
  refused otherwise; `flock` on the data dir so a second instance cannot corrupt it.

What it unlocks: the group-commit writer (#6) takes the `rw` handle from here; publish and peek
(#7) run vanilla SQL against these tables; the crash harness (#8) restarts against this recovery
path; the event pipeline (#19) writes into the `events` table this issue creates; `backup` and
`doctor` (#30) read the pragma state this issue enforces; the upgrade fixtures (#34) freeze the
schema this issue defines.

## Scope

**In scope**

- `internal/store` package: `Open`, `Close`, connection ownership, error taxonomy.
- Migration 0001 — the complete §4.2 schema v1 (`meta`, `streams`, `stream_seq`, `messages`,
  `consumers`, `deliveries`, `events` + all indexes), embedded via `go:embed`, forward-only.
- Migration runner: numbered ladder, whole ladder in one `BEGIN IMMEDIATE` transaction, version
  in `meta` (mirrored to `PRAGMA user_version` for forensics), per-file checksum guard, **refuse
  to start on a schema newer than the binary**.
- DSN construction and the two `database/sql` handles (`rw`, `ro`) with their pool sizes.
- Pragma enforcement: a connection hook that applies **and reads back** `journal_mode`,
  `synchronous`, `foreign_keys`, `busy_timeout`, `temp_store`, `cache_size`,
  `wal_autocheckpoint` (+ `query_only` on the read pool) on **every** pooled connection; any
  mismatch is a fatal startup error.
- `auto_vacuum=INCREMENTAL` set at file creation (it cannot be changed later without a full
  `VACUUM`).
- Durability mode plumbing: `full` → `synchronous=FULL`, `relaxed` → `synchronous=NORMAL`, with
  the mode reflected in the enforced expectation set. (The *response* semantics and the fsyncgate
  latch belong to #6.)
- Data-directory lifecycle: create `0700`, create `messq.db` `0600` ourselves (umask-proof),
  `fsync` the directory, `flock` a `LOCK` file for the process lifetime, refuse on
  group/other-readable modes or foreign ownership.
- `node_id` (ULID, from #3) minted once at DB creation and stable forever.
- Startup recovery (§4.4): unclean-shutdown detection, `PRAGMA quick_check` (or
  `integrity_check` under `--fsck`), migrations, **lease reclaim** (`INFLIGHT → READY` with
  jitter, `attempts` untouched), expired-dedup-key trim, `clean_shutdown` marker management,
  startup `wal_checkpoint(TRUNCATE)`, and a structured `RecoveryReport`.
- Recovery-time `events` rows (`recovery.unclean`, `recovery.reclaimed`) written **in the same
  transaction** as the reclaim update, plus the matching `slog` lines.
- Graceful `Close`: `PRAGMA optimize`, `wal_checkpoint(TRUNCATE)`, set `clean_shutdown=1`,
  release the lock.
- `//go:build cgosqlite` / `//go:build !cgosqlite` driver files and the CI matrix job that builds
  and tests both.

- The three-valued ledger oracle, the SIGKILL loop, and `messq verify` — **#8**.

## Design proposal

> Everything below is a starting point, not a mandate. Signatures and SQL are meant to be
> concrete enough to argue with; deviate where the implementation teaches you better.

### Connections (§4.1, exact)

Default build (`!cgosqlite`, `modernc.org/sqlite`, driver name `sqlite`):

```
rw: file:/var/lib/messq/messq.db?_txlock=immediate
      &_pragma=journal_mode(WAL)&_pragma=synchronous(FULL)&_pragma=foreign_keys(1)
      &_pragma=busy_timeout(5000)&_pragma=temp_store(MEMORY)
      &_pragma=cache_size(-65536)&_pragma=wal_autocheckpoint(4000)
    SetMaxOpenConns(1); SetMaxIdleConns(1); SetConnMaxLifetime(0)

ro: same pragmas, plus &_pragma=query_only(1), minus _txlock=immediate
    SetMaxOpenConns(runtime.NumCPU()); SetMaxIdleConns(NumCPU)
```

Two deviations from a literal reading of PLAN §4.1 ("`ro`: same + `&mode=ro&_pragma=query_only(1)`"),
both of which should be recorded as a short note in the ADR from #4:

1. **No `_txlock=immediate` on the read pool.** `query_only=1` forbids acquiring a write lock, so
   a `BEGIN IMMEDIATE` on a read connection fails. `immediate` exists to kill the
   deferred-upgrade `SQLITE_BUSY` class on the *writer*; the read pool never upgrades.
2. **`mode=ro` is opt-in, `query_only(1)` is the enforcement.** A read-only *file* handle on a
   WAL database cannot create the `-shm` file, so opening a quiescent copied data directory with
   `mode=ro` fails outright. The daemon opens `rw` first (which creates and holds `-shm`), so
   `mode=ro` would work there — but the same code path is reused by `messq verify` against a
   copy (#8) and by `doctor` (#30). Decision: the read pool opens the file read-write at the OS
   level and is made read-only by `query_only(1)`, which is verified by read-back on every
   connection. Add an `Options.ReadOnly` mode that sets `mode=ro` *and* skips the `rw` handle
   entirely, for offline inspection tools.

Deliberately **not** set: `mmap_size`. Memory-mapped I/O turns a read error into a SIGBUS instead
of an `EIO` the store can latch on, which would undermine the fsyncgate handling in #6 and the
EIO fault scenario in #32. Revisit only with a measured throughput reason.

### Pragma enforcement (the load-bearing part of D1)

The failure this defends against: a pooled connection silently running `synchronous=NORMAL` in
WAL mode, which does **not** fsync on commit. Every promise in §6 would be false and nothing
would look wrong.

`modernc.org/sqlite` exposes `RegisterConnectionHook(fn ConnectionHookFn)` where
`ConnectionHookFn = func(conn sqlite.ExecQuerierContext, dsn string) error`; it runs after all
DSN parameters are applied, on **every** new connection, and a returned error closes the
connection and surfaces from `Open`. Registration must happen before the first `sql.Open`.

```go
// pragma.go
type expect struct {
	name string // "synchronous"
	set  string // "PRAGMA synchronous=FULL"  (empty ⇒ verify only)
	want string // normalized expected read-back, e.g. "2"
}

// registry is keyed by the exact DSN string and populated by Open before any sql.Open call.
// A hook invocation for an unknown DSN is a no-op, so other tools may open SQLite freely.
var registry sync.Map // dsn string -> []expect

func hook(conn sqlite.ExecQuerierContext, dsn string) error {
	exp, ok := registry.Load(dsn)
	if !ok { return nil }
	// Pass 1: apply every non-empty e.set, in slice order.
	// Pass 2: re-read every pragma and compare against e.want; the first mismatch returns
	//         fmt.Errorf("%w: %s=%s, want %s", ErrPragmaMismatch, e.name, got, e.want),
	//         which closes the connection and surfaces from Open.
	return nil
}
```

Apply-all-then-verify-all (two passes) matters: `query_only` set in pass 1 must not stop pass 2
from *reading* pragmas, and a pragma silently ignored by the driver is only visible on re-read.

Ordering rules the hook must respect, each of which is a real SQLite constraint:

| Pragma | Constraint |
|---|---|
| `journal_mode` | must run **first**; it is a persistent file property, and on `query_only` connections it must already be `wal` (it will be — the `rw` handle set it) |
| `foreign_keys` | connection-scoped, **defaults OFF**, cannot change inside a transaction. `stream_seq → streams` `ON DELETE CASCADE` depends on it. This is the single most likely silent-correctness regression the hook catches. |
| `query_only` | must run **last** on the read pool; it blocks `journal_mode` changes and `wal_checkpoint` |
| `auto_vacuum` | **not** in the hook — it is settable only before the first table is created, so `Open` sets it on the freshly created file, before migration 0001 |
| `cache_size` | negative value = KiB; read-back returns the same negative number |

Read-back normalization: `journal_mode` → `"wal"`, `synchronous` → `"2"`/`"1"`, `foreign_keys`,
`query_only` → `"1"`/`"0"`. Compare case-insensitively for the textual ones.

The `cgosqlite` build uses `sql.Register("sqlite3_messq", &sqlite3.SQLiteDriver{ConnectHook: ...})`
with the same expectation sets and DSN keys renamed to mattn's spelling
(`_journal_mode`, `_synchronous`, `_busy_timeout`, `_foreign_keys`, `_txlock`). The whole
divergence stays inside `driver_cgo.go`.

### Data directory and locking

```
$MESSQ_DATA_DIR/            0700, owned by the running uid
├── LOCK                    0600, flock(LOCK_EX|LOCK_NB) held for the process lifetime
├── messq.db                0600, created by us with O_CREAT|O_EXCL before the driver sees it
├── messq.db-wal            SQLite-created (inherits 0600 from the parent file)
└── messq.db-shm
```

`lockDataDir` opens `LOCK` `0600`, takes `unix.Flock(fd, LOCK_EX|LOCK_NB)`, and on success
rewrites it with `pid=… boot=… started=…`. On failure it reads the existing line into the
`ErrDataDirLocked` message. Notes:

- **Never close the LOCK fd before exit** — `flock` is per open-file-description, so closing it
  silently releases the lock.
- The holder line is diagnostic, never authoritative; the `flock` is the truth. A stale `LOCK`
  file whose pid is gone still unlocks correctly, because the kernel released the lock.
- Advisory and **local-filesystem only**. `flock` over NFS is a lie; `doctor` (#30) warns on a
  non-local `statfs` type and the docs state the requirement.
- Permission check: refuse if `mode&0o077 != 0` on the directory or the DB file, or if
  `stat.Uid != os.Geteuid()`. Refuse rather than repair — silently `chmod`-ing someone's
  directory is worse than stopping.
- Creation order for a fresh dir: `MkdirAll(dir, 0700)` → create `messq.db` `O_EXCL` `0600` →
  `fsync(dir)` so the directory entry survives a crash → `flock` → open handles.

### Schema v1 (migration `0001_init.sql`)

The file is **PLAN §4.2 copied verbatim** — seven `STRICT` tables (`meta`, `streams`,
`stream_seq`, `messages`, `consumers`, `deliveries`, `events`) and nine indexes
(`messages_id`, `messages_dedup`, `messages_subj`, `messages_age`, `deliveries_ready`,
`deliveries_seq`, `events_msg`, `events_trace`, `events_ts`). Do not paraphrase, reorder or
"improve" it: this file becomes the golden artefact #34 pins forever, and the review question is
"is it byte-identical to §4.2", not "is it nice".

`meta` keys written by this issue: `schema_version`, `node_id` (ULID), `created_at`,
`clean_shutdown`, `schema_applied_at`, and one `migration_<n>_sha256` per applied migration.

Schema decisions worth stating explicitly, because reviewers will ask:

- **No `CHECK` constraints, no FKs from `messages`/`deliveries` to `streams`.** PLAN §4.2 is the
  frozen v1 schema; adding constraints would change the golden dump #34 pins and would put a
  second, weaker validity model next to `internal/queue`. Validity is a state-machine
  responsibility; drift is caught by `messq verify` (#8) and invariant I2/I4/I5 checks, not by
  the storage layer. `stream_seq`'s cascade is the one exception and it is in PLAN.
- **`STRICT` everywhere** so a Go type bug becomes a loud constraint error instead of a silently
  coerced value. Verified by a test that tries to write a string into `messages.size`.
- **Timestamps are Unix milliseconds** (`INTEGER`), never `TEXT`, never SQLite `julianday`.
  Wall-clock only; deadline arithmetic in the delivery engine uses the monotonic `Clock` seam.

### Migration runner

```go
//go:embed migrations/*.sql
var migrationFS embed.FS

type migration struct {
	n     int
	name  string // "0001_init.sql"
	sql   string
	sha   string // hex sha256 of sql
}

// Migrate applies every pending migration inside ONE transaction (PLAN §4.2 / §4.4 step 2).
func migrate(ctx context.Context, db *sql.DB) (from, to int, err error)
```

Algorithm:

1. `BEGIN IMMEDIATE` (the whole ladder is one transaction — either the DB is at version N or it
   is untouched; there is no "half-migrated" state to reason about, which is exactly what #34
   asserts).
2. `CREATE TABLE IF NOT EXISTS meta (...) STRICT` — the bootstrap row, harmless on an existing DB.
3. `from := int(meta['schema_version'])`, default 0.
4. If `from > len(embedded)` → `ErrSchemaTooNew`, rollback, refuse to start. **Never** partially
   parse a future schema and never guess.
5. For every already-applied `n ≤ from`, compare `sha256(file)` against
   `meta['migration_<n>_sha256']`; a mismatch is `ErrMigrationDrift`. (Forward-only means applied
   files are immutable; this catches the "I just tweaked 0001 during development" bug before it
   reaches a user's disk.)
6. For every pending `n > from`: execute the file's statements, insert its checksum.
7. `meta['schema_version'] = to`, `meta['schema_applied_at'] = now_ms`,
   `PRAGMA user_version = to` (mirror, for `sqlite3 messq.db 'PRAGMA user_version'` forensics —
   `meta` stays authoritative; a mismatch on open is a tampering signal and refuses to start).
8. `COMMIT`.

Edge cases:

- **Fresh file:** `auto_vacuum=INCREMENTAL` and `journal_mode=WAL` must be applied to the empty
  file *before* step 1, because `auto_vacuum` is immutable once a table exists.
- **`PRAGMA foreign_keys` cannot be toggled inside a transaction** — it is already ON from the
  hook, which is what we want during migrations.
- **Zero pending migrations** must be a no-op that still validates checksums and does not bump
  `schema_applied_at`. Opening twice in a row is idempotent and cheap.
- **Statement splitting:** do not hand-roll a `;` splitter. Either execute the whole file with a
  driver call that accepts multiple statements, or keep one statement per file segment separated
  by a `-- +migrate` style marker. Whichever is chosen must be covered by a test with a `;`
  inside a string literal.

### Startup recovery (§4.4)

```go
type RecoveryReport struct {
	NodeID          string
	SchemaFrom      int
	SchemaTo        int
	Unclean         bool          // clean_shutdown marker absent or "0"
	CheckKind       string        // "quick_check" | "integrity_check" | "skipped"
	CheckDuration   time.Duration
	Reclaimed       int64         // INFLIGHT deliveries flipped back to READY
	DedupExpired    int64
	CheckpointPages int64
	DBBytes         int64
	WALBytes        int64
	Duration        time.Duration
}
```

`Open` sequence, in order, all before any listener exists:

1. Resolve/create the data dir, verify permissions, create `messq.db` `0600`, `fsync(dir)`.
2. `flock` the `LOCK` file.
3. Set `auto_vacuum=INCREMENTAL` + `journal_mode=WAL` on a fresh file; register the pragma hook
   expectation sets; `sql.Open` the `rw` handle and `Ping` it (the hook runs here — a pragma
   mismatch fails the start *now*).
4. Read `meta.clean_shutdown`; absent-or-`"0"` on a pre-existing DB ⇒ `Unclean = true`, log
   `recovery.unclean` at WARN.
5. If `Unclean` (or always under `--fsck`): run `PRAGMA quick_check` / `PRAGMA integrity_check`.
   A non-`ok` result is `ErrCorrupt`: log `storage.fatal` at ERROR, print the restore-from-backup
   instructions, exit non-zero. **Never** try to repair.
6. Migrate (above). Refuse on `ErrSchemaTooNew`.
7. Open the `ro` pool (after `rw`, so `-shm` exists).
8. **Reclaim leases** — one transaction, one indexed `UPDATE`, plus its events:

```sql
BEGIN IMMEDIATE;

UPDATE deliveries
   SET state        = 0,                                    -- READY
       visible_at   = :now_ms + CASE WHEN :jitter_ms > 0
                                     THEN (random() & 0x7fffffff) % :jitter_ms
                                     ELSE 0 END,
       delivered_at = NULL,
       last_reason  = 'broker_restart'
 WHERE state = 1;                                           -- INFLIGHT
-- attempts is deliberately NOT touched (D6 / T9 / invariant I4)

INSERT INTO events (ts, event, detail)
VALUES (:now_ms, 'recovery.reclaimed',
        json_object('count', changes(), 'jitter_ms', :jitter_ms, 'reason', 'broker_restart'));

COMMIT;
```

9. Trim expired dedup keys so the partial unique index stays bounded (§5.1 publish dedup):

```sql
UPDATE messages
   SET dedup_key = NULL
  FROM streams s
 WHERE messages.dedup_key IS NOT NULL
   AND s.name = messages.stream
   AND messages.published_at + s.dedup_window_ms < :now_ms;
```

10. `PRAGMA wal_checkpoint(TRUNCATE)` to start from a clean, measurable baseline; record pages.
11. `meta.clean_shutdown = '0'` (we are now dirty until a graceful `Close`), committed.
12. Fill the `RecoveryReport`; the caller (#6/#17) emits `server.start`.

`Close(ctx)`: `PRAGMA analysis_limit=400; PRAGMA optimize;` → `wal_checkpoint(TRUNCATE)` →
`meta.clean_shutdown = '1'` → close `ro`, close `rw` → release the `flock` and close the LOCK fd.
Idempotent; safe to call after a failed `Open`.

Recovery edge cases and their handling:

| Edge case | Handling |
|---|---|
| `abs(random())` overflows on `-2^63` (SQLite raises "integer overflow") | use `(random() & 0x7fffffff)`, never `abs(random())` |
| `x % 0` yields `NULL` in SQLite, and `visible_at` is `NOT NULL` | the `CASE WHEN :jitter_ms > 0` guard above; `ReclaimJitter = 0` ⇒ `visible_at = now`, which is what the model suite (#13) and crash harness (#8) always use |
| Reclaimed row had a long `extend` pushing `visible_at` far out | still reset to `now + jitter`: T9 says a restart voids every lease, and no client can hold a live connection across a restart |
| A row is READY with `visible_at` in the past (mid-backoff at crash) | untouched — it is already correct, and rewriting it would erase the backoff |
| Fresh database (no prior open) | not "unclean": step 4 distinguishes "meta row created in this Open" from "marker missing" |
| `quick_check` clean but `foreign_key_check` dirty | only run `foreign_key_check` under `--fsck`; report as `ErrCorrupt` with the offending table |
| Data dir on a filesystem where `flock` is a no-op (NFS) | cannot be detected reliably; `doctor` (#30) warns on non-local `statfs` type, docs state the requirement |
| Second `Open` while the first still holds the lock | `ErrDataDirLocked`, with the holder line — see transcript below |
| Reclaim of a very large pending set (100k rows) | single indexed `UPDATE`, benchmarked; §12 budgets ≤ 2 s for the whole recovery |
| `SIGKILL` between step 8 and step 11 | harmless and idempotent: reclaim is `state=1 → state=0`, so re-running finds nothing; the marker stays `0` so the next open re-checks |

```
error: database schema is newer than this binary
  found:    schema_version 3        supports: schema_version 1
  why:      forward-only migrations; a newer messq wrote this directory
  next:     upgrade messq to >= the version that wrote it, or restore a backup

$ messq serve --data-dir /srv/messq
error: durability pragma read back with an unexpected value
  pragma:   synchronous=1 (NORMAL), want 2 (FULL)
  why:      --durability=full promises a 2xx survives power loss; NORMAL does not fsync on commit
  next:     messq doctor --data-dir /srv/messq    # prints live pragma values per connection
```

Forensic access — the reason D1 chose SQLite — must work with the daemon down, and a test asserts
it: `sqlite3 -readonly messq.db "PRAGMA user_version;"` prints the schema version, and
`SELECT event, count(*) FROM events GROUP BY 1` works on a live file.

## Acceptance criteria

- [ ] `store.Open` on an empty directory creates `messq.db` at schema version 1 with all seven
      §4.2 tables and all nine indexes; a normalized `sqlite_schema` dump matches
      `testdata/schema_v1.golden` byte for byte.
- [ ] All tables are `STRICT`: writing a `TEXT` value into `messages.size` returns an error rather
      than coercing.
- [ ] The data directory is created `0700` and `messq.db` `0600` regardless of the process umask;
      `Open` refuses with `ErrDataDirPerms` when either has group/other bits, and the error names
      the exact `chmod` to run.
- [ ] A second `Open` against the same data directory fails with `ErrDataDirLocked` and reports
      the holder's pid; it succeeds after the first `Close`.
- [ ] On **every** connection of **both** pools (verified on pooled connections, not just the
      first), read-back gives `journal_mode=wal`, `synchronous=2` under `--durability=full`
      (`1` under `relaxed`), `foreign_keys=1`, `busy_timeout=5000`, and `query_only=1` on the
      read pool.
- [ ] A forced pragma mismatch makes `Open` fail with `ErrPragmaMismatch` before any listener or
      goroutine exists; the daemon does not start.
- [ ] A data directory whose `meta.schema_version` exceeds the binary's is refused with
      `ErrSchemaTooNew`, the DB is left byte-identical, and the message names the required action.
- [ ] Editing an already-applied migration file is refused with `ErrMigrationDrift`.
- [ ] `Open` is idempotent: opening, closing and reopening a populated directory leaves
      `schema_version`, `node_id` and `created_at` unchanged.
- [ ] `PRAGMA user_version` equals `meta.schema_version` after migration; a hand-edited mismatch
      refuses to start.
- [ ] `node_id` is a ULID minted once at creation and stable across every subsequent open.
- [ ] Recovery of a dirty data directory flips every `INFLIGHT` delivery to `READY` with
      `visible_at ∈ [now, now+jitter]`, leaves **`attempts` unchanged** (D6/T9), and reports the
      exact count in `RecoveryReport.Reclaimed`.
- [ ] Recovery writes a `recovery.reclaimed` row into `events` **in the same transaction** as the
      reclaim `UPDATE`, with `detail.count` equal to the rows changed.
- [ ] A clean `Close` followed by `Open` reports `Unclean == false` and skips the integrity check;
      a `SIGKILL`ed process reports `Unclean == true` and runs `quick_check`.
- [ ] `quick_check` failure yields `ErrCorrupt`, a `storage.fatal` ERROR log, a non-zero exit, and
      **no** repair attempt.
- [ ] Expired dedup keys are `NULL`ed at startup according to each stream's `dedup_window_ms`;
      unexpired keys are untouched.
- [ ] `TakeWriter()` returns the `rw` handle once; the second call returns `ErrWriterTaken`.
- [ ] Read-pool queries complete while the `rw` handle holds an open `BEGIN IMMEDIATE`
      transaction (WAL readers never block the writer).
- [ ] `go build -tags cgosqlite ./...` compiles and the full `internal/store` suite passes under
      that tag in a dedicated CI matrix job.
- [ ] `internal/store` coverage is ≥ 85 % (the floor from #2), and no `time.Now()` call exists
      outside the `Clock` seam (lint from #2).
- [ ] Recovery of a directory with 100 000 in-flight deliveries completes in ≤ 2 s on the
      reference machine (§12), with the measured number recorded in the PR.

## Test plan

All store tests run against **real files in `t.TempDir()`, never `:memory:`** — `:memory:`
has no WAL, no fsync, no permissions and no crash behaviour, so it would test nothing this issue
is about. `-race` everywhere; no `time.Sleep` (lint-enforced by #2); timing via the `Clock` seam
from #3 and `testing/synctest` where a bubble is needed.

**Unit — schema & migrations** (`migrate_test.go`)
- Golden schema dump — normalized `SELECT type,name,sql FROM sqlite_schema ORDER BY name` vs.
  `testdata/schema_v1.golden`; this golden is the artefact #34 inherits and freezes.
- `STRICT` enforcement: a typed-mismatch insert per table returns an error.
- Fresh open → version 1; reopen → no-op with `schema_applied_at` unchanged.
- `ErrSchemaTooNew` (`meta.schema_version=999`): refusal **and** a byte-identical file afterwards.
- `ErrMigrationDrift`: mutate a migration in a test fixture FS, assert refusal.
- One-transaction property: a fixture FS with a deliberately invalid `0002` leaves the DB at
  version 1 with no partial objects.
- `user_version` mirrors `meta.schema_version`; a hand-edited mismatch refuses.
- Statement-splitting regression: a migration with `;` inside a string literal applies correctly.

**Unit — pragmas** (`pragma_test.go`)
- Read-back on **pooled** connections: force `ReadPoolSize` simultaneous in-flight queries so
  every pooled connection is created, then assert the expectation set on each via `db.Conn(ctx)`.
- `relaxed` yields `synchronous=1` plus the startup banner; `full` yields `2`.
- Negative: an expectation of `FULL` against a DSN requesting `NORMAL` ⇒ `ErrPragmaMismatch`
  from `Open`, before any goroutine starts.
- `foreign_keys=1` is *live*: deleting a `streams` row cascades `stream_seq` — the concrete proof
  the pragma is not merely reported.
- The read pool is genuinely read-only: an `INSERT` on `ro` fails with a `query_only` error.
- WAL non-blocking: a read completes while `BEGIN IMMEDIATE` is open on `rw` (`synctest`, no
  sleeps).

**Unit — data directory** (`datadir_test.go`)
- Umask-proof creation (`syscall.Umask(0)` then `Open`) → `0700`/`0600`.
- Broad-permission and foreign-owner refusals, with the user-facing error text asserted.
- Lock contention in-process and across two helper subprocesses; the holder pid appears in the
  error; the lock releases on `Close` and on process death.

**Unit — recovery** (`recovery_test.go`)
- Table-driven fixture builder seeds `deliveries` with READY/INFLIGHT rows at assorted
  `attempts`/`visible_at`/`generation`; recovery runs; the whole table is diffed with `go-cmp`
  against the expected post-state. This asserts T9 exactly: `attempts` unchanged, `state` flipped,
  `visible_at` in window, `delivered_at` cleared, `last_reason='broker_restart'`.
- `ReclaimJitter=0` → fully deterministic post-state (the mode #13 and #8 use).
  `ReclaimJitter=1s` over 10 000 rows → `visible_at ∈ [now, now+1000)` with a non-degenerate
  distribution (guards the `abs(random())` overflow and the `% 0 → NULL` traps).
- Event co-commit: exactly one `recovery.reclaimed` row with matching `detail.count`; a forced
  commit failure leaves **neither** the update nor the event.
- Marker matrix: clean close → clean open, no check; `SIGKILL` → unclean open + `quick_check`;
  fresh dir → clean.
- Corruption: flip bytes in a page of a copied DB ⇒ `ErrCorrupt` + `storage.fatal` + no mutation.
- Dedup trim: only expired keys are `NULL`ed, and the partial unique index accepts a re-publish
  of a trimmed key.
- Idempotence: running recovery steps 8–11 twice yields an identical end state.

**Crash (lite)** — a `TestMain`-driven helper subprocess writes rows and is `SIGKILL`ed at
randomized points; the parent reopens and asserts `quick_check` clean, no torn rows, and all
committed rows present. Seed of the full harness in **#8**; deliberately small here.

**Property** (`rapid`) — a light machine over `{open, write deliveries, close-clean,
kill-and-reopen}` asserting `schema_version` monotone, `node_id`/`created_at` immutable,
`attempts` never decreasing across a reopen, and no `INFLIGHT` row surviving an open. The full
model-based suite is #13; this is the storage-shaped subset that can exist today.

**CI matrix & benchmarks** — the same suite under `-tags cgosqlite` with `CGO_ENABLED=1` in a
dedicated job (D1 requires it exercised at least weekly; #2's nightly lane hosts it), plus
`CGO_ENABLED=0 go build ./...` to prove the default binary stays static.
`BenchmarkRecovery/{1k,10k,100k}_inflight` gates recovery at ≤ 2 s for 100k, and
`BenchmarkOpenFresh`/`BenchmarkOpenClean` set the startup baseline #6 and #8 compare against;
published numbers state hardware and durability mode (§12 honesty rule).

**Not tested here:** commit batching and fsync accounting (#6), publish/dedup DML (#7), the
three-valued ledger oracle (#8), the closed event vocabulary golden (#19), cross-version upgrade
fixtures (#34).
