## Context

PLAN.md sells one thing above all others: **answerability**. §1.2 promises that every state
transition is durably recorded, D11 makes the `events` table the source of truth with logs and
metrics as projections, and D12 states the security position bluntly — *"the in-transaction events
table is the audit trail."*

That audit trail has a shelf life. §4.5 trims it (`--event-retention` 72 h, `--event-max-rows` 5 M),
#30's `doctor` tells operators to tighten it when `events` exceeds 40 % of the database, and #35's
capacity guidance shows how to quarter event volume by dropping to 24 h. All of that advice assumes
the history is disposable. For a class of user it is not: *"a webhook didn't get processed last
Tuesday and we cannot prove what happened"* (§1.1) is the pitch, and **last Tuesday is outside a 72 h
window**. D15 lists audit export as phase 2 for exactly this reason; §14 puts it in M9.

Two artefacts, one format:

1. **`messq events export`** — a chunked, resumable, filterable NDJSON dump of the events table,
   optionally gzipped, self-describing (header/footer/digest), runnable against a live daemon **or**
   offline against a data dir or a `messq backup` snapshot. What you run *before* shrinking
   retention, and what answers a one-off auditor request.
2. **`--audit-sink`** — a daemon-side durable tailer that continuously appends terminal and admin
   events to a rotated NDJSON file, so long-term history accumulates without anyone remembering to
   run anything, and the 72 h in-database window stops being a data-loss decision.

Governing PLAN.md material:

- **§9 / D11** — one closed vocabulary across three surfaces. The archive is a fourth surface of the
  *same* rows; it must not invent a fourth field schema.
- **§9.2 + `docs/log-schema.md`** (#19) — the versioned operator contract. An archive line **is** a
  log-schema line; that is the whole "a SIEM ingests it without custom tooling" claim.
- **§4.5 Retention** — the trim this feature exists to survive, and the `retention.blocked`
  precedent: *a stuck consumer blocks deletion loudly rather than silently losing data.* §6 applies
  that precedent to the sink.
- **§5.2 I10** (folding events reproduces state), re-applied to an exported file as the new
  invariant; **I11** — every buffer, batch, hold and file series here is bounded.
- **D12** — we do **not** resurrect the hash-chained audit trail or Ed25519 checkpoints D12 rejected.
  A whole-file digest is transport integrity, not tamper evidence, and the docs say so.
- **D15 / §14 M9** — *"each feature ships with a new invariant, events, metrics, docs — or it does
  not ship."*
- **§3.2 goroutine census** — this issue adds the first new goroutine since 1.0 (the sink tailer,
  present only when `--audit-sink` is set). That is a PLAN amendment, flagged as one.

**Why this is an S.** Almost nothing here is new machinery. #20 froze the `type`-framed NDJSON line
format *specifically* so an export could reuse it ("a truncated audit export must also be able to say
something went wrong mid-stream, so #42 inherits this framing rather than inventing a second one"),
froze the `after_id` pagination that makes an export resumable, and shipped the read layer. #8
shipped the exhaustive I10 fold arms this reuses verbatim. #17 shipped the component lifecycle and
the SIGHUP reload registry the sink plugs into. The new code is a file writer with rotation, a
cursor, and one CLI verb.

## Scope

### In scope

- **`messq events export`** — filters, `--after-id` resume, `--out`/`--gzip`, page-walking against a
  daemon (`--addr`) or offline (`--data-dir`), `.part`+rename atomicity, progress on stderr, digest
  sidecar, exit-code contract.
- **The `messq.events.v1` archive format**: `export.header`, `event`, `gap`, `export.footer` (and
  `sink.open`/`sink.close`) line types layered on #20's framing; documented in `docs/log-schema.md`.
- **`--audit-sink`** and its flag family: the tailer goroutine, cursor recovery, size/time rotation,
  rotated-file retention and gzip, SIGHUP reopen, partial-line crash repair, disk-pressure and error
  policies.
- **The retention interlock** (§6): the event trim floor honours the sink cursor, bounded, with a
  loud `audit.sink.overrun` when the bound wins — an amendment to #27's janitor.
- **Reading archives back**: `messq verify --export FILE` (fold equivalence / filter completeness,
  reusing #8's fold) and `messq trace --from-export FILE <id>` (the #20 renderer, from a file alone).
- **The new invariant** and its checker in `internal/model`, per §5.2's rule that each invariant has
  a stable id, a checker and a named test.
- **Two events** (`audit.sink.gap`, `audit.sink.overrun`), an `audit` class column on #19's
  vocabulary table, and the single `admin.action` marker an export emits.
- **Metrics** for sink health and lag (registered in #21's catalogue) plus `AuditSinkStalled` /
  `AuditSinkGap` in `contrib/prometheus/alerts.yml`.
- **Docs**: an `OPERATIONS.md` section (export-then-shrink runbook, SIEM ingestion, restore/replay),
  the honest statement of what the digest proves, and the packaging note for a writable sink dir.

### Out of scope

- Event vocabulary, in-transaction write path, `Detail` sanitisation, the fan-out Hub, the trim
  itself → **#19** (janitor: **#27**). Consumed here; two kinds and one trim-floor constraint added.
- `GET /v1/events`, its filters, `after_id`, the scan budget, `follow=1`, the `type` framing →
  **#20**. The export is a *client* of that route and adds no query capability.
- The `trace` renderer and `trace.Assemble` → **#20**; this issue only supplies a file-backed source.
- The `verify` surface, exit codes and the I10 fold arms → **#8**; one flag and one input adapter are
  added, and the fold must not be forked.
- Metric registry, exposition, collector tiers, dashboard → **#21**; names proposed here.
- `pkg/client` → **#22**; cobra chassis, hint registry, completions → **#23**/**#24**.
- Database backup/restore and `doctor`'s findings engine → **#30** (one finding and one hint added).
- Hardened-unit changes (`LogsDirectory=messq`) → **#36**, amended here for its owner to review.
- **Importing an archive back into `events`** — explicitly refused, §7. No issue owns it.

## Design proposal

> A proposed starting point, not a mandate — except the five **_decisions_**, which are cheap now and
> expensive once an archive format sits on somebody's compliance storage. Two items amend merged work
> (#27's trim floor, §3.2's census) and are flagged for their owners.

### 1. One format, two producers

```
messq.events.v1   NDJSON, UTF-8, LF-terminated, one JSON object per line
```

```jsonc
{"type":"export.header","format":"messq.events.v1","schema_version":1,"binary":"1.0.0",
 "node_id":"01J8ZQ4K2M9V0X7Y3B5N6C8D1E","exported_at":1764633600000,
 "source":{"kind":"daemon","addr":"unix:///run/messq/messq.sock"},
 "range":{"after_id":0,"since":1764547200000,"until":1764633600000},
 "filters":{"stream":"orders","event":["msg.dead"]},"filtered":true,
 "horizon":{"min_id":88001,"min_ts":1764460800000},"durability":"full"}
{"type":"event","id":91002,"ts":1764547948190,"event":"msg.dead","stream":"orders",
 "consumer":"worker","subject":"orders.created","seq":10493,
 "msg_id":"01J8ZQ4K2M9V0X7Y3B5N6C8D1E","attempt":5,"trace_id":"4bf92f35…",
 "detail":{"cause":"max_deliver","reason":"upstream 503","dlq":{"stream":"orders.dlq","seq":7}}}
{"type":"gap","reason":"trimmed_during_export","from_id":91010,"to_id":91480,"ts":1764547961004,
 "hint":"the janitor trimmed rows this export had not reached; export from a backup snapshot"}
{"type":"export.footer","count":4821991,"first_id":88001,"last_id":9210044,
 "complete":false,"gaps":1,"sha256":"9f2c…","finished_at":1764633702113}
```

**_Decision 1: `type:"event"` lines are byte-identical to what `GET /v1/events` returns._** Same
frozen #19 field names, same top-level placement, same `detail`. One `jq` filter works on a history
page, a `--follow` tail, a sink file and an export — that is the entire no-custom-tooling claim, and
the reason #20 put a `type` discriminator on its lines. A golden asserts all three producers agree
byte-for-byte for the same row.

Sink files use the same line types with `sink.open`/`sink.close` in place of header/footer, so
**every rotated sink file is itself a valid archive** that `verify --export` accepts unchanged.

### 2. `messq events export` — surface

```
messq events export [--out FILE|-] [--gzip]
      [--since -7d|RFC3339|unix-ms] [--until …] [--after-id N]
      [--stream S] [--consumer C] [--verb msg.dead,msg.*] [--msg-id ID] [--trace-id T]
      [--page-size N] [--limit N] [--redact-reasons] [--verify] [--progress|--no-progress]
      [--addr ADDR | --data-dir DIR] [--output table|json]
```

```console
$ messq events export --since -30d --until -72h --out /srv/audit/2026-11.ndjson.gz --gzip --verify
exporting events  since 2026-11-02T00:00:00Z  until 2026-11-30T00:00:00Z  (no filter)
  4 821 991 events   1.31 GiB raw / 96.4 MiB gz   61.2s   78 800 ev/s
  range 88001…9210044   0 gaps   complete
  sha256(ndjson) 9f2c4a…   sha256(file) 1d0be7…  → /srv/audit/2026-11.ndjson.gz.sha256
verify: fold equivalence OK — archive folds to the same state as events[88001..9210044]

next  messq verify --export /srv/audit/2026-11.ndjson.gz
      messq serve --event-retention 24h    # safe now: this window is archived
```

```console
$ messq events export --verb dead,term --stream orders --since -24h | jq -r 'select(.type=="event").msg_id'
01J8ZQ4K2M9V0X7Y3B5N6C8D1E
```

Exit codes (§8's contract, inherited from #20/#8): `0` ok · `1` incomplete (a `gap` was written, or
`--verify` failed) · `2` usage · `3` dir/file not found · `5` range matched nothing (a valid empty
archive is still written — that is an answer) · `6` daemon unreachable · `7` permission. `--verify`
without `--out` is exit `2`: verifying requires re-reading what reached the disk. Narration to
stderr, data to stdout (§8), so `--out -` piped into `jq` stays clean.

### 3. The export algorithm

```go
// internal/audit — the page source is an interface, so live and offline modes share every line.
type PageSource interface {
    Page(ctx context.Context, f store.EventFilter) (store.EventPage, error) // #20's shapes
    Horizon(ctx context.Context) (minID, minTS int64, err error)
}

type Exporter struct {
    Src   PageSource
    W     io.Writer     // gzip.Writer or file, wrapped in a two-hasher tee
    Clock clock.Clock
    Opts  ExportOptions // filters, page size, limit, redaction
}

func (e *Exporter) Run(ctx context.Context) (Report, error)
```

Three things make the loop correct:

1. **Walk ascending by `id`, never `ts`.** #19 froze `events.id` as the ordering key because `ts` is
   wall clock and can move backwards (§11's clock-jump family). `--since`/`--until` translate to an
   id range once via `events_ts`; everything after is a PK walk.
2. **`complete:false` is a pagination signal, not an error.** A filtered page can exhaust #20's
   `--event-scan-budget`; the response carries `scanned_to_id`, and the export continues from it —
   more round trips, zero data loss. Treating it as the end of the range is the obvious bug here, and
   a test seeds enough rows to force it.
3. **Watch the horizon.** Trimming removes a *prefix*, so rows already passed cannot vanish behind
   us; rows ahead of the cursor can. After each page, re-read `MIN(id)`: when it exceeds the cursor,
   write a `gap` line with exact bounds, set `complete:false`, carry on. Never a silently shorter
   file.

Constant memory: one page (`--page-size`, default = the server's `--event-query-max-limit`) is
buffered and released; a benchmark asserts flat allocation across sizes.

**Atomicity.** `--out FILE` writes `FILE.part`, then footer → `Sync` → `rename` → `.sha256` sidecar.
A killed export leaves a `.part`, never a truncated archive that looks complete. With `--out -`,
truncation is detectable only by the missing footer — documented, because a pipe cannot be atomic.

**Digests (two, one pass).** The footer `sha256` covers the *uncompressed* NDJSON from header up to
but excluding the footer (survives recompression, validatable while streaming); the sidecar is
`sha256sum` format over the file as it sits on disk. Docs state plainly: **transport integrity, not
tamper evidence** — anyone who can rewrite the archive can rewrite the digest, and D12 declined to
build the thing that would fix that.

**Offline mode.** `--data-dir DIR` (or `--file backup.db`) opens read-only with `query_only(1)`
exactly as #8's `verify` does. This is how you export from a `messq backup` snapshot — the
recommended path for large exports, because a snapshot cannot be trimmed underneath you, so the
horizon race cannot happen at all.

**The one write an export makes (_decision 2_).** Over a daemon, an export enqueues a single
`admin.action` command before the first page (`detail={action:"events.export", since, until, filters,
actor}`). *Who exported the audit trail* is itself an audit question, and D12 answers audit questions
with the events table. One command per export, not per page; the streaming touches only the read
pool. If the store is latched read-only (#6's EIO path) the marker is skipped with a WARN and **the
export proceeds** — forensics during an incident must never require a writable store. Offline exports
cannot emit it, documented rather than papered over (offline access already requires filesystem
access to a 0600 file).

### 4. The sink is a durable tailer, not a fan-out subscriber (**_decision 3_**)

The obvious implementation — register a `Subscriber` on #19's Hub and write what arrives — is wrong.
The Hub is deliberately lossy: §3.2 says overflow "drops loudly", `Publish` is select-default, and
#19 drops whole batches to guarantee the writer is never blocked. **An audit sink that drops is not
an audit sink.** So the sink reads the source of truth instead:

```go
// internal/audit/sink.go — a lifecycle.Component (#17). Never holds a write connection.
type Sink struct {
    ro     *store.Reader   // read pool only
    hint   <-chan struct{} // non-blocking wake from the Hub; a missed hint costs latency, not data
    clock  clock.Clock
    cfg    SinkConfig
    cursor int64           // last id durably written
    f      *os.File
}

func (s *Sink) Start(ctx context.Context) error // open+recover file, derive cursor, spawn tailer
func (s *Sink) Stop(ctx context.Context) error  // final tail read to MAX(id), flush, fsync, close
func (s *Sink) Cursor() int64                   // read by the janitor (§6) and the metric collector
```

Loop: wake (Hub hint, or every `--audit-sink-flush`) → `SELECT … WHERE id > cursor AND <class> ORDER
BY id LIMIT --audit-sink-batch` on the read pool → encode → write → fsync → advance cursor; repeat
while the page is full. Consequences, all wanted:

- **A Hub drop delays the sink; it never loses a line.** The Hub is a wake-up hint; SQLite is the
  data path. This is the most important sentence in the issue.
- **The sink cannot block the writer**: it enqueues no command and holds no write connection. A
  stalled disk under the sink file stalls the sink and nothing else (benchmark-gated).
- **The sink is at-least-once**, like everything else in messq: a crash between write and cursor
  advance replays the tail, and `id` is the dedup key. §6 of PLAN.md's honesty rule applies — we say
  so rather than implying exactly-once.

**Cursor recovery (_decision 4: the file is the cursor_).** On start: `flock` the sink file (a second
daemon on the same path is a startup error, like the data-dir lock in §3.1); if it does not end in
`\n`, a crash cut a line — truncate back to the last newline and log `audit.sink.repair` (discarded
ids are re-read next tick: duplicates, not loss); scan the tail for the last `type:"event"` line and
take its `id`. A `.state` sidecar is a fast path, but **the file always wins**, because the file is
what exists. A brand-new sink records the current `MAX(id)`, then backfills existing matching history
up to `--audit-sink-backfill-max` (1 M) so enabling the sink on a running broker does not produce a
mysteriously empty first file. If a gap is unavoidable (daemon down longer than the trim window),
write a `gap` line, emit `audit.sink.gap` (a real event — the gap is itself in the audit trail) and
increment the counter.

**Rotation.** Size (`--audit-sink-max-bytes`, 128 MiB) or wall clock (`--audit-sink-rotate
none|hourly|daily`, UTC), whichever first, **between records only and after an fsync**: `sink.close`
with range and digest → fsync → rename to `audit-20261202T000000Z.ndjson` → fresh file with
`sink.open` → optional gzip in a one-shot goroutine → prune beyond `--audit-sink-keep`. The cursor is
a property of the *series*, not of one file.

**SIGHUP.** #17's rule is "SIGHUP re-reads every file the daemon was pointed at by a path-valued
flag", so the sink registers a `Reloader` whose `Validate` opens the path and `Apply` swaps the
descriptor — exactly the reopen semantics external `logrotate` needs (`create` + `postrotate
systemctl reload messq`). `copytruncate` is documented as **unsupported**: it races the appender and
loses bytes.

**Lifecycle placement (easy to get wrong).** #17 stops components in exactly the reverse of start
order, and the sink must flush **after** the writer's final commit — so it must start **before** the
writer: `store`(1) → **`auditsink`**(2) → `writer`(3) → `fanout`(4) → sweeper, janitor. Stop order
then runs janitor → sweeper → fanout → writer → **sink** → store, so the last committed event before
SIGTERM reaches the file. The final flush is bounded by `--audit-sink-drain-timeout` (5 s); on
timeout the sink stops where it is and **backfills on the next start** — the table still has every
row, so a slow sink delays the archive, it does not puncture it.

**Failure policy.** `--audit-sink-on-error=degrade` (default): a write error, or free space below
`--audit-sink-min-free-bytes`, stops the sink, emits `disk.degraded` + `audit.sink.gap`, sets
`messq_audit_sink_up 0` and **leaves the broker untouched** — §4.5's rule that a full disk must never
wedge the ack path applies with more force to an optional observability file. `=fatal` exists for
deployments not permitted to run un-audited: it latches like `storage.fatal` (read-only, drain, exit
74). Two values, a documented default, and an explicit note on which one a compliance reviewer picks.

### 5. What the sink writes

`--audit-sink-events` takes `audit` (default), `problems`, `all`, or an explicit #20-style verb list.
`audit` is a new boolean column on #19's generated vocabulary table — a one-file diff plus a
`log-schema.md` golden change, which is the extension mechanism #19 designed.

| Class | Events |
|---|---|
| `audit` | `msg.dead` `msg.term` `msg.ack_stale` `dlq.redrive` `consumer.seek` `consumer.create/update/delete` `stream.create/update/delete/purge` `retention.blocked` `auth.denied` `admin.action` `storage.fatal` `server.*` `recovery.*` `audit.sink.*` |
| `problems` | `audit` + `msg.nak` `msg.timeout` `flow.blocked` `disk.degraded` `api.error` |
| `all` | the whole §9.2 vocabulary, hot path included |

`all` is honest about cost: at 5 000 msg/s that is ~15 000 lines/s and ~2 GiB/hour, and the docs give
that arithmetic (the shape of #35's `event_rows` formula) instead of letting an operator discover it
by filling a disk. `TestEveryEventHasAClass` over `obs.AllEvents()` fails if a new event is
unclassified, so an M9 feature cannot add an event that silently escapes the audit set.

### 6. Retention interlock: the trim floor honours the sink (**_decision 5_ — amends #27**)

Without this the feature has a hole: the sink falls behind (slow disk, degraded state), the janitor
trims by age, and rows are deleted before they were ever written. Silent loss, in the one subsystem
whose purpose is not losing things. §4.5 already solved the identical problem for messages — a
message with an outstanding delivery row is not deleted, and the sweep emits `retention.blocked`.
Apply the precedent:

```go
floor := trimFloorByAgeAndRows(now, cfg)                     // #19/#27
if cfg.AuditSinkHoldRetention && sink != nil {
    if c := sink.Cursor(); c < floor {
        if held(now, c) <= cfg.AuditSinkMaxHold && rows(events) <= cfg.EventMaxRows {
            floor = c                                        // hold the un-archived rows
            emitOnce("audit.sink.overrun", "holding", …)      // rate-limited, WARN
        } else {
            emit("audit.sink.overrun", "bound_won", …)        // ERROR, names the doomed id range
        }
    }
}
```

The hold is **bounded** (I11) by `--audit-sink-max-hold` (1 h) and by the existing `--event-max-rows`
hard bound: an audit sink must not fill the disk any more than a stuck consumer can. When the bound
wins, the loss is announced at ERROR **before** it happens, with the id range and a firing alert —
the difference between an incident and a discovery. `--audit-sink-hold-retention=false` restores
unconditional trimming.

The runbook this creates (`OPERATIONS.md`, and the hint #30's `doctor` prints for its existing
`storage.events_share` finding):

```console
$ messq doctor
  storage.events_share   WARN   events is 61 % of a 4.2 GiB database (--event-retention=72h)
  next: messq events export --until -24h --out /srv/audit/$(date +%F).ndjson.gz --gzip --verify
        then restart with --event-retention 24h
```

### 7. Reading an archive back — and the import that does not exist

**There is no import path into `events`, ever.** D11's guarantee is that an event row committed in
the same transaction as its state change cannot disagree with reality. A row inserted later by a CLI
has none of that provenance and turns the audit trail into a place where someone can write whatever
they like. Restoring the *database* is `messq backup` + stop/copy/start (§4.5); restoring the
*history* means reading the archive.

Reading is cheap, because #20 made `trace.Assemble` a pure function of events:

```console
$ messq trace --from-export /srv/audit/2026-11.ndjson.gz 01J8ZQ4K2M9V0X7Y3B5N6C8D1E
message 01J8ZQ4K2M9V0X7Y3B5N6C8D1E   stream=orders subject=orders.created seq=10493
trace 4bf92f35…  (from archive 2026-11.ndjson.gz; message no longer stored)

  09:14:02.114  publish
  09:14:02.190  deliver   worker  attempt 1/5           deadline 09:14:32.190
  …
  09:19:08.190  dead      worker  attempt 5/5  cause=max_deliver  reason="upstream 503"
                                              → orders.dlq seq 7

  duplicates: 4 — all accounted for (2× timeout, 2× nak)
```

The archive source is a single-pass, id-ordered streaming filter bounded by `--trace-max-events`, so
the flagship output works with no daemon, no database and no network — the state an auditor or a
post-mortem is usually in. `messq events --from-export FILE --verb dead` does the same for listing.

**The new invariant**, proposed as **I12** (number provisional — #37–#41 also add invariants and M9
collates the final numbering):

> **I12** — for an *unfiltered* export over id range `[a,b]`, folding the archive through the I10
> fold yields the same `model.View` as folding `events` over `[a,b]`. For a *filtered* export, the id
> set in the archive equals the id set in `events` matching the same filter over `[a,b]`, and every
> `gap` range is disjoint from both.

```
messq verify --export FILE [--data-dir DIR] [--output table|json]
```

Without `--data-dir` it checks the archive alone: framing (every line parses; exactly one header;
exactly one footer, last), strict id monotonicity, digest match, well-formed ordered gaps, and fold
coverage of every event present — reusing #8's `exhaustive`-linted switch, because **a second fold
implementation would be the bug this invariant exists to catch**. With `--data-dir` it runs I12
proper. Exit codes are #8's (`0` clean, `1` violations). `export --verify` re-reads the written file
and calls the same code: verifying a buffer proves nothing about a disk.

A filtered archive cannot fold to state (an archive of only `msg.dead` folds to nothing meaningful);
`--verify` reads `filtered:true` from the header, runs the completeness check instead, and **prints
which check it ran** — silently running the weaker check is how a compliance report ends up meaning
less than its reader thinks.

**Redaction.** `--redact-reasons` replaces `detail.reason` with `"[redacted]"` and sets
`reason_redacted:true`, because #25's `--exec` puts the worker's first 4 KiB of stderr in `reason`
and stderr routinely contains fragments of the data being processed. Redaction is restricted to
**fold-irrelevant keys**, so a redacted archive still satisfies I12 (asserted by a test comparing
folds with and without). Bodies never enter events at all (#19's redaction + canary test).

### 8. Flags (`messq serve`)

| Flag | Env (`MESSQ_…`) | Default | Meaning |
|---|---|---|---|
| `--audit-sink` | `AUDIT_SINK` | `""` | Path to the append-only NDJSON file. Empty = off: **no goroutine, no cost** |
| `--audit-sink-events` | `…_EVENTS` | `audit` | `audit` \| `problems` \| `all` \| explicit verb list |
| `--audit-sink-flush` | `…_FLUSH` | `200ms` | Max time a committed event waits before write+fsync |
| `--audit-sink-batch` | `…_BATCH` | `1000` | Rows per tail read/write batch (I11) |
| `--audit-sink-sync` | `…_SYNC` | `batch` | `batch` = fsync before advancing the cursor · `none` |
| `--audit-sink-max-bytes` | `…_MAX_BYTES` | `128MiB` | Size rotation; `0` = never |
| `--audit-sink-rotate` | `…_ROTATE` | `daily` | `none` \| `hourly` \| `daily` (UTC) |
| `--audit-sink-keep` | `…_KEEP` | `14` | Rotated files retained; `0` = all |
| `--audit-sink-compress` | `…_COMPRESS` | `true` | gzip rotated files |
| `--audit-sink-min-free-bytes` | `…_MIN_FREE_BYTES` | `64MiB` | Stop writing below this on the sink's filesystem |
| `--audit-sink-on-error` | `…_ON_ERROR` | `degrade` | `degrade` (broker unaffected) \| `fatal` (latch, exit 74) |
| `--audit-sink-hold-retention` | `…_HOLD_RETENTION` | `true` | Trim floor never passes the sink cursor (§6) |
| `--audit-sink-max-hold` | `…_MAX_HOLD` | `1h` | Bound on that hold |
| `--audit-sink-backfill-max` | `…_BACKFILL_MAX` | `1000000` | Rows a newly enabled sink pulls from history |
| `--audit-sink-drain-timeout` | `…_DRAIN_TIMEOUT` | `5s` | Final flush budget on shutdown |

The §4.4 `server.start` banner prints the sink state (path, class, rotation, error policy) — §1.2's
"durability modes are named and printed at startup" applied to the audit path, so nobody discovers
three months later that the sink was never configured.

### 9. Events, metrics, authorization

Two new `obs.Kind`s (fold arms added to #8's switch; both fold to no state change):

| Event | Level | Detail |
|---|---|---|
| `audit.sink.gap` | ERROR | `{from_id,to_id,count,reason:"trim_overtook"\|"write_error"\|"disk_full"\|"restart_gap"}` |
| `audit.sink.overrun` | WARN→ERROR | `{cursor,floor,held_ms,rows,outcome:"holding"\|"bound_won"}` |

Metrics — process-level, **no labels** (§9.4's cardinality rule): `messq_audit_sink_up`,
`_last_id`, `_lag_events` (← the SLI), `_lag_seconds`, `_written_total`, `_bytes_total`,
`_rotations_total`, `_errors_total`, `_gap_events_total` (alert on any increase). `alerts.yml` gains
`AuditSinkStalled` (`up == 0` for 5 m or `lag_seconds > 300`) and `AuditSinkGap`; #21's anti-rot test
covers them.

Authorization inherits #20 unchanged: unfiltered `/v1/events` requires `admin`; with `stream=`, a
`consume` token on that stream suffices and results are filtered to it regardless of what was asked.
Events are **not** less sensitive than payloads (`msg.nak.detail.reason` is worker stderr), so the
posture is closed and `--redact-reasons` exists for archives leaving the host. Offline mode is
governed by filesystem permissions (§10), identically to `verify` and `sqlite3 messq.db`. The sink
file is `0640`; #36's hardened unit gains `LogsDirectory=messq` so `/var/log/messq` is writable under
`ProtectSystem=strict`; `doctor` warns if the sink path is inside `--data-dir` (it inflates `backup`
and confuses disk-ETA arithmetic) or on a tmpfs.

### 10. Edge cases, decided

| Case | Handling |
|---|---|
| Janitor trims ahead of a running export | `gap` line with exact bounds, `complete:false`, exit `1`; the hint recommends exporting from a `backup` snapshot, which avoids the race entirely |
| `--since` predates the retention horizon | Header carries `horizon`; stderr warns "events before T were trimmed; this archive starts mid-history"; exit `0` if nothing was lost *during* the run |
| `events.id` has gaps (rolled-back savepoints consume rowids, #19) | Legal and expected. Completeness is set membership against the source, never `last-first+1`. A test seeds a rejected command mid-batch |
| `ts` moves backwards (clock jump) | Ordering is by `id`; `--since`/`--until` become an id range once, so a jump cannot reorder or drop lines |
| Export killed mid-run | `FILE.part` remains, no `FILE`; rerun, or resume with `--after-id`. The archive never exists partially |
| `--out -` truncated by a broken pipe | Missing footer is the signal; `verify --export` reports `stream truncated`. SIGPIPE exits `0` per §8 |
| Empty range | Valid header + footer, `count:0`, exit `5` |
| Store latched read-only (EIO) | Export works from the read pool; the `admin.action` marker is skipped with a WARN — the journal *is* the incident evidence |
| Sink file deleted or moved (`rm`, unmanaged logrotate) | Appends continue to the unlinked inode until SIGHUP; a stat check each flush detects the inode change, reopens, logs `audit.sink.repair`. Docs: use `create`, not `copytruncate` |
| Crash mid-line | Trailing partial line truncated at the last `\n`; discarded ids re-read (duplicates, not loss) |
| Two daemons, one sink path | `flock`; the second refuses to start with the data-dir lock's error shape |
| Sink filesystem full | `degrade`: sink stops, `disk.degraded` + `audit.sink.gap`, `up=0`; publishes, acks and DLQ writes continue (§4.5). `fatal` mode latches instead |
| Sink enabled on a long-running broker | Backfills to `--audit-sink-backfill-max`, then `sink.open` states the true start id — never a mysteriously empty first file |
| Daemon down longer than `--event-retention` | Unavoidable gap: `audit.sink.gap` `reason:"restart_gap"` with exact bounds on the next start |
| Sink lag grows without bound | Retention hold (§6), bounded; when the bound wins the loss is announced before it happens |
| `--durability=relaxed` | The sink cannot be more durable than its source; docs state the last commits may be missing from both |
| Rotation name collision (clock moved back) | `-1`, `-2` suffix; rotation never overwrites |
| Control chars / ANSI escapes in a `reason` | Already sanitised at `Event` construction (#19's `obs.sanitize`); a fuzz target re-asserts it at the encoder |
| Unknown `detail` key from a future #37–#41 event | Passed through verbatim; the fold switches on `event`, not `detail`, so parsing, folding and rendering are unaffected |
| Archive gzipped afterwards by an external tool | Footer digest still validates (uncompressed bytes); the sidecar does not, and the docs say which is which |
| Export against a draining daemon (#17) | Pages answer until the listener closes; the CLI reports the partial range with `complete:false` and the resume command |

### Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| A dedicated `GET /v1/events/export` streaming route | Paginating #20's `after_id` is gapless, resumable and adds zero wire surface; 10 k round trips over a Unix socket is seconds | Export over TCP+TLS where per-request overhead dominates, measured |
| Hash-chained records / signed checkpoints (plan-08) | D12 rejected them by name for this ICP; a whole-file digest plus filesystem permissions is the honest tier | A genuine tamper-evidence requirement, with an ADR |
| Direct S3 / object-lock upload | `messq events export \| aws s3 cp -` is one documented line and no dependency (§13's budget) | Probably never |
| CEF / LEEF / OTLP output | §13 refuses the OTel SDK; NDJSON with a frozen schema is what modern SIEMs ingest | Three users on a SIEM that cannot read NDJSON |
| Importing an archive into `events` | Structurally destroys D11's guarantee (§7) | Never |
| Sink fed directly from the Hub | Lossy by design (§3.2) | Never |
| Per-stream sink files | Multiplies handles, rotation state and failure modes for a `jq`-able filter | Demonstrated demand with a rotation story |

## Acceptance criteria

- [ ] Archive `type:"event"` lines are **byte-identical** to the same rows from `GET /v1/events` and
      from `follow=1` (one golden asserts all three producers agree).
- [ ] Exactly one `export.header` first and one `export.footer` last; the footer carries `count`,
      `first_id`, `last_id`, `complete`, `gaps`, `sha256`; the `.sha256` sidecar passes `sha256sum -c`.
- [ ] A 10 M-row export runs in constant memory (flat allocations across `--page-size`) and
      round-trips: `messq verify --export --data-dir …` reports fold equivalence.
- [ ] **I12 holds**: for an unfiltered export over `[a,b]` the archive folds to the same
      `model.View` as `events[a..b]`; mutating, deleting or reordering one line fails the check and
      names the offending id.
- [ ] A filtered export is detected via `filtered:true`, verified by set equality, and `verify`
      prints which of the two checks it ran.
- [ ] `--verify` requires `--out` (else exit `2`) and re-reads the file from disk, not a buffer.
- [ ] Export is resumable: interrupting at any page and rerunning with `--after-id last_id` yields
      the same id set as an uninterrupted run — no gaps, no repeats.
- [ ] A page with `complete:false` (scan budget exhausted) continues from `scanned_to_id`; a seeded
      >200 k-row filtered range proves it.
- [ ] Trimming during an export produces a `gap` with exact bounds, `complete:false` and exit `1` —
      never a silently shorter archive.
- [ ] `--out FILE` is atomic: SIGKILL mid-export leaves `FILE.part` and no `FILE`; the sidecar is
      written only after a successful rename.
- [ ] Offline `--data-dir` mode produces a byte-identical archive to daemon mode for the same range,
      opens the DB read-only, and works with the daemon stopped.
- [ ] Exit codes: `0` ok · `1` incomplete/violation · `2` usage · `3` missing dir/file · `5` empty
      range (valid archive still written) · `6` unreachable · `7` permission.
- [ ] With `--audit-sink` under load with rotation firing repeatedly, `{ids in the file series} ==
      {ids in events matching the class}` — **zero dropped terminal events**.
- [ ] The sink enqueues no writer command (a `cmdCh` counter is zero across a scripted workload,
      excluding an export's single `admin.action` marker) and reads only from the read pool.
- [ ] Publish throughput with the sink enabled is within 2 % of disabled, and a sink stalled on a
      blocked filesystem leaves `messq_commit_duration_seconds` unchanged.
- [ ] Forcing the fan-out ring to overflow loses nothing from the file series: a Hub drop delays the
      sink only.
- [ ] SIGKILL mid-write leaves a partial trailing line; on restart the file is truncated at the last
      `\n`, the cursor is re-derived from the file, and the series contains every id at least once.
- [ ] Rotation never splits a record: every rotated file parses standalone, starts with `sink.open`,
      ends with `sink.close`, and is accepted by `verify --export`.
- [ ] A `logrotate` cycle (`create` + `postrotate reload`) under load loses no line; `copytruncate`
      is documented as unsupported and detected.
- [ ] Retention interlock: with the sink stalled, the janitor does not trim past the sink cursor
      within `--audit-sink-max-hold`; when the bound or `--event-max-rows` wins,
      `audit.sink.overrun` is emitted at ERROR **before** deletion, naming the id range.
- [ ] The hold is bounded in both time and rows (I11), and `--audit-sink-hold-retention=false`
      restores unconditional trimming.
- [ ] A full sink filesystem degrades the sink only — publishes, acks, naks and DLQ writes keep
      working, `messq_audit_sink_up` is `0`; `--audit-sink-on-error=fatal` latches and exits `74`.
- [ ] Two daemons on one sink path: the second fails to start with a lock error naming the holder.
- [ ] Shutdown ordering: the last event committed before SIGTERM is in the file; on drain-timeout
      expiry the next start backfills it with no gap.
- [ ] `messq trace --from-export FILE <id>` renders the #20 flagship timeline with no daemon and no
      database, byte-identical modulo the `(from archive …)` header line.
- [ ] `--redact-reasons` removes `detail.reason` and preserves I12 (identical fold with and without).
- [ ] `TestEveryEventHasAClass` fails on an unclassified event; both new events have fold arms in
      #8's exhaustive switch.
- [ ] `docs/log-schema.md` documents all line types and regenerates cleanly under the CI diff gate;
      `OPERATIONS.md` carries the export-then-shrink runbook; `doctor`'s `storage.events_share` hint
      names the export command.
- [ ] Every proposed metric is in #21's catalogue and in the shipped alerts/dashboard, with #21's
      anti-rot test green; no metric carries a `subject` or id label.
- [ ] `--audit-sink` unset ⇒ no goroutine, no file handle, no measurable cost (goroutine count equals
      1.0's census).
- [ ] Coverage floors from #2 pass; no `time.Sleep` in tests; no `time.Now()` outside the Clock seam.

## Test plan

Per §11 / D13: `-race` everywhere, real SQLite files in `t.TempDir()` (never `:memory:`), timing via
`testing/synctest` and the Clock seam, every fixed bug landing with a committed reproduction artifact.

**Unit — `internal/audit` (fixture-driven)**
- Encoder goldens for every line type: one object per line, LF-terminated, no embedded newline even
  when a `reason` contains one, deterministic key order (#19's ordered `Detail`).
- Header/footer construction (filters echoed, `filtered` correct, horizon recorded); both digests
  over a fixture; gzip and plain agree on the footer digest.
- Decoder errors, each typed and never a panic: truncated file, missing footer, two headers, footer
  not last, unknown `type`, unknown `detail` key, 1 MiB line, invalid JSON.
- Cursor derivation: empty file, mid-line end, clean end, sidecar disagreeing (file wins), no sidecar.

**Unit — exporter (fake `PageSource`)**
- Pagination totality across page sizes and ranges; `complete:false` continuation from
  `scanned_to_id`; horizon advancing mid-run → exactly one correct `gap`; `--limit` truncation.
- `.part`+rename lifecycle including a failure injected before the footer (no `FILE` created).

**Property (`pgregory.net/rapid`)** — where the real bugs are
- **Export completeness**: random publish/fetch/nak/timeout/ack/seek/purge against a real store, then
  an export over a random id range with random filters and page sizes → the id set equals the SQL
  answer for the same predicate; gap ranges are disjoint from it.
- **I12 fold equivalence**: fold archive vs fold table, compared with `go-cmp`; a mutation operator
  (drop / duplicate / reorder / edit one line) must make it fail.
- **Sink gaplessness**: random production interleaved with rotations, flush timings, injected Hub
  drops and restarts → the series covers every matching id; every missing subrange is preceded by a
  `gap`; duplicates occur only at restart boundaries.
- Failfiles committed to `testdata/regressions/`.

**Deterministic timing (`testing/synctest`)** — flush cadence, day-boundary rotation, hold expiry at
`--audit-sink-max-hold`, drain timeout: an hour of sink behaviour in microseconds of wall clock.

**Integration — real `messq serve`, real files**
- Sink under sustained publish/nak/dead load with rotation and `--keep` pruning: id-set equality
  against the events table; every rotated file independently valid.
- `logrotate` (`create` + reload) under load; `copytruncate` detected and warned about; deleted or
  moved sink file → inode change detected, reopen, `audit.sink.repair`.
- Retention interlock: stalled sink + aggressive `--event-retention` → hold observed, then the
  bound-won path with `audit.sink.overrun` ordered *before* deletion (asserted by event order, not
  timing).
- Shutdown ordering; export racing the janitor (gap) vs export from a `backup` snapshot of the same
  moment (no gap); export against a read-only-latched store (succeeds, marker skipped).
- Every transcript in this issue executes in CI (#18's harness, #26's testscript suite).

**Crash (extends #8's harness)**
- SIGKILL at named fault points (`MESSQ_FAULTS`, tag `messq_fault`): mid-line, between write and
  fsync, between fsync and cursor advance, mid-rotation, mid-gzip. After restart: file parses, id set
  complete, duplicates only at the boundary, `verify --export` clean.
- SIGKILL mid-export → `.part` only; resume yields the same id set.
- The whole existing crash suite re-run with `--audit-sink` on: three-valued ledger verdicts must be
  identical, proving the sink never changes broker outcomes.

**Fault injection (#32's matrix)** — ENOSPC on a loopback filesystem under the sink (degrade, broker
keeps acking, recovery without restart; `fatal` mode latches and exits `74`); EIO on sink write; a
read-only sink directory at startup (clean error, not a panic); clock jump backwards across a
rotation boundary.

**Fuzz** (60 s/target per PR, corpus committed) — the archive decoder against arbitrary bytes (no
panic, no unbounded allocation on a crafted line length); the encoder against arbitrary `Detail`
values (always one valid line, never a control character); the shared `--since`/`--until`/`--verb`
parsers re-fuzzed at this entry point.

**Golden** — the `log-schema.md` binding test (every emitted field documented and vice versa); the
three-producer byte-identity test; CLI transcripts and exit codes for `export`, `verify --export`,
`trace --from-export`.

**Benchmarks (#31 publishes the numbers)** — `BenchmarkExport/{1M,10M}` (rows/s, bytes/s, plain and
gzip, allocation flatness); `BenchmarkPublishWithSink/{off,audit,problems,all,stalled-disk}` — the
writer-isolation gate and a second data point for §12's "event journaling overhead" line;
`BenchmarkFoldArchive/10M`, so the runbook can quote a duration for `verify --export`.

**Not tested here:** the event write path, vocabulary and trim (#19/#27); `/v1/events` semantics and
the trace renderer (#20); metric exposition (#21); the fold arms themselves (#8); packaging (#36).
