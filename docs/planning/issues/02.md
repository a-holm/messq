## Context

PLAN.md §11 opens with "the value proposition is *trustworthy*; the test suite is the product" and
then lists ground rules that only work if they are mechanical: `-race` everywhere, **no
`time.Sleep` in tests (lint-enforced)**, coverage floors on the two packages that carry the
semantics, and a PR pipeline that stays under 10 minutes so nobody learns to route around it.
D13 adopts that discipline explicitly. This issue installs those gates **before any feature code
exists**, because every one of them is cheap to add to an empty repo and expensive to retrofit
onto 6 000 lines of working Go.

These gates are load-bearing for architectural decisions taken elsewhere in the plan, and every
one of them erodes silently without enforcement:

| Gate | Protects | PLAN reference |
|---|---|---|
| `forbidigo`: no `time.Sleep` | the Clock seam and `testing/synctest` timing discipline — the dominant flake source | §11 ground rules, §3.3 |
| `forbidigo`: no `time.Now` outside the seam | `internal/queue` stays a pure function (`Apply(state, cmd, now)`), which is what makes the reference model and property suite cheap | §3.3, D13 |
| `forbidigo`: no `prometheus.DefaultRegisterer` | the custom-registry + `stream`/`consumer`-only cardinality rule | D11, §9.4 |
| `exhaustive` | the delivery-state enum and the closed event vocabulary get handled everywhere they are switched on | §5.1, §9.2 |
| coverage floors | `internal/queue` ≥ 90 %, `internal/store` ≥ 85 % — "no vanity global number" | §11 |
| `govulncheck` | supply-chain posture promised in D12 / §10 | D12, §10 |

What it unlocks: #5 (the SQLite store) is the first substantial package in the repo. It should
land into a repository where a missing `rows.Err()`, an unclosed `*sql.Rows`, a swallowed error,
or a `time.Sleep(50*time.Millisecond)` "just to let the writer catch up" is a failed build on the
first push, not a code-review conversation repeated forty times.

Governing sections: **§11 Testing strategy**, **D13**, plus D11 (registry/cardinality), §3.3
(package layout and the Clock seam), §13 (dependency budget: linters and `govulncheck` are *tool*
dependencies and must never enter the main module's `go.mod`).

## Scope

**In scope**

- `.golangci.yml` — golangci-lint **v2** schema, pinned version, `config verify`-clean.
- The `forbidigo` rule set and its narrow, documented exclusions.
- `go test -race` as the default test invocation for every Go package, with the CGO caveat
  handled explicitly in CI.
- Per-package coverage floors in a checked-in `coverage.floors` file, enforced by a tiny
  in-repo Go tool, ratcheting upward only, with a merge-base comparison that refuses lowering.
- `govulncheck` in the PR lane and again nightly (new CVEs land without code changes), with a
  documented, expiring suppression path.
- Tool version pinning via a separate `tools/` module so the main module's direct-dependency
  budget (≤ 8, §1.5/§13) is untouched.
- Splitting CI into `pr.yml` (fast lane, hard budget ≤ 10 min wall clock) and `nightly.yml`
  (skeleton with named placeholder jobs that later issues fill in).
- **Gate self-tests**: a sabotage matrix proving each gate actually bites, so the gates
  themselves are tested rather than assumed.
- `make ci`, `make lint`, `make test`, `make cover`, `make cover-ratchet`, `make vuln`,
  `make gates-selftest` documented in `CONTRIBUTING.md`.

## Design proposal

Everything below is a **starting point**, not a mandate. Linter names, thresholds and file paths
are the parts worth arguing about; the shape (gates in the repo from commit #2, each gate proven
by a sabotage test) is the part that is settled.

### 1. `.golangci.yml`

golangci-lint v2 config schema (`version: "2"`, `linters.settings`, separate `formatters:`
section). Pin the binary version in `tools/` and in the action so local and CI agree.

```yaml
version: "2"

linters:
  default: standard          # errcheck, govet, ineffassign, staticcheck, unused
  enable:
    - bodyclose              # HTTP response bodies — the API layer and pkg/client
    - containedctx           # no ctx smuggled into structs (writer/sweeper own their own)
    - errorlint              # %w, errors.Is/As — sentinel errors are an API (see #3)
    - exhaustive             # delivery state + event vocabulary switches
    - forbidigo              # the architectural bans, see §2 below
    - gosec
    - makezero
    - nilerr
    - noctx                  # every outbound HTTP call carries a context
    - nolintlint             # a //nolint must name a linter and give a reason
    - rowserrcheck           # database/sql: rows.Err() after the loop
    - sqlclosecheck          # database/sql: rows/stmt always closed
    - usetesting             # t.TempDir/t.Setenv/t.Chdir over os.* in tests
    - wastedassign

  settings:
    errcheck: { check-type-assertions: true, check-blank: true,
                exclude-functions: ["(*database/sql.Tx).Rollback"] }
    govet:    { enable-all: true, disable: [fieldalignment] }
    exhaustive:
      check: [switch, map]
      default-signifies-exhaustive: false  # a default: must not hide a new state/event
    nolintlint: { require-explanation: true, require-specific: true, allow-unused: false }
    gosec:      { excludes: [G404] }       # jitter uses math/rand deliberately; see note below
    forbidigo:
      analyze-types: true                  # match by resolved type, not by source text
      exclude-godoc-examples: true
      forbid: []                           # filled in §2

  exclusions:
    generated: lax
    rules:
      # The Clock seam is the one place allowed to read the wall clock.
      - path: 'internal/clock/'
        text: 'time\.(Now|Since|NewTimer|NewTicker|After)'
        linters: [forbidigo]
      # The soak test is explicitly exempted from the sleep ban (PLAN §11 ground rules).
      - path: 'test/soak/'
        text: 'time\.Sleep'
        linters: [forbidigo]
      # Metrics registration lives in exactly one package.
      - path: 'internal/obs/'
        text: 'prometheus\.'
        linters: [forbidigo]
      - path: '_test\.go'
        linters: [gosec, containedctx]

formatters:
  enable: [gofumpt, goimports]
  settings:
    goimports:
      local-prefixes: [github.com/messq/messq]   # match go.mod from #1

issues:
  max-issues-per-linter: 0
  max-same-issues: 0
```

Note on `only-new-issues`: **do not enable it.** The repo is two commits old; a clean baseline is
achievable now and never again.

### 2. The `forbidigo` rules — the architectural bans

These are the rules PLAN.md names, plus two that fall out of decisions taken elsewhere. Each one
gets a message that says *what to do instead*, because a lint message is documentation with a
100 % read rate.

```yaml
forbid:
  - pattern: '^time\.Sleep$'
    msg: >-
      time.Sleep is banned (PLAN §11). Use the Clock seam (internal/clock) or a
      testing/synctest bubble. test/soak is the only exemption.

  - pattern: '^time\.(Now|Since|NewTimer|NewTicker|After|Tick)$'
    msg: >-
      Wall-clock access outside internal/clock breaks the pure state machine
      (PLAN §3.3). Take a clock.Clock and call c.Now()/c.NewTimer().

  - pattern: '^prometheus\.(DefaultRegisterer|DefaultGatherer|MustRegister|Register)$'
    msg: >-
      messq uses a custom registry only (D11). Register through internal/obs.

  - pattern: '^promauto\.(New|New[A-Za-z]+)$'
    msg: 'Use promauto.With(reg) via internal/obs — package-level promauto uses the default registry (D11).'

  - pattern: '^os\.Exit$'
    msg: >-
      Only cmd/messq and internal/cli may exit. Return an error; the run() pattern
      maps it to the documented exit-code contract (PLAN §8).

  - pattern: '^(fmt\.Print|fmt\.Printf|fmt\.Println)$'
    msg: >-
      Data goes to the injected stdout writer, narration to stderr (PLAN §8).
      Library packages must not print at all.
```

`os.Exit` and `fmt.Print*` get path exclusions for `cmd/messq/` and `internal/cli/` respectively.
`analyze-types: true` makes these match the resolved package path rather than the identifier
text, so a `import stdtime "time"` alias cannot smuggle a `Sleep` past the gate.

**Why ban `time.Sleep` in non-test code too**, when PLAN §11 only says "in tests": production code
has the same obligation (the Clock seam exists precisely so deadlines are testable), and one
module-wide rule with two documented exclusions is easier to reason about than a path-scoped
pattern list. If a real need appears in daemon code, it is a two-line exclusion plus a review.

**On the `exhaustive` linter:** the enums it protects (`deliveries.state`, the event vocabulary of
§9.2) do not exist yet — they arrive with #5 and #19. Enabling it now costs nothing and means the
first `switch ev.Kind` is checked on the day it is written.

**On `gosec` G404:** the ±20 % backoff jitter (§5.1) and the recovery jitter (§4.4) deliberately
use non-cryptographic randomness. Excluding G404 globally is the pragmatic call; the alternative
(a `//nolint:gosec` on each site) is noise. Ack tokens contain no secret (D7), so no crypto-random
requirement exists anywhere in v1 outside the auth token *generator* in #16 — which must use
`crypto/rand` and should carry its own explicit review note.

### 3. Race detector — and the CGO trap

PLAN §1.5 requires `CGO_ENABLED=0` for the shipped binary; **the Go race detector requires cgo**.
These are not in conflict but they are easy to get wrong once and never notice.

```make
GO       ?= go
PKGS     ?= ./...
COVERPKG ?= ./internal/...,./pkg/...

.PHONY: test race build vuln lint cover cover-ratchet ci gates-selftest

build:                       ## the shipped artifact: static, no cgo
	CGO_ENABLED=0 $(GO) build -trimpath -ldflags "$(LDFLAGS)" ./cmd/messq

test race:                   ## tests always run with the race detector => cgo ON
	CGO_ENABLED=1 $(GO) test -race -count=1 -shuffle=on -timeout=5m $(PKGS)
```

Notes and edge cases:

- `-count=1` is not optional: without it a cached `ok (cached)` line makes the gate pass
  vacuously after any unrelated change.
- `-shuffle=on` catches order-dependent tests early, when there are few of them.
- The race detector inflates `modernc.org/sqlite` runtime substantially. If `internal/store`
  starts dominating the 10-minute budget after #5/#6, shard it into its own CI job rather than
  dropping `-race` — dropping `-race` is not on the table (§11 ground rules).
- CI must keep one `CGO_ENABLED=0` build job (from #1) so the "static binary" promise is checked
  on every PR, and separately run tests with cgo enabled. Both facts belong in a comment in the
  workflow, because the next person will try to unify them.

### 4. Coverage floors that ratchet

`coverage.floors` — checked in, reviewed like code:

```
# package                          floor%   note
internal/queue                     90.0     PLAN §11 — the pure state machine
internal/store                     85.0     PLAN §11 — durability and recovery
# packages below are opt-in; add a line when a package earns a floor.
```

Measurement:

```make
cover:
	CGO_ENABLED=1 $(GO) test -race -count=1 -covermode=atomic \
		-coverpkg=$(COVERPKG) -coverprofile=cover.out $(PKGS)
	$(GO) run ./internal/tools/covergate -profile cover.out -floors coverage.floors
```

`-covermode=atomic` is mandatory under `-race`. `-coverpkg=./internal/...,./pkg/...` is a
deliberate choice: `internal/queue` is exercised by the reference-model tests that will live in
`internal/model` (#13), and `internal/store` is exercised through the API and crash harness.
Per-package-only profiles would undercount both and push people to write tests in the wrong
package to satisfy a number. The cost is a slower coverage run — which is why `make cover` is its
own CI job in parallel with `make test`, not a serial step.

Tool sketch (`internal/tools/covergate/main.go`, stdlib only — no dependency budget impact):

```go
// Package main enforces per-package statement-coverage floors.
// PROPOSAL: ~150 lines, stdlib only, table-driven tests over synthetic profiles.
package main

type floor struct{ Pkg string; Min float64; Note string }
type result struct{ Pkg string; Covered, Total int64; Pct float64 } // statements, not lines

// parseProfile reads a -covermode=atomic profile and aggregates statement
// counts per package (the directory part of each block's filename).
func parseProfile(r io.Reader) (map[string]*result, error)

// check returns one violation per floor that is unmet OR whose package is
// absent from the profile entirely. Absence is a FAILURE, never a pass:
// deleting a package's tests must not silently satisfy its floor.
func check(got map[string]*result, floors []floor) []violation

// Exit codes: 0 all floors met · 1 violation · 2 bad input.
```

Output shape (this is what a developer sees on a red build, so it should say the next command):

```
$ make cover
covergate: FAIL internal/queue 87.4% < 90.0% (PLAN §11 — the pure state machine)
           uncovered hot spots:
             internal/queue/apply.go:118-131   (nak at max_deliver)
             internal/queue/apply.go:204-209   (extend beyond --max-ack-wait)
covergate: OK   internal/store 88.1% >= 85.0%
next: go tool cover -html=cover.out
make: *** [cover] Error 1
```

**The ratchet.** Floors only go up. Two mechanisms, because one is not enough:

1. `make cover-ratchet` rewrites `coverage.floors` to `floor(actual)` rounded down to whole
   percent, but only where `actual >= floor + 1.0` (avoids churn commits from ±0.3 pp noise).
   Run by a human, committed, reviewed. **Never** run by CI — a bot that edits the gate is not a
   gate.
2. A CI step `coverage-ratchet` that fetches the merge base and refuses a decrease:

```bash
git show "$(git merge-base HEAD origin/main)":coverage.floors > /tmp/base.floors 2>/dev/null || exit 0
go run ./internal/tools/covergate -compare-floors /tmp/base.floors -floors coverage.floors
# exits 1 with: "internal/store floor lowered 85.0 -> 80.0; floors ratchet upward only"
```

Escape hatch, documented in `CONTRIBUTING.md`: lowering a floor requires a commit whose message
contains `coverage-floor-lowered:` and a reason; the check greps for it on the *head* commit only,
so it is a conscious, auditable act rather than a habit.

### 5. `govulncheck`

```make
vuln:
	$(GO) run golang.org/x/vuln/cmd/govulncheck@$(GOVULNCHECK_VERSION) -show verbose ./...
```

- Source mode (the default for `./...`) reports only vulnerabilities **reachable from our code**,
  which is the right signal-to-noise for a PR gate. Exit status 3 means findings.
- It also runs in the nightly lane on an unchanged tree: a CVE published on Tuesday must fail
  Tuesday night, not on the next PR.
- **Suppression** (govulncheck has no native mechanism): a wrapper reads `-format=json` and drops
  findings listed in `.govulncheck-allow`, which is a small file with mandatory fields:

```
# osv-id       expires      reason
GO-2026-1234   2026-09-30   only reachable via the cgosqlite build tag; tracked in #NN
```

  Entries past `expires` are a hard failure regardless of whether the vuln is still reported —
  suppressions must rot loudly. An empty allow-file is the expected steady state and the wrapper
  says so when it finds one.

### 6. Tool version pinning without touching the dependency budget

PLAN §13 caps the main module at ≤ 8 direct non-test dependencies, so linters and `govulncheck`
must not appear in the root `go.mod`. Proposal: a separate `tools/` module (`go 1.25`) whose
`go.mod` carries `tool` directives for `golangci-lint/v2/cmd/golangci-lint`,
`golang.org/x/vuln/cmd/govulncheck` and `mvdan.cc/gofumpt`, with its own `go.sum`.

```make
lint:
	cd tools && $(GO) tool golangci-lint config verify --config ../.golangci.yml
	cd tools && $(GO) tool golangci-lint run --config ../.golangci.yml ../...
```

`config verify` runs first so a typo in `.golangci.yml` fails with a schema error instead of
silently disabling half the linter set. Acceptable alternative if the tool-module indirection
proves annoying: `go run <tool>@<version>` with versions as Makefile variables — same `go.mod`
guarantee, weaker reproducibility. What is **not** acceptable is an unpinned `latest` in CI: a
linter release then breaks unrelated PRs.

### 8. Proving the gates bite (the sabotage matrix)

A gate nobody has seen fail is a gate nobody knows works. `test/gates/` holds one sabotage
fixture per gate, in a directory excluded from the main build (`//go:build gatecheck`, or a
`testdata/` subdirectory so `./...` never compiles it), plus a driver that applies each sabotage
to a scratch copy of the repo, runs the corresponding make target, and asserts a **non-zero exit
and a matching message**.

| # | Sabotage | Target | Must fail with |
|---|---|---|---|
| G1 | `time.Sleep(time.Millisecond)` in a `_test.go` | `make lint` | `time.Sleep is banned` |
| G2 | `time.Now()` in `internal/queue` | `make lint` | `Wall-clock access outside internal/clock` |
| G3 | `prometheus.MustRegister(...)` outside `internal/obs` | `make lint` | `custom registry only` |
| G4 | a `switch` over the state enum missing a case | `make lint` | `exhaustive` |
| G5 | an ignored `error` return | `make lint` | `errcheck` |
| G6 | delete a test file from `internal/queue` | `make cover` | `< 90.0%` |
| G7 | lower `internal/store` floor to 80 in `coverage.floors` | `make cover` | `floors ratchet upward only` |
| G8 | a `//nolint` with no reason | `make lint` | `nolintlint` |
| G9 | an expired entry in `.govulncheck-allow` | `make vuln` | `suppression expired` |
| G10 | `rows.Err()` omitted after a `sql.Rows` loop | `make lint` | `rowserrcheck` |

Transcript of the driver:

```
$ make gates-selftest
gates: G1  time.Sleep in _test.go                 lint  exit=1  matched  ok
gates: G2  time.Now in internal/queue             lint  exit=1  matched  ok
gates: G3  prometheus.MustRegister outside obs    lint  exit=1  matched  ok
gates: G4  non-exhaustive state switch            lint  exit=1  matched  ok
gates: G5  unchecked error                        lint  exit=1  matched  ok
gates: G6  internal/queue below floor             cover exit=1  matched  ok
gates: G7  lowered coverage floor                 cover exit=1  matched  ok
gates: G8  //nolint without reason                lint  exit=1  matched  ok
gates: G9  expired vuln suppression               vuln  exit=1  matched  ok
gates: G10 missing rows.Err()                     lint  exit=1  matched  ok
gates: 10/10 gates verified in 71s
```

Fixtures G4, G6 and G10 depend on packages that do not exist yet (#3, #5). Land them as
`t.Skip("waiting for internal/queue — #3")` **with the assertion already written**, and remove the
skip in the issue that creates the package. `t.Skip` on `main` is otherwise forbidden by §11's
ground rules, so these three skips are listed by name in `CONTRIBUTING.md` with their unblocking
issue, and the driver fails if a skip has no such entry.

### 9. Known edge cases and how they are handled

- **Race detector needs cgo; the product needs no cgo.** Two jobs, both mandatory, with a comment
  in the workflow explaining why they differ. Getting this backwards produces either an unraced
  test suite or a dynamically-linked release binary.
- **`testing/synctest` (Go ≥ 1.25, §13).** Bubbles are race-detector compatible; ensure the
  toolchain pin from #1 is ≥ 1.25 and that `go-version-file: go.mod` is used everywhere so CI
  cannot drift to a toolchain that lacks it.
- **Coverage of a package with no test files.** Treated as a failure ("listed in floors, absent
  from profile"), not 0 % and not a pass.
- **`-coverpkg` and embedded files.** Migrations embedded via `go:embed` (#5) contain no
  statements and do not move the denominator; generated files are excluded for lint via
  `linters.exclusions.generated` and should be excluded by path in `covergate`.
- **Linter version drift.** A `golangci-lint` minor release adds checks. Version pinned in
  `tools/go.mod` *and* the action input; a bump is its own PR whose diff shows exactly which new
  findings it introduced.
- **The 10-minute budget is a constraint, not an aspiration.** Record per-job durations in the run
  summary; when a job crosses 8 minutes, shard it or move it to nightly — never weaken a gate.
- **`errcheck` `check-blank` vs. `defer tx.Rollback()`.** Excluded by function name above; the
  deferred-rollback-after-commit pattern is correct for `database/sql` and appears on every writer
  path in #6.

## Acceptance criteria

- [ ] `.golangci.yml` exists, uses `version: "2"`, and `golangci-lint config verify` passes.
- [ ] `golangci-lint run` is clean at HEAD (no baseline file, no `only-new-issues`).
- [ ] `forbidigo` bans at minimum: `time.Sleep`; `time.Now`/`Since`/`NewTimer`/`NewTicker`/`After`
      outside `internal/clock`; `prometheus.DefaultRegisterer`/`MustRegister` and package-level
      `promauto.New*` outside `internal/obs`; `os.Exit` outside `cmd/messq`; `fmt.Print*` outside
      `internal/cli` — each with a message naming the alternative.
- [ ] `exhaustive` is enabled for `switch` and `map` with `default-signifies-exhaustive: false`.
- [ ] `make test` runs `go test -race -count=1` over all packages, and a deliberately-racy fixture
      is detected.
- [ ] A `CGO_ENABLED=0` build job and a `CGO_ENABLED=1` race-test job both run on every PR; the
      build job asserts the binary is static.
- [ ] `coverage.floors` is checked in with `internal/queue 90.0` and `internal/store 85.0`.
- [ ] `covergate` fails when a floored package is below its floor **or** absent from the profile,
      and prints the uncovered ranges plus a next command.
- [ ] A PR lowering any floor fails the `coverage-ratchet` check unless its head commit message
      contains `coverage-floor-lowered:` with a reason; `make cover-ratchet` never lowers a floor
      and is a no-op on an unchanged tree.
- [ ] `govulncheck` runs on every PR and nightly; a finding fails the build; `.govulncheck-allow`
      entries past their `expires` date fail the build even when no vulnerability is reported.
- [ ] No lint or vulnerability tool appears in the root `go.mod`; the root module's direct
      non-test dependency count is unchanged by this issue, and tool versions are pinned so CI and
      a clean local checkout run identical binaries.
- [ ] `.github/workflows/pr.yml` and `.github/workflows/nightly.yml` exist; the PR lane completes
      in ≤ 10 minutes wall clock on the empty repository, with per-job durations in the summary.
- [ ] The nightly lane has named jobs for `crash-sweep`, `property-deep`, `fuzz-long`, `soak`,
      `bench`, `upgrade-fixtures`, `cgosqlite`, `flake-hunt`, `vuln`; the last two are real, the
      rest are green no-op placeholders naming their issue.
- [ ] `make gates-selftest` runs the sabotage matrix; every gate is verified by a non-zero exit
      **and** a matching message, and a gate that does not fail its sabotage fails the target.
- [ ] Sabotage fixtures blocked on future packages are skipped **with the assertion written**, and
      each such skip is listed in `CONTRIBUTING.md` with its unblocking issue number.

## Test plan

Consistent with §11: gates are code, so they get tested like code.

**Unit (Go, table-driven)**
- `internal/tools/covergate`: synthetic `-covermode=atomic` profiles covering — floor met exactly
  at the boundary (`90.0` vs `90.0` passes, `89.99` fails), package absent from profile, package
  present with zero statements, malformed profile line, floors file with comments/blank
  lines/duplicate packages, and the `-compare-floors` path (raised / unchanged / lowered).
- The `govulncheck` wrapper: canned `-format=json` outputs for — no findings, one reachable
  finding, one finding suppressed by a live allow entry, one suppressed by an **expired** entry
  (must fail), an allow entry that matches nothing (must warn, and fail nightly).

**Integration — the sabotage matrix** (`make gates-selftest`, CI job `gates`)
- Each of G1–G10 applied to a scratch copy of the tree; assert non-zero exit **and** a matching
  message fragment. Asserting only the exit code is insufficient: a build that fails for an
  unrelated reason would look like a passing gate.

**Workflow lint**
- `actionlint` over `.github/workflows/*.yml` in the `lint` job — catches the YAML and expression
  errors that otherwise only surface on `main`.

**Timing**
- The PR lane records per-job wall time in the GitHub step summary. A follow-up assertion (a
  simple threshold check in the `gates` job) fails if total PR-lane wall clock exceeds 10 minutes,
  making §11's budget an enforced number rather than an aspiration.

**Not tested here** (deliberately): anything that requires a state machine, a store, or a daemon.
Those tests arrive with the packages they cover; this issue only guarantees they will run under
`-race`, be measured for coverage, and be unable to use `time.Sleep`.
