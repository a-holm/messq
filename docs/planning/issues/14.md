## Context

M3 ends with a complete delivery engine: consumers, cursors, claims with durable attempt counters
(#9), fenced settle verbs (#10), a timeout sweeper (#11) and dead-lettering (#12). Every one of
those is reachable only from Go test code. **This issue is where messq becomes a product**: the
hot path — publish, fetch, ack/nak/term/extend — gets an HTTP surface, and the promise in PLAN §7
that *"`curl` is the universal client and the 3 a.m. debugger"* becomes true or does not.

It opens **M4: API & daemon** and is the root of that milestone's dependency tree. Everything else
in M4 hangs off the server, the router, the middleware chain and the error envelope built here
(#15, #16, #17, #18), and so do the metrics (#21), the Go client (#22) and the load generator
(#31).

Governing PLAN.md material:

- **D2 — HTTP/1.1 + JSON on stdlib `net/http`.** Go 1.22+ `ServeMux` method+pattern routing, no
  router dependency, no codegen, no protoc. Unix socket by default. Long-poll pull, because
  *"flow control is an argument to a request"* — the credit/streaming state machine that gRPC or a
  push protocol would need does not exist in this design, and this issue is where that pays off.
- **§7 API / protocol.** The route table, the raw-body publish convention, `body_b64` on fetch, the
  `Messq-*` header conventions, trace-id propagation, and *"response to publish/ack is sent only
  after the commit's fsync"*.
- **§7 error envelope.** `{"error":{"code":…,"message":…,"next":[…],"trace_id":…}}` with a **closed,
  documented enum** of machine codes that is *"part of the 1.0 compatibility contract"*. #3 built
  the sentinel registry precisely so this issue can map it exhaustively in a test.
- **§3.1 / §3.2 Architecture.** Handlers *"parse → auth → build Cmd → send on cmdCh → wait"*; they
  never touch SQLite for writes. The **waiters registry** wakes parked long-poll fetches. No
  goroutine per message; every channel bounded (**I11**).
- **D4 / §4.3.** A 2xx on publish *or* ack is a durability promise; the response leaves only after
  the group commit's fsync returned.
- **§12 Performance targets.** Long-poll wake latency after publish **< 5 ms**; p99
  publish→durable-ack ≤ 10 ms. Both are properties of the code in this issue plus #6.

The five-line shell worker from §7 is not a documentation flourish — it is the widest funnel in the
product and a CI-executed golden test. If it does not work, this issue is not done.

What it unlocks: **#15** (admin/inspection routes register into this router), **#16** (auth
middleware slots into this chain and the route registry it exposes), **#17** (drain releases the
waiters this issue owns), **#18** (contract tests lock these shapes), **#21** (HTTP-level metrics),
**#22** (the Go client speaks exactly this wire), **#31** (`messq bench` drives it).

## Design proposal

> Concrete enough to argue with, not a mandate — **except** the wire shapes and the machine-code
> enum, which become a 1.0 compatibility contract the moment #18 locks them.

### 1. Package layout

```
internal/api/
  server.go      Server, Config, New, listeners, http.Server tuning, Shutdown
  routes.go      routes() — the ONE place patterns are registered; exported registry for #16
  middleware.go  recover → request id → conn limit → body limit → (authz: #16) → handler
  errors.go      the sentinel→(status,code) table, Envelope, writeError
  publish.go     raw-body publish + NDJSON batch
  fetch.go       the long-poll loop
  settle.go      ack / nak / term / extend
  waiters.go     the sharded, bounded registry; implements store.Waker (#11) and obs.Sink (#6)
  codec.go       decodeJSON (MaxBytesReader + DisallowUnknownFields), writeJSON
```

`internal/api` imports `internal/store`, `internal/queue`, `internal/errs`, `internal/clock`,
`internal/obs` — never the other way round. It contains **no queue policy**: every decision it makes
is about HTTP.

### 2. The handler shape

```go
// A handler returns an error instead of writing one; there is exactly one error-writing path.
type handler func(w http.ResponseWriter, r *http.Request) error

func (s *Server) h(route string, fn handler) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if err := fn(w, r); err != nil {
			s.writeError(w, r, route, err)
		}
	}
}
```

A handler that has already written a response returns `nil`. `writeError` is the only place that
consults the mapping table, the only place that emits `api.error`, and the only place that can
produce an envelope — which is what makes the exhaustiveness test meaningful.

### 3. Routing (Go 1.22 `ServeMux`, no dependency)

| Method | Pattern | Handler |
|---|---|---|
| `POST` | `/v1/streams/{stream}/messages` | publish (raw body) |
| `POST` | `/v1/streams/{stream}/messages:batch` | batch publish (NDJSON) |
| `POST` | `/v1/streams/{stream}/consumers/{consumer}/fetch` | long-poll fetch |
| `POST` | `/v1/ack` | settle (batch or single) |
| `POST` | `/v1/nak` | settle |
| `POST` | `/v1/term` | settle |
| `POST` | `/v1/extend` | settle |
| `GET` | `/healthz` | liveness only — an unconditional `200` proving the listener is up; `/readyz` and its "recovery complete and store writable" semantics are #15 |

`messages` and `messages:batch` are distinct literal segments, so both register without conflict.
Path values come from `r.PathValue("stream")`; they are validated with #3's name grammar **before**
any store call, so a path like `/v1/streams/../../etc/messages` is a `bad_request`, not a lookup.

**Stdlib 404/405 bodies are not envelopes.** `ServeMux` writes plain text for an unmatched path and
plain text plus an `Allow` header for a matched path with the wrong method. Both must speak the
envelope. Proposal: register `mux.HandleFunc("/", notFound)` for the catch-all, and wrap the mux in
a small `ResponseWriter` that intercepts a `404`/`405` whose body has not been written by one of our
handlers (tracked with a flag set by `writeJSON`/`writeError`) and replaces it with
`{"error":{"code":"not_found"|"method_not_allowed",…}}`, preserving the `Allow` header. ~40 lines,
and it means *no* response from messq is ever un-parseable by a client.

`routes()` returns a `[]Route{Method, Pattern, Name, Mutating}` slice that the mux is built from;
#16 asserts every `Mutating` route declares a required role, and #18 iterates it for coverage.

### 4. The error envelope and the closed enum

```go
type Envelope struct{ Error ErrorBody `json:"error"` }

type ErrorBody struct {
	Code    string         `json:"code"`              // closed enum, §7 compatibility contract
	Message string         `json:"message"`           // human sentence; never payload, never secrets
	Next    []string       `json:"next,omitempty"`    // "what to type next" (PLAN §8)
	Detail  map[string]any `json:"detail,omitempty"`  // machine-readable specifics
	TraceID string         `json:"trace_id,omitempty"`
}
```

The table lives in `errors.go` and is the single source of truth:

| Code | Status | Sentinel(s) | Produced by |
|---|---|---|---|
| `bad_request` | 400 | `ErrBadRequest` | malformed JSON, missing/conflicting subject, bad `msg_id` |
| `bad_subject` | 400 | `ErrBadSubject` | wildcard or malformed publish subject |
| `subject_mismatch` | 400 | `ErrBadSubject` + code refinement | subject matches no stream pattern |
| `reserved_header` | 400 | `ErrBadRequest` + refinement | user header in the `Messq-` namespace |
| `reserved_name` | 400 | `ErrBadRequest` + refinement | `*.dlq` stream name (#7) |
| `invalid_token` | 400 | `ErrUnknownToken` | unparseable / impossible-generation ack token |
| `unauthorized` | 401 | `ErrUnauthorized` | **#16** (reserved here, unproduced) |
| `forbidden` | 403 | `ErrForbidden` | **#16** |
| `not_found` | 404 | `ErrNotFound` | unknown stream, consumer, seq, route |
| `method_not_allowed` | 405 | — | router |
| `conflict` | 409 | `ErrConflict` | generic conflict (#7 stream states) |
| `stream_exists` | 409 | `ErrConflict` + refinement | #7 |
| `stale_ack` | 409 | `ErrStaleAck`, `ErrWrongGen` | attempt/generation fence (#10) |
| `extend_capped` | 409 | `ErrStaleAck` + refinement | extend past `--max-ack-wait` (#10) |
| `would_lose_data` | 409 | `ErrConflict` + refinement | #7/#15 narrowing PATCH |
| `paused` | 409 | `ErrPaused` | non-fetch paths; **fetch never uses it** (see §6) |
| `too_large` | 413 | `ErrTooLarge` | body > `max_msg_size`, batch/settle over limit |
| `unsupported_media_type` | 415 | `ErrBadRequest` + refinement | JSON endpoint given a non-JSON body |
| `flow_control` | 429 | `ErrFlowControl` | reserved; **fetch returns 200 + `hold_reason`** |
| `rate_limited` | 429 | — | reserved for **#39** |
| `internal` | 500 | (unwrapped errors, recovered panics) | bug path |
| `commit_unknown` | 503 | `ErrCommitUnknown` (#6) | commit failed *or possibly succeeded* |
| `busy` | 503 | — | writer submit timeout, `--max-conns` exceeded |
| `too_many_waiters` | 503 | — | `--max-waiters` / per-consumer cap |
| `read_only` | 503 | `ErrReadOnly` | fsyncgate latch (#6) |
| `shutting_down` | 503 | `ErrShuttingDown` | **#17** |
| `disk_full` | 507 | `ErrDiskFull` | **#27** (reserved) |
| `stream_full` | 507 | `ErrStreamFull` | **#27**, `discard=new` (reserved) |

Two mechanisms make this honest:

1. **Code refinement.** Several codes share one sentinel because the sentinel set is deliberately
   small. Proposed one-function amendment to `internal/errs` (#3): `errs.WithCode(err, "…") error`,
   attached to the `errs.Error` carrier and preserving `errors.Is`. `writeError` prefers an attached
   code and falls back to the sentinel's default. A test asserts every attached code is a member of
   the enum — an unknown code is a compile-time-adjacent failure, not a silent new API string.
2. **Exhaustiveness in both directions.** `TestEverySentinelIsMapped` iterates `errs.All()` and
   requires each to be in the table **or** in `neverOverHTTP` (`ErrLocked`, `ErrSchemaNewer`,
   `ErrUnavailable` — startup and client-side conditions), with a reason string.
   `TestEveryCodeIsProduced` maps each enum member to a scenario function and fails on a code no
   test can produce, so dead codes cannot accumulate in the contract.

`503` responses carry `Retry-After` (seconds, integer). `commit_unknown` says so in prose:
*"the commit may or may not have succeeded — retry with the same `Messq-Msg-Id`"*, which is exactly
the UNKNOWN class of #8's three-valued ledger.

### 5. Publish (promoted from #7)

Behaviour, headers, dedup and validation are #7's; this issue owns the HTTP policy around them.

```console
$ curl -s -D- --unix-socket /run/messq/messq.sock \
    -H 'Messq-Msg-Id: order-4711-confirm' -H 'Messq-Header-Tenant: acme' \
    --data-binary @order.json 'http://x/v1/streams/orders/messages?subject=orders.eu.created'
HTTP/1.1 201 Created
Messq-Seq: 10493
Messq-Msg-Id: 01J8ZQ4K2M9V0X7Y3B5N6C8D1E
Messq-Trace-Id: 4bf92f3577b34da6a3ce929d0e0e4736
Messq-Request-Id: 01J8ZQ4K2N7T3W1P8Q9R0S2V4X
{"stream":"orders","seq":10493,"id":"01J8ZQ4K2M9V0X7Y3B5N6C8D1E",
 "trace_id":"4bf92f3577b34da6a3ce929d0e0e4736","duplicate":false,"published_at":1758878042190}
```

- The body is wrapped in `http.MaxBytesReader(w, r.Body, maxMsgSize+1)` **before** the first read;
  a declared `Content-Length` over the limit is rejected without reading a byte.
- `Expect: 100-continue`: Go sends the continue only when the handler reads the body. The size
  pre-check therefore runs first, and an oversized publish gets its `413` *instead of* a `100` —
  the client never uploads the payload. Tested explicitly, because it is the difference between
  rejecting a 2 GiB publish in 1 ms and in 20 s.
- **Publish is not cancelled by client disconnect.** #6's batch uses `context.Background()`; a
  publisher that hangs up after the command is queued still gets its message committed. That is
  correct (at-least-once, publisher retries dedup on `Messq-Msg-Id`) and is stated in
  `PROTOCOL.md` so nobody "fixes" it.

### 6. Fetch and the long-poll — the meat

**Request** (JSON body only; an empty body means defaults):

```json
{"batch": 16, "wait_ms": 30000, "max_bytes": 1048576}
```

Query parameters are **rejected** with `bad_request` naming the JSON body. Two ways to say the same
thing is the bug factory #7 already refused for `subject`.

**Response** — one shape, always, including timeout:

```json
{"messages":[
   {"stream":"orders","seq":10493,"id":"01J8ZQ4K2M9V0X7Y3B5N6C8D1E",
    "subject":"orders.eu.created","headers":{"Tenant":"acme"},
    "body_b64":"eyJvcmRlcl9pZCI6NDB9","size":1234,
    "attempt":2,"max_deliver":5,"ack_token":"orders/worker/10493/2/1",
    "deadline":"2026-09-26T09:14:32.190Z","deadline_ms":1758878072190,
    "published_at":"2026-09-26T09:14:02.114Z",
    "trace_id":"4bf92f3577b34da6a3ce929d0e0e4736"}],
 "hold_reason":"","retry_after_ms":0,
 "pending":3,"backlog":1204,
 "batch":16,"max_bytes":1048576,"wait_ms":30000}
```

`hold_reason ∈ {"", "no_messages", "max_ack_pending", "backoff", "paused", "shutting_down"}` comes
straight from #9's `FetchResult.Hold`. Effective (post-clamp) `batch` / `max_bytes` / `wait_ms` are
echoed — clamping silently is how people build wrong dashboards. Mirrored as headers
`Messq-Pending`, `Messq-Backlog`, `Messq-Hold-Reason` so a shell worker can branch without `jq`.

**The loop** (`internal/api/fetch.go`):

```go
func (s *Server) fetch(w http.ResponseWriter, r *http.Request) error {
	req, key := decodeFetch(r)                       // clamps, validates names
	wait := min(req.WaitMS, s.cfg.MaxFetchWait)
	deadline := s.clock.Now().Add(wait)

	// (1) SUBSCRIBE BEFORE THE FIRST CLAIM — see the lost-wakeup note.
	sub, err := s.waiters.Subscribe(key, filtersOf(key))
	if err != nil {                                  // --max-waiters
		return errs.E(errTooManyWaiters, "api.fetch", "…")
	}
	defer sub.Close()

	rc := http.NewResponseController(w)
	_ = rc.SetWriteDeadline(deadline.Add(s.cfg.WriteSlack))

	for {
		res, err := s.store.Fetch(submitCtx(r), store.FetchCmd{...})
		if err != nil { return err }
		switch {
		case len(res.Messages) > 0,                   // work
			res.Hold == store.HoldPaused,             // parking cannot help (#9)
			res.Hold == store.HoldMaxAckPending,      // ditto: no publish can unblock it
			!s.clock.Now().Before(deadline):          // wait budget spent
			return writeFetch(w, res, req)
		}
		timer := s.clock.NewTimer(sleepFor(deadline, res.NextVisibleAt, s.cfg.EmptyWakeDamper))
		select {
		case <-sub.C:                                 // publish matched / redelivery due / resume
		case <-timer.C():
		case <-r.Context().Done():
			return nil                                // client gone; nothing was claimed
		case <-s.closing:
			res.Hold = store.HoldShuttingDown
			return writeFetch(w, res, req)            // 200 empty; the worker loops, #17 drains
		}
		timer.Stop()
	}
}
```

Seven decisions that make this correct rather than merely plausible:

1. **Subscribe before the first claim.** The classic lost wakeup is: fetch returns empty → a publish
   commits and wakes nobody → the handler parks → 30 s of silence with work sitting in the stream.
   Subscribing first makes a wake that arrives *during* the fetch land in the buffered channel and
   cause one immediate, harmless re-fetch.
2. **A wake is a level, not an edge.** Each waiter's channel is `chan struct{}` with capacity 1 and
   a non-blocking send; N wakes collapse into one retry. The store, never the wake, is the
   authority on whether work exists.
3. **Flow-blocked and paused fetches do not park** (#9's rule). No publish can unblock them, so
   parking would burn a waiter slot and hide the problem. They return immediately with
   `hold_reason` and `retry_after_ms`.
4. **`NextVisibleAt` caps the sleep.** If a READY row is scheduled at T, the timer fires at
   `min(deadline, T)` even if #11's `Waker` is late. Belt and braces: the sweeper wake is the fast
   path, the timer is the guarantee.
5. **The empty-wake damper.** Under load, one publish wakes every parked worker on that consumer;
   all but one re-fetch into an empty result. 100 parked workers × 1000 publishes/s would be 100k
   fetch commands/s through the single writer. After an *empty* wake, the loop coalesces further
   wakes for `--fetch-empty-damper` (5 ms, ±20 % jitter) before re-fetching. First wake after work
   arrives is never damped, so the § 12 "< 5 ms wake latency" target holds for an idle consumer.
6. **Client disconnect while parked costs nothing** — no claim was made. Client disconnect *after*
   the claim committed costs one redelivery: `attempts` was spent, the worker never saw the token,
   and the sweeper redelivers at `ack_wait` with `msg.timeout`. That is I9-compliant (the duplicate
   has a named cause) and it is why the claim happens as late as possible. Proposed metric
   `messq_fetch_abandoned_total{stream,consumer}` for #21.
7. **No global `WriteTimeout`.** It would kill every long poll. The per-response deadline is set
   from the fetch's own budget with `http.NewResponseController`, so a dead peer still cannot pin a
   handler forever. `ReadTimeout` is also **0**, with per-request read deadlines set before reading
   a body: a server-wide `ReadTimeout` expires under the handler of a 5-minute long poll and takes
   the connection's close-detection read with it.

### 7. The waiter registry

```go
// Registry implements store.Waker (#11) and obs.Sink (#6). Bounded — invariant I11.
type Registry struct {
	shards [64]shard              // sharded by stream name; the writer contends with one shard
	total  atomic.Int64           // fast "is anyone parked?" for Waiting()
	max, maxPerKey int
}

type waiter struct {
	c       chan struct{}         // cap 1, non-blocking send
	filters subject.Set           // snapshot at Subscribe; used to match msg.publish subjects
}

func (r *Registry) Subscribe(k queue.ConsumerKey, f subject.Set) (*Sub, error)
func (r *Registry) Wake(k queue.ConsumerKey)             // store.Waker
func (r *Registry) Waiting() []queue.ConsumerKey         // store.Waker; nil when total == 0
func (r *Registry) Publish(evs []obs.Event)              // obs.Sink — MUST NOT block
func (r *Registry) ReleaseAll()                          // #17 drain
```

Wake sources, all of them:

| Source | Mechanism |
|---|---|
| A publish committed | `obs.Sink.Publish` sees `msg.publish{stream, subject}`; wakes parked waiters of that stream whose **snapshot filter set matches the subject**. Filter matching is #3's allocation-free matcher. |
| A redelivery became due | #11's sweeper calls `Waiting()` then `Wake(key)` (≤ 250 ms after `visible_at`). |
| A nak with an immediately-visible result | the settle handler calls `Wake(key)` after the commit returns. |
| `consumer.update` / `consumer.resume` (#15) | wake the key unconditionally — a filter edit invalidates the snapshot, so this closes that hole. |
| Shutdown (#17) | `ReleaseAll` closes every channel; parked fetches return 200 with `hold_reason:"shutting_down"`. |

Why sharding: `Publish` runs **on the writer goroutine** immediately after commit (#6 §3) and must
never block. Sharding by stream means 10 000 workers subscribing and unsubscribing contend with the
writer only on their own shard, and the critical section is "iterate the parked waiters of one
stream". `Waiting()` short-circuits on the atomic counter, so the 4 Hz sweeper probe costs one
atomic load on an idle broker.

Bounds: `--max-waiters` (10 000 process-wide) and `--max-waiters-per-consumer` (256). Over either →
`503 too_many_waiters` + `Retry-After: 1` and a `next` naming `--max-waiters`. A worker fleet that
outgrows the cap gets a typed answer, not an OOM.

### 8. Settle endpoints

Shapes are #10's; this issue registers and hardens them.

```console
$ curl -s -X POST --unix-socket /run/messq/messq.sock http://x/v1/ack \
    -d '{"tokens":["orders/worker/10493/2/1","orders/worker/10494/1/1"]}'
{"results":[{"token":"orders/worker/10493/2/1","result":"ok"},
            {"token":"orders/worker/10494/1/1","result":"stale","reason":"attempt_fence",
             "token_attempt":1,"current_attempt":2}],
 "ok":1,"stale":1,"unknown":0}
```

- `/v1/ack` accepts `{"token":…}` and `{"tokens":[…]}`; `/v1/nak`, `/v1/term`, `/v1/extend` accept
  the single form and an `{"items":[…]}` batch form (PLAN §7).
- **Status codes describe the request, not the tokens** (*decision*). A single-token request maps
  its outcome onto the status (200 ok / 409 `stale_ack` / 404 `not_found`), because that is what a
  shell worker branches on. A **batch always returns 200** with per-token results and the
  `ok`/`stale`/`unknown` counters; there is no defensible status for "3 ok, 1 fenced", and a client
  that wants strictness reads `stale == 0`. Documented in `PROTOCOL.md` and contract-tested.
- Over `--max-settle-batch` (#10) → `413 too_large` naming the limit.
- After a successful nak whose `visible_at <= now`, the handler wakes the consumer's waiters.

### 9. Listeners, server tuning, flags

```go
srv := &http.Server{
	Handler:           chain,
	ReadHeaderTimeout: cfg.ReadHeaderTimeout, // 10s — slowloris
	ReadTimeout:       0,                     // per-request deadlines instead (see §6.7)
	WriteTimeout:      0,                     // long-poll owns its deadline
	IdleTimeout:       cfg.IdleTimeout,       // 120s
	MaxHeaderBytes:    cfg.MaxHeaderBytes,    // 16 KiB
	ErrorLog:          slog.NewLogLogger(h, slog.LevelWarn), // never the stdlib default logger
}
```

Unix socket: create in the data dir's runtime path, `chmod 0660`, `chown` to `--socket-group` when
set, and **remove a stale socket only when nothing answers on it** — the data dir `flock` from #5 is
the authority on "another instance is running", so a live socket plus a lost flock is a bug report,
not a race to win. TCP: bind refused for non-loopback addresses until #16 exists (fatal startup
error, naming `--auth-file`). h2c is **not** enabled (request-smuggling surface, zero benefit at
this scale); HTTP/2 arrives with TLS in #40.

### 10. JSON decoding policy

```go
func decodeJSON[T any](w http.ResponseWriter, r *http.Request, max int64) (T, error) {
	if ct := r.Header.Get("Content-Type"); ct != "" && !isJSON(ct) { /* 415 */ }
	r.Body = http.MaxBytesReader(w, r.Body, max)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()          // a misspelled wait_ms must not silently become 0
	var v T
	if err := dec.Decode(&v); err != nil { /* bad_request, or too_large on MaxBytesError */ }
	if dec.More() { /* bad_request: trailing data */ }
	return v, nil
}
```

`DisallowUnknownFields` is a deliberate strictness choice: a typo in `wait_ms` silently turning a
30-second long poll into a hot loop is a support incident; a rejected typo is a fixed bug. It is
forward-compatible by construction because new request fields are only ever *added server-side*,
and older servers rejecting newer clients loudly is the behaviour we want. Stated in the
compatibility section of `PROTOCOL.md`.

### 11. Edge cases, decided

| Case | Handling |
|---|---|
| Fetch returns empty at `wait_ms` | `200` with `messages: []` — never `204`, never a different shape. Clients parse one thing (D2). |
| `batch` omitted or `0` | Defaults to **1**. A naive client that omits it gets one message, not 256; `messq sub` (#24) sets it explicitly. |
| `batch`/`max_bytes`/`wait_ms` above server caps | Clamped and the **effective** value echoed in the response and in `Messq-*` headers. |
| `wait_ms` negative or non-integer | `400 bad_request`. |
| Fetch on unknown stream or consumer | `404 not_found` with `next: ["messq consumer add orders worker"]`. |
| Consumer flow-blocked or paused | `200` empty, `hold_reason`, `retry_after_ms`; **does not park** (#9). |
| Waiter caps exceeded | `503 too_many_waiters` + `Retry-After: 1`, naming the flag. |
| Client disconnects while parked | Return silently; nothing claimed; the waiter is released by `defer`. |
| Client disconnects after the claim commits | Messages redeliver at `ack_wait` with `msg.timeout` — a *named* duplicate (I9). Documented in §6 of the README. |
| Writer `cmdCh` full | Handler blocks up to `--writer-submit-timeout`, then `503 busy` + `Retry-After: 1`. Backpressure is visible, not infinite. |
| Store latched read-only (#6) | Publish, fetch (it claims) and settle all return `503 read_only`. Peek/inspection keep working. The consequence — acks failing means mass redelivery — is exactly why #6 exits after a short drain. |
| Commit returned an error | `503 commit_unknown`, message says *retry with the same `Messq-Msg-Id`*. Never "it failed": #6 §10.2. |
| Oversized publish with `Content-Length` | `413 too_large` before reading the body, and before any `100-continue`. |
| Oversized publish, chunked | `MaxBytesReader` trips mid-stream → `413` naming the limit but not the actual size. |
| Request headers over 16 KiB | Stdlib `431`; mapped to the envelope by the response wrapper. |
| Slowloris (1 byte/s headers) | Connection closed at `ReadHeaderTimeout`; no handler ever ran. |
| `GET`/`HEAD` on a `POST` route | `405` + `Allow` header + envelope. |
| Unknown path | `404 not_found` envelope, not stdlib text. |
| Non-JSON `Content-Type` on fetch/settle | `415 unsupported_media_type`; publish accepts any content type (raw body, #7). |
| Two fetches parked on one consumer, one message published | Both wake, both re-fetch; one wins, the other loops with its remaining budget. Correct and cheap; damped by §6.5. |
| Filter edited while a fetch is parked | The snapshot filter may miss a publish wake; `consumer.update` (#15) wakes the key unconditionally, and the wait budget bounds the worst case anyway. |
| Panic in a handler | Recovered at the middleware boundary: `500 internal`, `api.error` event at ERROR with the request id, connection stays serving. The daemon never panics for an *operational* condition (#3). |
| Shutdown while parked | `ReleaseAll` → `200` empty with `hold_reason:"shutting_down"`; the worker's next fetch gets `503 shutting_down` (#17). |

### Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| NDJSON / chunked streaming fetch responses | The response shape is what a gateway would reuse; streaming adds flush, deadline and partial-failure semantics for a batch that is already bounded | D2's post-1.0 gateway, on three real requests |
| Server-push / SSE delivery | Deletes the "flow control is an argument to a request" property that D2 bought | Never before 2.0 |
| One shared wake queue with hand-off to a single waiter | Needs a fairness policy and a queue; waking all and letting the store arbitrate is 30 lines and provably correct | `messq_fetch_empty_wakes_total` dominates a bench run |
| `429` for flow control on fetch | #9 chose `200` + `hold_reason` so a shell worker's loop does not need error handling for a normal condition | Never (documented) |
| Per-request `?pretty=1` JSON | `jq` exists | Never |
| Accepting fetch parameters as query args | Two ways to say one thing (#7's `subject` precedent) | Never |

## Acceptance criteria

- [ ] `messq serve` binds the Unix socket at mode 0660 (and `--socket-group` when set), refuses a
      non-loopback TCP bind with a fatal startup error naming `--auth-file`, and removes a stale
      socket only when nothing answers on it.
- [ ] Every route in the §3 table responds on both a Unix socket and a loopback TCP listener with
      byte-identical bodies.
- [ ] **Every response messq produces is an envelope or a documented success shape**: an unknown
      path returns `404 not_found` as JSON, a wrong method returns `405 method_not_allowed` as JSON
      with an `Allow` header, and oversized headers return `431` as JSON.
- [ ] `TestEverySentinelIsMapped` iterates `errs.All()` and fails when a sentinel is neither in the
      mapping table nor in `neverOverHTTP` with a reason; adding a sentinel without a mapping fails
      CI.
- [ ] `TestEveryCodeIsProduced` exercises every member of the closed code enum through a real
      request (or asserts it is explicitly reserved for a named future issue), and every produced
      envelope validates against the committed golden shape.
- [ ] A publish returns `201` only after the group commit's fsync returned under
      `--durability=full`, proven over HTTP by the #8 crash harness at the
      `store.tx.after_commit_before_reply` fault point; a dedup hit returns `200` with
      `duplicate: true`.
- [ ] A publish whose `Content-Length` exceeds `max_msg_size` is rejected with `413 too_large`
      **without reading the body and without emitting `100-continue`**.
- [ ] A publisher that disconnects after the command is queued still has its message committed, and
      a retry with the same `Messq-Msg-Id` returns `duplicate: true`.
- [ ] An empty fetch with `wait_ms=N` returns `200` with `messages: []` in `N ± one sweeper tick`,
      measured under `testing/synctest` (no `time.Sleep`), and its `hold_reason` is `no_messages`.
- [ ] A publish that matches a parked fetch's filter wakes it and the fetch responds with the
      message in **< 5 ms** on the reference machine (PLAN §12), measured with a histogram in the
      bench, not asserted with a sleep.
- [ ] **No lost wakeups:** a randomized publish/fetch interleaving test (10⁵ rounds, `-race`) never
      produces a fetch that returned empty at its deadline while a matching, claimable message
      existed for the whole wait window.
- [ ] A redelivery becoming due wakes a parked fetch within one sweeper tick, via #11's `Waker`
      interface implemented by the registry, and also via the `NextVisibleAt` timer with the
      `Waker` disabled.
- [ ] A flow-blocked or paused consumer's fetch returns immediately with `hold_reason` and
      `retry_after_ms`, and **occupies no waiter slot** (asserted on the registry's counter).
- [ ] Waiter caps hold: 10 001 concurrent long polls with `--max-waiters=10000` produce exactly one
      `503 too_many_waiters` with `Retry-After`, and per-consumer parking is capped independently.
- [ ] After 10 000 long polls time out or are cancelled, goroutine count and registry size return to
      their pre-test baseline (no leak), and `Registry.Waiting()` returns nil.
- [ ] A client that disconnects while parked leaves no claim, no delivery-row mutation and no
      leaked waiter; a client that disconnects after the claim commits causes exactly one
      redelivery, attributed to `msg.timeout` in the events table.
- [ ] Fetch clamps `batch`, `max_bytes` and `wait_ms` to the server caps and echoes the effective
      values in both the body and the `Messq-*` headers; `batch` omitted defaults to 1.
- [ ] Fetch rejects query parameters with `bad_request` naming the JSON body, and rejects unknown
      JSON fields, trailing data and a non-JSON `Content-Type`.
- [ ] Single-token settle requests map their outcome onto the status (`200` / `409 stale_ack` /
      `404 not_found`); a batch settle returns `200` with per-token results in request order and
      correct `ok`/`stale`/`unknown` counters even when some tokens fence.
- [ ] A settle batch above `--max-settle-batch` returns `413 too_large` naming the limit.
- [ ] With the store latched read-only, publish, fetch and settle all return `503 read_only` with
      `Retry-After`, while inspection endpoints keep answering.
- [ ] A saturated writer queue produces `503 busy` after `--writer-submit-timeout` rather than an
      unbounded handler park; a failed commit produces `503 commit_unknown` whose message names
      `Messq-Msg-Id`.
- [ ] Hardening holds: 1 byte/s header trickle is closed at `ReadHeaderTimeout` with no handler
      invocation; there is **no global `WriteTimeout`** (asserted by a 60 s long poll completing);
      a panic in a handler yields `500 internal` plus an `api.error` event and the server keeps
      serving.
- [ ] **The five-line shell worker from PLAN §7 runs green in CI**: publish → fetch → work → ack,
      over the Unix socket, with `curl` and `jq` only.
- [ ] The §7 curl transcript in `docs/PROTOCOL.md` executes in CI with normalized output
      (ULIDs/timestamps masked) — the seed of #18's harness.
- [ ] `routes()` exposes the route registry (`Method, Pattern, Name, Mutating`) that #16 and #18
      consume; a mutating route added without a registry entry fails a test.
- [ ] Coverage floors from #2 still pass; no `time.Sleep` in tests; no `time.Now` outside the Clock
      seam (lint-enforced).

## Test plan

Per PLAN §11 / D13: `-race` everywhere, real SQLite files in `t.TempDir()` (never `:memory:`), no
`time.Sleep` outside soak, all timing through the Clock seam and `testing/synctest`, every fixed bug
landing with a committed reproduction artifact.

**Unit — errors (`internal/api/errors_test.go`)**
- `TestEverySentinelIsMapped` / `TestEveryCodeIsProduced` (see acceptance criteria).
- Envelope goldens per code: exact JSON, sorted keys, `next` present where §8's teaching-error rule
  demands it, `trace_id` populated from the message trace id when known and the request id
  otherwise.
- `errs.WithCode` preserves `errors.Is` for the underlying sentinel (table test over all sentinels).

**Unit — waiter registry (`waiters_test.go`)**
- Subscribe/wake/coalesce/close; a wake with no subscriber is a no-op; a double close is safe.
- Cap enforcement, both global and per-consumer, with the counter asserted after every operation.
- Filter matching: a publish on `orders.eu.created` wakes a waiter filtered `orders.eu.*` and not
  one filtered `orders.us.*`.
- `Publish([]obs.Event)` never blocks: a test calls it with 10 000 events while 1 000 subscribers
  churn, asserting a bounded upper time bound via the fake clock and `-race` cleanliness.
- `Waiting()` returns nil with zero parked waiters (the sweeper's 4 Hz probe must be free).

**Deterministic timing (`testing/synctest`)**
- Empty fetch returns at exactly `wait_ms`; clamping to `--max-fetch-wait`; the `NextVisibleAt`
  cap; the empty-wake damper window; the settle-driven wake after a `delay_ms=0` nak. Hours of
  simulated time in microseconds of wall clock.

**Integration — real listeners**
- A real `messq serve` process (or an in-process `Server` on a real `net.Listen("unix", …)`) for
  every route: success shapes and every error code, compared against committed goldens with ULIDs,
  timestamps and db sizes normalized.
- End-to-end: create stream + consumer via the store, publish over HTTP, fetch over HTTP, ack over
  HTTP; assert the delivery row is gone and the event sequence is
  `msg.publish → msg.deliver → msg.ack`.
- The five-line shell worker executed as a `testscript`/shell test.

**Property (`pgregory.net/rapid`)**
- **The lost-wakeup property.** Random interleavings of `publish`, `fetch(wait)`, `ack`, `nak`,
  `timeout`, `pause/resume` across several consumers; the invariant hook asserts *"no fetch
  returned empty at its deadline while a matching claimable message existed for the entire wait
  window"* and *"no waiter outlives its handler"*. Failfiles committed to `testdata/regressions/`.
- Clamping/echo property: for any request, the echoed effective values are exactly
  `min(requested, cap)` and the returned batch respects them.

**Fuzz** (60 s per target in CI, corpus committed)
- The fetch and settle JSON decoders (no panic, no accepted unknown field, no accepted trailing
  data).
- Publish header extraction: `Messq-Subject`, `Messq-Msg-Id`, `Messq-Trace-Id`, `traceparent`,
  `Messq-Header-*`, including duplicated and pathological header names.
- Path-value validation: `{stream}`/`{consumer}` against #3's name grammar, seeded with traversal
  and percent-encoding attempts.

**Hardening**
- Slowloris header trickle → closed at `ReadHeaderTimeout`, handler never invoked.
- Oversized `Content-Length` publish → `413` with zero bytes of body read (asserted with a counting
  reader) and no `100-continue` emitted.
- Chunked oversized publish → `413` mid-stream.
- `--max-conns` exceeded → `503 busy`; existing connections unaffected.
- 60-second long poll completes (proves no global `WriteTimeout`); a killed peer mid-park releases
  the handler.

**Crash (extends #8's harness over HTTP)**
- The ledger is driven through the HTTP client instead of the store API: a `201` marks `OK` and the
  message must exist after `SIGKILL` + restart; a request in flight at the kill is `UNKNOWN`; a
  `4xx` is `FAILED` and must not exist. Same three-valued oracle, now proving the *wire* promise.
- Fault points `after_commit_before_reply` (client sees a dropped connection, message is durable)
  and `before_commit` (client sees `commit_unknown`, message absent).

**Golden / contract (seed of #18)**
- Route registry golden: adding, renaming or removing a route changes a checked-in file.
- `/v1/ack` batch response with mixed outcomes, byte-for-byte.
- The `docs/PROTOCOL.md` curl transcript executed and diffed.

**Benchmarks**
- `BenchmarkPublishHTTP` (1 KiB, `full`/`relaxed`, 1/8/64 publishers) — the HTTP-framing delta over
  #7's store-level number, so we know what the wire costs.
- `BenchmarkFetchLongPoll`: wake latency histogram from publish-commit to response write; asserts
  the §12 `< 5 ms` target and reports p50/p99.
- `BenchmarkWaiters/10000`: RSS, goroutine count and FD count with 10 000 parked fetches; flat
  across the run.
- `BenchmarkEmptyWakes`: 100 parked workers, 1 000 publishes/s — measures fetch commands per publish
  with and without the damper, justifying the default.

**Not tested here:** admin/inspection shapes (#15), auth matrices (#16), drain and signals (#17),
schema-locked contract enforcement (#18), metric names (#21).
