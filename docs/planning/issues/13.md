## Context

PLAN.md §11.2 names this suite and says what it is for: *"This is where the real bugs are found."*
Everything before it in M3 — consumers, cursor and flow control (#9), the fenced settle verbs (#10),
the timeout sweeper (#11), atomic dead-lettering (#12) — is one state machine assembled from four
issues, each tested against its own reading of `SEMANTICS.md`. This issue builds the **independent
second implementation** and runs the two against each other under randomised, shrinking,
restart-including operation sequences, checking every invariant after every single action.

The decisions that govern it:

- **D13 (testing)** — the adjudicated discipline names exactly this component: *"independent
  reference model driven by `rapid` with invariants checked after every action (including a
  `restart` action)"*. Rejected in the same breath: mutation testing as a gate, porcupine
  linearizability, gosim. This suite is *the* load-bearing correctness argument, not one of several.
- **PLAN §3.3 / §5** — the state machine in `internal/queue` is a **pure function**, explicitly
  because that makes property testing, the reference model and deterministic timing all cheap
  ("09's load-bearing decision, adopted whole"). This issue is the payoff for that constraint: if
  decision logic has leaked into SQL anywhere in #9–#12, this suite finds it and pushes it back into
  `internal/queue`.
- **PLAN §5.1 / §5.2** — the model is a 1:1 transcription of transitions T1–T11 from the normative
  spec (#4), written from prose and never from the implementation; invariants I1–I11 each get a
  checker over a state snapshot, invoked from rapid's `""` hook after every action, using the same
  stable IDs `internal/verify` (#8) uses.
- **PLAN §11 ground rules** — `-race` everywhere, real SQLite files under `t.TempDir()` (**never
  `:memory:`** — persistence is under test), no `time.Sleep`, PR CI ≤ 10 min, and every fixed bug
  lands with a committed reproduction artifact.
- **M3 exit criterion** — *"invariants green over 10⁵ random ops incl. restart"*. M3 does not close
  without this suite green.

What it unlocks: **#32** (the fault-injection matrix reuses this action set and these checkers at
named fault points), **#33** (the soak generator draws from the same action distribution), **#38**
(a new transition rule — the model grows an arm and the suite proves it before the feature ships).
From here on every semantic change arrives as *"add a rule to the model, add an invariant, watch the
suite"*, which is why this lands at the end of M3 rather than during M8 hardening.

## Scope

**In scope**

- `internal/model`: the naive, spec-derived, in-memory broker (~300–400 lines) — publish + dedup,
  top-up, claim, settle, sweep, dead-letter, consumer update, seek, purge, restart — plus a naive
  subject matcher. **Imports nothing but the standard library** (architecture-tested).
- `internal/model`: the `View` snapshot type, an event-stream `History`, and invariant checkers
  **I1–I11** sharing stable IDs with `internal/verify`'s SQL checkers (#8).
- `test/property`: the `Broker` driver interface, two adapters (real store on a real SQLite data
  dir; the model), and the rapid action set including **`restart`** (clean and unclean).
- The **determinism seams** that make *exact* observational equivalence possible: identity-keyed
  jitter, borrowed ids, total orders on every scan, zero reclaim jitter, strictly sequential
  driving — plus the two small amendments this requires of #10 and #11.
- **Observational equivalence** at three levels: per-action responses (including ack tokens), the
  post-action `View`, and the emitted event stream.
- **Vacuity guards**: an action/outcome coverage report that *fails* the run if the sequences never
  reached the interesting states (a suite that never dead-letters proves nothing).
- The **sabotage corpus** (`messq_sabotage` build tag) — named, deliberately broken behaviours, each
  asserted caught and shrunk — and the **regression corpus** discipline: committed rapid failfiles
  plus the distilled deterministic replays derived from them, replayed on every run.
- CI wiring and budgets: `-rapid.checks=200` on PRs, `20000` nightly, and the 10⁵-op multi-seed job
  that is the M3 exit gate.

**Out of scope**

- SIGKILL, torn tails, fsync failure, ENOSPC/EIO, real subprocess death, and therefore the durability
  half of invariant **I1** → **#8** (ledger oracle, `messq verify`, already landed) and **#32**
  (fault points, crash matrix). The `restart` action here is an in-process close/reopen of the data
  dir: it proves **recovery** (T9), not power loss, and the package doc says so.
- The HTTP surface. This suite drives `internal/store` + `internal/queue` in process; API-level
  contract checks → **#18**, API-level randomised load → **#33**.
- `seek` and `purge` **against the SUT** → **#28**. The *model* implements T10 and purge now; the
  adapter is registered as pending and #28 flips it on.
- Retention, workqueue reaping, the janitor and dedup-window expiry as *actions* → **#27** (same
  arrangement: model implements them, adapter pending).
- DLQ redrive as an action → **#29**.
- The full I10 fold over the persisted `events` **table** → **#19**; at M3, I10 is checked over the
  *emitted* event stream, and #8's `verify --deep` covers the table.
- Concurrency: two commands in flight, group-commit batching, long-poll waiters → **#8**, **#14**,
  **#33**. This suite is deliberately sequential (see "Why sequential", §4).
- Parser fuzzing and the soak generator → **#33**. Benchmarks → **#31**.
- General mutation testing (`gremlins`) — **rejected by D13**. The sabotage corpus is a small,
  hand-written, fixed set with a different purpose: validating the oracle, not scoring coverage.

## Design proposal

> Sketches, not mandates. The shapes below exist so a reviewer can argue with a concrete design;
> deviate wherever the code teaches better — except on the two rules in §2, which *are* the issue.

### 1. Where the code lives

```

internal/model/match.go        naive subject matcher (split on '.', walk; no compilation)

test/property/gen.go           generators: names, subjects, bodies, consumer configs, tokens
```

### 2. The two rules that make this worth doing

**Rule 1 — the model is written from `SEMANTICS.md`, never from the code.** When the model and the
SUT disagree, exactly one of three things is true, and the triage order is fixed:

1. the SUT is wrong → fix the SUT, commit the regression;
2. the model is wrong → fix the model, commit the regression;
3. **`SEMANTICS.md` is silent or ambiguous** → amend the spec first (#4), *then* change both sides to
   match it. Never "make the model match what the code does".

Case 3 is the most valuable output of this issue and should be expected several times — #9 and #10
have already produced four such clarifications (ack-on-READY, extend-on-READY, nak idempotency,
`max_ack_pending` shrink) that this suite must encode. `git log docs/SEMANTICS.md` acquiring commits
during this work is a success signal, not scope creep.

**Rule 2 — the model stays naive.** Maps, slices, linear scans, `sort.Slice` on every read. No index,
no cache, no early exit. If a line in `internal/model` needs a comment explaining why it is fast,
delete the cleverness. A test asserts the package stays within a line budget (proposal: 600
non-blank, non-comment lines across `model.go` + `match.go`); the budget is a smell detector, and
raising it requires saying why in the commit message.

### 3. `internal/model` — the naive broker

```go
// Package model is an independent, deliberately naive implementation of docs/SEMANTICS.md.
// It exists to disagree with internal/store. It imports nothing outside the standard library
// (enforced by TestModelIsIndependent), so it cannot inherit a bug by sharing code.
package model

type Key struct{ Stream, Consumer string }

type Model struct {
	now       int64                // unix ms; monotone within a process (see E4)
	streams   map[string]*stream
	consumers map[Key]*consumer
	events    []Event              // drained after every action
	jitter    Jitter               // injected; see §4
	limits    Limits               // mirrors the server flags the suite configures
}

type stream struct {
	cfg     StreamCfg
	nextSeq int64                  // monotone across purge (PLAN §4.2 stream_seq)
	msgs    map[int64]*Msg         // a map, not a slice: retention and purge leave holes
	dedup   map[string]dedupEntry  // key -> {seq, id, expiresAt}
}

type consumer struct {
	cfg        ConsumerCfg
	cursor     int64
	generation int32
	paused     bool
	rows       map[int64]*Delivery // seq -> row. Ack = delete(rows, seq). D5, literally.
}

type Delivery struct {
	Seq         int64
	State       State // READY | INFLIGHT
	Attempts    int32
	VisibleAt   int64
	Generation  int32
	DeliveredAt int64
	LastReason  string
	Subject     string
}

func New(l Limits, j Jitter) *Model

func (m *Model) Advance(toMS int64)                          // clock only; no sweep (E6)
func (m *Model) CreateStream(StreamCfg) error
func (m *Model) CreateConsumer(ConsumerCfg) error
func (m *Model) UpdateConsumer(Key, ConsumerPatch) (UpdateRes, error) // incl. the shrink rule, #9
func (m *Model) Publish(PublishOp) (PublishRes, error)       // dedup, limits, discard policy
func (m *Model) Fetch(FetchOp) (FetchRes, error)             // T1 top-up + T2 claim
func (m *Model) Settle(SettleOp) (SettleRes, error)          // T3/T3a/T3b/T4/T5/T6/T7
func (m *Model) Sweep(maxRows int) (SweepRes, error)         // T8 + the timeout half of T5
func (m *Model) Seek(SeekOp) (SeekRes, error)                // T10  (SUT adapter pending, #28)
func (m *Model) Purge(PurgeOp) (PurgeRes, error)             //      (SUT adapter pending, #28)
func (m *Model) Restart(clean bool) error                    // T9 lease reclamation
func (m *Model) View() View
func (m *Model) DrainEvents() []Event
```

`Fetch` reads exactly as #9 §4–§5 specify, because that is where the subtle rules live:

1. collect every `seq >= cursor` in ascending order, at most `limits.ScanLimit` of them;
2. match with the naive matcher; insert a READY row per match while `pending < max_ack_pending`;
3. write the cursor using the **three-case rule** — stopped by flow control at a match *k* → cursor
   stays at *k*; scan filled `ScanLimit` with last examined *k* → *k+1*; scan returned fewer →
   `stream.nextSeq`;
4. walk rows in ascending `seq`, claiming those with `now >= visible_at` until `Batch`, `MaxBytes`
   or the pending bound stops it — **always returning at least one message even if it alone exceeds
   `MaxBytes`**;
5. set `Hold` to `HoldNone` / `flow_control` / `catching_up` and report `CursorSeq`, `Pending`,
   `Inflight`, `Backlog`.

Thirty naive lines, no index, obviously the spec. The three-case cursor rule and the
at-least-one-message rule are the two places a plausible-looking implementation quietly differs —
which is why the model is written from #9's prose, not sketched from memory.

`Settle` transcribes **#10's decision table verbatim**, including the four rows PLAN.md does not
have: `ack` on a READY row is `ok` with `late=true`; `term` on a READY row is `ok` with `dead=true`;
`nak` on a READY row sets `visible_at = min(current, computed)` and emits an event only if the row
moved; `extend` on a READY row is `stale_ack` with `reason="not_inflight"`. The outcome enum
compared by the harness is `{ok, stale, unknown, wrong_generation, stale_ack}` plus the `late` and
`dead` flags; `stale` vs. `unknown` is decided by `seq < cursor`.

### 4. Determinism: five sources, five seams

Exact equivalence is worth a lot — an interval comparison hides off-by-one bugs — so every source of
nondeterminism gets a seam rather than a loosened assertion.

| # | Source | Seam | Notes |
|---|---|---|---|
| N1 | **±20 % backoff jitter** (PLAN §5.1, not configurable off; applied to explicit `nak --delay` too, per #10) | an **identity-keyed** `Jitter` injected into both sides | see below |
| N2 | **ULID message/trace ids** and mint time | the model *borrows* the id from the SUT response; the suite usually supplies `Messq-Msg-Id`/`Messq-Trace-Id` explicitly | identity properties checked separately (E3) |
| N3 | **SQLite row order** on the sweep scan | total `ORDER BY` on both sides (amendment to #11) | `LIMIT` over a partial order is a coin flip at ties |
| N4 | **Restart reclaim jitter** (#5, `--reclaim-jitter`, default 1 s, SQLite `random()`) | the suite sets `--reclaim-jitter=0`; #5 already provides the knob and documents it as "what the model suite (#13) and crash harness (#8) always use" | nonzero reclaim jitter is #32's subject |
| N5 | **Goroutine scheduling / group commit** | the suite is strictly sequential and drives the sweeper by *calling* it, not by ticking it | see "Why sequential" |

**Identity-keyed jitter (N1).** A sequence-based RNG diverges the instant the two sides visit rows in
a different order or batch them differently. Jitter must be a pure function of the row identity:

```go
// internal/model/jitter.go — and the widened production seam it plugs into.
type Jitter interface {
	// Delay returns the jittered delay for one scheduling decision.
	// Pure: same key, same answer, regardless of call order or batch composition.
	// Invariants (inherited from #11): result ∈ [0.8d, 1.2d], never negative, Delay(…, 0) == 0.
	Delay(k Key, seq int64, attempt int32, kind Kind, d time.Duration) time.Duration
}

type Kind uint8 // KindNak | KindTimeout | KindReclaim

func KeyedJitter(seed uint64) Jitter    // FNV-1a over (seed,key,seq,attempt,kind) → uniform frac
func RandJitter(src rand.Source) Jitter // production: ignores the key, draws from src
```

Production behaviour is unchanged (a random draw per decision, `math/rand/v2` PCG per writer, never
`crypto/rand` — #10). `KeyedJitter` is **test-only and never wired to a flag**, the same rule #11
already applies to `NoJitter`.

**Amendments this issue needs from its blockers** — both are small, both improve the code on their
own merits; raise them as review comments on #10/#11 if those have not merged yet:

| Issue | Amendment | Why |
|---|---|---|
| #11 | `type Jitter func(time.Duration) time.Duration` becomes the identity-carrying interface above; `DecideSweep(rows, pol, nowMS, j Jitter)` keeps its signature shape and gains the row key it already has in `ExpiredRow` | N1: without the row key the two sides cannot agree on a `visible_at` |
| #11 | the expiry scan's `ORDER BY d.visible_at` becomes `ORDER BY d.visible_at, d.stream, d.consumer, d.seq` — already the index order, so it is free | N3: `LIMIT` over ties is otherwise nondeterministic |
| #10 | `queue.Jitter` (the settle-side seam sharing `backoff.go` with #11) widens identically; `JitterFraction = 0.20` is unchanged | one seam, not two, or nak and timeout diverge from each other |

Explicitly **not** amendments: #5 (use `--reclaim-jitter=0`), #9 (`--scan-limit` is already a flag,
default 4096; the suite sets it to 4 so the truncation branch of the cursor rule is hit constantly).

**Why sequential.** Concurrency plus exact-state comparison is a linearizability problem, and D13
rejected porcupine. This suite issues one operation at a time and waits for its commit; interleaving
belongs to #8, #14 and #33. The honest cost is stated in the suite's package doc: *this suite proves
the state machine, not the concurrency of the writer.*

### 5. The driver interface and the two adapters

```go
// test/property/driver.go
type Broker interface {
	Advance(toMS int64)
	CreateStream(model.StreamCfg) error
	CreateConsumer(model.ConsumerCfg) error
	UpdateConsumer(model.Key, model.ConsumerPatch) (model.UpdateRes, error)
	Publish(model.PublishOp) (model.PublishRes, error)
	Fetch(model.FetchOp) (model.FetchRes, error)
	Settle(model.SettleOp) (model.SettleRes, error)
	Sweep(maxRows int) (model.SweepRes, error)
	Seek(model.SeekOp) (model.SeekRes, error)   // sutBroker: returns errPending until #28
	Purge(model.PurgeOp) (model.PurgeRes, error)
	Restart(clean bool) error
	View() model.View
	DrainEvents() []model.Event
}
```

`refBroker` is a thin wrapper over `*model.Model`. `sutBroker` owns a real data dir:

```go
type sutBroker struct {
	dir string        // a real directory; a real messq.db; a real WAL on disk
	clk *clock.Fake   // #3; owned by the harness, survives reopen
	st  *store.Store  // writer + ro pool, opened through the production Open path
	swp *store.Sweeper
}

func (b *sutBroker) Restart(clean bool) error {
	if clean {
		return b.reopen(b.st.Close)        // clean_shutdown=1, checkpoint TRUNCATE
	}
	return b.reopen(b.st.CloseUnclean)     // test-only: drop handles, leave clean_shutdown=0
}
```

`CloseUnclean` releases handles without the shutdown ceremony, so the reopen takes §4.4's
`recovery.unclean` path — `quick_check`, lease reclaim, `recovery.reclaimed` — with `attempts`
untouched (D6/T9). It is a `store` export guarded by a doc comment and the `internal/` boundary; the
*real* unclean case (SIGKILL, torn WAL tail) stays with #8.

**Temp-dir hygiene.** `rapid.T.TempDir()` inside `rapid.Check` accumulates one directory per check —
20 000 on the nightly run, none removed until the binary exits. The harness instead creates each
check's dir with `os.MkdirTemp(runRoot, "")` and removes it in the check body, keeping it only when
the check failed or `-property.keep` is set.

### 6. The action set


| Action | What rapid draws | Spec | Notes |
|---|---|---|---|
| `create_stream` | name, subjects, limits, `discard`, dedup window | §4.2 | small alphabets (3 streams, 4 consumers, 6 subjects) so collisions are frequent |
| `create_consumer` | filters, `ack_wait`, `max_deliver ∈ {0,1,2,5}`, `max_ack_pending ∈ {1,2,8,1000}`, backoff ∈ {`[]`, `[0]`, `[1s]`, default} | §4.2 | D13's boundary configs are *weighted*, not merely possible |

### 7. The invariant hook

```go
"": func(t *rapid.T) {
	sv, rv := w.sut.View(), w.ref.View()
	if d := cmp.Diff(rv, sv, viewOpts...); d != "" {
		w.dumpTranscript(t)
		t.Fatalf("state divergence after %s:\n%s", w.lastAction, d)
	}
	w.history.Observe(sv, w.sutEvents, w.refEvents)
	model.CheckAll(t, sv, w.history)   // I1..I11 over the SUT's own state
},
```

`History` turns point-in-time snapshots into temporal invariants: per check it accumulates acked
pairs, DEAD pairs, per-`(consumer,seq)` delivery counts, per-consumer cursor/generation history, and
the concatenated event stream.

| ID | Statement (PLAN §5.2) | How it is checked here |
|---|---|---|
| I1 | no acknowledged loss after a crash | **partial** — `restart` asserts the *recovery* half: nothing published-and-committed disappears, nothing acked reappears. The fsync/power-loss half is #8/#32; the doc comment says so rather than claiming it. |
| I2 | every `(consumer, seq)` below the cursor is resolved, READY or INFLIGHT — exactly one | `View` walk |
| I3 | an acked pair is never redelivered except via seek/replay/redrive | `History.Acked` vs. every later `msg.deliver` for the pair, keyed by generation |
| I4 | `attempts ≤ max_deliver` (when `max_deliver > 0`), across restarts | `View` walk; `restart` is the interesting case |
| I5 | `count(deliveries[c]) ≤ max_ack_pending(c)` | **admission form** (#9): no top-up inserts a row while `pending ≥ max_ack_pending`; the at-rest bound holds except during a deliberate shrink, where `overshoot` is asserted to be non-increasing until it reaches 0 |
| I6 | `cursor_seq` monotone non-decreasing within a generation | previous vs. current `View` in `History`; the shrink rewind bumps the generation-free exception documented in #9 and is asserted to only rewind to a seq with no delivery row |
| I7 | no stale-fenced settle mutates a live row | the `settle` action snapshots the `View` before a forged token and requires **byte-identical** state after (events excepted) |
| I8 | each pair enters DEAD at most once, with exactly one DLQ message | `History.Dead` vs. `<stream>.dlq` contents, keyed on `(origin_stream, origin_seq, origin_consumer)` per #12 — *not* on message id, since two consumers legally produce two DLQ rows sharing one id; provenance headers, preserved `id` and `trace_id` compared against the origin |
| I9 | every duplicate has a named cause | fold the event stream: every `msg.deliver` with `attempt > 1` is preceded, for that pair, by `msg.nak`, `msg.timeout` or `recovery.reclaimed` |
| I10 | folding events reproduces state | fold the **emitted** event stream into a `View` and compare (the table-level fold is #19; `verify --deep` is #8) |
| I11 | no unbounded collection | per-consumer rows bounded by `max_ack_pending`, total rows by `Σ max_ack_pending`; plus #2's architecture test for unbounded channels/slices |

`model.CheckAll` and `verify.Registry()` (#8) are two implementations of the same IDs — Go over a
snapshot, SQL over a data dir — and that redundancy is intentional. `TestInvariantCoverageMatrix`
prints the matrix and fails if an ID is checked in neither place:

```

I2         yes          yes          TestPropertyInvariants/I2

```

### 8. Observational equivalence: what is compared

Three levels, all after every action:

1. **Responses** — `PublishRes{Seq, Duplicate}`; `FetchRes{Messages[], Hold, CursorSeq, Pending,
   Inflight, Backlog}` including **`AckToken` as an exact string** (a fence bug then shows up as a
   token diff before it becomes a state diff) and `Attempt`, `MaxDeliver`, `DeadlineMS`;
   `SettleRes{Outcome, Reason, Late, Dead, VisibleAt}`; `SweepRes{Redelivered, Dead, Truncated}`;
   `UpdateRes{Dropped, Overshoot, CursorRewoundTo}`. Errors are compared by **sentinel identity**
   (`errors.Is` against #3's set), never by message text — that is #18's job.
2. **State** — the full `View`, `cmp.Diff`'d.
3. **Events** — kind and key fields in order, plus an allow-listed subset of `detail` per kind
   (`reason`, `cause`, `delay_ms`, `late`, `duplicate`, `degraded`, `count`), declared in one table
   so it cannot silently drift.

The ignore list is small, closed and asserted:

```go
var viewOpts = []cmp.Option{
	// Message ids are minted by the SUT; the model borrows them (N2). Identity is checked
	// separately: ULID-shaped, unique within an origin stream, stable across restart,
	// preserved into the DLQ copy (#12 dropped the global UNIQUE index on messages.id).
	cmpopts.IgnoreFields(model.MsgView{}, "ID", "TraceID"),
	cmpopts.EquateEmpty(),
}
// TestIgnoreListIsClosed fails if viewOpts grows: every addition is a claim that a field is not
// comparable, and that claim gets reviewed.
```

**Loosening the comparison is never the fix for a flake.** A newly discovered nondeterminism is
resolved by adding a seam (§4) or by amending the spec; if neither is possible, the field moves to
the ignore list *with a comment naming the reason and the issue that will remove it*.

### 9. Vacuity guards

A property suite that never reaches an interesting state passes forever. Mirroring #8's guards, each
run accumulates a coverage report and **fails** if a required outcome was never observed:

| Guard | Requirement over a full run |
|---|---|
| action mix | every live action fires ≥ 2 % of total operations |
| dead by `max_deliver` | ≥ 1 |
| dead by `term` | ≥ 1 |
| stale ack rejected (attempt fence, both directions) | ≥ 1 each |

### 11. The regression corpus

Rapid writes a failfile under `.rapid/` and shrinks automatically. The discipline (PLAN §11: *every
bug fix lands with a committed reproduction artifact*):

1. Commit the failfile to `testdata/regressions/rapid/<issue>-<slug>.failfile`; every run replays the
   whole directory via `-rapid.failfile` before drawing anything new (≤ 20 s budget).
2. **Also** distil the shrunk sequence into a hand-written deterministic test in `regress_test.go`.
   Failfiles are tied to the action set and rot when actions are renamed or reweighted; the distilled
   test is the durable artifact. The harness makes this cheap by printing a paste-ready transcript:

```
--- FAIL: TestBrokerModel (2.41s)
    property: divergence after settle#7
    transcript (paste into regress_test.go):
        w.CreateStream("s0", []string{"a.>"})
        w.CreateConsumer("s0", "c0", model.ConsumerCfg{AckWaitMS: 30_000, MaxDeliver: 2,
            BackoffMS: []int64{1_000}, MaxAckPending: 1})
        w.Publish("s0", "a.x", 16, "")
        w.Fetch("s0", "c0", 1, 0)
        w.Advance(30_001)
        w.Sweep(512)
        w.Fetch("s0", "c0", 1, 0)
        w.Settle(model.Ack, "s0/c0/1/1/1")   // token from attempt 1; attempt 2 is in flight
    diff (-model +sut):
        View.Deliveries["s0/c0/1"].State: READY(0) != <absent>
    failfile: .rapid/TestBrokerModel-20260923T101104
    reproduce: go test ./test/property -rapid.failfile=.rapid/TestBrokerModel-20260923T101104
    data dir: kept at /tmp/messq-prop-84213/check-0091 (-property.keep)
```

3. A stale failfile that no longer replays is reported as `SKIP: stale failfile` naming its distilled
   test; it is deleted only once that test exists.

### 13. Edge cases

| # | Case | Handling |
|---|---|---|
| E1 | **Jitter divergence** — the two sides schedule the same nak to different `visible_at`. | Identity-keyed jitter (§4 N1), including `Delay(…, 0) == 0` so an empty/zero backoff is not jittered into the future. A residual divergence is a real ordering bug — investigate; do not switch to an interval comparison. |
| E2 | **Settling a READY row** (timed out, not yet re-claimed). | #10's table decides it: `ack` → `ok, late=true` (the duplicate is *avoided*, and the counter is separate from `stale_ack` on purpose); `term` → `ok, dead=true`; `nak` → accepted, `visible_at = min(current, computed)`, event only if the row moved; `extend` → `stale_ack, reason="not_inflight"`. The model implements exactly that and the guard list requires the late-ack case to be *observed*, so if #10's decision ever changes, this suite fails loudly rather than drifting. |
| E3 | **Minted ids.** | Model borrows (N2). Identity is asserted separately: ULID shape, unique *within an origin stream* (#12 dropped the global unique index so two consumers can dead-letter the same message), stable across restart, preserved into the DLQ copy along with `trace_id`. |
| E4 | **`now` after `restart`.** | The fake clock is owned by the harness and survives the reopen, so both sides see the same `now`. #6's `batchNow() = max(clock.Now(), lastNow)` monotonic guard is re-implemented in the model, so a drawn backwards jump behaves identically on both sides. |
| E5 | **Reclaim scheduling on unclean restart.** | `--reclaim-jitter=0` (N4): every reclaimed row becomes visible at exactly `now`. #5 already documents this as the model-suite setting; nonzero reclaim jitter is exercised by #32. |
| E6 | **Time advanced past several deadlines with no `sweep`.** | Legal and important: rows sit expired-but-unswept, exactly as they do between real ticks. I2/I4 must hold in that state, and `fetch` must **not** claim an INFLIGHT row whose deadline has passed — only the sweeper moves it. A favourite bug location; `advance_time` exists as a separate action precisely to reach it. |
| E7 | **`sweep(maxRows=1)` with 5 rows due.** | Both sides apply the total order `(visible_at, stream, consumer, seq)` and the same limit; `Truncated` is compared. Catches an accidental `ORDER BY` change in SQL. |
| E8 | **`max_deliver = 0`** (unlimited). | Never dead-letters; the backoff index still saturates at the last entry. Drawn often enough to keep the arm alive, rarely enough that DLQ coverage does not starve. |
| E9 | **Empty or `[0]` backoff schedule.** | `visible_at = now`, immediately claimable. The model does not "helpfully" floor it to the sweep interval — that floor is an emergent property of the real sweeper's 250 ms tick, and the explicit `sweep` action makes it visible instead of assumed. |
| E10 | **`max_ack_pending = 1`.** | The tightest flow-control arm; drawn deliberately. Exercises "top-up refuses, cursor does **not** advance past the refused match, `Hold = flow_control`, other consumers unaffected". |
| E11 | **Lowering `max_ack_pending` below current `pending`** (#9's shrink rule). | `update_consumer` is a live action. Undelivered rows (`READY`, `attempts = 0`) are dropped tail-first, `cursor_seq` rewinds to the lowest dropped seq, the remainder is reported as `overshoot`. I5 is checked in its **admission** form during the drain, and #8's SQL I5 check must report the same situation as an advisory, not a violation — a disagreement between the two checkers is a first-class bug in this issue. |
| E12 | **Dedup window expiry.** | The janitor is not running at M3, so `dedup_window_ms` is set long enough that no key expires mid-check. The model already implements expiry; the `janitor` action arrives with **#27** and only the adapter is pending. |
| E13 | **Stream/consumer deleted with live rows.** | Drawn rarely; cascade rules come from #7/#9 and a disagreement is a spec question (Rule 1, case 3). Likely amendment: a consumer recreated under the same name starts at `generation = 1`, so old tokens fail the row lookup — which is why `stale` (below cursor) and `unknown` (at or above it) must stay distinguishable in `SettleRes`. |
| E14 | **The suite gets slow.** | The dominant cost is per-check SQLite creation plus `synchronous=FULL` commits. Mitigations, in order: copy a template DB per check; run at `-property.durability=relaxed` (durability is #8's and #32's subject, not this one's); shorten `-property.ops`. **Never**: fewer invariant checks. |
| E15 | **Failfile rot.** | §11 step 3. A rotted failfile is a `SKIP` with a name, never a silent pass. |
| E16 | **Two consumers on one stream.** | Drawn frequently and load-bearing: "the message is acked" is meaningless (PLAN §5), so per-consumer independence — one consumer's ack, seek or dead-letter never moves another's row — falls out of the `View` comparison, and two-consumers-dead-letter-the-same-seq is a required coverage outcome (#12: two DEADs, two DLQ records, one id). |
| E17 | **Publishing into, and consuming from, `<stream>.dlq`.** | The DLQ is a real stream (D3) and drawn occasionally. #12 already decided the recursion rule: `dead_policy=dlq` on a `.dlq` consumer is refused with `dlq_recursion`, `.dlq` consumers default to `drop`, and the dead path degrades to `drop` rather than creating `orders.dlq.dlq`. The model encodes that; no spec question remains. |
| E18 | **Model/SUT disagree about an error.** | Compare `errors.Is` against #3's sentinel set only. Error strings are #18's contract, not this suite's. |
| E19 | **A model bug produces a false failure.** | Expected occasionally. Triage order is fixed (Rule 1). The model's simplicity is the mitigation: a reviewer must be able to decide which side is wrong by reading it in five minutes. |

- [ ] The rapid suite drives the live action set (`create_stream`, `create_consumer`,
      `update_consumer`, `publish`, `fetch`, `settle`, `sweep`, `advance_time`, `restart`) against
      both brokers, comparing responses, the full `View` and the emitted event stream **after every
      action** via the `""` invariant hook.
- [ ] `restart` (clean and unclean) is a first-class action; an unclean restart with in-flight rows

- [ ] Ack tokens are compared as exact strings, so an attempt- or generation-arithmetic bug fails at

- [ ] The model reproduces #9's three-case cursor rule exactly, including "cursor does not advance

- [ ] Forged tokens (wrong attempt in both directions, wrong generation, unknown seq, below cursor,

- [ ] The vacuity guard fails the run when any of the 16 required outcomes was not observed; the

- [ ] `go test ./test/property -rapid.checks=200 -race` passes in ≤ 3 minutes and is a required PR
      check.
- [ ] `TestPropertyLong` executes **≥ 10⁵ operations across 100 seeds with zero invariant violations

- [ ] Each named sabotage is detected within ≤ 100 checks and shrunk to ≤ 12 actions;

## Test plan

The deliverable *is* a test suite, so the plan splits into "tests of the system" (what the suite
does) and "tests of the suite" (why anyone should believe it).

**Tests of the system**

- `TestBrokerModel` — the rapid entry point: 200 checks on PRs, 20 000 nightly, `-race`,
  `-rapid.shrinktime=2m`. Invariants I2–I11 plus three-level equivalence after every action.
- `TestPropertyRestart` — a narrowed action set (`publish`, `fetch`, `settle`, `restart`) with a
  restart weight around 25 %, at high check counts. Recovery bugs are rare per action, so the draws
  are concentrated where they live.
- `TestPropertyBoundaryConfigs` — the suite pinned to D13's boundary matrix (`max_deliver ∈ {0,1}`,
  `max_ack_pending = 1`, empty and `[0]` backoff, single-subject and `>` filters, `batch=1` with a
  `max_bytes` below one message size), because uniform generation visits these too rarely.
- `TestPropertyDLQ` — DLQ-weighted draws (`max_deliver = 1`, frequent `term`, two consumers per
  stream) asserting I8, the full provenance header set, preserved `id`/`trace_id`, the
  `dlq_recursion` refusal, and DLQ-stream equivalence (#12).
- `TestPropertyFlowControl` — `update_consumer` shrink-weighted draws asserting I5's admission form,
  the cursor rewind, and `overshoot` draining monotonically to zero (#9's spec amendment).
- `TestPropertyLong` — 100 seeds × 1000 ops; the M3 exit gate.

**Tests of the suite**

- `TestSabotageIsCaught` — every sabotage in §10, each asserted caught, bounded, and shrunk small.
- `TestModelIsIndependent` — `go list -deps ./internal/model` contains no project package.
- `TestModelLineBudget` — the naivety budget.
- `TestIgnoreListIsClosed`, `TestActionRegistryComplete`, `TestInvariantCoverageMatrix`.
- `TestCoverageGuardFailsWhenVacuous` — a deliberately crippled generator (publish only) must make
  the coverage guard **fail**; a guard that cannot fail is decoration.
- `TestTranscriptReplays` — a transcript printed by a synthetic failure compiles and reproduces the
  same divergence when pasted into `regress_test.go`; the distillation path is itself tested.
- `TestFailfileCorpusReplays` — every committed failfile either replays or is reported stale.

**Unit tests inside `internal/model`** (the model must be trustworthy *before* it is used as an
oracle)

- One test per transition T1–T11, hand-written from the §5.1 table, `go-cmp` diffs, no assertion DSL
  (PLAN §13).
- The three-case cursor rule and the at-least-one-message byte-budget rule, each as its own table.
- `KeyedJitter`: result in `[0.8d, 1.2d]`, never negative, `Delay(…, 0) == 0`, pure in the key,
  uniform over 10⁵ keys, identical across processes and architectures.
- Naive matcher vs. `internal/subject` (#3) differential property test — a second naive
  implementation of the matcher #3 already fuzzes. A disagreement between two independent naive
  implementations is worth knowing about.

**Integration with existing harnesses**

- `internal/verify` (#8) and `model.CheckAll` both run against the same final data dir at the end of
  each check batch. A check that passes the `View` invariants but fails `messq verify` means the SQL
  checkers and the Go checkers disagree — a first-class bug in *this* issue, not a flaky test.
- The nightly coverage report is written as JSON and trended, so a generator regression (an outcome
  that used to occur 200× and now occurs 3×) is visible before the suite becomes green-but-blind.

**Not tested here, by design:** concurrency (#33), SIGKILL and fsync durability (#8, #32), HTTP
shapes and error strings (#18), throughput (#31). The suite's package doc names each of these and the
issue that owns it, so nobody mistakes a green property run for a durability proof.
