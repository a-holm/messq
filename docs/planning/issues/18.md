## Context

#14, #15 and #16 finished the wire: the data plane, the control plane, the closed error-code enum
and the auth/listener policy. Every shape a client will ever see now exists — and **nothing stops
any of them from changing tomorrow.** A field rename in a struct literal, an `omitempty` added
during a refactor, a `409` quietly becoming a `400`: each is a silent break for every shell worker,
`pkg/client` user (#22) and CLI JSON consumer (#24) in existence, and each is invisible in a diff
that looks like a cleanup.

PLAN.md §7 states the promise this issue turns into machinery:

> All errors share one envelope with stable machine codes … **Codes are a closed, documented enum
> and part of the 1.0 compatibility contract.**

and §11.5 states the second half:

> Golden log/metric/API tests — scripted scenario asserts exact event sequences and field names …
> every documented error code is exercised; **the README curl transcript and every doc command
> block execute in CI (`testscript`) — documentation cannot rot.**

This issue builds both, and closes **M4's exit criterion**: *"the five-line shell worker is a
passing CI test."* Two things ship:

1. **A contract suite** — black-box HTTP cases over a real daemon covering every route's success
   shape and every documented error code, with committed *shape digests* so removing, renaming or
   retyping a JSON field fails the build with a message demanding a compatibility decision.
2. **The executable-documentation harness** — every command block in `README.md` and
   `docs/PROTOCOL.md` is extracted, run against a fresh daemon, normalised and diffed against the
   output printed in the document itself. The doc *is* the golden file.

Governing PLAN.md material:

- **§7 API / protocol** — the endpoint list, the error envelope, the raw-body-in/`body_b64`-out
  convention, the `Messq-*` header set, and the five-line shell worker.
- **D2** — HTTP/JSON was chosen because *"`curl` is the universal client and the 3 a.m. debugger."*
  A curl transcript that no longer works is that decision quietly failing. D2 also promises *"stable
  JSON shapes"* as the door to a post-1.0 gateway; stability is a test, not an intention.
- **§11 Testing strategy** — golden API tests, executable documentation, `-race`, no `time.Sleep`,
  PR CI ≤ 10 min wall clock, every fixed bug landing with a committed reproduction artifact.
- **D13** — *"the quality-advocate's discipline at the pragmatic-shipper's scale"*: goldens and
  executable docs are in; a shipped conformance binary and a linearizability checker are not.
- **§10 / D12** — the security model whose *denials* are contract surface: `401`/`403` shapes, the
  non-loopback-without-auth fatal startup, socket and file modes.
- **§14 M8 / #36** — the v1.0 compatibility promise ("HTTP API shapes, CLI `--json` shapes, log
  schema, on-disk format, error codes"). This issue produces the artifact that promise is made
  *about*.

What it unlocks: #26 reuses the harness for the CLI `.txtar` suite, #35 writes the 1.0 doc set
knowing every block executes, #34/#36 replay the frozen contract against later builds, #22 has a
byte-level spec to code against.

## Scope

### In scope

- **`test/contract/`** — the black-box HTTP contract suite: a case table over a real `messq serve`
  on a Unix socket *and* a loopback TCP listener, asserting status, contract headers and
  canonicalised body against committed goldens.
- **Shape digests** (`testdata/wire/*.shape`) for every request and response type on the wire, plus
  the **change classifier** that labels a digest diff `ADDITIVE` or `BREAKING` and refuses to let
  `-update` launder a break.
- **Enum freeze**: committed lists of every closed string set that crosses the wire — error `code`,
  `hold_reason`, delivery/pending `state`, DLQ `cause`, `degraded[].kind`, settle result `ok|stale|
  unknown` — and the `code → HTTP status` table.
- **Coverage binding**: the suite iterates #14/#15's route registry and #14's code enum; a route
  without a case, or a code neither produced nor listed as reserved-for-#N, fails CI.
- **Auth-denial and listener-policy cases**: missing/malformed/unknown/wrong-role/wrong-stream-scope
  tokens over TCP; the startup matrix (non-loopback bind without `--auth-file` is fatal); socket
  `0660`, data dir `0700`, DB `0600` verified from the outside.
- **`test/docs/`** — the executable-documentation harness: fenced-block extraction with directives,
  the session model, the sandboxed runner (built on `testscript`), the normaliser, and the
  `-update` flow that rewrites the expected output **inside the markdown**.
- **`internal/wirecheck/`** — the shared, importable pieces (canonical JSON, normaliser, shape
  digest + classifier) so #26, #34 and #36 do not each grow their own.
- **The five-line shell worker** (PLAN §7) as a first-class case in both suites.
- **CI wiring**: `contract` and `docs` jobs in `pr.yml` with stated wall-clock budgets, the
  `-update` developer flow documented in `CONTRIBUTING.md`, and **gate self-tests** (sabotage a
  field name / a status code / a doc block; assert each gate bites) in the style #2 established.

### Out of scope

- The CLI `.txtar` golden suite, `quickstart`, completions and help topics → **#26**. This issue
  ships the harness and the shared packages #26 builds on; it adds no CLI cases because the CLI
  does not exist yet.
- Writing the 1.0 documentation set — final README, `PROTOCOL.md`, `OPERATIONS.md`, runbooks,
  comparisons → **#35**. This issue makes every block in whatever documents exist at M4 executable,
  and hands #35 a harness that fails on prose that lies.
- Metric names, label sets and exposition goldens → **#21**; log field-schema goldens → **#19**.
  Same discipline, different surface, different owner.
- Implementing auth, roles, the token file and the listener policy → **#16**. This issue only pins
  their observable behaviour.
- Cross-version replay (previous release's contract dir against the current binary) and the
  released compatibility promise → **#34** / **#36**. The frozen artifacts land here in the shape
  those issues will consume.
- Fuzzing beyond this issue's own parsers, the nightly fuzz job and soak → **#33**.
- Durability/crash proof over HTTP (a `201` survives SIGKILL) → **#14** on **#8**'s harness; the
  fault-point matrix → **#32**.
- A shipped `messq conform <addr>` command (plan-07's idea) → deferred, see the table below.
- `429 rate_limited` cases → **#39**; TLS listener cases → **#40**. Both are reserved codes here.

## Design proposal

> Proposal, not mandate — **except** the four frozen artifacts in §1 and the rule that `-update`
> cannot approve a breaking change. Those are cheap now and expensive after #22, #24 and #35 build
> on the wire.

### 1. What "the contract" is — four artifacts, one directory

```
test/contract/testdata/
  wire/<Type>.shape        field-level shape digest per request/response type
  enums/<name>.txt         closed string sets (codes, hold_reason, state, cause, kind, …)
  codes.tsv                code → HTTP status → owning issue|"produced"
  golden/<case>.txt        status + allow-listed headers + canonical JSON body, normalised
```

Everything else in the suite is code that produces or checks these. #36's compatibility promise
cites this directory by path; #34 copies it per released version.

```
test/contract/            contract_test.go, cases_*.go (publish, fetch, settle, streams,
                          consumers, pending, info, health, auth, errors, ndjson)
test/docs/                docs_test.go, extract.go, runner.go, testdata/
internal/wirecheck/       canonical.go (canonical JSON), normalize.go, shape.go, classify.go
internal/testutil/daemon/ StartDaemon(t, opts) — real subprocess, unix + tcp, ready-polling
```

### 2. The contract suite

```go
package contract

type Case struct {
    Name     string            // golden file name; stable, referenced by docs/guarantees.md (#35)
    Route    string            // "POST /v1/streams/{stream}/messages" — must exist in api.Routes()
    Setup    func(*Env)        // fixtures via the HTTP API only — black box, no store access
    Request  Request           // method, path, query, headers, raw or JSON body
    Want     Want              // status, code (for errors), header expectations
    Listener Listener          // Both (default) | UnixOnly | TCPOnly
    Token    string            // "" = none; names a token from the fixture auth file (#16)
}

type Want struct {
    Status int
    Code   string   // "" for success; must be a member of the frozen enum
    Shape  string   // type name whose digest the body must validate against
}
```

Three assertions per case, in increasing strictness:

1. **Status and contract headers** match. Only an allow-list is recorded — `Content-Type`, `Allow`,
   `Retry-After`, `WWW-Authenticate`, `ETag`, `Cache-Control`, `X-Content-Type-Options` and
   `Messq-*`. `Date`, `Content-Length` and `Connection` are excluded: they vary and freezing them
   buys nothing.
2. **The body validates against its shape digest** — no undeclared field, no missing required
   field, no wrong JSON type. This catches the response built as a `map[string]any` that drifted
   from the struct nobody updated.
3. **The canonicalised, normalised body equals the golden** — the human-readable half, and the one
   that shows up in review as *"this response changed"*.

Both listeners run the same cases with the same goldens, which is how #14's *"byte-identical bodies
on Unix and TCP"* criterion becomes continuously true rather than true once.

**Coverage binding** (the part that makes the suite self-maintaining):

```go
func TestEveryRouteHasACase(t *testing.T)   // api.Routes() ▷ cases; unmatched route = failure
func TestEveryCodeIsProduced(t *testing.T)  // codes.tsv ▷ cases; a code must be produced by a
                                            // case, or carry an owning issue (#27, #39, #40)
func TestEveryCaseNamesARealRoute(t *testing.T) // no orphan cases after a route is removed
```

#14 already asserts sentinel→code exhaustiveness *in-process*; this is the black-box counterpart —
a code that exists in the table but can never actually leave the process is a documentation lie.

### 3. Shape digests and the breaking-change classifier

A digest is generated by reflecting over the Go type, sorted by JSON path so field reordering — not
a wire change — does not churn the file:

```
# PublishResponse.shape — generated by `go test ./test/contract -update`.
# Editing by hand does nothing; changing it is governed by docs/compatibility.md.
duplicate      bool     always
id             string   always
published_at   number   always   int64,unix_ms
seq            number   always   uint64
stream         string   always
trace_id       string   always
```

```
# FetchResponse.shape (excerpt)
messages                    array    always
messages[].ack_token        string   always
messages[].attempt          number   always   int
messages[].body_b64         string   always   base64
messages[].deadline         string   always   rfc3339
messages[].headers          object   optional map[string]string
hold_reason                 string   always   enum:hold_reason
pending                     number   always   int64
```

`always` vs `optional` is `omitempty`, and it is **contract**, not formatting: a shell worker doing
`jq -e '.duplicate'` breaks the day `duplicate: false` starts disappearing. The suite therefore also
asserts a small hand-maintained list of fields that must *never* be `omitempty` —
`duplicate`, `hold_reason`, `attempt`, `applied`, `changed`, `stale`, `complete` — every field whose
zero value is meaningful.

**Classifier** (`internal/wirecheck/classify.go`):

| Digest change | Verdict |
|---|---|
| Field added (`optional`) | `ADDITIVE` |
| Field added (`always`) to a **response** | `ADDITIVE` |
| Field added (`always`) to a **request** | `BREAKING` — old clients stop working |
| Field removed or renamed | `BREAKING` |
| JSON type changed (incl. scalar↔array, number↔string) | `BREAKING` |
| `always` → `optional` | `BREAKING` — a field that used to always appear can now vanish |
| `optional` → `always` | `ADDITIVE` |
| Enum member added | `ADDITIVE` (clients must tolerate unknown members; stated in `PROTOCOL.md`) |
| Enum member removed/renamed, or a `code`'s HTTP status changed | `BREAKING` |

**Governance — the rule that gives the gate teeth.** `go test ./test/contract -update` regenerates
goldens and digests, but on any `BREAKING` verdict it **fails anyway**, printing:

```
wire contract: BREAKING change in FetchResponse
  - removed field: messages[].max_deliver (number)
  - retyped field: pending  number → string
This is a v1 compatibility break (PLAN §7: codes and shapes are part of the 1.0 contract).
If it is intended, add an entry to docs/compatibility.md naming the version that breaks it and
re-run with MESSQ_WIRE_BREAK=1. If it is not, you probably renamed a struct field.
```

`MESSQ_WIRE_BREAK=1` is additionally refused unless `docs/compatibility.md` gained a new entry in
the same working tree — an accident cannot be a one-flag mistake, and the audit trail is a file in
the repo rather than a memory of a review.

### 4. Normalisation — masked narrowly, on purpose

Golden comparison happens after canonicalisation (keys sorted, 2-space indent, so `jq`'s and Go's
whitespace are irrelevant) and normalisation:

| Kind | Rule | Replacement |
|---|---|---|
| Global | ULID `[0-9A-HJKMNP-TV-Z]{26}` | `<ULID>` |
| Global | RFC3339 timestamp | `<TS>` |
| Global | 32-hex trace id | `<TRACE>` |
| Global | the daemon's temp dir / socket path | `/run/messq/messq.sock`, `/var/lib/messq` |
| Global | `version`, `commit`, `go` values | `<VERSION>`, `<COMMIT>`, `<GO>` |
| Path-scoped | `uptime_ms`, `db_bytes`, `wal_bytes`, `disk_free_bytes`, `stats_age_ms`, `age_ms`, `*_at` ms fields | `<NUM>` |

**Never masked**, and the reason this table is an allow-list rather than a regex sweep: `seq`,
`attempt`, `max_deliver`, `pending`, `backlog`, counts, `hold_reason`, `duplicate`, `code`,
`applied`, and **`ack_token`**. The token is `stream/consumer/seq/attempt/generation` (D7) — every
component is deterministic in a scripted run, so a golden that contains
`orders/worker/3/2/1` is a free assertion that fencing arithmetic did not move. Masking it would
throw that away.

Normalisation must be idempotent (property-tested) or `-update` oscillates between two goldens.

### 5. The executable-documentation harness

**Extraction.** Blocks are marked with an HTML comment directive so rendered docs stay clean:

````markdown
<!-- messq:run session=quickstart timeout=20s -->
```console
$ curl -s -XPOST --unix-socket /run/messq/messq.sock \
    -d '{"name":"orders","subjects":["orders.>"]}' http://localhost/v1/streams
{"name":"orders","subjects":["orders.>"],"retention":"limits","created_at":<TS_MS>,"changed":true}
```
````

| Directive | Meaning |
|---|---|
| `session=NAME` | Blocks sharing a session run in document order against one daemon and data dir. Sessions are the unit of parallelism and isolation. |
| `timeout=D` | Per-block wall-clock budget (default 10 s); a long-poll demo says `timeout=20s`. |
| `exit=N` | Expected exit status (default 0) — how error transcripts are pinned to the §8 exit-code contract. |
| `preseed=orders:10492` | Publish N throwaway messages first, so a doc showing `seq 10493` shows a *real* 10493 instead of a mask. |
| `env=K=V` | Extra environment for the block. |
| `mask=$.storage.db_bytes` | Extra path-scoped mask for this block. |
| `nocompare` | Run it (it must succeed) but do not diff the output — for genuinely nondeterministic demos. |
| `no-run="reason"` | Do not execute; the reason is mandatory and shows up in review. |
| `requires=curl,jq` | External tools the block needs. |

**Running.** Each session materialises as a synthesized `.txtar` script executed with
`rogpeppe/go-internal/testscript` — already an approved dependency (§13), already what #26 will use,
and it brings `-update`, a hermetic `$WORK`, an environment allow-list and CI integration for free.
Per session: a fresh data dir, a fresh `messq serve` on `$WORK/messq.sock`, `TZ=UTC`, `LC_ALL=C`,
`NO_COLOR=1`, a `PATH` containing only the built `messq`, `curl`, `jq` and coreutils. Each block
becomes `bash -euo pipefail block-NN.sh`; the documented socket path and `/var/lib/messq` are
rewritten to `$WORK` on the way in and back again on the way out, so the document shows the path an
operator actually has.

**`-update` writes back into the markdown.** `go test ./test/docs -update` replaces the non-`$`
lines inside each fence with the normalised actual output. The document is the golden file; doc
drift appears in `git diff` as a documentation change, reviewed as one. Continuation lines ending
in `\` belong to the preceding command; everything else is output.

**Doc lint** (same package, no daemon needed): every `console`/`bash`/`shell` fence in the scanned
document set carries either a `messq:run` directive or `no-run="…"`; no block contains a
token-shaped string that is not the harness's own fixture; all transcripts use exactly one canonical
socket path and one canonical `Host` (`http://localhost`), since the two forms floating around the
issue drafts would otherwise both be "correct" forever.

**Tool availability is not a skip.** Locally, a missing `curl` or `jq` skips with a loud message.
In CI, `MESSQ_DOCS_REQUIRE_TOOLS=1` turns that skip into a failure, and the job pins and logs the
`curl`/`jq` versions — a green run that silently executed nothing is exactly how documentation rots
while a badge stays green.

### 6. Auth denial and listener policy (#16's behaviour, pinned)

Contract cases over TCP, each with a golden envelope:

| Case | Want |
|---|---|
| No `Authorization` header | `401 unauthorized`, `WWW-Authenticate: Bearer`, message names `--auth-file` |
| Malformed header (`Basic …`, empty, `Bearer` alone) | `401 unauthorized`, identical body — a parse failure and a wrong secret must be indistinguishable |
| Unknown token | `401 unauthorized`, identical body to the above |
| Valid `publish` token → `fetch` | `403 forbidden`, message names the required role |
| Valid `consume` token → stream `DELETE` | `403 forbidden` |
| Valid `admin` token scoped `orders.*` → `POST /v1/streams/billing/messages` | `403 forbidden`, message names the scope, **not** the token |
| Any denial | an `auth.denied` event exists; the response body contains no token id, no secret, no stack |
| Unauthenticated `/healthz`, `/readyz` | `200` — the two probe routes, asserted to stay open |

**Startup matrix** — the real binary as a subprocess, asserting exit status and stderr:

| `--listen` | `--auth-file` | Expect |
|---|---|---|
| unix (default) | absent | starts; socket mode `0660`, data dir `0700`, `messq.db` `0600` (stat'd from the test) |
| `tcp://127.0.0.1:0` | absent | starts, with a loud WARN banner naming the exposure |
| `tcp://0.0.0.0:4390` | absent | **exits non-zero before binding**; stderr names `--auth-file`; nothing ever listened (asserted by a connect attempt) |
| `tcp://0.0.0.0:4390` | present | starts |
| any | auth file mode `0644` | exits non-zero naming the file and the required mode |
| unix, pre-existing data dir mode `0777` | — | exits non-zero naming the path and the required mode |

Plus the canary: a token secret written into the fixture auth file must not appear anywhere in the
daemon's combined stdout/stderr across the whole suite run (D12's `slog.LogValuer` promise, checked
from outside the process).

### 7. The five-line shell worker

PLAN §7's transcript, verbatim, as both a doc block and a contract case: publish → long-poll fetch →
`jq -r '.messages[0].ack_token'` → work → ack. Asserted: the ack returns `ok`, the delivery row is
gone (via `GET …/pending`), a second ack with the same token is idempotent-stale, and the whole
block runs in under its `timeout`. **This is the M4 exit criterion**; it fails loudly with a message
saying so, not as case #47 of a table.

### 8. CI wiring

| Job | Lane | Budget | Contents |
|---|---|---|---|
| `contract` | PR | ≤ 90 s | `go test -race ./test/contract/...` on Unix + loopback TCP |
| `docs` | PR | ≤ 120 s | `go test ./test/docs/...` with `MESSQ_DOCS_REQUIRE_TOOLS=1`, pinned `curl`/`jq` |
| `gates-selftest` | PR | ≤ 60 s | extends #2's sabotage matrix with the three wire gates |

The self-tests are the point: a gate nobody has seen fail is a gate nobody knows works. Three
sabotages, run against a scratch copy of the tree:

1. Rename a JSON tag on a response struct → the `contract` job must fail with `BREAKING`.
2. Change a code's HTTP status in the mapping table → `codes.tsv` diff must fail.
3. Edit an output line inside a documented block → the `docs` job must fail, naming file and line.

### 9. Edge cases, decided

| Case | Handling |
|---|---|
| Struct fields reordered | No digest change (paths are sorted), goldens re-canonicalised — not a wire change, must not churn |
| Response built as `map[string]any` drifting from its struct | Caught by assertion 2 (body ▷ digest), which is why shape validation is separate from the golden diff |
| Field added during a refactor | `ADDITIVE`; `-update` accepts it; the golden diff shows it in review |
| `omitempty` added "to tidy the JSON" | `BREAKING` — the most likely accidental break in the product, and the one this issue exists to catch |
| `seq` beyond 2^53 | Serialised as a JSON number per §7; `PROTOCOL.md` documents the JS-consumer caveat and the contract suite asserts a large-seq response round-trips through `encoding/json` exactly |
| `jq` version differences in whitespace/number rendering | Output declared JSON is re-canonicalised before diffing; only structure and values are compared |
| Non-UTF-8 or binary payload echoed in a doc block | Blocks must use `body_b64` or `--output-raw` into `xxd`; a raw binary byte in a golden fails the doc lint |
| Daemon readiness in the harness | Poll `/readyz` until `200` with a deadline — never `time.Sleep` (forbidigo, #2) |
| A doc block leaves the daemon wedged | Session-scoped daemon, `t.Cleanup` SIGKILL, temp dir removed; one bad block cannot poison another session |
| Blocks in one document that must share state | `session=NAME`, executed in document order; different sessions are parallel and isolated |
| A genuinely nondeterministic demo (`--follow`, bench numbers) | `nocompare` — it must still run and exit 0; the harness proves the command exists, not the numbers |
| An illustrative block that cannot run (a cluster, a systemd unit) | `no-run="reason"`; the mandatory reason is reviewed like code |
| Human (TTY) CLI output in docs | Deferred to #26 with a note: the harness supports `env=MESSQ_OUTPUT=table`, so the M6 doc blocks showing tables have a seam waiting for them |
| Case fixtures needing store-level state | Refused: fixtures are built through the HTTP API only. A black-box suite that reaches behind the wire stops proving the wire |
| A route deleted without deleting its case | `TestEveryCaseNamesARealRoute` fails — orphan goldens rot silently otherwise |
| A code reserved for a future issue (`disk_full`, `rate_limited`) | Listed in `codes.tsv` with an owning issue; producing it without moving the marker fails, as does leaving it reserved after #27/#39 ship |
| Two listeners disagreeing | Same case, same golden, both listeners — a divergence is a failure, not a variant golden |
| Timestamps in a golden the reader is meant to reason about (a `deadline` 30 s after a `delivered_at`) | Masked values, but the suite asserts the *relation* in code (`deadline - delivered_at == ack_wait_ms`) — the assertion the mask would otherwise destroy |

### 10. Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| JSON Schema (draft 2020-12) files + a validator dependency | A test-only dependency and ~10× the bytes to express what the digest expresses; the digest is diff-readable, which is the whole point | A user asks for a machine-readable schema artifact |
| Generated OpenAPI document | Genuinely attractive — the route registry (#15) plus the digests already contain everything needed | Post-1.0, on the first integration request; generate it from these artifacts, never by hand |
| A shipped `messq conform <addr>` binary (plan-07) | D13 cut the shipped conformance suite; the value is real but the audience (a second implementation) does not exist | A second implementation, or an operator wanting to self-verify a build |
| Cross-version replay in this issue | Needs released artifacts to replay | **#34** / **#36**, which copy this directory per version |
| Property-based request fuzzing against the schema | Overlaps #14's decoder fuzzing and #33's corpus | #33 |
| Recording goldens from a proxy/VCR of real traffic | Non-hermetic, and hides which case produced which shape | Never |
| Byte-for-byte (non-canonicalised) body goldens | Freezes Go's field order as contract, punishing harmless refactors and teaching people to ignore the gate | Never |

## Acceptance criteria

- [ ] `test/contract` runs the whole case table against a real `messq serve` over **both** a Unix
      socket and a loopback TCP listener, with the same goldens for both; a divergence fails.
- [ ] Every route in #14/#15's route registry has at least one success case and at least one error
      case; adding a route without a case fails `TestEveryRouteHasACase`.
- [ ] Every member of the closed error-code enum is either produced by a real HTTP response in the
      suite or listed in `codes.tsv` with an owning future issue; a code that is neither fails CI,
      and so does a reserved code that has started being produced.
- [ ] `codes.tsv` freezes `code → HTTP status`; changing a status is classified `BREAKING`.
- [ ] Every wire type has a committed shape digest, and every response body in the suite validates
      against its digest (no undeclared field, no missing `always` field, no wrong JSON type).
- [ ] Renaming, removing or retyping a JSON field fails CI with a message naming the field, the
      classification and `docs/compatibility.md` — verified by the sabotage self-test, not by
      assertion.
- [ ] `-update` regenerates goldens and digests for `ADDITIVE` changes and **fails on `BREAKING`
      ones**, even with `-update`; `MESSQ_WIRE_BREAK=1` is refused unless `docs/compatibility.md`
      changed in the same tree.
- [ ] Adding `omitempty` to `duplicate`, `hold_reason`, `attempt`, `applied`, `changed`, `stale` or
      `complete` fails CI.
- [ ] Closed string sets (`hold_reason`, `state`, `cause`, `degraded[].kind`, settle results) are
      frozen; adding a member is `ADDITIVE`, removing or renaming one is `BREAKING`.
- [ ] Contract headers are asserted from an allow-list — `Allow` on `405`, `Retry-After` on every
      `503`, `WWW-Authenticate` on `401`, `Content-Type: application/json` on every enveloped
      response, `Messq-*` on publish and fetch — and volatile headers are excluded.
- [ ] Every command block in `README.md` and `docs/PROTOCOL.md` either executes against a fresh
      daemon in CI or carries `no-run="reason"`; the doc lint fails on an unmarked block.
- [ ] Editing a single output character inside a documented block fails the `docs` job, naming the
      file and line (sabotage self-test).
- [ ] `go test ./test/docs -update` rewrites expected output **inside the markdown**, and running it
      twice produces no diff (normaliser idempotence).
- [ ] **The five-line shell worker from PLAN §7 passes in CI** — publish, long-poll fetch, ack over
      `curl` + `jq` on the Unix socket — and its failure message names the M4 exit criterion.
- [ ] Auth denials are pinned: missing, malformed and unknown tokens produce byte-identical `401`
      bodies; wrong role and out-of-scope stream produce `403` naming the requirement but never the
      token or secret; `/healthz` and `/readyz` answer unauthenticated.
- [ ] The listener-policy startup matrix passes, including: a non-loopback bind without
      `--auth-file` exits non-zero **before** anything listens, and socket `0660` / data dir `0700`
      / DB `0600` are verified by `stat` from outside the process.
- [ ] A canary token secret appears nowhere in the daemon's stdout/stderr across the entire suite.

## Test plan

Per PLAN §11 / D13. This issue is mostly *made of* tests, so the plan below is about testing the
harness itself — an untested gate is a decoration.

**Unit — `internal/wirecheck`**
- Canonical JSON: key sorting, nested objects/arrays, unicode escapes, `null`, empty object vs
  absent, numbers that must not be reformatted (large int64), idempotence.
- Normaliser: table of inputs per mask rule including near-misses (a 25- and a 27-character
  Crockford string is **not** a ULID; a 12-digit and a 14-digit integer is not an epoch-ms value);
  path-scoped masks apply only at the declared path; **never-mask** fields survive.
- Shape digest: struct → digest over embedded structs, pointers, slices, maps, `json:"-"`,
  `omitempty`, custom `MarshalJSON` types (must be declared explicitly, not guessed), unexported
  fields.
- Classifier: exhaustive table over the verdict matrix in §3, plus combined diffs where one addition
  and one removal appear together (verdict must be `BREAKING`).

**Property (`pgregory.net/rapid`)**
- Normaliser idempotence: `normalize(normalize(x)) == normalize(x)` over generated JSON documents.
- Digest round-trip: `parse(render(d)) == d` for generated digests.
- Classifier soundness: applying a generated `ADDITIVE` mutation to a digest never yields
  `BREAKING`, and every generated removal/rename/retype always does. Failfiles committed to
  `testdata/regressions/`.

**Unit — `test/docs` extraction**
- Directive parsing: every directive, unknown directive (hard error, never ignored), duplicate
  directives, malformed `timeout`, `session` with one block, blocks with no output, blocks with
  multiple command/output pairs, continuation lines, nested fences inside a fence.
- `-update` rewriting: a block whose output changed is rewritten in place with surrounding prose,
  indentation and fence info-strings preserved byte-for-byte.
- Doc lint: unmarked fence, `no-run` without a reason, a token-shaped literal, a non-canonical
  socket path or Host.

**Fuzz** (60 s per target in CI, corpus committed, extended nightly by #33)
- `FuzzExtractBlocks` over adversarial markdown: never panics, never runs a block it did not
  extract, never loses text on `-update` (round-trip property: extract → rewrite unchanged →
  identical bytes).
- `FuzzNormalize`: no panic, output always valid UTF-8, idempotent.

**Integration — the suites themselves**
- Full contract table on both listeners against a real daemon subprocess (`internal/testutil/daemon`).
- The auth matrix and the startup matrix (§6), each a subprocess with asserted exit status, stderr
  and — for the fatal cases — a connect attempt proving nothing bound.
- File-mode assertions by `stat` on socket, data dir and DB.
- The canary-secret grep over captured daemon output.
- The five-line shell worker as its own named test, plus a `-count=5` run to catch a race in the
  long-poll path surfacing as flake.

**Gate self-tests (extends #2's sabotage matrix)**
- Rename a response JSON tag in a scratch copy → `contract` fails `BREAKING`.
- Change a code's HTTP status → `codes.tsv` diff fails.
- Add `omitempty` to `duplicate` → fails with the never-omitempty message.
- Mutate one output character in a doc block → `docs` fails naming file and line.
- Run `-update` on a breaking change → still fails; add a `docs/compatibility.md` entry and set
  `MESSQ_WIRE_BREAK=1` → passes. All five are asserted, so the gates are proven rather than trusted.

**Timing budgets**
- The suites record their own wall clock and fail over budget, so the PR lane degrades visibly
  instead of silently eating the 10-minute allowance.

**Not tested here:** delivery semantics and invariants (#13), durability over HTTP (#14 on #8),
metric names (#21), log field schema (#19), CLI faces (#26), cross-version replay (#34/#36).
