## Context

Two commands, one theme: **the operator should never have to trust us — they should be able to
check.**

PLAN.md §4.5 ends the storage chapter with one sentence:

> Backup: `messq backup out.db` runs `VACUUM INTO` on the read pool — consistent online snapshot;
> restore is stop + copy + start. That is the whole story, in one sentence.

That sentence is the honest answer to the biggest thing messq does not have. D15 and §14 both say
it plainly: **replication is not on the roadmap.** A single node with a good backup and a five-line
restore procedure is the ceiling we deliberately chose, so the backup has to be trustworthy:
consistent under load, self-verifying, self-describing, restorable by someone who never read the
source.

`messq doctor` is the other half. PLAN §8 lists it as *"opinionated health & misconfiguration
diagnosis in prose"*, §12 says the performance targets are *"re-baselined per host by `messq doctor`
(which measures the operator's actual fsync latency and prints achievable rates — nobody has to
trust our README)"*, and §4.1 makes it the answer to the durability-in-a-DSN trap: *"the daemon
refuses to start, and `messq doctor` prints the live values"*. A dozen earlier issues have already
deposited findings here by name — #5 (pragma mismatch, `flock` on a non-local filesystem), #6
(`relaxed` flagged), #8 (the fsync probe and the lying-write-cache cross-check), #10
(`future_attempt` after a restore), #11 (`max_deliver=0`, `--sweep-interval` > `ack_wait`,
`TimeToDead`), #12 (DLQ template drift), #16 (`auth.Preflight()`), #17 (unclean shutdown, restart
loops), #19 (event retention vs. `TimeToDead`), #21 (dropped metric series), #22 (heartbeats), #24
(*`lag` reports, `doctor` judges*). This issue is where all of them land in one place.

Governing PLAN.md material: **§4.1** (connections, pragma read-back), **§4.4** (recovery), **§4.5**
(disk safety, backup), **§8** (CLI design: the three output modes, the exit-code contract, teaching
errors), **§9.2** (the event vocabulary is **closed** — this issue adds no new event names), **§9.4**
(the metrics doctor reads), **§10** (permissions, redaction), **§12** (per-host re-baselining),
**D4**, **D8**, **D12**, and **§14 M7**, whose exit criterion this issue completes with
#27/#28/#29/#31.

What it unlocks: **#35**'s runbooks ("disk filling", "torn tail after crash", "restore") are written
against these two commands; **#36** packages `contrib/systemd/messq-backup.{service,timer}` and runs
`messq doctor` in the clean-VM install test; **#34** gains a second source of golden data dirs (a
snapshot is a data dir in one file); **#31** quotes the same fsync probe.

## Scope

### In scope

- **`messq backup <path>`** — `VACUUM INTO` against a read-only open of the data dir, into a private
  temp directory, self-verified, then atomically renamed into place. Free-space precheck, WAL-growth
  warning, ENOSPC/permission/destination refusals with teaching errors, all three output modes.
- **Snapshot provenance**: `snapshot_*` rows stamped into the snapshot's own `meta` table (source
  node id, timestamp, schema and tool version, per-stream heads) so the file explains itself.
- **Restore detection**: `internal/store` recognises a restored snapshot at `Open`, converts the
  `snapshot_*` rows into permanent `restored_*` rows, reports them on `RecoveryReport`, and they
  surface in `GET /v1/info` and in `server.start`'s detail — *"a missing tail is never a mystery"*.
  (A small, additive amendment to #5 and #15; §9 below.)
- **The documented restore procedure** (`docs/backup-restore.md`, folded into `OPERATIONS.md` by
  #35), the example systemd timer, and the flat statement that `cp messq.db` is **not** a backup.
- **`messq doctor`** — `internal/doctor`: a registry whose checks are **pure functions over a
  collected `Snapshot`**, a two-source collector (live daemon over `pkg/client`, or an offline
  read-only data dir), prose findings with exact fix commands, `--fail-on` exit semantics for cron,
  `--list`/`--explain`, frozen JSON field names.
- **The check set** in §7: durability/pragma, fsync probe + lying-write-cache heuristic + projected
  rate, filesystem type and mount options, permissions (#16's `auth.Preflight()`), disk headroom and
  days-to-full, WAL and events-table share, `ack_wait` vs. observed ack p99, stale acks,
  `max_deliver=0`, `TimeToDead` vs. event retention, idle/paused/stuck consumers, DLQ growth without
  drain, DLQ template drift, typo-shaped streams, filters matching nothing, restart loops,
  read-only latch, backup age, restore provenance.
- `docs/doctor.md`: one section per check ID — the target of every finding's `Docs` field and the
  body of `--explain`.

### Out of scope

- The invariant checker, `PRAGMA integrity_check` and event/state folding → **#8** (`messq verify`).
  Doctor diagnoses configuration and operations, never re-implements an invariant, and ends its
  output by pointing at `messq verify --deep`.
- Retention enforcement, `--min-free-bytes`, the disk-degraded state, WAL checkpoint policy, the
  janitor → **#27**. Doctor *reports* what #27 enforces.
- `messq dlq ls|show|redrive|purge` and the redrive guard rails → **#29**. Doctor names the command;
  it never redrives.
- `messq bench`, coordinated-omission correction, published numbers → **#31**. The fsync probe here
  is a 1 000-sample measurement, not a benchmark.
- Alert rules and the Grafana dashboard → **#21**.
- `auth.Preflight()` itself, the listener policy table, token-file grammar → **#16**.
- The hardened systemd unit and lifecycle state machine → **#17**; packaging the backup timer into
  `.deb`/`.rpm`/container → **#36**.
- `OPERATIONS.md`, runbooks, README wording → **#35**.
- Upgrade/migration fixtures → **#34** (this issue hands it snapshots as fixture material).
- The ENOSPC/EIO/clock fault matrix → **#32**; this issue ships only the destination-ENOSPC test for
  `backup`.
- Native TLS (a doctor finding says *"terminate TLS in front of the socket"* today) → **#40**.
- **Deliberately not planned at all** (a line in `docs/non-goals.md`, not a deferred issue): remote
  backup targets (S3/rsync/ssh), compression or streaming to stdout, incremental/point-in-time
  backup, WAL shipping, a scheduler inside the daemon, and `messq restore` as a verb — PLAN §4.5
  says restore is *stop + copy + start*, and a verb wrapping `install(1)` would be a liability.
- **Deliberately rejected: `POST /v1/admin/backup`.** PLAN §7 lists no such route, and it would hand
  an authenticated `admin` caller an arbitrary-file-write primitive running as the daemon user.
  `backup` reads the data dir locally; that is a security property, and the docs say so.

## Design proposal

> Sketches are a concrete starting point, not a mandate. Four things **are** contracts because other
> issues, users and alerts depend on them: the finding **ID namespace** (§7), the **JSON shapes**
> (§8, §11), the **snapshot `meta` keys** (§4), and the **exit-code semantics** (§10).

### 1. Package layout

```

  estimate.go    page_count/freelist_count → size estimate; destination statfs precheck
  stamp.go       snapshot_* meta rows, written before the rename

internal/doctor/
  check.go       Check, Finding, Severity, Source, Subject — the vocabulary
  registry.go    Register(); duplicate-ID panic; List(); Explain()
  collect.go     Snapshot + the two collectors (live via pkg/client, offline via store)
  promtext/      ~60-line scanner for the handful of /metrics families doctor reads
  fsyncprobe/    write 4 KiB + fdatasync × N (shared with #8's probe)
  checks/        one file per family: durability.go storage.go consumers.go dlq.go
                 streams.go server.go security.go backups.go
  render.go      human / json / ndjson; sorting; NO_COLOR; --quiet
internal/store/
  provenance.go  AMENDMENT to #5: snapshot/restore meta rows, Provenance(), Open() step 4.5

  backup.go doctor.go        (cobra commands on #23's chassis, #24's renderer)
docs/backup-restore.md  docs/doctor.md
contrib/systemd/messq-backup.service  contrib/systemd/messq-backup.timer
```

**The architectural rule:** a check may not perform I/O. Collection happens once, up front, into a
`Snapshot`; every check is `func(ctx, *Snapshot) []Finding`, unit-tested against a hand-written
snapshot literal. An HTTP call or a `db.Query` inside `internal/doctor/checks` is a design
violation. This is what makes 40 checks testable without a daemon and keeps the wall-clock budget
honest.

### 2. `messq backup` — the pipeline

```go
// internal/ops/backup
type Options struct {
    DataDir   string
    Dest      string
    Force     bool          // overwrite an existing destination
    Verify    VerifyMode    // VerifyQuick (default) | VerifyFull | VerifyNone
    TempDir   string        // SQLite scratch for index rebuild sorting; default = dest dir
    CacheBytes int64        // backup connection cache_size; default 16 MiB
    Clock     clock.Clock   // #3
    Progress  func(Stage)   // stderr narration; nil in --output json
}

type Result struct {
    Dest           string
    Bytes          int64
    SourceBytes    int64          // db + wal at start
    Pages, Freelist int64
    Duration       time.Duration
    WALGrowth      int64          // measured: how much WAL the backup's read txn pinned
    TakenAt        time.Time
    SourceNodeID   string
    SchemaVersion  int
    StreamHeads    map[string]int64   // stream → last_seq at snapshot time
    InflightAtSnapshot int64          // deliveries in INFLIGHT — these redeliver after a restore
    Verified       string             // "quick_check" | "integrity_check" | "skipped"
}

func Plan(ctx context.Context, o Options) (*Plan, error) // all refusals happen here
func Run(ctx context.Context, p *Plan) (*Result, error)
```

Ordered steps, each with its own refusal:

1. **Open the source read-only.** `store.Open` with `Options.ReadOnly` (#5) — no `rw` handle, no
   recovery, no lock write. Works with the daemon running (WAL readers never block the writer) *and*
   with it down: the property that makes backup usable during an incident.
2. **Refusals, before a single page is copied.** Destination exists without `--force` → exit 4;
   destination inside the data dir → exit 2 (*"it would be included in the next snapshot and
   confuses `verify`"*); destination directory not writable → exit 7; free bytes < estimate × 1.1 →
   exit 1 with both numbers.
3. **Size estimate** `≈ (page_count − freelist_count) × page_size`; the 10 % headroom covers
   index-rebuild scratch.
4. **A dedicated snapshot connection**, not a pooled read connection:
   `file:…?_pragma=query_only(0)&_pragma=temp_store(FILE)&_pragma=cache_size(-16384)`,
   `SetMaxOpenConns(1)`, closed when done. Three reasons, all load-bearing:
   - `query_only(1)` is set on every pooled read connection (#5) and `VACUUM` is a statement SQLite
     may refuse under it; the snapshot connection is the one place that flag is off, and it still
     never writes the source (`VACUUM INTO` only reads it).
   - The store's pragma set uses `temp_store=MEMORY` (§4.1). `VACUUM INTO` **rebuilds every index**,
     and the sort scratch for that would go to RAM — an OOM on a multi-GiB database. The snapshot
     connection overrides `temp_store` to `FILE` and honours `--temp-dir`.
   - Holding a pooled connection for minutes would starve `peek`/`trace`/`lag` under
     `SetMaxOpenConns(NumCPU)`.
5. **`VACUUM INTO ?`** with the target inside a private `0700` temp dir
   (`<destdir>/.messq-backup-<ulid>/snap.db`) — SQLite requires the `INTO` file **not to exist**, so
   we cannot pre-create it with `O_EXCL`; a private directory gives the same safety against symlink
   games. The statement runs with the command's context, so `Ctrl-C`/`--timeout` interrupts it.
6. **Stamp provenance** (§4) into the snapshot, `synchronous=FULL`, then `chmod 0600`, `fsync` the
   file.
7. **Self-check** (`--verify`): reopen the snapshot read-only and assert `PRAGMA quick_check` = `ok`
   (`integrity_check` under `--verify full`), `meta.schema_version` and `PRAGMA user_version` equal
   the source's, `page_size`/`auto_vacuum` preserved, per-stream `count(*)`/`max(seq)` ≥ the values
   recorded at step 3. Failure deletes the temp dir and exits 1 — **a backup that cannot be opened
   is not a backup, and we find that out now, not during an incident.**
8. **`rename(2)`** into place, `fsync` the parent directory, remove the temp dir, sweep temp dirs in
   the destination older than 1 h (a killed backup leaves one; the next run says so).

```console
$ messq backup /var/backups/messq/2026-11-04T0200Z.db
source   /var/lib/messq/messq.db   1.41 GiB (db) + 12.4 MiB (wal)   schema v1   node 01J8ZQ…
plan     ~1.28 GiB to /var/backups/messq (41.2 GiB free)            estimate excludes 3.1% freelist
copy     ████████████████████  1.28 GiB in 9.4s (139 MiB/s)
verify   quick_check ok · schema v1 · 4 streams · heads orders=1057201 jobs=88214 …
wrote    /var/backups/messq/2026-11-04T0200Z.db   1.28 GiB   mode 0600   9.9s
note     the WAL grew 41 MiB while the snapshot's read transaction was open; it will be
         checkpointed by the janitor within 60s
next: messq verify --data-dir /var/backups/messq/2026-11-04T0200Z.db
```

```console
$ messq backup /var/backups/messq/2026-11-04T0200Z.db
error: destination already exists
  path:  /var/backups/messq/2026-11-04T0200Z.db  (1.28 GiB, written 2026-11-04T02:00:11Z)
  why:   overwriting a backup in place destroys the only good copy if this run fails
  next:  messq backup /var/backups/messq/2026-11-04T0300Z.db   # or pass --force

```

**Flags** (D8: flags + `MESSQ_*` env, no config file):

| Flag | Env | Default | Meaning |
|---|---|---|---|
| *(arg)* `<path>` | — | *required* | Destination file. `-` is **rejected**: `VACUUM INTO` needs a seekable file. |
| `--data-dir` | `MESSQ_DATA_DIR` | `/var/lib/messq` | Source data directory. |
| `--force` | — | `false` | Overwrite an existing destination (still writes temp + renames). |
| `--verify` | `MESSQ_BACKUP_VERIFY` | `quick` | `quick` \| `full` \| `none`. `none` prints a WARN line. |
| `--temp-dir` | `MESSQ_BACKUP_TEMP_DIR` | destination dir | SQLite scratch for the index rebuild. |
| `--cache-size` | `MESSQ_BACKUP_CACHE_SIZE` | `16MiB` | Bounds the backup connection's RSS. |
| `--timeout` | `MESSQ_BACKUP_TIMEOUT` | `0` (none) | Cancels the `VACUUM INTO` and cleans up. |

### 3. Restore — a procedure, not a verb

`docs/backup-restore.md`, executed verbatim as a testscript case:

```console
$ systemctl stop messq
$ mv /var/lib/messq /var/lib/messq.broken            # never delete the evidence
$ install -d -m 0700 -o messq -g messq /var/lib/messq
$ install -m 0600 -o messq -g messq \
      /var/backups/messq/2026-11-04T0200Z.db /var/lib/messq/messq.db
$ messq verify --data-dir /var/lib/messq             # (#8) — before anything starts
$ systemctl start messq
$ messq doctor                                       # tells you what the restore cost
```

Three facts the doc must state, because each of them is a support ticket otherwise:

- **A snapshot is one self-contained file.** There is no `-wal` and no `-shm` to copy, and there
  must not be: #8's edge case 15 (a lone `.db` next to a missing `-wal`) is exactly what
  `cp messq.db` produces, and it silently loses the WAL tail. `messq backup` exists so that `cp` is
  never the answer.
- **The restored file is behind.** Everything published after the snapshot's read transaction began
  is gone. Doctor prints the snapshot time and the per-stream heads.
- **Everything in flight at snapshot time is redelivered.** §4.4 step 3 flips `INFLIGHT` → `READY`
  with jitter and does **not** touch `attempts` (D6): `max_deliver` still holds and every duplicate
  carries the named cause `recovery.reclaimed` (I9). Workers holding tokens from the lost tail fail
  fencing — their token attempt is *ahead* of the row, which #10 records as `stale_ack` with
  `detail.anomaly="future_attempt"`: 409, never a mutation. The restore finding says so.

### 4. Snapshot & restore provenance (contract)

Written into the **snapshot's** `meta` table at step 6 — never into the source (the source is opened
read-only and owned by another process):

| Key | Value |
|---|---|
| `snapshot_taken_at` | Unix ms, when the `VACUUM INTO` read transaction started |
| `snapshot_source_node` | source `meta.node_id` |
| `snapshot_source_path` | absolute path of the source `messq.db` |
| `snapshot_tool_version` | `messq` version + commit that wrote it |
| `snapshot_source_live` | `1` if the source data dir was flocked by a running daemon |
| `snapshot_stream_heads` | JSON `{"orders":1057201,…}` — capped at 64 streams, else omitted with `snapshot_stream_heads_truncated=1` |
| `clean_shutdown` | forced to `1`: a `VACUUM INTO` output is transactionally consistent by construction, so a restore must not be reported as an unclean crash |

`store.Open` gains step **4.5** (amendment to #5, additive, no existing test changes): if
`snapshot_taken_at` is present, the first write transaction rewrites the `snapshot_*` keys as
permanent `restored_*` keys (`restored_at`, `restored_from_node`, `restored_snapshot_at`,
`restored_stream_heads`, `restored_tool_version`) and `RecoveryReport` gains
`Restored *Provenance`. Rewriting rather than keeping means a second restart does not re-announce a
restore, and the record survives forever (five rows).

```go
// internal/store
type Provenance struct {
    RestoredAt, SnapshotAt time.Time
    SourceNodeID           string
    StreamHeads            map[string]int64
    ToolVersion            string
}
func (s *Store) Provenance() *Provenance   // nil when this dir was never restored
```

**No new event names** (§9.2 is closed): the restore is reported as fields on `server.start`
(`detail.restored_from_snapshot_at`, `detail.restored_source_node`) and as an `admin.action` row
with `detail={"action":"restore_detected",…}`. #19's field-schema golden gets two new keys, not a
new verb.

### 6. `messq doctor` — the model

```go
type Severity uint8 // SevSkipped, SevOK, SevInfo, SevWarn, SevFail

type Finding struct {
    ID       string          // "consumer.ack_wait_below_p99" — stable, greppable, documented
    Severity Severity
    Subject  Subject         // {Stream, Consumer, Path} — never a message body, never a token
    Title    string          // one line, no trailing period
    Detail   string          // 1–3 sentences: what happened, why it matters
    Fix      []string        // exact commands, in order
    NoFix    string          // required when Fix is empty ("this is informational")
    Evidence map[string]any  // frozen keys per check; numbers, not prose
    Docs     string          // docs/doctor.md#<id>
}

type Check struct {
    ID      string
    Summary string           // one line for `messq doctor --list`
    Explain string           // the teaching paragraph for `--explain <id>`
    Needs   Source           // SourceLive | SourceDataDir | SourceEither
    Budget  time.Duration    // default 2s; exceeded ⇒ SevSkipped with reason "timed out"
    Eval    func(context.Context, *Snapshot) []Finding   // PURE over Snapshot
}
```

```go
type Snapshot struct {
    Now      time.Time
    Source   Source
    Window   time.Duration     // --since
    Info     *client.Info      // /v1/info               (live)
    Streams  []StreamState     // /v1/streams | SQL      (either)
    Consumers []ConsumerState  // …/consumers | SQL      (either)
    Metrics  promtext.Set      // /metrics               (live)
    Events   EventStats        // bounded event aggregates (either)
    Storage  StorageFacts      // sizes, pages, statfs, mount options, LOCK holder
    Fsync    *FsyncProbe       // p50/p99/p99.9 fdatasync on the data dir
    Files    auth.PreflightResult   // #16, verbatim
    Backups  []BackupFile      // --backup-dir listing + each file's snapshot_* meta
    Collect  []CollectError    // a failed collector degrades checks to SevSkipped, never fatal
}
```

**Two sources, one honest story.** `--addr` (default) collects from the running daemon; `--data-dir`
from an offline read-only open (`store.Options.ReadOnly`). A check declares what it needs; what it
cannot get is `[skip] <id> — needs a running daemon (try --addr)`, never silently omitted. One
honesty rule with teeth: offline, the pragma check reports *"the `synchronous` value on **my**
connection"*, which is **not** proof about the daemon's writer; live, it reads
`/v1/info.durability.synchronous`, which #15 reads back from a live pooled connection. Doctor says
which one it did.

**Doctor is cheap on a busy broker** — a hard design constraint, since operators run it during
incidents:

- No unbounded `count(*)`. Live mode uses #15's cached stream stats (printing `stats_age_ms` when it
  exceeds `--since`/4); offline mode may do one `count(*)` per stream and prints the cost.
- Idleness comes from the **pending set**, not the event log:
  `SELECT max(delivered_at), count(*) FROM deliveries WHERE stream=? AND consumer=?` rides the
  primary-key prefix, and the pending set is small by construction (D5). Scanning 24 h of
  `msg.deliver` events at 5 000 msg/s would be 400 M rows — the trap doctor must not fall into.
- Event statistics take the **most recent N rows**, never a whole window:
  `… WHERE event=? AND ts >= :since ORDER BY id DESC LIMIT :max_scan` (default 200 000); a check that
  hits the cap records `sample capped at 200k rows` instead of pretending.

```sql
-- ack held-time p99 per consumer (offline source; live source uses the histogram buckets)
WITH acks AS (
  SELECT stream, consumer, CAST(json_extract(detail,'$.held_ms') AS INTEGER) AS held_ms
    FROM events
   WHERE event='msg.ack' AND ts >= :since AND detail IS NOT NULL
   ORDER BY id DESC LIMIT :max_scan
), ranked AS (
  SELECT stream, consumer, held_ms,
         row_number() OVER w AS rn,
         count(*)     OVER (PARTITION BY stream, consumer) AS n
    FROM acks WINDOW w AS (PARTITION BY stream, consumer ORDER BY held_ms)
)
SELECT stream, consumer, n, max(held_ms) AS p99_ms
  FROM ranked
 WHERE rn <= (n * 99 + 99) / 100
 GROUP BY stream, consumer
HAVING n >= 20;              -- fewer than 20 samples ⇒ SevSkipped, never a guess from 3 acks
```

A cross-source test asserts the live path (`messq_ack_latency_seconds_bucket`) and the offline path
(the SQL above) land in the same histogram bucket on the same fixture.

### 7. The check set (IDs are a contract; `docs/doctor.md` has a section per ID)

| ID | Fires when | Sev | Source | Fix printed |
|---|---|---|---|---|
| `durability.pragma` | live `synchronous` ≠ what the mode demands | fail | either | restart; `messq doctor --data-dir …` |
| `durability.mode_relaxed` | `--durability=relaxed` | warn | live | `--durability=full` and what it costs (D4) |
| `durability.fsync_probe` | always: p50/p99/p99.9 + projected `batch/fsync` rate (§12) | ok/info | data-dir writable | — (`NoFix`: informational) |
| `durability.fsync_implausible` | probe median < 25 µs and not tmpfs | warn | data-dir | check VM write-back / `nobarrier` / consumer SSD |
| `durability.tmpfs` | data dir on tmpfs under `full` (info under `--dev`) | fail | either | move `--data-dir` to a real filesystem |
| `storage.fs_type` | `statfs` magic is NFS/CIFS/FUSE/overlay | fail | either | `flock` is a lie there (#5); move the data dir |
| `storage.mount_options` | `nobarrier` / `barrier=0` on the data-dir mount | warn | either | remount; durability claims are void |
| `storage.disk_headroom` | free < `--min-free-bytes` × 4, or days-to-full < max_age | warn/fail | either | raise retention or add disk; ETA in evidence |
| `storage.wal_size` | WAL > `--wal-max-bytes`, or a reader has pinned checkpoints > 10 min | warn | either | name the long reader (often a backup) |
| `storage.events_share` | `events` > 40 % of DB bytes | warn | either | `--event-retention` / `--event-max-rows` |
| `storage.readonly_latch` | `messq_readonly=1` (fsyncgate, D4) | fail | live | the storage runbook; this is a page, not a chore |
| `consumer.ack_wait_below_p99` | `ack_wait` < observed ack p99 (≥ 20 samples) | warn | either | `messq consumer edit <s> <c> --ack-wait <p99×2>` |
| `consumer.stale_acks` | `messq_stale_acks_total` rate > 0 (§9.4: *alert on any nonzero rate*) | warn | live | raise `ack_wait` / use heartbeats (#22, #25) |
| `consumer.max_deliver_unlimited` | `max_deliver=0` | warn | either | `--max-deliver 5` |
| `consumer.max_deliver_unlimited_no_dlq` | `max_deliver=0` **and** `dead_policy=drop` | fail | either | `--dead-policy dlq --max-deliver 5` |

### 10. Exit codes (#23's contract)

| Code | When |
|---|---|
| `0` | No finding at or above `--fail-on` (and `--fail-on never` always). |
| `1` | At least one finding at or above `--fail-on`. |
| `2` | Usage: unknown check ID in `--only`/`--skip`, bad duration, `--output json --follow`. |
| `7` | Neither source is readable: no daemon **and** the data dir cannot be opened (permissions). |

**Doctor never exits 6.** An unreachable daemon is a *finding* (`server.unreachable`, fail), not a
transport failure escaping to `exit.Of(err)` — doctor's whole job is to run when things are broken.
Collection converts `client.Kind` transport errors into findings, and a test asserts that stopping
the daemon moves doctor's exit from 0 to 1, never to 6.

### 11. Edge cases and how they are handled

| Case | Handling |
|---|---|
| **`VACUUM INTO` and `query_only(1)`** | Pooled read connections keep `query_only(1)`; the snapshot connection is a separate single-connection handle with it off, and still never writes the source. Even if the driver *does* permit `VACUUM INTO` under `query_only`, the dedicated connection stays right (isolation, `temp_store`, pool starvation). A test asserts the source's `PRAGMA data_version` and mtime are unchanged. |
| **`temp_store=MEMORY` + index rebuild** | Overridden to `FILE`; `--temp-dir` defaults to the destination dir so scratch and output share the prechecked budget. `BenchmarkVacuumInto` caps peak RSS at 256 MiB for a 4 GiB database — the guard against anyone "simplifying" the pragma set. |
| **WAL growth during a long backup** | The snapshot's read transaction pins the WAL, so a 10-minute backup on a busy broker grows `messq.db-wal` by roughly the write volume. `backup` reports measured growth, `storage.wal_size` names the long reader, the docs say off-peak + `ionice -c3`. Not a bug — a cost, stated. |
| **Journal mode / `auto_vacuum` / `user_version` of the output** | The self-check *reads them back* rather than assuming. `journal_mode` may be `delete` on the copy — fine, `store.Open` sets WAL on first open, which is why the restored file must be writable and owned by the daemon user. If `auto_vacuum` did not survive, the self-check fails loudly: it cannot be turned on later without a full `VACUUM`. |
| **Destination exists / is a symlink / is inside the data dir** | Existing → exit 4 unless `--force`; the temp dir is private `0700` so a symlink at the final path is replaced by `rename`, not followed; inside the data dir → exit 2 with the reason. |
| **ENOSPC on the destination** | Prechecked (estimate × 1.1). Mid-run: temp dir removed, exit 1 printing bytes written / needed / free. The source is untouched — a failing backup can never damage the thing it backs up, asserted on a loopback filesystem. |
| **The backup process is killed** | The final path never appears (rename is the last step). A `.messq-backup-<ulid>` directory is left behind; the next run sweeps entries older than 1 h and reports how many it removed. |
| **The daemon is SIGKILLed mid-backup** | Irrelevant to the snapshot: the reader holds its own consistent view, the run completes and verifies, and the *source* recovers normally on restart. Asserted in the crash test. |
| **The old data dir still exists after a restore** | Both dirs carry the same `node_id`; `flock` protects only within a directory. Documented as: never run two daemons from one lineage. Doctor's `server.restored` finding says the node id is shared. |
| **Tokens minted before the restore** | Attempt/generation in the restored file can be *behind* the token → #10's `future_attempt` anomaly → `409 stale_ack`, no mutation. The safe direction, and now a documented consequence of restoring. |
| **Dedup keys inside the window at snapshot time** | Restored with the messages; the janitor (#27) trims them at `dedup_window_ms` as usual, so a publisher retrying across a restore is still deduplicated inside the window. Correct, no special case. |
| **Doctor on a data dir it cannot write** | The probe is skipped: `[skip] durability.fsync_probe — data dir not writable by uid 1000 (run as messq or root)`. Never fatal; read-only diagnosis still has value. Probe files are `<data-dir>/.messq-fsync-probe-<pid>`, removed on defer *and* swept at startup. |
| **Doctor while the broker is in the read-only latch** | `storage.readonly_latch` fires first and the renderer hoists it to the top regardless of sort order — during an fsyncgate latch nothing else matters. |
| **A check panics** | The runner recovers per check and renders `[skip] <id> — internal error (please file a bug with --output json)`. One broken check must not cost the operator the other thirty during an incident. |
| **`--since` larger than event retention** | The window is clamped to the oldest retained event and the evidence records `window_clamped_to_ms`; a check whose sample is thinner than its minimum reports `skipped`, never a conclusion from four rows. |
| **Payload/secret leakage** | Findings carry `Subject{Stream, Consumer, Path}` and numeric evidence only — never a body, header value or token (#16's `Secret` cannot be formatted anyway). The canary-leak CI test greps both output modes for a published canary. |

## Acceptance criteria

- [ ] `messq backup <path>` produces a single self-contained file via `VACUUM INTO`, written to a
      private temp directory and `rename(2)`d into place, mode `0600`, with the parent directory
      fsynced.
- [ ] The backup uses a dedicated single-connection handle with `temp_store=FILE` and a bounded
      `cache_size`; the pooled read connections keep `query_only(1)`, and a test proves the source
      database file is not modified by a backup.
- [ ] `messq backup` refuses, with a teaching error and the documented exit code, when: the
      destination exists without `--force` (4), the destination is inside the data dir (2), the
      destination directory is not writable (7), or the estimated size exceeds free space × 0.9 (1).
- [ ] Before returning 0, `messq backup` reopens the snapshot read-only and asserts `quick_check`
      (`integrity_check` under `--verify full`), matching `schema_version`/`user_version`, preserved
      `page_size`/`auto_vacuum`, and per-stream head sequences; a failed self-check deletes the
      temp dir and exits 1.
- [ ] The snapshot's `meta` carries `snapshot_taken_at`, `snapshot_source_node`,
      `snapshot_source_path`, `snapshot_tool_version`, `snapshot_source_live`,
      `snapshot_stream_heads` and `clean_shutdown=1`.
- [ ] `store.Open` converts `snapshot_*` into permanent `restored_*` rows on first start, exposes
      them via `Store.Provenance()` and `RecoveryReport.Restored`, and reports them in
      `server.start`'s detail plus one `admin.action` row — **no new event verb is added to §9.2**.
- [ ] `GET /v1/info` includes the optional `restored` object when the data dir was restored, and
      omits it otherwise.
- [ ] A backup taken **while publish/fetch/ack load is running** restores into a data directory that
      passes `messq verify --data-dir` and `PRAGMA integrity_check`, starts, and serves.
- [ ] After such a restore: every message whose publish returned 2xx **before** the backup started
      is present; every message published **after** the backup completed is absent; messages in
      between are permitted either way (the three-valued ledger oracle from #8).
- [ ] After such a restore, deliveries that were `INFLIGHT` at snapshot time are `READY` with
      `attempts` unchanged, and `messq trace` shows `recovery.reclaimed` as the cause of the
      resulting duplicates.
- [ ] `docs/backup-restore.md` contains the stop/copy/start procedure, executes as a testscript
      case, and states that `cp messq.db` is not a backup, that there is no `-wal` to copy, and what
      a restore costs.
- [ ] `messq doctor` runs against a live daemon and against an offline data dir; every check
      declares its source and unavailable checks are reported as `[skip]` with a reason.
- [ ] Every check in §7 exists, has a `docs/doctor.md#<id>` section, a `Summary`, an `Explain`, and
      either a `Fix` or a `NoFix`; a registry test enforces all five and rejects duplicate IDs.
- [ ] A fixture daemon seeded with each misconfiguration produces exactly the expected finding ID at
      the expected severity — one sub-test per check, and a "clean fixture" sub-test that asserts
      **zero** findings above `info` (no false positives).
- [ ] `messq doctor` prints live durability pragma state as prose (*"A 201 from publish survives
      power loss: YES"*) sourced from `/v1/info` in live mode, and says explicitly when it is only
      reporting its own connection in offline mode.
- [ ] `messq doctor` measures `fdatasync` on the data dir (default 1 000 samples), prints
      p50/p99/p99.9 and a projected durable msg/s from the observed commit batch size, warns when the
      median is implausibly fast, and fails when the data dir is tmpfs under `--durability=full`.
- [ ] Exit code: 0 with nothing at or above `--fail-on`, 1 otherwise, 2 on usage, 7 when no source
      is readable; an unreachable daemon is a finding and **never** exit 6.
- [ ] `--output json` emits the frozen shape in §8 and passes a JSON-schema golden test;
      `--output ndjson` emits one finding per line with the summary last.
- [ ] Doctor completes in < 2 s (excluding the fsync probe) against a fixture with 1 000 streams and
      10 000 consumers, and performs no unbounded `count(*)` or full event scan in live mode.
- [ ] No doctor output — human or JSON — contains a message body, a header value or a token secret
      (canary test).

## Test plan

Ground rules from §11 / D13 apply: `-race` everywhere, no `time.Sleep` outside soak, real SQLite
files in `t.TempDir()` (never `:memory:`), every fixed bug lands with its reproduction artifact.

**Unit — `internal/doctor/checks` (the bulk of the value)**
- One table-driven test per check ID over hand-written `Snapshot` literals: fires / does not fire /
  boundary (`ack_wait` exactly equal to p99; `max_deliver=0` with each `dead_policy`; DLQ growth of
  exactly zero; a snapshot exactly `--backup-max-age` old).
- Purity: a test runs every check with a `Snapshot` whose collectors are nil — no panic, no I/O,
  `SevSkipped` where data is missing.
- Registry: unique IDs, `Fix`-or-`NoFix`, a `docs/doctor.md` anchor per ID (parsed from the file),
  every ID in `--list`.
- Renderer: sorting determinism, `--quiet`, `NO_COLOR`, the fail-latch hoist, summary counts, and
  the JSON `exit_code` agreeing with the process exit.

**Unit — `internal/ops/backup`**
- `estimate.go` against known page/freelist counts; the free-space precheck arithmetic.
- `tmp.go`: temp dir mode, stale sweep boundary at 1 h, cleanup on every error path, rename
  atomicity (the destination is the old file or the new one, never a truncated file).
- `stamp.go`/`selfcheck.go`: round-trip of every `snapshot_*` key; a page-flipped snapshot fails
  `quick_check` and its temp dir is removed.

**Property / fuzz**
- Typo detector (`stream.typo_suspect`) differentially fuzzed against a naive edit-distance
  reference — the pattern #3 uses for the subject matcher.
- `promtext` fuzzed against `prometheus/common/expfmt` output shapes (labels, `NaN`, `+Inf`,
  comments): never panic, never mis-associate a label.
- Finding renderer fuzzed with arbitrary `Detail`/`Evidence` (control characters, invalid UTF-8,
  huge values): ndjson stays one finding per line and no ANSI when colour is off.

**Deterministic timing (`testing/synctest`)**
- Per-check `Budget` expiry → `SevSkipped` `reason:"timed out"`; the whole-run `--timeout`;
  `--idle-after`, `--since` clamping and `backup.stale` boundaries on the #3 Clock seam.

**Integration — backup under load (the headline acceptance test)**
- Real `messq serve`; publish + fetch + ack + nak load from #8's generator with its fsynced external
  ledger; `messq backup` mid-run; `verify --data-dir` and `integrity_check` clean on the snapshot.
- Restore into a fresh data dir, start a daemon, reconcile against the ledger with the
  **three-valued oracle**: `OK`-before-backup-start present, `FAILED`/after-backup-complete absent,
  in-between `UNKNOWN`. Assert `INFLIGHT` → `READY` with `attempts` preserved and one
  `recovery.reclaimed` event per reclaimed row.
- Both durability modes; one run with the backup taken during a WAL checkpoint.

**Crash**
- SIGKILL the daemon during a backup → the backup completes and verifies; the source recovers.
- SIGKILL the backup process at random points → the destination path never exists partially; a temp
  dir may remain and the next run sweeps it and says so.
- Restore a snapshot taken from an unclean (SIGKILLed) source → `Open` reports clean and `verify`
  passes.

**Fault injection (the one case this issue owns; #32 industrialises the rest)**
- Destination on a small loopback ext4 filled to ENOSPC → both the precheck and mid-run paths leave
  the source untouched, remove the temp dir, exit 1 with the byte numbers.
- Destination directory read-only → exit 7 with the `chmod`/`chown` fix line.

**Golden / testscript (`test/script/backup.txtar`, `doctor.txtar`, `restore.txtar`)**
- `backup` success, `--force`, destination-exists, inside-data-dir, `--verify none` — byte-for-byte
  under the fake clock.
- `doctor` on the clean fixture (exit 0) and the seeded fixture (exit 1) in all three output modes;
  `--only`/`--skip`/`--list`/`--explain`; `--fail-on never` exits 0 with the same findings.
- `docs/backup-restore.md` executed verbatim — documentation cannot rot (§11.5).
- Daemon stopped mid-script → doctor still runs, reports `server.unreachable`, exits 1 (not 6).
- Cross-source: the same fixture through both collectors yields identical IDs and severities, and
  `consumer.ack_wait_below_p99` agrees within one histogram bucket between `/metrics` and SQL.

**Benchmarks**
- `BenchmarkVacuumInto` at 100 MiB / 1 GiB / 4 GiB: MB/s, wall clock, **peak RSS** (the `temp_store`
  regression guard); recorded in `docs/perf/` next to #8's numbers.
- `BenchmarkDoctorCollect` at 1 000 streams × 10 000 consumers holds the < 2 s budget, with an
  `EXPLAIN QUERY PLAN` assertion that no query scans `messages`.

**Security**
- Canary-leak: publish a canary payload and header, grep `doctor`'s JSON and human output for it;
  assert `security.*` findings carry token **ids**, never secrets.
- Snapshot mode `0600`, temp dir `0700`, asserted from a `umask 022` process.
