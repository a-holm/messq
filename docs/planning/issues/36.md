## Context

Thirty-five issues built a broker. This one turns it into **something a stranger can install**, and
then declares it finished.

At the moment the only way to obtain messq is `git clone && make build` (#1). `packaging/` holds a
hardened systemd unit, a sysusers snippet and an env example (#17); `contrib/` holds Prometheus
alert rules, a Grafana dashboard (#21) and the backup service/timer (#30); `make dist-docs` emits
man pages and shell completions (#26). None of it is installed by anything. There is no `.deb`, no
`.rpm`, no container image, no checksum, no signature, no `install.sh`, and no released version at
all.

Governing PLAN.md material:

- **§14 M8 exit criterion** — *"packaging (deb/rpm/container), 1.0 docs … **tag v1.0.0**;
  `apt install` → quickstart works on a clean VM."* That sentence is this issue, verbatim, and it is
  the last gate of the MVP.
- **§1.5 Success criteria** — *"Time from download to first acked message < 60 s, no config file"*
  and *"Runtime dependencies ≤ 8 direct Go modules, `CGO_ENABLED=0`, one static binary."* The first
  is a property of the **distribution path**, not of `quickstart`: if the reader spends four minutes
  finding a working download, the 60 s tour is irrelevant.
- **§13 Library choices** — the ≤ 8 direct-module budget. `goreleaser`, `nfpm`, `cosign` and `syft`
  are build-time tools and must live in the `tools/` module (#2), never in the main `go.mod`.
  `scripts/dep-budget.sh` will catch a mistake here, which is the point of having written it.
- **§10 / D12 Security model** — the hardened unit, the `messq` system user, socket `0660`, data dir
  `0700`, and the deliberate *absence* of SLSA ceremony and signed audit chains. Checksums, a cosign
  signature over them and an SBOM are the right tax bracket; a provenance framework is not.
- **D8 — flags + `MESSQ_*` env only.** There is no config file to package, which is why the `.deb`
  ships an `EnvironmentFile` and nothing else. This is a packaging *simplification* the plan bought
  at M4 and this issue collects.
- **§4.2 / §7 / §8 / §9.2** — the surfaces that get **frozen** here: on-disk schema, HTTP shapes and
  error codes, CLI JSON shapes and exit codes, log field schema, event vocabulary, metric names.
  Every one of them already has a frozen artifact and a test that guards it (#18, #19, #21, #26,
  #34). This issue writes the promise those artifacts have been quietly enforcing since M4 and
  attaches it to a version number.

So the issue has two halves that must not be split: **the distribution path**, and **the release
gate + compatibility promise**. Shipping the first without the second gives users a binary with no
stated contract; the second without the first gives a contract nobody can install.

What it unlocks: every M9 issue (#37–#42) is blocked on this tag, because "phase 2" is defined as
"after 1.0" — and because each of them adds a field, a flag or an event to a surface that must
already be frozen for "additive" to mean anything.

## Scope

### In scope

- **`.goreleaser.yaml`** — the single source of build/package/publish truth: static `linux/amd64` +
  `linux/arm64` binaries, `tar.gz` archives, `.deb`/`.rpm` via nfpm, container images, checksums,
  SBOMs, signatures, release notes.
- **Reproducibility**: `CGO_ENABLED=0`, `-trimpath`, pinned `mod_timestamp`, deterministic ldflags —
  plus a **test** that two independent runners produce byte-identical artifacts.
- **Package layout**: binary, systemd unit, sysusers snippet, `/etc/default/messq`, man pages, shell
  completions, `contrib/` (alerts, dashboard, backup timer), docs, licence — at FHS paths, with
  idempotent maintainer scripts that never touch a byte of user data.
- **Container image**: `scratch`-based, non-root numeric UID, multi-arch manifest, OCI labels, and a
  default command that is *secure by default* rather than convenient (see §5).
- **`install.sh`** — arch detection, checksum verification (mandatory), signature verification when
  `cosign` is present, `--version`/`--dir`/`--dry-run`, honest failure messages.
- **`apt install messq` / `dnf install messq`**: a signed package repository published by the release
  workflow (§8), plus the always-works `apt install ./messq_1.0.0_amd64.deb` fallback.
- **`.github/workflows/release.yml`** — tag-triggered, gated on the full release-gate suite, least
  privilege, actions pinned by SHA, keyless cosign via OIDC.
- **`docs/compatibility.md`** — the v1.0 compatibility promise: the frozen surfaces, the artifact
  that guards each, what counts as a break, the deprecation policy, and the support window.
- **`messq version --output json`** gains a `compat` block reporting the frozen format numbers
  (additive change to #1's golden, classified `ADDITIVE` by #18's classifier).
- **`RELEASE.md` + `make release-gate`** — the v1.0 checklist as executable code: every item is a
  named CI job whose status is queried, printed and exited on.
- **The clean-VM install matrix** (debian, ubuntu, rocky, fedora, with systemd as PID 1) as a
  nightly + pre-release job.
- **Tagging `v1.0.0`**, the release notes, and the post-tag verification pass.

### Out of scope

- Writing the tests the gate consumes: fault matrix and crash sweep → **#32**; fuzz corpus and soak
  → **#33**; upgrade fixtures → **#34**; the 1.0 documentation set → **#35**. This issue *runs* them
  and refuses to publish when they are red; it does not author them.
- The systemd unit's content and its `systemd-analyze` gate → **#17**. This issue installs the file
  and adds the score to the release checklist.
- `contrib/prometheus/alerts.yml`, `contrib/grafana/messq.json` → **#21**;
  `contrib/systemd/messq-backup.{service,timer}` → **#30**. Packaged here, authored there.
- Man-page and completion **generation** (`make dist-docs`) → **#26**. Installed here.
- The HTTP contract artifacts, shape digests and the ADDITIVE/BREAKING classifier → **#18**. Reused
  wholesale; the compatibility promise cites `test/contract/testdata/` by path.
- macOS/Windows/FreeBSD builds, Homebrew, Nix, AUR, Scoop → **not planned**. PLAN §1.2 says "a
  single-binary queue daemon **for Linux**"; a Homebrew tap for a Linux daemon is a support burden
  with no user. Recorded in `docs/non-goals.md` (#35).
- SLSA provenance, in-toto attestations, a reproducible-build attestation service, hash-chained
  release manifests → deferred per **D12**; see *Considered and deferred*.
- Native TLS in the image → **#40**; audit export → **#42**; any behaviour change at all — a release
  issue that changes semantics is a release issue that missed its gate.

## Design proposal

> Proposal, not mandate — **except** three rules that are expensive to reverse once a version number
> is public: (1) no package script ever deletes user data; (2) the container never binds a
> non-loopback listener without auth; (3) `-update` on a frozen artifact cannot approve a break, and
> the release workflow re-checks it independently of the PR lane.

### 1. The artifact matrix

| Artifact | Name | Contents |
|---|---|---|
| Archive | `messq_1.0.0_linux_amd64.tar.gz` (+ `arm64`) | binary, LICENSE, NOTICE, README, man pages, completions, `contrib/` |
| Debian package | `messq_1.0.0_amd64.deb` (+ `arm64`) | §4 layout |
| RPM package | `messq-1.0.0.x86_64.rpm` (+ `aarch64`) | §4 layout |
| Container | `ghcr.io/<org>/messq:1.0.0`, `:1.0`, `:1`, `:latest` | §5 |
| Checksums | `checksums.txt` | SHA-256 of every file above |
| Signature | `checksums.txt.sig` + `checksums.txt.pem` | cosign keyless (OIDC) |
| SBOM | `<artifact>.sbom.json` | SPDX JSON via syft, per archive and per package |
| Installer | `install.sh` | attached to the release and served from `https://messq.dev/install.sh` |

Everything a user needs is reachable from one release page, and every download can be verified with
two commands that appear in the release notes.

### 2. Reproducible builds (**decision**)

A "static binary" claim that cannot be re-derived is marketing. The rules:

```
CGO_ENABLED=0            no libc, no dynamic loader — arm64 cross-build without a toolchain
-trimpath                no $HOME, no GOPATH in the binary
-ldflags "-s -w -X …"    version/commit/date only; date = commit date, never build date
mod_timestamp            {{ .CommitTimestamp }} — archive/package mtimes are the commit's
GOFLAGS unset in CI      no ambient flags that only one machine has
```

`scripts/assert-static.sh` (#1) already asserts `CGO_ENABLED=0` and `-trimpath=true` from
`go version -m`. This issue adds `make repro-release`: build the release artifacts twice — once on
`ubuntu-latest`, once in a container with a different kernel and `$HOME` — and diff `checksums.txt`.
Reproducibility is asserted, not argued.

### 3. `.goreleaser.yaml` (proposal)

Pin the goreleaser version in `tools/` and run `goreleaser check` in the PR lane: config keys move
between minors (`archives.format` → `formats`, `dockers`/`docker_manifests` → `dockers_v2`), and a
release day is the worst possible time to discover a deprecation.

### 4. Package layout and maintainer scripts

| Source | Destination | Type |
|---|---|---|
| `dist/messq` | `/usr/bin/messq` | binary |
| `packaging/systemd/messq.service` (#17) | `/usr/lib/systemd/system/messq.service` | file |
| `packaging/systemd/messq.sysusers.conf` (#17) | `/usr/lib/sysusers.d/messq.conf` | file |
| `packaging/messq.env.example` (#17) | `/etc/default/messq` | `config|noreplace` |
| `man/man1/messq*.1`, `man/man8/messq.8` (#26) | `/usr/share/man/man{1,8}/` | file |
| `completions/messq.bash` (#26) | `/usr/share/bash-completion/completions/messq` | file |
| `completions/messq.zsh` | `/usr/share/zsh/site-functions/_messq` | file |
| `completions/messq.fish` | `/usr/share/fish/vendor_completions.d/messq.fish` | file |
| `contrib/prometheus/alerts.yml` (#21) | `/usr/share/messq/contrib/prometheus/alerts.yml` | file |
| `contrib/grafana/messq.json` (#21) | `/usr/share/messq/contrib/grafana/messq.json` | file |
| `contrib/systemd/messq-backup.{service,timer}` (#30) | `/usr/lib/systemd/system/` | file |
| `LICENSE`, `NOTICE`, `README.md`, `docs/OPERATIONS.md` (#35) | `/usr/share/doc/messq/` | file |

`/etc/default/messq` is `config|noreplace` and ships **fully commented out**, so an unedited file is
a no-op and an edited one survives every upgrade. The data directory is *not* in the package:
`StateDirectory=messq` (#17) creates `/var/lib/messq` mode 0700 owned by `messq` the first time the
unit starts, which is exactly one mechanism instead of two disagreeing ones.

```sh
# packaging/scripts/postinstall.sh — proposal; must be idempotent, must never write user data
set -eu
if command -v systemd-sysusers >/dev/null 2>&1; then
    systemd-sysusers messq.conf || true
elif ! getent passwd messq >/dev/null; then
    useradd --system --no-create-home --shell /usr/sbin/nologin \
            --home-dir /var/lib/messq messq
fi
command -v systemctl >/dev/null 2>&1 && systemctl daemon-reload >/dev/null 2>&1 || true

if systemctl is-active --quiet messq 2>/dev/null; then
    echo "messq: a new binary is installed; run 'systemctl restart messq' to apply it."
else
    echo "messq installed. Next:  systemctl start messq   then:  messq quickstart"
fi
```

Three decisions encoded there:

1. **No auto-enable, no auto-start.** The acceptance criterion is
   `apt install messq && systemctl start messq`; a package that starts a daemon the operator did not
   ask for is the behaviour Debian is criticised for. The postinstall message *is* the next step,
   matching PLAN §8's "every command ends with the next useful command".
2. **No auto-restart on upgrade.** Draining is safe (#17) and losing nothing across restart is
   tested (#14/#32), but a silent restart is still a surprise. Print, don't act. `messq doctor` (#30)
   gains a `version.skew` finding — *proposal* — comparing `/v1/info`'s version against
   `messq version`.
3. **`preremove` stops the unit; `postremove` deletes nothing.** Not the data directory, not the
   backups, not on `purge`. If the `messq` user must go, the removal message tells the operator the
   two commands to run. A packaging script that can destroy a queue is a packaging script that
   eventually will.

### 5. Container image

```dockerfile
# packaging/Dockerfile — proposal
FROM busybox:1.37-uclibc AS prep
RUN mkdir -p /out/var/lib/messq /out/run/messq \
 && chown -R 65532:65532 /out/var/lib/messq /out/run/messq \
 && chmod 0700 /out/var/lib/messq && chmod 0750 /out/run/messq

FROM scratch
COPY --from=prep /out/ /
COPY messq /usr/bin/messq
USER 65532:65532
VOLUME ["/var/lib/messq"]
EXPOSE 4390
ENTRYPOINT ["/usr/bin/messq"]
CMD ["serve", "--data-dir", "/var/lib/messq", "--log-format", "json"]
HEALTHCHECK --interval=10s --timeout=2s --start-period=5s \
  CMD ["/usr/bin/messq", "version", "--remote"]
```

Notes that are load-bearing rather than decorative:

- **`scratch` works because of PLAN §4.1.** `temp_store=MEMORY` means SQLite never needs `/tmp`;
  `modernc.org/sqlite` means no libc; nothing in the daemon dials outward, so no CA bundle is
  needed. A test asserts the image runs with `--read-only` and no `/tmp` mount.
- **The default `CMD` binds only the Unix socket.** Exposing TCP requires
  `--listen tcp://0.0.0.0:4390 --auth-file …`, and #16 makes a non-loopback bind without auth a
  *fatal startup error* — so the insecure configuration is unreachable, not merely discouraged. The
  image documentation shows the two-flag form. `EXPOSE 4390` documents the port without opening it.
- **Numeric UID 65532** (no `/etc/passwd` in `scratch`). The pre-created, pre-chowned `/var/lib/messq`
  is why a plain `docker run -v messq-data:/var/lib/messq` works: Docker seeds a new named volume
  from the image directory, ownership included.
- **`messq version --remote`** (#23) is the health check: it is the only binary in the image, it has
  a 2 s budget, and it exercises `/v1/info` rather than a TCP dial.
- Size budget: **< 25 MB compressed**, asserted in CI. If it grows, something was linked in that
  should not have been.

### 6. Signing, checksums, SBOM — and what we deliberately skip

| Ships | Why |
|---|---|
| `checksums.txt` (SHA-256) | The floor. `install.sh` refuses to install without a match. |
| cosign **keyless** signature over the checksums file | No key to store, rotate or leak; verification is one command with a documented OIDC identity. Signing every artifact individually buys nothing once the checksum file is signed. |
| SPDX SBOM per archive and per package | A one-line goreleaser stanza; answers the "what is in this binary" question that a security review will ask. |
| Repository GPG signing key (§8) | `apt` will not use an unsigned repo, and teaching users `[trusted=yes]` is teaching them a bad habit. |
| **Not**: SLSA L3 provenance, in-toto attestations, signed release manifests | **D12** — *"real designs, wrong tax bracket for the ICP."* Revisit trigger: a downstream distributor or a security review asks for it in writing. |

### 7. `install.sh`

```console
$ curl -fsSL https://messq.dev/install.sh | sh
messq installer
  version   v1.0.0 (latest release)
  platform  linux/amd64
  target    /usr/local/bin/messq

  downloading messq_1.0.0_linux_amd64.tar.gz ... ok (11.4 MiB)
  verifying  sha256 ......................... ok
  verifying  cosign signature ............... ok
  installing /usr/local/bin/messq ............ ok

messq v1.0.0 installed.

  next:  messq quickstart        # 60-second guided tour, throwaway data dir
  then:  messq serve --dev       # a real daemon on an ephemeral data dir
  docs:  https://messq.dev/docs
```

Rules: `--version vX.Y.Z` pins (default: latest **non-prerelease**); `--dir` overrides the target,
which is `/usr/local/bin` when writable and `~/.local/bin` otherwise (**never** self-`sudo`, and it
says which it chose and why); `--dry-run` prints the exact URLs and exits; checksum verification is
**mandatory** with `sha256sum` → `shasum -a 256` → `openssl dgst -sha256` fallbacks, and the script
aborts if none is available rather than installing unverified bytes; signature verification is
best-effort and reported honestly (`skipped: cosign not installed`); after install it runs
`messq version` and aborts if the version does not match what was requested. `shellcheck` clean,
POSIX `sh`, no bashisms — it runs under busybox `ash` in CI.

### 8. Making `apt install messq` true (**decision**)

The acceptance criterion says *"`apt install messq` … with no other steps"*, which requires a
repository. Recommended path, in order of preference:

1. **Self-hosted flat repository on GitHub Pages** at `https://apt.messq.dev` / `https://rpm.messq.dev`.
   The release workflow generates it with `apt-ftparchive` + a GPG-signed `InRelease`, and
   `createrepo_c` + `gpg --detach-sign repomd.xml` for RPM; the public key is published at a stable
   URL with its fingerprint printed in the README and in `docs/compatibility.md`. Cost: one signing
   key in repository secrets, ~60 lines of workflow. Benefit: no third party in the install path.
2. **Fallback if the signing-key infrastructure is not ready on release day:** goreleaser's `furies`
   publisher (Gemfury free tier) gives a working apt/yum repo for one config block. Ship 1.0 with it
   and migrate later — the repository URL is documentation, not a compatibility surface.
3. **Always documented, always works:**
   `curl -fsSLO <release-url>/messq_1.0.0_amd64.deb && apt install ./messq_1.0.0_amd64.deb`.

The install test matrix (§Test plan) exercises path 1 or 2 *and* path 3, so the README never claims
an install method that CI has not run.

### 9. Release workflow

```yaml
# .github/workflows/release.yml — proposal
on:
  push:
    tags: ["v*"]
permissions: { contents: read }
jobs:
  gate:                      # refuses to release on a red gate; see §12
    runs-on: ubuntu-latest
    steps: [ …checkout…, "make release-gate REF=${{ github.ref_name }}" ]
  release:
    needs: [gate]
    permissions:
      contents: write        # create the release
      packages: write        # push to ghcr.io
      id-token: write        # cosign keyless OIDC
    steps:
      - …checkout with fetch-depth 0…, setup-go from go.mod
      - uses: sigstore/cosign-installer@<sha>
      - uses: anchore/sbom-action/download-syft@<sha>
      - run: goreleaser release --clean
  verify:                    # the release is not done until it is re-verified from outside
    needs: [release]
    steps: [ "scripts/verify-release.sh ${{ github.ref_name }}" ]
  install-matrix:
    needs: [release]
    strategy: { matrix: { image: [debian:12, ubuntu:24.04, rockylinux:9, fedora:41] } }
    steps: [ "scripts/test-install.sh ${{ matrix.image }} ${{ github.ref_name }}" ]
```

`scripts/verify-release.sh` downloads the published artifacts from the internet (not from the build
directory), verifies checksums and the cosign signature, extracts the binary, runs
`messq version --output json` and asserts the version matches the tag. A release that cannot be
verified by a stranger with a shell is not a release.

### 10. The v1.0 compatibility promise (`docs/compatibility.md`)

The promise is short because the enforcement already exists. Semantic versioning applies to these
surfaces and **nothing else** (internal package APIs are explicitly excluded):

| Frozen surface | Guarded by | A break is… |
|---|---|---|
| HTTP request/response field shapes | `test/contract/testdata/wire/*.shape` + #18's classifier | removing/renaming a field, narrowing a type, changing a status code |
| Error `code` enum and `code → status` map | `test/contract/testdata/enums/code.txt`, `codes.tsv` (#18) | removing a code or remapping its status |
| CLI `--output json`/`ndjson` shapes | `.txtar` goldens + shape digests (#26) | same rule as HTTP |
| CLI exit codes | the generated `exit-codes` help topic (#23/#26) | reassigning a code's meaning |
| Log field schema | `docs/log-schema.md` + golden log tests (#19) | renaming a field or an event |
| Event vocabulary (PLAN §9.2) | `internal/obs` constants + SEMANTICS.md (#4/#19) | renaming or removing an event name |
| Metric names and label sets | `/metrics` exposition golden (#21) | renaming a metric or adding a label |
| On-disk **format family** | `testdata/datadirs/` fixtures (#34) | any change a 1.x binary cannot migrate forward |
| Ack-token grammar | parser tests + fuzz corpus (#10/#33) | changing field count or order |

Policy text to write:

- **Additive is always allowed** in 1.x: new endpoints, new response fields, new events, new metrics,
  new flags, new migrations *within* format family 1. Clients must ignore unknown fields; the docs
  say so and the Go client (#22) does so.
- **Deprecation** requires: an entry in `docs/compatibility.md`, a `WARN` log on use, a `doctor`
  finding, and a minimum of **two minor releases** before removal — and removal still waits for 2.0.
- **Support window**: the current minor and the one before it get security fixes; stated as a table
  in `SECURITY.md`, with dates, or it means nothing.
- **What is not promised**: internal Go package APIs, exact human-readable output (the `table` face
  is *not* frozen — that is what `--output json` is for), log *levels*, timing, wall-clock
  performance, and the on-disk file's private byte layout (SQLite owns it).

### 11. `messq version` reports the frozen numbers

```console
$ messq version --output json
{"version":"v1.0.0","commit":"9f3c1ab77d20","date":"2026-11-20T10:04:00Z","dirty":false,
 "go_version":"go1.26.5","platform":"linux/amd64",
 "compat":{"format":1,"api":1,"log_schema":1,"cli_json":1}}
```

`format` is the **on-disk format family**, deliberately distinct from `meta.schema_version` (#5),
which is a migration counter that keeps incrementing during 1.x. Family 1 means "every 1.x binary
can migrate this directory forward"; a family bump is a major version and a documented migration.
`api`, `log_schema` and `cli_json` are the contract version numbers referenced by
`docs/compatibility.md`.

This adds keys to the JSON object #1 froze. That is exactly the case #18's classifier calls
`ADDITIVE`: this issue updates #1's golden and records the classification in the PR, which is the
mechanism working as designed rather than an exception to it.

### 13. Edge cases, decided

| Case | Handling |
|---|---|
| Tag pushed from a dirty tree or a non-`main` commit | `goreleaser release --clean` refuses dirty; a workflow guard asserts the tag commit is an ancestor of `main`. Fail before publishing, never after. |
| Pre-release tag (`v1.0.0-rc.1`) | `prerelease: auto` marks it; **no** `latest` docker tag, **no** package-repo publish; `install.sh` skips prereleases unless `--version` names one explicitly. |
| Re-running a release / re-tagging | goreleaser fails on an existing release, and that is correct. A published checksum is never overwritten; ship `v1.0.1`. |
| `arm64` vs `aarch64` | nfpm maps per format (deb `arm64`, rpm `aarch64`); `install.sh` maps `uname -m`: `x86_64`→`amd64`, `aarch64`\|`arm64`→`arm64`, anything else → a one-line error naming the supported set. |
| Upgrade over an edited `/etc/default/messq` | `config|noreplace` keeps it; the shipped file is entirely comments, so an untouched file is inert. |
| Package removal / `apt purge` | Stops the unit; deletes **no** data, no backups, and leaves the `messq` user. The removal message names the two commands an operator can run if they really mean it. |
| Distro without `systemd-sysusers` | `useradd --system` fallback; both paths idempotent and both tested. |
| SELinux enforcing (Rocky/Fedora) | The daemon writes only under `StateDirectory`/`RuntimeDirectory`, which carry correct contexts. Restore-from-backup can not; `OPERATIONS.md` (#35) documents `restorecon -Rv /var/lib/messq`, and the Rocky install test runs with SELinux enforcing. |
| Lintian `manpage-not-compressed` | Man pages ship uncompressed (rpm compresses them itself; dpkg does not care). The tag goes in an allow-list with the reason written next to it, not silenced globally. |
| Container with a read-only rootfs | Works — `temp_store=MEMORY`, no `/tmp`, no writes outside the volume. Asserted by a test, since it is easy to break by accident. |
| Container run without a volume | The daemon writes to the image's writable layer and the data dies with the container. The image docs lead with `-v`; `messq doctor` (#30) already warns on a data dir that looks ephemeral. |
| goreleaser/nfpm/cosign creeping into `go.mod` | `tools/` module (#2) plus `scripts/dep-budget.sh` (#1). The gate exists precisely for this issue. |
| GHCR push fails after the GitHub release is created | The `release` job is not atomic. `verify-release.sh` fails, the release is marked **draft-broken** in the workflow summary, and the documented recovery is to re-run the image publish step only. |
| Signing key or OIDC unavailable | The release **fails**. Publishing unsigned artifacts "just this once" is how a supply chain gets a precedent. |
| `install.sh` piped to `sh` with no TTY | Fully non-interactive by design: no prompts ever, all decisions from flags/env, everything narrated to stderr. |

### Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| SLSA L3 provenance / in-toto attestations | D12: wrong tax bracket for the ICP; checksums + cosign + SBOM answer the real questions | A distributor or a written security review asks |
| Homebrew tap, Nix flake, AUR, Snap, Flatpak | messq is a Linux **daemon**; each channel is a support surface with no proven user | Three real users ask for a specific one (the #11 rule) |
| Official Debian/Fedora inclusion | Needs a stable release cadence and a maintainer with upload rights; a 1.0 tag is the prerequisite, not the follow-up | After 1.x has shipped a few times |
| Auto-restart on package upgrade | Silent restarts surprise operators; drain safety is not the same as consent | Never by default; a `/etc/default/messq` opt-in if asked for |
| Nightly/edge channel and `:nightly` images | A pre-1.0 project needs one channel that is trustworthy more than two channels that are confusing | Post-1.0, when there is a stable branch to diverge from |
| Windows/macOS binaries for the **CLI only** | The CLI talks HTTP and would genuinely work; but it doubles the test matrix for a client whose users have Linux nearby | Real demand from a user whose laptop is not Linux |

## Test plan

Per PLAN §11: `-race` where Go code is involved, no `time.Sleep`, every gate proven by a sabotage
fixture in the style #2 established. This issue's surface is mostly shell and CI, so its tests are
mostly *black box against real distributions*.

**Package/install integration (`test/install/`, container-based, nightly + pre-release)**

- `TestInstallMatrix` — for each of debian:12, ubuntu:24.04, rockylinux:9, fedora:41 run a container
  with systemd as PID 1: install the package, `systemctl start messq`, poll `systemctl is-active`,
  `messq quickstart`, `messq doctor` (expect no `fail` findings), `curl --unix-socket …/v1/info`.
  Asserts M8's exit criterion literally.
- `TestUpgradePreservesState` — install a synthetic `0.9.0` package, publish and leave messages
  pending, edit `/etc/default/messq`, install `1.0.0`, assert: data directory unchanged, conffile
  unchanged, daemon **not** restarted, restart hint printed; then restart and assert the ledger from
  #8's oracle still holds (nothing lost, nothing spuriously redelivered).
- `TestRemoveKeepsData` — remove and purge; assert the data directory is byte-identical (checksum of
  every file) and the daemon can be reinstalled and resumed.
- `TestSELinuxEnforcing` — Rocky 9 with enforcing mode; install, start, quickstart, and assert an
  empty `ausearch -m avc` for the daemon.
- Package lint: `lintian --fail-on error` on the `.deb`, `rpmlint` on the `.rpm`, with a documented,
  commented allow-list; `systemd-analyze verify` + `security` on the installed unit.

**Container (`test/container/`)**

- Multi-arch manifest present for amd64 + arm64 (`docker manifest inspect`).
- Runs as 65532; no shell; compressed size under budget; `--read-only` rootfs + volume works.
- Publish/consume round trip against the image over TCP **with** an auth file; the same invocation
  without `--auth-file` must fail with #16's typed startup error (a negative test that would
  otherwise rot into an insecure default).

**Installer (`test/install/install_sh_test.go` + shellcheck in the lint job)**

- Table over `{arch, tool availability, tampered checksum, missing cosign, prerelease-only releases,
  unwritable /usr/local/bin}` executed inside a busybox container against a local HTTP server that
  serves fabricated release assets. Each row asserts exit code, the operative stderr line, and
  whether a file was written.

**Reproducibility & supply chain**

- `repro-release` job: build twice in differing environments, diff `checksums.txt`. Failure prints
  the first differing artifact and a `diffoscope` hint.
- `verify-release.sh` runs post-publish and again in the nightly lane against the newest release, so
  a broken artifact is detected even if nobody downloads it that week.
- SBOM: `syft` output parses as SPDX and lists `modernc.org/sqlite`; a sabotage test that adds a
  9th direct module fails `dep-budget` before it can reach an SBOM.

**Compatibility promise**

- `TestCompatDocResolves` — every artifact path cited in `docs/compatibility.md` exists; every
  invariant ID and CI job name it references is real. A promise pointing at a deleted file is worse
  than no promise.
- `TestVersionCompatBlock` — `messq version --output json` contains the `compat` keys with the frozen
  values, and the shape digest diff versus #1's golden classifies as `ADDITIVE`.
- Cross-version replay (#34's fixtures + #18's contract directory) runs as a **release gate**, not
  only as a nightly, so a break cannot ship while the nightly is red.

**Release-gate self-test**

- `test/gates/release/` sabotages one gate at a time (fake a red soak run, fake a `BREAKING`
  classification, drop an invariant test, leave a `TODO(#33)` in `nightly.yml`) and asserts
  `make release-gate` exits non-zero naming the specific gate. A gate nobody has seen fail is a gate
  nobody knows works.

**Budgets**: the PR lane adds only `goreleaser check`, `shellcheck`, and a `--snapshot` build
(≤ 3 min, no publish, no signing). Everything else lives in the nightly and pre-release lanes, so
PLAN §11's 10-minute PR budget is untouched.
