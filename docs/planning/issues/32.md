## Context

M8's exit criterion is *"every §5.2 invariant has a named passing test"* — and the invariants that
matter most (I1 no acknowledged loss, I3 no acked message redelivered, I4 the delivery bound holds
across restarts, I8 DLQ conservation) are all statements about **what happens when something goes
wrong**. Up to this point the suite has proved them under *timing* faults: #8 kills the process at a
seeded wall-clock moment, #13 restarts the store between two random operations. Neither can aim, and
a kill 400 µs after a commit is a different bug class from a kill 400 µs before it.

This issue makes the crash points **addressable**: a named fault point in the code, an env-driven
activation grammar, and a matrix runner that walks every point × every durability mode. It then adds
the four fault families a kill can never simulate, because they are not about the process dying —
they are about the machine underneath it misbehaving:

- **ENOSPC.** §4.5 makes a strong, unusual promise: below `--min-free-bytes` publishes are rejected
  with a typed error *while acks, naks and DLQ writes keep working*, because a wedged ack path turns
  a full disk into mass redelivery. #27 implemented the guard; nothing has ever filled a real
  filesystem underneath it.
- **EIO.** D4 adopts the fsyncgate rule verbatim: a failed sync is fatal, latched, never retried,
  because Linux clears the page error flag and a retried `fsync` can return success over lost data.
  #6 implemented the latch against a Go-level error injection. Nothing has proved the daemon
  *cannot write* after that latch, at the byte level, against a real `EIO` from a real block device.
- **Clock jumps.** #6 §10.6 clamps wall-clock timestamps monotone, #11 caps mass-timeout drain rate
  and detects steps > 5 s. Both were written against a fake clock inside one process.
- **Client disconnect and slow consumers.** The long-poll waiter registry (#14) is the one piece of
  unbounded-by-nature in-memory state in the design (§3.2, I11), and `max_ack_pending` (#9) is the
  only thing between a never-acking worker and an unbounded pending set.

Governing sections: **D13** (nine fault families reduced to the six that matter under D1: kill,
torn tail via SQLite, ENOSPC, EIO, clock jump, client disconnect/slow consumer; LazyFS and
`dm-log-writes` explicitly *not* 1.0 gates), **§11 Testing strategy** layers 3–4, **D4** and
**§4.3** (durability modes, group commit, fsync failure is fatal), **§4.4** (crash recovery),
**§4.5** (retention, housekeeping, disk safety), **§5.2** (the invariant register), **§12**
(recovery ≤ 2 s).

What it unlocks: **#36** — the v1.0 release gate is a checklist of green job names, and six of them
are produced here. `docs/fault-matrix.md` is the artifact #35's `guarantees.md` links each invariant
row to; a guarantee without a named CI job gets deleted, so this issue decides which guarantees
survive to 1.0.

This issue **adds no product behaviour**. Every scenario it writes is an assertion about behaviour
that #5–#27 already claim. When a scenario finds a claim to be false, the *fix* lands in the owning
issue with the failing test moving there; this issue owns the apparatus and the matrix, not the
repairs.

## Scope

**In scope**

- `internal/fault` — the ~150-line fault-point package behind the `messq_fault` build tag: the
  `MESSQ_FAULTS` activation grammar (percent / count / action), the seeded activator, the durable
  activation log, and the zero-cost production no-op.
- The **fault-point registry**: one declared list with an owning issue per point, the AST lint that
  rejects an undeclared name, and the meta-test that fails when a declared point has no test.
- Wiring the points that #5–#27 **reserved** but left as no-ops, plus the missing ones.
- `test/matrix` — the crash-matrix runner over #8's harness: fault point × durability mode ×
  workload profile, seeded, with per-scenario oracle rules.
- Extending #8's ledger and reconciler from a **publish-only** oracle to a **settle** oracle
  (`ack`/`nak`/`term` intents with three-valued verdicts) plus the consumer side of
  `internal/testutil/loadgen`, so settle-path fault points have an oracle at all.
- `test/fsfault` — the real-filesystem lane: loopback ext4 ENOSPC (soft, guarded; and hard,
  unguarded), `dm-flakey`/`dm-error` write `EIO`, and the skip-guard that stops the lane from
  passing by skipping everything — plus the **write-after-latch byte-level assertion**.
- The clock lane: fault-build wall-clock offsets (±1 h, ±1 y, forward, backward, during recovery,
  during a sweep), plus NTP-slew negative tests.
- The disconnect / slow-consumer lane: parked long-poll disconnects, disconnect-after-claim,
  publish disconnect mid-body, never-acking consumer, acking at 0.9× and 1.1× `ack_wait`.
- The **sabotage suite** (one-line deliberate defects behind a `messq_sabotage` tag, each mapped to
  the detector that must catch it) and the **fsync-accounting oracle** that catches `synchronous=OFF`.
- `docs/fault-matrix.md`, generated from the registry, and the CI lanes: `fault-smoke` (PR),
  `crash-matrix` (main), `fs-fault` + `crash-matrix-full` (nightly), `sabotage` (weekly).

**Out of scope** (named where the work lands)

- Fuzz targets, corpora and the soak run — **#33** (which reuses this issue's loadgen extension and
  fault grammar but does not extend the matrix).
- Schema-upgrade fault scenarios (kill mid-migration *from an older version*) — **#34**. Kill
  mid-migration *at the current version* is scenario `K12` here.
- Wiring the release gate and enforcing "no fault symbols in a released artifact" inside
  goreleaser — **#36**. This issue ships the check; #36 runs it on the artifact.
- Operator-facing runbook prose ("disk filling", "torn tail after crash", "duplicate deliveries

- `messq doctor`'s lying-write-cache diagnosis — **#30**; its fsync probe is reused, not rewritten.
- Throughput regression detection and `benchstat` — **#31**. The matrix records wall time per

- Any *fix* a scenario provokes: slow publish resume after ENOSPC clears is #27's bug, a missing

## Design proposal

Everything below is a **starting point, not a mandate**. The settled parts are: fault points are
zero-cost and absent from production builds, an activation must be durable before a `kill` action,
every registered point is exercised by a test, the ENOSPC contract is *degrade without latching*,
the EIO contract is *latch and prove no further writes*, and no scenario passes by skipping.

### 1. `internal/fault` — the grammar without the codegen

`pingcap/failpoint`'s activation grammar is the good idea; its `failpoint-ctl enable` → build →
`disable` source-rewriting workflow is the part we skip (D13's spirit: adopt the discipline, not the
machinery). A build tag gives the same zero production cost with no risk of a half-transformed
working tree.

```go
// Package fault provides named, env-activated fault points. In production builds
// (no messq_fault tag) every exported call compiles to an empty function that the
// inliner deletes. Proposal; the grammar is the settled part.
package fault

// Point activates the named fault if MESSQ_FAULTS selects it. It never returns.
func Point(name string)

// Err returns a non-nil error when the named point is configured with error(...),
// so a caller can inject ENOSPC/EIO into a real code path:
//     if err := fault.Err("store.wal.fsync"); err != nil { return err }
func Err(name string) error
```

```
MESSQ_FAULTS="store.tx.before_commit=1*kill;store.wal.fsync=50%error(EIO);api.fetch.before_send=pause(2s)"
MESSQ_FAULT_SEED=1730489          # seeds the percent draws; printed at startup
MESSQ_FAULT_LOG=/tmp/faults.jsonl # one fsynced line per activation
```

Grammar: `<point>=[<percent>%][<count>*]<verb>[(<args>)]`, `;`-separated.

| Verb | Args | Effect | Primary use |
|---|---|---|---|
| `kill` | — | `syscall.Kill(os.Getpid(), SIGKILL)` after the activation log is fsynced | the crash matrix |
| `exit` | code | `os.Exit(code)` — an *orderly* death, unlike `kill` | supervisor/exit-code tests |
| `panic` | msg | `panic()` at the point | #6's panic-in-`Apply` → latch path |
| `error` | `EIO`, `ENOSPC`, `SQLITE_FULL`, or a sentinel name | `fault.Err` returns it | Go-level I/O faults |
| `sleep` | duration | blocks, then continues | widening a race window |
| `pause` | duration | blocks; a bounded `sleep` by another name, kept separate so intent is greppable | disconnect-mid-response |
| `off` | — | explicitly disabled (documents a point the scenario deliberately does not fire) | matrix readability |

`50%` is a probability per activation; `3*` means "the first three activations only"; combined
(`50%3*kill`) means "of the activations that win the draw, the first three". Draws come from a
`math/rand.Rand` seeded by `MESSQ_FAULT_SEED`, so a scenario replays.

Non-negotiable mechanics:

- **The activation log is fsynced before `kill` runs.** Otherwise the harness cannot distinguish
  "the point fired and killed us" from "the point never fired and the scenario tested nothing" —
  the vacuity hole that makes a fault matrix look green forever.
- **A fault build announces itself, loudly and everywhere**: WARN on `server.start` naming the
  expression, `faults_active: true` in `/v1/info`, `messq_build_info{faults="on"}`. A fault binary
  mistakable for a release binary is a worse bug than any it finds.
- **Unknown point names are a startup error**, not a silent no-op — a typo would otherwise produce a
  passing test that fires nothing.
- **Production absence is asserted, not assumed**: `go tool nm dist/messq | grep -c internal/fault`
  must be `0`, and a publish-path benchmark shows no delta between tagged and untagged builds (the
  tagged build costs one map lookup per point, which is why it is also not the benchmark binary).

Two meta-tests guard it, and they are the reason fault points do not rot into decoration:

1. **`TestEveryPointIsExercised`** — the matrix runner records which points fired across a full run
   into `testdata/fault-coverage.json`; a declared point that no scenario fires fails the test with
   *"declare a scenario or delete the point"*.
2. **`TestNoUndeclaredPoints`** — an AST walk over the repo collects every `fault.Point`/`fault.Err`
   string literal and diffs it against `Registry`. Non-literal arguments are a hard error (a computed
   fault name defeats both meta-tests).

`docs/fault-matrix.md` is `go:generate`d from `Registry` plus the scenario table, so the published
matrix cannot drift from the code — the same trick #19 uses for `docs/log-schema.md`.

### 3. The oracle, extended to settles

#8's ledger records publishes. Half the interesting fault points sit on the settle path, where the
question is not *"does the message exist?"* but *"was an acked message redelivered?"* (I3) and *"did
a dead message land in exactly one DLQ?"* (I8). The ledger therefore grows a second record kind:

```go
type Kind uint8 // Publish | Ack | Nak | Term

type SettleRecord struct {
    Kind     Kind    `json:"kind"`
    Token    string  `json:"token"`     // stream/consumer/seq/attempt/generation (D7 — readable)
    Stream   string  `json:"stream"`
    Consumer string  `json:"consumer"`
    Seq      uint64  `json:"seq"`
    Attempt  int64   `json:"attempt"`
    Verdict  Verdict `json:"verdict"`   // OK | UNKNOWN | FAILED, same three values
    Result   string  `json:"result"`    // "ok" | "stale" | "unknown" — the per-token result from #10
    SentAt   int64   `json:"sent_at_ms"`
    CRC      uint32  `json:"crc"`
}
```

The consumer side of `internal/testutil/loadgen` gains `W` worker goroutines that fetch, do fake
work, and settle with a configurable verb mix — every fetch and every settle recorded before the
request goes out, exactly as #8's publishers do.

New reconciler rules, joining the settle ledger against post-recovery state and the `events` table:

| Rule | Assertion | Invariant |
|---|---|---|
| `ACK-REDELIVERED` | no `(consumer, seq)` with an `OK` ack has a `msg.deliver` event at a later `id`, absent an intervening `consumer.seek`/`dlq.redrive` | **I3** |
| `ACK-RESURRECTED` | no `(consumer, seq)` with an `OK` ack has a live `deliveries` row after recovery | **I3** |
| `ATTEMPT-OVERRUN` | `max(attempt)` observed by the workers ≤ `max_deliver` for every pair | **I4** |
| `DEAD-CONSERVED` | every `OK` term, and every pair whose events reach `msg.dead`, has exactly one DLQ message carrying that origin — and no pending row | **I8** |
| `DEAD-ORPHAN` | no DLQ message exists whose origin pair never reached `msg.dead` | **I8** |
| `UNNAMED-DUPLICATE` | every `msg.deliver` with `attempt > 1` is preceded, for that pair, by `msg.nak`, `msg.timeout` or `recovery.reclaimed` | **I9** |
| `TOKEN-FORGERY` | no settle recorded `ok` for an attempt other than the row's live attempt | **I7** |

`UNKNOWN` settles assert nothing individually — an ack in flight at the kill may or may not have
landed — but the **survivorship guard** from #8 §5 is extended: across a sweep, at least one
`UNKNOWN` ack must be found applied and at least one found not applied. Both outcomes must be
observed or the window is not real and the matrix is testing nothing.

### 4. The crash matrix

```go
type Scenario struct {
    Name       string          // "K07-settle-after-commit"
    Faults     string          // MESSQ_FAULTS expression
    Durability []string        // {"full"} | {"full","relaxed"}
    Profile    loadgen.Profile // PublishOnly | PublishConsume | Poison | Mixed | Purge
    Expect     []string        // oracle rules that MUST be evaluated (not merely pass)
    Repeat     int             // per lane; scaled by -matrix.repeat
}
```

A scenario is one cycle: start the daemon with the fault expression → run the profile → the point
fires (`kill`, or an injected error) → observe the death (or the latch) → restart → reconcile ledger
↔ state → `verify --deep` → `PRAGMA integrity_check`.

| K02 | `store.tx.before_commit=1*kill` | Mixed | a reply sent before the commit (`OK-LOST`) |
| K03 | `store.tx.after_commit_before_reply=1*kill` | Mixed | UNKNOWN handled as FAILED; dedup retry returning a new seq |
| K04 | `store.wal.fsync=1*error(EIO)` | Mixed | fsyncgate: a retried commit, or a write after the latch |

### 5. ENOSPC on a real filesystem

Neither `statfs` mocking nor a small `max_bytes` proves anything here: the promise is about what the
*kernel* does when the writes stop fitting. A loopback ext4 image is small, cheap and works with
`sudo` on a stock GitHub-hosted runner.

```bash
truncate -s 96M "$IMG"
mkfs.ext4 -q -F -m 0 -O ^has_journal -b 1024 "$IMG"   # -m 0: no root reserve; small blocks: fine-grained fill
sudo mount -o loop,noatime "$IMG" "$MNT" && sudo chown "$(id -u):$(id -g)" "$MNT"
messq serve --data-dir "$MNT/messq" --durability full --min-free-bytes 8MiB &
```

**Soft ENOSPC (the guarded path — this is the contract):**

1. Baseline: publish, consume and ack normally; record the pending set and the DLQ depth.
2. Squeeze: grow a ballast file (`fallocate`) until free space drops below `--min-free-bytes`.
3. Within one statfs-cache interval, assert **all** of:
   - publishes are rejected with `507 disk_full` and the typed error code — never a 500, never a hang;
   - **acks, naks, extends, terms and dead-letter copies all still succeed**, and the pending set
     drains to zero while the disk is full — the §4.5 promise, and the whole reason the guard exists;
   - a poison message still reaches the DLQ (a dead-letter is a *write*, and it must be on the
     protected side of the guard);
   - no latch: `messq_readonly == 0`, zero `storage.fatal`, the process is alive;
   - `/readyz` still returns 200 — readiness is deliberately **not** coupled to disk pressure
     (§4.5's RabbitMQ-on-Kubernetes lesson), and a test asserting the orchestrator would not kill us
     here is the point of that decision;
   - exactly one `disk.degraded` event, not one per rejected publish.
4. Release the ballast. Publishes resume **without a restart**, within
   `statfs-cache + one janitor tick`; the resume latency is asserted with a bound and *recorded*;
   a matching `disk.degraded state=ok` event is emitted once.
5. Stop; `verify --deep` and `integrity_check` clean; reconcile: **zero `OK` lost**, and every
   `507` classified `FAILED` and absent (the `FAILED-PRESENT` rule from #8 — a rejected publish that
   actually landed would be the worst outcome here).

**Hard ENOSPC (the guard deliberately disabled, `--min-free-bytes=0`):** fill until `COMMIT` itself
fails. Assert exactly one `storage.fatal class=enospc`, the latch, `ErrReadOnly` on every write
including acks, reads still working (`peek`, `trace`, `/metrics`, `verify`), exit 74 after
`--fatal-drain`; then free space, restart, and assert recovery is clean and no `OK` was lost. Every
request in the doomed batch must have received `ErrCommitUnknown` → `UNKNOWN`, **never** `FAILED`
(#6 §10.2: a failed commit's fate is unknown, and telling a client "it did not happen" is the one
answer we may never give).

**A measurement, not just an assertion:** the soft run records how many bytes were actually required
to drain N pending deliveries into the DLQ. That number is the sizing rule for `--min-free-bytes`
and belongs in `docs/OPERATIONS.md` (#35) instead of the current round 256 MiB guess.

### 6. EIO, and proving the daemon stopped writing

Two mechanisms, deliberately both:

- **Go level** (`store.wal.fsync=1*error(EIO)`) — runs on every PR, no privileges, exact timing.
- **Kernel level** (nightly, privileged): a `dm-flakey`/`dm-error` mapping over the loop device,
  flipped to erroring writes mid-load, so the error arrives through the real path with real errno
  propagation through `modernc.org/sqlite`. (This is also why #5 refuses to set `mmap_size`: an
  mmap read fault is a `SIGBUS`, not an `EIO` the store can latch on.)

```bash
LOOP=$(sudo losetup -f --show "$IMG"); SZ=$(sudo blockdev --getsz "$LOOP")
echo "0 $SZ linear $LOOP 0" | sudo dmsetup create messqfail          # healthy
# ... load ...
echo "0 $SZ error"          | sudo dmsetup load messqfail            # now every write fails
sudo dmsetup suspend --noflush --nolockfs messqfail && sudo dmsetup resume messqfail
```

The assertions the summary demands — *"a test asserts the daemon cannot keep writing after a failed
sync"* — are three, in increasing strength:

1. **API level**: every subsequent write, *including acks*, returns `503 read_only`; reads keep
   answering; `messq_readonly == 1`; `messq_commit_errors_total{class="eio"} == 1`.
2. **Attempt level**: the commit was attempted **exactly once**. A counter around the commit call
   asserts `1`; there is no retry path, and D4 says there must never be one.
3. **Byte level (the real one)**: snapshot `(size, mtime, sha256)` of `messq.db`, `-wal` and `-shm`
   immediately after the latch; then hammer the API with 1 000 publishes and acks for two seconds;
   re-snapshot. **Byte-identical.** Under `strace -f -e trace=pwrite64,fdatasync,fsync -p <pid>`,
   zero write syscalls against any data-dir fd after the latch. An API that says "read-only" while
   the process is still writing is exactly the failure mode fsyncgate is about, and only the byte
   snapshot can tell the difference.

A read-side `EIO` (on the `ro` pool) is a separate scenario and a *different* contract: it must fail
that one query with a 500 and increment a metric, and must **not** latch the writer.

### 7. Clock scenarios

`libfaketime` is not usable here and the reason should be in a comment so nobody tries: our binary
is `CGO_ENABLED=0` and reads the clock through the vDSO, so an `LD_PRELOAD` shim never sees it.
Instead the fault build installs a wrapping clock on #3's seam:

```
MESSQ_FAULT_CLOCK="30s:+1h,90s:-1h"   # at t+30s step wall clock forward 1h; at t+90s back
```

The wrapper offsets **wall-clock reads only**; monotonic durations (timers, the commit window, the
sweep ticker, long-poll deadlines, HTTP timeouts) are untouched — which is precisely the distinction
under test. A privileged VM lane that moves the real `CLOCK_REALTIME` is a nice-to-have; the seam is
the honest primary, because it tests the code path the daemon actually uses.

The contract is *bounded, named, observable damage* — not "nothing happens". `visible_at` is a
wall-clock millisecond timestamp (§4.2), so a forward jump genuinely does expire every lease, and
pretending otherwise would be the dishonest test.

| Scenario | Assertion |
|---|---|
| **+1 h forward, under load** | every in-flight lease expires; drain rate is capped at `--sweep-batch × --sweep-catchup` per tick; **`attempts` is unchanged for every row** (before/after column diff — D6); **no message dies early** (`msg.dead` count matches the pre-jump projection); exactly one WARN with `clock_step_ms ≈ 3600000`; `detail.clock_step_ms` is stamped on the affected `msg.timeout` events so `trace` explains the burst; redelivery times spread across `[0.8, 1.2] × backoff[0]` and the distribution is not degenerate; I4, I5, I9 hold throughout |
| **−1 h backward** | **nothing expires**; stored timestamps are non-decreasing (#6's `batchNow()` clamp); `events.id` order still agrees with `ts` order up to ties; `messq trace` renders no negative `waited`/`held_ms` value — a rendering bug class that only a backwards clock finds |
| **±1 year** | same two contracts at a magnitude that overflows nothing; `max_age_ms` retention does not mass-delete a live stream (it may legally expire messages, but not ones holding delivery rows — `retention.blocked` fires instead) |
| **Jump during recovery** | `MESSQ_FAULT_CLOCK="0s:+1h"` with `store.recovery.mid_reclaim`: reclaim jitter still lands rows within `[now, now+--reclaim-jitter]`, `attempts` untouched, `recovery.reclaimed` count correct |
| **Jump during a sweep** | forward step between `store.sweep.after_scan` and the commit: rows decided against a stale `now` are still legal (they redeliver, they do not die) |
| **NTP slew (±2 s, gradual)** | the 5 s step detector does **not** fire — a negative test, because a detector that cries at every NTP correction is a detector operators mute |
| **Long-poll across a jump** | a `wait_ms=5000` fetch returns at its monotonic deadline ±1 tick regardless of a ±1 h wall step; the commit-window histogram records no negative or absurd durations |

### 8. Client disconnect and slow consumers

| Test | Setup | Assertion |
|---|---|---|
| `TestDisconnectParked` | 200 clients parked in long-poll; 100 closed with `SetLinger(0)` (RST) | waiter gauge returns to 0, goroutine count returns to baseline, driver+daemon fd counts flat, **zero delivery rows created** (nothing was claimed), survivors still wake on the next publish |
| `TestDisconnectAfterClaim` | `api.fetch.before_send=pause(2s)`; client closes during the pause | the claim is committed and `attempts` is spent (D6); exactly one `msg.timeout` at `ack_wait`; redelivery is `attempt 2` with `cause=timeout`; `messq_redelivered_total{cause="timeout"}` +1; `trace` names the cause — a duplicate with a name is the product working (I9) |
| `TestDisconnectMidResponse` | `api.fetch.mid_write=1*pause(2s)`, client closes mid-body | same as above; no partial state, no leaked waiter, no panic in the handler |
| `TestPublishDisconnectMidBody` | close after headers, before the body completes | `400` (or a transport error), classified `FAILED`, **absent** after recovery |
| `TestPublishDisconnectBeforeReply` | close after the full body, before the response | committed (#6 §10.1: the batch uses `context.Background()`, so one client disconnecting cannot abort 255 siblings); `UNKNOWN`; a retry with the same `Messq-Msg-Id` returns `duplicate:true` **with the original seq** |
| `TestNeverAckingConsumer` | 5 000 messages, `max_ack_pending=1000`, a worker that fetches and never settles | pending caps at exactly 1000 (**I5**) and never exceeds it; `flow.blocked` is rate-limited, not one per attempt; RSS and goroutine count flat over the run; a **second** consumer on the same stream is unaffected; every message eventually dead-letters after exactly `max_deliver` **`msg.deliver` events** (counted from events, not read off a row) |
| `TestSlowConsumer0_9x` | acks at `0.9 × ack_wait` | zero duplicates, zero stale acks, zero timeouts — the "your `ack_wait` is fine" baseline |
| `TestSlowConsumer1_1x` | acks at `1.1 × ack_wait` | `messq_stale_acks_total > 0`; every late ack gets `409 stale_ack` (**I7**) and a WARN event; **no acked message is redelivered** (**I3**); every duplicate has a named cause (**I9**); this is the exact signature `doctor` (#30) tells operators to look for |

Where the clock can be faked in-process these run under `testing/synctest` (§11: no `time.Sleep`
outside soak); the RST/fd-leak cases need a real socket and a real subprocess, and say so in a
comment.

### 9. Sabotage: proving the harness can fail

A green suite that has never been watched fail is decoration. Each sabotage is a one-line defect
behind `//go:build messq_sabotage`, selected by `MESSQ_SABOTAGE=<name>`, and each is **mapped to the
named detector that must catch it**. The mapping itself is the test: `TestSabotageMatrix` builds
each sabotage binary, runs its detector lane, and fails if the lane passes.

| Sabotage | Defect | Must be caught by |
|---|---|---|
| `sync_off` | force `PRAGMA synchronous=OFF` on the rw pool | (a) #5's pragma readback refuses to start; (b) with the readback also disabled, the **fsync-accounting oracle** below; (c) the optional LazyFS lane shows `OK-LOST` |
| `retry_commit` | retry a failed commit once | `fs-fault` EIO: commit-attempt counter ≠ 1 |
| `write_after_latch` | let acks through after `storage.fatal` | EIO byte-level snapshot differs |
| `attempts_after_reply` | increment `attempts` after the fetch response instead of before | K06 → `ATTEMPT-OVERRUN` / I4 |
| `reply_before_commit` | send the publish reply before `tx.Commit()` | K02 → `OK-LOST` |
| `dlq_outside_tx` | copy to the DLQ in a second transaction | K09 → `DEAD-CONSERVED` (a half-dead message) |
| `enospc_total_bytes` | disk guard compares total instead of free bytes | soft-ENOSPC lane latches instead of degrading |
| `no_monotone_clamp` | drop #6's `batchNow()` clamp | backwards-clock test sees a negative `held_ms` |
| `ack_no_fence` | ignore the attempt in the ack token | `TOKEN-FORGERY` / I7 (also caught by #13 — belt and braces) |

**The fsync-accounting oracle** deserves its own paragraph, because it is the only thing that
catches `sync_off` under SIGKILL: a process kill leaves the page cache intact, so a
`synchronous=OFF` daemon loses nothing when killed and every existing test stays green. The oracle
counts syscalls instead of trusting outcomes — `strace -f -c -e trace=fdatasync,fsync` (or an eBPF
counter) around a run, asserting `fdatasync_count ≥ commit_count ≥ 1` under `--durability=full`.
Under `sync_off` the count collapses to roughly zero while acks keep flowing, and the lane fails
naming the ratio. The same measurement doubles as a lying-write-cache cross-check when paired with
#8's fsync-latency probe: syncs that complete far faster than the device's physical sync latency
invalidate a durability claim (handed to #30 as a `doctor` finding).

### 10. Edge cases and how they are handled

| # | Edge case | Handling |
|---|---|---|
| 1 | **A lane passes by skipping everything** — no loop device, no `dmsetup`, no `sudo` | every skip is recorded with a reason and the lane fails below its declared executed-scenario floor. `fs-fault` reporting "0 run, 12 skipped" must be red. This is the most likely way this issue silently stops working. |
| 2 | **Loop device / mount leaked by a failed test** | `t.Cleanup` does `umount -l`, `dmsetup remove --retry`, `losetup -d`, deletes the image; plus a pre-flight sweep of stale `messq-fault-*` mounts at lane start. A leaked loop device breaks every later run. |
| 3 | **The fault point never fired** | The fsynced activation log is checked after every scenario; a point that did not fire fails as `FAULT-NOT-REACHED`, never passes quietly. |
| 4 | **`panic` in an HTTP handler does not kill the process** — `net/http` recovers per connection | documented in the grammar table: use `kill` for process death; `panic` exercises #6's recover-and-latch path inside `Apply`. |
| 5 | **ENOSPC while the WAL grows, not the DB** | Both live on the same filesystem and both are covered; `store.checkpoint.mid` is run *while* squeezed, because a `TRUNCATE` checkpoint needs space and failing it must degrade, not corrupt. |
| 6 | **ENOSPC at startup** — cannot write `clean_shutdown=0`, cannot checkpoint | fail loudly naming the data dir and free bytes; never open for business half-recovered. Asserted with an image filled before start. |
| 7 | **`relaxed` is not weaker under SIGKILL** | Same rule as #8 edge case 9: a process kill leaves the page cache intact, so `relaxed` must lose nothing either. Loss is legal only under real power loss (the non-gating LazyFS lane). No oracle path here permits loss in either mode. |
| 8 | **Torn WAL tail** | Free with SQLite: replay stops at the last frame with a valid checksum. A scenario additionally truncates `-wal` mid-frame *after* a kill and asserts recovery succeeds, `integrity_check` is clean, and only `UNKNOWN` records may have vanished. `-wal`/`-shm` are never deleted before a restart. |
| 9 | **Matrix runtime explodes** | Lanes are fixed, named subsets (§11), never randomly sampled — a scenario that only runs sometimes is one nobody trusts. |
| 10 | **Fault builds leaking into a release** | `go tool nm` symbol check in `make release-gate` (run by #36 on the artifact); goreleaser never sets the tag; `/v1/info` and `messq_build_info` report it at runtime. |
| 11 | **`cgosqlite` escape hatch drift** | The matrix runs the default `modernc` build; a weekly job runs the smoke subset with `-tags cgosqlite`, because errno propagation is exactly where the drivers may differ and D1 keeps that hatch alive. |
| 12 | **`strace` unavailable / `ptrace_scope=3`** | The fsync oracle degrades to an eBPF counter, then to a skip — **with the lane floor enforcing that it ran somewhere**. It gates the release; it may not silently vanish. |
| 13 | **Poison profile reaching the DLQ needs time** | Matrix consumers use `ack_wait=250ms`, `backoff=[0]`, `max_deliver=3`, so a message dies in under a second. Timing knobs are config, not sleeps. |
| 14 | **A scenario finds a real product bug at M8** | Expected — the reason the matrix precedes the tag. The fix lands in the owning issue; this PR carries the failing test and the cross-reference, and `docs/fault-matrix.md` records the finding. |

## Acceptance criteria

- [ ] `internal/fault` implements the `[<percent>%][<count>*]<verb>[(<args>)]` grammar with verbs
      `kill`, `exit`, `panic`, `error`, `sleep`, `pause`, `off`; draws are seeded by
      `MESSQ_FAULT_SEED`; an unknown point name or unparsable expression is a **startup error**.
- [ ] A fault build announces itself: WARN on `server.start`, `faults_active` in `/v1/info`, and
      `messq_build_info{faults="on"}`.
- [ ] The activation log is **fsynced before a `kill` action executes**, and every scenario asserts
      its point actually fired (`FAULT-NOT-REACHED` is a failure, not a pass).
- [ ] Production builds contain no fault code: `go tool nm dist/messq` shows zero `internal/fault`
      symbols, and a publish-path benchmark shows no measurable delta versus a pre-issue baseline.
- [ ] The registry is the single declaration site; `TestNoUndeclaredPoints` (AST walk, literals only)
      and `TestEveryPointIsExercised` both pass, and every point reserved by #5, #6, #7, #9, #10,
      #11, #12, #14, #15, #19 and #27 is wired and firing.
- [ ] `docs/fault-matrix.md` is `go:generate`d from the registry and the scenario table; CI fails on
      any diff against a regeneration.
- [ ] The ledger and reconciler are extended to settles; `ACK-REDELIVERED`, `ACK-RESURRECTED`,
      `ATTEMPT-OVERRUN`, `DEAD-CONSERVED`, `DEAD-ORPHAN`, `UNNAMED-DUPLICATE` and `TOKEN-FORGERY`
      are implemented and each demonstrated to fire by a sabotage or fixture case.
- [ ] The survivorship guard covers settles: across a sweep, at least one `UNKNOWN` ack is observed
      applied **and** at least one observed not applied.
- [ ] Scenarios K01–K18 exist, are green across `full` and `relaxed`, and every cycle ends with
      `messq verify --deep` clean and `PRAGMA integrity_check` clean.
- [ ] **Soft ENOSPC on a real loopback ext4**: publishes are rejected with the typed `507 disk_full`
      while acks, naks, terms, extends **and dead-letter copies keep succeeding** and the pending set
      drains to zero; no latch, no `storage.fatal`, `/readyz` still 200; exactly one `disk.degraded`
      event; freeing space resumes publishes **without a restart** within an asserted bound; the
      ledger shows zero `OK` lost and no `507` present.
- [ ] The bytes required to drain the pending set into the DLQ while full are **measured and
      recorded** as the `--min-free-bytes` sizing rule.
- [ ] **Hard ENOSPC** (guard disabled) latches exactly once with `class=enospc`, refuses all writes
      including acks, keeps reads working, exits 74 after `--fatal-drain`, and recovers cleanly with
      zero `OK` lost; every request in the doomed batch is `UNKNOWN`, never `FAILED`.
- [ ] **EIO** (Go-level and real `dm-error`) latches read-only, and the daemon is proven not to write
      afterwards at the **byte level**: `messq.db`, `-wal` and `-shm` are byte-identical after two
      seconds of hammering, and zero write syscalls against data-dir fds are observed.
- [ ] The commit is attempted **exactly once** on failure — asserted by a counter; a sabotage build
      that retries is caught.
- [ ] A read-side `EIO` fails one query and does **not** latch the writer.
- [ ] The §7 clock table passes end to end: a forward step burns no `attempts`, kills nothing early,
      logs exactly one WARN with `clock_step_ms`, stamps affected events, and drains at the capped
      rate; a backward step expires nothing and produces no negative rendered duration; an NTP-sized
      slew does **not** trip the detector; a `wait_ms` long-poll is unaffected by either.
- [ ] The §8 disconnect/slow-consumer table passes, including flat goroutine, fd and RSS counts for a
      never-acking consumer at `max_ack_pending`, and `409 stale_ack` observed at 1.1× `ack_wait`
      with no acked message ever redelivered.
- [ ] `TestSabotageMatrix` builds every sabotage variant and fails if its mapped detector lane passes;
      `sync_off` is caught by pragma readback **and** by the fsync-accounting oracle.
- [ ] Every lane enforces a minimum executed-scenario floor: a lane that skips everything is red.
- [ ] CI lanes `fault-smoke`, `crash-matrix`, `crash-matrix-full`, `fs-fault`, `clock-fault` and
      `sabotage` exist under those names, publish `fault-report.json`, and are listed as gates in
      #36's release checklist; `lazyfs`, if added, is marked non-gating.
- [ ] No `time.Sleep` outside the deliberately-real-time subprocess paths (`forbidigo` clean); those
      paths carry a comment saying why `synctest` cannot apply.

## Test plan

The apparatus is code and is tested like code; the scenarios are the deliverable and are proved by
being **made to fail on purpose** (§11's ground rule, D13's discipline).

**Unit — `internal/fault`**
- Grammar table test: one case per verb, percent-only, count-only, combined, multiple points,
  whitespace, empty value, unknown verb, unknown point, bad duration, bad errno — each parses to the
  expected plan or produces a startup error naming the offending clause.
- `FuzzParseFaults`: no input panics; anything that parses round-trips to the same plan.
- Seeded determinism: one `MESSQ_FAULT_SEED` reproduces a `50%` point's activation sequence over
  10 000 evaluations; `3*` fires exactly three times, including across concurrent callers (`-race`).
- Activation log: a `kill` action's record is on disk before the signal (fake-syncer ordering probe,
  since the real one cannot report after `SIGKILL`).

**Meta-tests**
- `TestNoUndeclaredPoints` (AST walk; a non-literal fault name is a hard error),
  `TestEveryPointIsExercised` (coverage map), `TestNoFaultSymbolsInProductionBuild` (`go tool nm`),
  `TestFaultMatrixDocIsGenerated` (regenerate and diff).

**Reconciler (fixture-driven, no daemon)**
- One violating fixture per new rule (`ACK-REDELIVERED`, `ACK-RESURRECTED`, `ATTEMPT-OVERRUN`,
  `DEAD-CONSERVED`, `DEAD-ORPHAN`, `UNNAMED-DUPLICATE`, `TOKEN-FORGERY`), built by direct SQL into a
  migrated schema plus a synthetic ledger — *a rule that cannot be made to fire is not a rule* — and
  a clean fixture that triggers none of them.

**Crash matrix (`test/matrix`)**
- `TestMatrix` — K01–K18, parameterised by subset flag; the PR, main and nightly lanes are this test
  with different `-matrix.subset`/`-matrix.repeat`.
- `TestMatrixArtifacts` — force one violation; assert the artifact bundle and the one-line
  reproduction command.
- `TestTornWalTail` — kill, truncate `-wal` mid-frame, restart: recovery succeeds,
  `integrity_check` clean, no `OK` lost.

**Filesystem lane (`test/fsfault`, privileged, nightly)** — each registers its skip reason and the
lane asserts its executed floor.
- `TestENOSPCGuarded` (the six-step soft scenario incl. the drain-bytes measurement),
  `TestENOSPCUnguarded` (latch → exit 74 → restart → recovery), `TestENOSPCAtStartup`,
  `TestENOSPCDuringCheckpoint`.
- `TestEIOOnCommit` (`dm-error` flip; the three-level write-after-latch assertion),
  `TestEIOOnRead` (no writer latch), `TestFsyncAccounting` (`full` vs `relaxed` vs `sync_off`).

**Clock lane (`test/clockfault`)**
- One test per §7 row against a real subprocess with `MESSQ_FAULT_CLOCK`; forward/backward variants
  also run in-process under `testing/synctest` on the PR lane.
- `TestBackwardsJumpRendersSanely` drives `messq trace` through #20's golden renderer and fails on
  any negative duration — the bug class fake-clock unit tests structurally cannot see.

**Disconnect / slow consumer (`test/faultclient`)**
- The §8 table: `synctest` where the clock can be faked, real sockets with `SetLinger(0)` for the RST
  and fd-leak cases. After every test: goroutine-stack diff, `/proc/self/fd` count on both sides,
  daemon RSS delta under a threshold.

**Sabotage (`test/sabotage`, weekly)**
- `TestSabotageMatrix` — build each variant, run its mapped detector lane, fail if the lane passes.
  The mapping table is the test's data, so a sabotage without a detector fails to compile.

**Property / model reuse**
- #13's `rapid` suite gains a `fault` action drawing from a small subset of Go-level points
  (`error(EIO)` on commit, `sleep` on the settle path), with all §5.2 invariants checked after every
  action as usual; failfiles land in the existing regression corpus.

**Explicitly not tested here**: fuzz corpora and the soak run (#33), schema-upgrade faults (#34),
throughput regressions (#31), power-loss data loss as a gate (D13 — optional non-gating lane only).
