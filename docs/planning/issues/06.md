## Context

Every durable state change in messq goes through **exactly one goroutine**. PLAN.md §3.2 fixes
the goroutine census: `writer` is the sole owner of the read-write SQLite connection; HTTP
handlers, the sweeper and the janitor never touch it directly, they send commands. That single
constraint buys four things at once:

1. **Group commit** (PLAN §4.3, D4) — N concurrent publishes/acks share one fsync, which is the
   only reason `--durability=full` is affordable at the ≥ 5 000 msg/s M2 gate (PLAN §12).
2. **No `SQLITE_BUSY` class at all** — writes are serialised in the application, not fought over
   with busy timeouts (D1, PLAN §4.1).
3. **Atomic multi-table transitions** — a state change, its delivery bookkeeping, its DLQ copy
   and its audit event row are one transaction (D1 reason 1, D11): "the audit trail cannot
   disagree with reality" becomes a structural property rather than a promise.
4. **Determinism for tests** — concurrency lives at one channel boundary, so `-race`,
   `testing/synctest` and the property suite (#13) cover it completely.

This issue builds that engine and nothing else: the bounded command channel, the batching loop,
the one-transaction-per-batch commit, the reply-only-after-commit discipline, the two named
durability modes with pragma enforcement, and the **fsyncgate rule** — a commit error is fatal
and never retried (D4, PLAN §4.3/§4.5).

Governing PLAN.md sections: **§4.3 Durability modes and group commit**, **§3.2 Goroutine
census**, **§4.1 Engine and connections**, **D4 (fsync policy)**, **D1 (storage engine)**,
**§12 Performance targets**.

What it unlocks: #7 (publish is the first real command), #8 (the crash harness needs a real
`serve` write path plus the after-commit-before-reply window to kill in), and transitively every
write path in M3 — claim (#9), settle (#10), sweeper (#11), dead-lettering (#12) — plus the
event fan-out (#19), the commit histograms in the metric set (#21), retention/disk safety (#27)
and the fault-point matrix (#32). Those later issues add *commands*; none of them should need to
change this engine.

## Scope

**In scope**

- `internal/store.Writer`: the writer goroutine, sole holder of the `rw` `*sql.DB`
  (`MaxOpenConns(1)`, `_txlock=immediate`) opened by #5.
- The `Cmd` interface and the `Do(ctx, cmd) (Result, error)` submission API — the seam every
  later write path plugs into.
- Bounded command channel with blocking (never dropping, never growing) backpressure.
- Batch closing rules: `--commit-window` (2 ms), `--commit-max-batch` (256),
  `--commit-max-bytes` (proposed byte budget), whichever fires first.
- One `BEGIN IMMEDIATE … COMMIT` per batch; per-command `SAVEPOINT` isolation so one rejected
  command cannot poison its batch.
- Reply-after-commit ordering: no caller observes a result that is not durable.
- Durability modes `full` / `relaxed`: flag + env, pragma demand + read-back verification,
  refuse-to-start on mismatch, the loud `relaxed` startup banner.
- The fsyncgate latch: classify commit errors, latch read-only exactly once, emit
  `storage.fatal` at ERROR, close the rw pool so further writes are structurally impossible,
  surface a fatal signal for the process to exit non-zero after a short drain, **never retry**.
- `messq_commit_batch_size` and `messq_commit_duration_seconds` histograms behind a small
  observer seam.
- The committed-event sink seam (post-commit hand-off only), with a no-op default.
- Test-only fault hook names reserved for #32: `store.tx.before_apply`, `store.tx.before_commit`,
  `store.tx.after_commit_before_reply`.
- Writer `Close(ctx)` drain semantics (the mechanism; signal handling is #17's).

**Out of scope**

- Any actual command implementation: publish/dedup/peek → **#7**; consumer CRUD, top-up and
  claim → **#9**; ack/nak/term/extend → **#10**; timeout sweeper → **#11**; dead-lettering →
  **#12**.
- Schema, migrations, pool construction, flock, permission checks, startup recovery and lease
  reclamation — all delivered by **#5**; this issue consumes them.
- Event vocabulary, in-transaction event rows, slog handlers and sampling → **#19**. Here events
  are opaque values carried from `Apply` to a sink.
- The full metric set, registry ownership, alert rules and golden exposition → **#21** (which
  must include the two histograms registered here).
- Signal handling, graceful drain orchestration, `wal_checkpoint(TRUNCATE)`, `clean_shutdown`
  marking and the systemd unit → **#17**.
- WAL checkpoint scheduling, incremental vacuum, `--min-free-bytes` proactive disk guard →
  **#27**.
- The `messq_fault` build tag, the `MESSQ_FAULTS` grammar, real ENOSPC/EIO on a loopback
  filesystem → **#32** (this issue only reserves the hook points and ships a Go-level seam).
- SIGKILL loops, the three-valued ledger oracle and the measured D1 throughput gate → **#8**.
- Adaptive commit linger, lone-publisher fast path, priority lanes for settle commands, request

## Design proposal

Code below is a starting point, not a mandate; names and shapes may change as long as the
properties in "Acceptance criteria" hold.

### 1. Package surface

```go
// internal/store/writer.go

// Cmd is one unit of durable work. Implementations live in the feature issues
// (#7 publish, #9 claim, #10 settle, #11 sweep, #12 dead-letter).
type Cmd interface {
	// Kind is a closed-set label used for metrics and log fields. Never a message id.
	Kind() CmdKind

	// Apply runs INSIDE the batch transaction, on the writer goroutine.
	// Contract:
	//   - MUST NOT block, sleep, call time.Now, do network or file I/O, or call Writer.Do.
	//   - MUST use only tx for storage access.
	//   - now is the single batch timestamp; all rows written by the batch share it.
	//   - A returned CmdError is a business rejection: the command's writes are rolled
	//     back to its savepoint, siblings still commit.
	//   - Any other error aborts the whole batch (see §6).
	Apply(ctx context.Context, tx *sql.Tx, now time.Time) (Result, []obs.Event, error)

	// Bytes is an upper-bound estimate of the payload this command will write, used
	// for the batch byte budget. 0 for metadata-only commands.
	Bytes() int
}

// Result is command-specific; typed wrappers assert it at the call site, e.g.
//   func (s *Store) Publish(ctx context.Context, p PublishArgs) (PublishResult, error)
// keeps the engine monomorphic while callers stay typed.
type Result any
```

> Generic alternative considered: `func Do[R any](ctx, *Writer, TypedCmd[R]) (R, error)`. Rejected
> for now — it forces the queue element to be an interface anyway and complicates the fault
> hooks. Typed wrappers over `any` are two lines each and keep one queue type.

```go
type Writer struct {
	rw     *sql.DB        // the ONLY reference in the process; #5 hands it over at construction
	clock  clock.Clock    // #3 seam; no time.Now anywhere below
	cfg    Config
	ch     chan *request  // bounded, cap = cfg.QueueDepth
	obs    CommitObserver // metrics seam (§8)
	events obs.Sink       // post-commit fan-out seam (§8), NopSink by default
	hooks  hooks          // test/fault seam, no-ops in production builds

	fatal   atomic.Pointer[FatalError]
	fatalC  chan *FatalError // buffered 1; the process supervisor selects on it
	closing atomic.Bool
	done    chan struct{} // closed when run() has returned
	lastNow atomic.Int64  // monotonic guard for batch timestamps (§10.6)
}

type Config struct {
	Durability     Durability    // full | relaxed
	CommitWindow   time.Duration // 2ms; 0 = commit whatever is queued immediately
	CommitMaxBatch int           // 256
	CommitMaxBytes int64         // 8 MiB
	QueueDepth     int           // 2048
	FatalDrain     time.Duration // 2s: how long we keep answering reads before exit
}

func NewWriter(rw *sql.DB, clk clock.Clock, cfg Config, opts ...WriterOption) (*Writer, error)

func (w *Writer) Do(ctx context.Context, cmd Cmd) (Result, error)
func (w *Writer) Fatal() <-chan *FatalError
func (w *Writer) Close(ctx context.Context) error // drain, final commit, stop; idempotent
```

`NewWriter` verifies its preconditions and refuses otherwise (they are cheap and they are the
whole safety story): `rw.Stats().MaxOpenConnections == 1`, `PRAGMA journal_mode` reads `wal`,
and `PRAGMA synchronous` reads back the value `cfg.Durability` demands (§5).

**Structural enforcement of "exactly one writer":** `#5`'s `Store` keeps the rw handle private
and exposes only `Store.RO() *sql.DB` and `Store.Writer() *Writer`. An architecture test walks
the package graph and fails if any package outside `internal/store` can reach a read-write
handle.

### 2. The batch loop

```go
func (w *Writer) run() {
	defer close(w.done)
	batch := make([]*request, 0, w.cfg.CommitMaxBatch)
	timer := w.clock.NewTimer(0)
	if !timer.Stop() { <-timer.C() }

	for {
		first, ok := <-w.ch          // block: a batch is never empty
		if !ok { return }
		batch, bytes := append(batch[:0], first), int64(first.cmd.Bytes())

		if w.cfg.CommitWindow > 0 {
			timer.Reset(w.cfg.CommitWindow)
		fill:
			for len(batch) < w.cfg.CommitMaxBatch && bytes < w.cfg.CommitMaxBytes {
				select {
				case r, ok := <-w.ch: // drain whatever is already queued, then linger
					if !ok { break fill }
					batch = append(batch, r)
					bytes += int64(r.cmd.Bytes())
				case <-timer.C():
					break fill
				}
			}
			timer.Stop() // and drain if it already fired
		} else {
			// CommitWindow == 0: same loop with a `default:` arm instead of the timer —
			// take everything already queued, then commit without lingering.
			batch, bytes = w.drainAvailable(batch, bytes)
		}
		w.commitBatch(batch)
	}
}
```

Properties that fall out of this shape, and are worth stating because tests assert them:

- **A batch is never empty** — the loop blocks for the first command, so we never fsync nothing.
- **Lingering only happens when the queue is empty.** The `select` prefers the channel; the timer
  only wins when there is nothing left to drain. Under load the queue refills during the previous
  commit's fsync, so batching is **self-clocking** and the window barely matters; at low rate a
  lone caller pays at most `--commit-window`.
- **`--commit-window=0` is a documented low-latency setting**: commit whatever is queued right
  now. Still batches under load, for the self-clocking reason above.
- The window is measured on the `Clock` seam, so `testing/synctest` drives it deterministically
  and there is no `time.Sleep` anywhere.

Timeline of two commits under load (illustrative):

```
t=0.0ms  P1 arrives  → batch opens
t=0.3ms  P2,P3 arrive (drained, no linger)
t=0.4ms  queue empty → linger starts
t=2.4ms  window closes, batch = {P1,P2,P3}
t=2.4ms  BEGIN IMMEDIATE … COMMIT  ── one fsync ──▶ returns t=3.6ms
         A1,A2,P4,P5 queued while the fsync was in flight
t=3.6ms  replies to P1..P3, events published
t=3.6ms  next batch opens with 4 already-queued commands → committed immediately
```

### 3. Commit sequence (the ordering is the crash-safety story)

```go
func (w *Writer) commitBatch(batch []*request) {
	if fe := w.fatal.Load(); fe != nil { w.failAll(batch, fe.asDoError()); return }

	now := w.batchNow()                 // single timestamp, monotonic-guarded (§10.6)
	ctx := context.Background()         // NOT a caller's ctx: see §10.1
	tx, err := w.rw.BeginTx(ctx, nil)   // _txlock=immediate ⇒ BEGIN IMMEDIATE
	if err != nil { w.abortBatch(batch, "begin", err); return }

	var events []obs.Event
	for i, r := range batch {
		if _, err := tx.ExecContext(ctx, fmt.Sprintf("SAVEPOINT c%d", i)); err != nil {
			w.abortBatch(batch, "savepoint", err); return
		}
		res, evs, err := r.cmd.Apply(ctx, tx, now)
		switch {
		case err == nil:
			_, err = tx.ExecContext(ctx, fmt.Sprintf("RELEASE c%d", i))
			if err != nil { w.abortBatch(batch, "release", err); return }
			r.res, events = res, append(events, evs...)
		case isCmdError(err):            // business rejection: undo just this command
			if _, e := tx.ExecContext(ctx, fmt.Sprintf("ROLLBACK TO c%d", i)); e != nil {
				w.abortBatch(batch, "rollback_to", e); return
			}
			_, _ = tx.ExecContext(ctx, fmt.Sprintf("RELEASE c%d", i))
			r.err = err
		default:                         // infrastructure error: the batch is not trustworthy
			w.abortBatch(batch, "apply", err); return
		}
	}

	w.hooks.beforeCommit()               // fault point store.tx.before_commit (#32)
	start := w.clock.Now()
	err = tx.Commit()                    // ← the fsync lives here (synchronous=FULL)
	dur := w.clock.Since(start)
	w.obs.ObserveCommit(len(batch), dur, err)
	if err != nil { w.commitFailed(batch, err); return }   // §6 — never retried

	w.hooks.afterCommitBeforeReply()     // fault point (#32): the client-visible UNKNOWN window
	for _, r := range batch { close(r.done) }              // 1. replies — callers unblock
	w.events.Publish(events)                               // 2. fan-out (non-blocking, #19)
}
```

Reply-before-fan-out follows PLAN §3.2 ("commits, replies to waiters, publishes events"): the
fan-out must never be on the latency path and must never be able to block the writer — #19's sink
is a bounded ring that drops loudly on overflow. Events are handed over **only after a successful
commit**, so a dropped/rolled-back batch can never produce a log line, a metric increment or a
`/v1/events` record — the audit trail cannot claim something that did not happen.

### 4. Per-command failure isolation

Two error classes, and every command author must know which one they are returning:

| Class | Example | Effect on the batch | Caller sees |
|---|---|---|---|
| `CmdError` (business) | dedup conflict, `ErrTooLarge`, `ErrStaleAck`, `ErrNotFound`, `ErrFlowControl` | `ROLLBACK TO` that command's savepoint; **siblings still commit** | the sentinel error (#3), mapped to a typed API code by #14 |
| anything else (infrastructure) | `SQLITE_IOERR*`, `SQLITE_FULL`, `SQLITE_CORRUPT`, driver/protocol errors, panics | whole batch rolled back | `ErrCommitUnknown` (see §10.2) |

Savepoints cost two statements per command and no fsync. They are the difference between "one
oversized publish rejects 255 innocent siblings" and "one oversized publish is rejected". A panic
inside `Apply` is recovered by the writer, converted to an infrastructure error, and treated as a
latching fault — a bug in a command must not silently take out the batch loop.

### 5. Durability modes

| `--durability` | `PRAGMA synchronous` | Guarantee | Startup log |
|---|---|---|---|
| `full` (default) | `FULL` (2) | A returned OK on publish **or** ack means it survived a power cut | INFO `server.start durability=full` |
| `relaxed` | `NORMAL` (1) | Survives SIGKILL; the last commits may be lost on power loss/kernel panic. **Never corrupts.** | WARN banner, and `doctor` (#30) flags it |

```go
type Durability uint8

const (
	DurabilityFull Durability = iota // synchronous=FULL
	DurabilityRelaxed                // synchronous=NORMAL
)

func ParseDurability(string) (Durability, error) // "full" | "relaxed"; anything else is a
                                                 // startup error naming both valid values
func (d Durability) Synchronous() int            // 2 | 1
```

Enforcement (D1's answer to "durability lives in a DSN string is a trap"): #5's connection hook
sets the pragma on **every** pooled connection; `NewWriter` additionally reads it back on the rw
connection and refuses to start on mismatch:

```
FATAL durability mismatch: --durability=full demands PRAGMA synchronous=FULL(2),
      connection reports NORMAL(1)
      the data directory may have been opened with a conflicting DSN
      next: messq doctor --data-dir /var/lib/messq
```

The `relaxed` banner, printed exactly once at startup and never suppressible:

```
WARN durability=relaxed — acknowledged writes may be lost on power loss or kernel panic
     (they are never corrupted, and SIGKILL is still safe). Use --durability=full for the
     strong guarantee. messq_build_info{durability="relaxed"} is exported.
```

The mode is a field on `server.start` and part of `/v1/info` (#15) and `messq_build_info` (#21);
this issue only makes it available, it does not build those surfaces.

### 6. fsyncgate: commit failure is fatal, never retried

Linux clears the page error flag after a failed writeback, so a **retried fsync can return
success while the data is gone** — the PostgreSQL fsyncgate bug whose accepted fix was "panic
instead of retry". PLAN D4 adopts that rule verbatim.

```go
type FatalError struct {
	Op       string    // "commit" | "begin" | "apply" | "savepoint"
	Err      error     // wrapped driver error, errno preserved
	Class    string    // "eio" | "enospc" | "corrupt" | "unknown"
	At       time.Time
	Batch    int       // commands in the doomed batch
}

func (w *Writer) commitFailed(batch []*request, err error) {
	fe := classify("commit", err, w.clock.Now(), len(batch))
	if w.fatal.CompareAndSwap(nil, fe) {   // first error wins; exactly one storage.fatal
		obs.Fatalf("storage.fatal", fe)     // ERROR level, never sampleable (D11)
		w.obs.SetReadOnly(true)
		_ = tx.Rollback()                   // best-effort, errors logged not acted on
		_ = w.rw.Close()                    // further writes are now structurally impossible
		w.fatalC <- fe
	}
	w.failAll(batch, ErrCommitUnknown)      // NOT "failed": see §10.2
}
```

After the latch:

- every subsequent `Do` returns `ErrReadOnly` (wrapping the `FatalError`) **immediately**,
  including acks/naks — a latched process refuses all writes (D4);
- the **ro pool stays open**, so `trace`, `peek`, `pending`, `verify` and `/metrics` keep working
  while the operator investigates — forensics are the product;
- `messq_readonly` goes to 1, `messq_commit_errors_total{class}` increments;
- the process supervisor (`cmd/messq`, finished in #17) selects on `Fatal()`, keeps serving reads
  for `--fatal-drain` (2 s), then exits **74 (`EX_IOERR`, proposed — confirm in #17)**. systemd
  restarts into #5's recovery, which re-derives truth from disk.

**No commit or fsync is ever retried**, anywhere, under any error. A test counts commit attempts
per batch and asserts it is exactly 1.

**ENOSPC, and the tension with PLAN §4.5.** §4.5 requires that disk pressure never wedge the ack
path (a wedged ack path becomes mass redelivery). That is a **proactive** guard implemented in
#27: below `--min-free-bytes` publishes are rejected with a typed `507 disk_full` while
acks/naks/DLQ writes continue. It works *before* the commit. If ENOSPC nevertheless reaches
`COMMIT`, the guard has already failed and the transaction did not complete — D4's rule applies
and we latch. #32's loopback-ENOSPC scenario asserts the guard prevents the latch; this issue
asserts the latch happens if it does not.

### 7. Backpressure and cancellation

```go
func (w *Writer) Do(ctx context.Context, cmd Cmd) (Result, error) {
	if fe := w.fatal.Load(); fe != nil { return nil, fe.asDoError() }
	if w.closing.Load()               { return nil, ErrShuttingDown }

	r := &request{cmd: cmd, done: make(chan struct{})}
	select {                             // ① enqueue — cancellable
	case w.ch <- r:
	case <-ctx.Done():   return nil, ctx.Err()
	case <-w.done:       return nil, ErrShuttingDown
	}
	select {                             // ② wait — NOT cancellable, see below
	case <-r.done:
	case <-ctx.Done():   return nil, fmt.Errorf("%w: %w", ErrCommitUnknown, ctx.Err())
	}
	return r.res, r.err
}
```

- The channel is bounded at `--commit-queue`. A full channel **blocks the calling handler** —
  that is backpressure, and it propagates to the socket exactly as PLAN §3.2 requires. Nothing is
  dropped, nothing grows without bound (I11).
- **Once a command is enqueued it always runs**, even if the caller's context is cancelled. The
  caller may stop waiting; the write still happens. This is deliberate: skipping cancelled
  commands mid-queue would add a race with no benefit, and a client that disconnects mid-publish
  is *already* in the UNKNOWN class (that is what `Messq-Msg-Id` dedup, #7, exists for). The rule
  is written into `docs/SEMANTICS.md` (#4) so the crash-harness ledger (#8) classifies it
  correctly.
- `Apply` must never call `Do` (self-deadlock). Documented, plus a cheap guard: `Do` panics if
  called while `w.inApply` is set.
- **Fairness:** one FIFO, no lanes. Known risk: a publish flood can queue ahead of acks and add
  latency to the settle path. Deferred deliberately — see below.

### 9. Configuration surface added by this issue

|---|---|---|---|
| `--durability` | `MESSQ_DURABILITY` | `full` | `full` \| `relaxed` (§5) |

| `--commit-max-batch` | `MESSQ_COMMIT_MAX_BATCH` | `256` | commands per transaction (PLAN §4.3) |

| `--commit-queue` | `MESSQ_COMMIT_QUEUE` | `2048` | *proposed*: bounded cmdCh depth; full ⇒ handlers block |
| `--fatal-drain` | `MESSQ_FATAL_DRAIN` | `2s` | *proposed*: read-only serving window after `storage.fatal` before exit |

No `--commit-timeout`. A hung `fsync` is the kernel's problem; cancelling a commit mid-flight
buys nothing and adds a code path that cannot be tested honestly. Escalation is the systemd
watchdog (#17) plus the `messq_commit_duration_seconds` histogram.

### 10. Edge cases and how they are handled

1. **Caller contexts must not reach `BeginTx`.** If a handler's context were the transaction's
   context, one client disconnecting would abort a 256-command batch. The batch uses
   `context.Background()`; caller cancellation only stops *waiting* (§7).
2. **A failed commit is UNKNOWN, never FAILED.** SQLite rolls back on a failed `COMMIT`, but the
   error may also arrive after the WAL fsync completed. We therefore never tell a caller "it did
   not happen": all requests in a failed batch get `ErrCommitUnknown`, which #14 maps to a 5xx
   whose documented meaning is *"unknown — retry with the same `Messq-Msg-Id`"*. This is exactly
   the UNKNOWN class of #8's three-valued ledger oracle.
3. **Crash between commit and reply.** Durable but unacknowledged. Reserved fault point
   `store.tx.after_commit_before_reply` makes it reproducible for #8/#32; the ledger treats it as
   UNKNOWN.
4. **One command in a batch panics.** Recovered, logged with the command kind and stack, treated
   as an infrastructure error: whole batch rolled back with `ErrCommitUnknown`, latch, exit. A
   command bug must never be able to half-apply a transaction.
5. **Byte budget vs. a single oversized command.** If one command alone exceeds
   `--commit-max-bytes` it still commits alone (the budget closes batches, it never rejects
   commands; size limits are the stream's `max_msg_size`, #7).
6. **Clock jumps backwards.** `batchNow()` returns `max(clock.Now(), lastNow)` and stores it, so
   stored wall-clock timestamps are non-decreasing within a process lifetime. Deadlines and the
   commit window use monotonic durations and are unaffected (PLAN §11 fault family "clock jump").
   All rows in one batch share one timestamp — ties are expected; ordering is by `seq`, never by
   timestamp.
7. **Close races.** `Close(ctx)` sets `closing`, closes `ch`, lets `run()` drain and commit every
   already-accepted command, then returns. Commands offered after `Close` get `ErrShuttingDown`.
   If `ctx` expires mid-drain, the remainder fail with `ErrShuttingDown` and the count is logged.
   Close is idempotent and safe to call after a fatal latch (queued commands fail with the fatal
   error).
8. **`Close` before `Fatal` is observed.** `fatalC` is buffered (1) so the writer never blocks on
   a supervisor that has not started selecting yet.
9. **Empty batch impossible.** The loop blocks for the first command; no fsync is ever spent on
   nothing, and no idle-CPU burn (PLAN §12: idle daemon < 0.5 % of one core — a ticker-driven
   loop would fail that).
10. **Two processes, one data dir.** Prevented by #5's `flock`; this engine assumes it and
    documents it (SQLite would otherwise still be safe, but our single-writer invariant would not
    hold).

## Acceptance criteria

- [ ] `internal/store.Writer` exists and is the only holder of a read-write `*sql.DB` in the
      process; an architecture test fails if any package outside `internal/store` can obtain one.
- [ ] `NewWriter` refuses to construct unless `MaxOpenConns==1`, `journal_mode=wal`, and the
      live `PRAGMA synchronous` read-back matches the configured durability mode; the mismatch
      error names both the demanded and the observed value.
- [ ] A batch is closed by whichever fires first: `--commit-window`, `--commit-max-batch`,
      `--commit-max-bytes`; each rule has a test that isolates it under `testing/synctest`.
- [ ] A batch is never empty, and an idle writer consumes no CPU (no polling loop).
- [ ] `Do` never returns a success before that batch's `COMMIT` returned nil (verified by an
      ordering hook, not by timing).
- [ ] Under 256 concurrent callers, transactions are strictly fewer than commands
      (`count(messq_commit_batch_size) < sum(messq_commit_batch_size)`), and the observed mean
      batch size is printed by the bench so it is recorded rather than asserted on CI hardware.
- [ ] Commands are applied in enqueue order; if `Do(A)` returned before `Do(B)` was called, A is
      in the same or an earlier batch than B.
- [ ] A `CmdError` from one command rolls back only that command (savepoint) and its siblings
      still commit — verified after reopening the database file.
- [ ] An infrastructure error from `Apply` or from `COMMIT` rolls back the entire batch and every
      caller in it receives `ErrCommitUnknown` (never a definite failure).
- [ ] An injected commit error latches read-only exactly once: `storage.fatal` is emitted at
      ERROR with op/class/errno, `messq_readonly` = 1, the rw pool is closed, and **no retry of
      the commit or the fsync occurs** (asserted by counting commit attempts == 1).
- [ ] After a latch, every subsequent `Do` (including ack-class commands) returns `ErrReadOnly`,
      while the read-only pool still answers queries.
- [ ] `Fatal()` yields exactly one `*FatalError` and does not block the writer; the process exits
      non-zero after `--fatal-drain` (exit code recorded and documented).
- [ ] `--durability=relaxed` prints the WARN banner exactly once at startup; the mode is a field
      of `server.start`; `full` is the default when the flag is absent.
- [ ] The command queue is bounded: `len(ch)` never exceeds `--commit-queue`, a blocked `Do`
      returns `ctx.Err()` when its context expires, and no command is ever dropped.
- [ ] Batch timestamps are single-valued per batch and non-decreasing across batches, including
      when the fake clock jumps backwards.
- [ ] `Close(ctx)` applies and commits every already-accepted command, rejects new ones with
      `ErrShuttingDown`, is idempotent, and is safe after a fatal latch.
- [ ] `messq_commit_batch_size` and `messq_commit_duration_seconds` are registered on the injected
      registry with no stream/consumer/subject labels.
- [ ] Committed events reach the sink only after a successful commit, and a slow sink cannot block
      the writer.
- [ ] Fault hook names `store.tx.before_apply`, `store.tx.before_commit`,
      `store.tx.after_commit_before_reply` exist as no-ops and are documented for #32.
- [ ] No `time.Now()` and no `time.Sleep` in the writer or its tests (lint-enforced, #2/#3);
      `internal/store` coverage stays at or above its 85 % floor.

## Test plan

Per PLAN §11: `-race` everywhere, real SQLite files in `t.TempDir()` (never `:memory:`), timing
via `testing/synctest` or the Clock seam.

**Unit / table (`internal/store`)**
- Batch-closing rules, one test per rule, in a synctest bubble: window-only, max-batch-only,
  max-bytes-only, and their interactions; `--commit-window=0` commits immediately.
- FIFO ordering; batch never empty; single batch timestamp; monotonic guard under a backwards
  clock jump.
- `Do` result plumbing: typed `Result` round-trip, `CmdError` sentinel pass-through.
- Savepoint isolation: batch of 3 with the middle command failing → reopen the file, assert rows
  1 and 3 present, 2 absent, and the middle caller got the sentinel.
- Durability construction matrix: `full`/`relaxed` × correct/incorrect pragma → constructs or
  refuses with the naming error.
- Backpressure: queue depth 4 with a stalled writer; 8 callers; assert 4 blocked, `len(ch) <= 4`,
  cancelling a blocked caller returns `ctx.Err()`, and its command never runs.

**Fault injection (Go-level seam; the OS-level version is #32)**
- `commitFn` / `hooks.beforeCommit` injecting `syscall.EIO` and `syscall.ENOSPC`: latch once,
  `ErrCommitUnknown` to all callers in the batch, `ErrReadOnly` afterwards, rw pool closed,
  commit attempted exactly once, ro pool still readable, one `FatalError` on `Fatal()`.
- Panic inside `Apply` → recovered, batch rolled back, latch, no partial rows after reopen.
- `hooks.afterCommitBeforeReply` blocking → callers still waiting, data already durable
  (the UNKNOWN window #8 kills in).

**Property (`pgregory.net/rapid`)**
- Random schedules of arrivals, batch sizes, `CmdError` positions and injected infrastructure
  failures against a trivial `insert into t(k,v)` command. Invariants after every action, checked
  against a reopened database: every OK caller's row exists; every `CmdError` caller's row does
  not; every `ErrCommitUnknown` caller's row may or may not exist but the batch is all-or-nothing;
  `sum(batch_size) == commands applied`; `count(batch_size) == transactions`; queue length never
  exceeds the bound. Failfiles committed as regression corpus.

**Concurrency**
- `go test -race -count=20` on a mixed publish/settle-shaped workload with 64 goroutines and a
  randomised writer stall, asserting no data race, no goroutine leak (`goleak`-style check after
  `Close`), and flat allocation growth.

**Metrics**
- `prometheus/testutil.CollectAndCompare` golden for the two histograms' names, help and label
  sets; a test asserts a stream-labelled commit metric fails (cardinality rule).

**Bench (`go test -bench`, feeds #31)**
- `BenchmarkWriterCommit/{full,relaxed}/{1,8,64,256}_concurrent`: report commands/s, commits/s,
  mean batch size, p50/p99 commit duration. Recorded as the pre-#8 baseline for the D1 gate; the
  real ≥ 5 000 msg/s gate is measured end-to-end in #8.

**fsync accounting (nightly, Linux-only)**
- `modernc.org/sqlite`'s `vfs` package exposes a read-only `fs.FS` VFS, so a counting write VFS
  is not available to us; instead a nightly job runs the bench under
  `strace -f -c -e trace=fsync,fdatasync` and asserts `fsync_count ≈ commit_count` (allowing the
  WAL-header and checkpoint syncs). The per-merge oracle stays the commit-count histogram.

**Handover to later suites**
- #8 consumes the reserved fault points for the SIGKILL loop; #13's rapid suite drives real
  commands through this engine including `restart`; #32 replaces the Go-level hooks with the
  `messq_fault` build-tag grammar. No test written here is expected to be deleted by them.
