## Context

#19 built the observability spine: a closed event vocabulary written in the same transaction as the
state change, fanned out to `slog` and to followers. PLAN.md **D11** says those surfaces are
*projections* of that one journal:

> **Observability: events table in-transaction is the source of truth; logs and metrics are
> projections.** … Three surfaces, one closed event vocabulary. … Metrics: prometheus
> client_golang on a custom registry; labels are only `stream` and `consumer` — never `subject`,
> never ids (unanimous cardinality rule).

Two of the three surfaces exist. This issue builds the third, and it is the surface an operator
watches *before* an incident rather than during one. `messq trace` (#20) answers "what happened to
message X" after somebody notices. `/metrics` is what makes somebody notice.

Governing PLAN.md material:

- **§9.4 Metrics** — the normative metric list, the cardinality rule, the sentence that fixes the
  gauge architecture (*"Backlog/depth gauges are computed by a custom `Collector` from SQLite at
  scrape time (5 s cache) — a gauge recomputed from the source of truth cannot drift after a
  restart or a purge"*), and the two shipped artifacts: `contrib/prometheus/alerts.yml` and
  `contrib/grafana/messq.json`.
- **§9.4 annotations that are product decisions, not commentary** — `messq_stale_acks_total`
  *"alert on any nonzero rate (ack_wait too short)"* and `messq_oldest_pending_age_seconds`
  *"THE user-facing SLI; alert on it"*. Both become shipped alert rules here.
- **D11 / §9.1** — *"grep, SQL and PromQL speak one language."* Concretely: counters are driven from
  committed events through one projection table, never from ad-hoc `Inc()` calls in the writer. If a
  counter can move without an event row, D11 is a slogan instead of a design.
- **§13 library choices** — `prometheus/client_golang`: *"Custom registry + promauto +
  `promhttp.HandlerFor(MaxRequestsInFlight)`; custom Collector for scrape-time gauges."*
  10's hand-rolled exposition was explicitly rejected. `prometheus/prometheus` is **not** a
  dependency (§11 below keeps `promtool` out of `go.mod`).
- **§5.2 I11** — *"No unbounded queue or collection exists anywhere."* A label-value cache and a
  `CounterVec` are collections; §8 below bounds them and reaps deleted streams/consumers.
- **§14 M5 exit criterion** — *"golden log/metric tests green"*, and the M5 milestone line:
  *"metrics + alerts + dashboard"*.

What it unlocks: **#30**'s `doctor` reads these gauges to write prose findings; **#31**'s bench run
is the first thing the dashboard is pointed at; **#27** replaces the `statfs` disk reading and
supplies retention counters; **#35** links every alert to a runbook; **#36** packages `contrib/`
into the `.deb`/`.rpm`. No issue lists #21 in its `blockedBy`, but five assume the names frozen
here.

## Scope

### In scope

- **`internal/obs/metrics`**: the custom registry, the `Metrics` struct, the `promhttp` handler, and
  the single registration point for *every* metric in the binary — including those sibling issues
  proposed (#6 commit histograms, #10 ack counters, #11 sweeper metrics, #12 DLQ counters, #14
  fetch/waiter metrics). They supply observer interfaces; names, labels, buckets and help are
  decided here.
- **The event→counter projection table**: one `map[obs.Event]projection` consumed by #19's fan-out,
  plus an exhaustiveness test over the closed vocabulary (§9.2) so a new event forces an explicit
  "yes, a counter" or "no, and here is why".
- **The scrape-time `Collector`**: `Describe`/`Collect` + `prometheus.NewConstMetric`, two cache
  tiers (5 s cheap / 60 s heavy), read-pool queries only, never fails a scrape.
- **Metric definitions that are actually definitions**: what `pending`, `inflight`, `backlog` and
  `oldest_pending_age_seconds` mean, including the unmaterialised-backlog case (a consumer that
  never fetches has *no* delivery rows).
- **Cardinality enforcement**: a label allow-list test over `reg.Gather()`, a `forbidigo` rule
  banning the default registerer, and a `messq_sabotage` (#13) entry that registers a
  subject-labelled metric so "a subject-labelled metric fails CI" is an executed test, not a claim.
- **Golden exposition test** via `testutil.GatherAndCompare` / `ScrapeAndCompare`, driven by the
  *same* scripted scenario as #19's golden log test and #20's golden trace.
- **`contrib/prometheus/alerts.yml`** — DLQ growth, `oldest_pending_age > 15m`, stale-ack rate,
  `retention.blocked`, disk ETA, plus the read-only latch — each with severity, runbook id and
  annotations; validated by `promtool check rules` and unit-tested with `promtool test rules`.
- **`contrib/grafana/messq.json`** — one screen, four rows: *alive / working / suffering / losing*.
- **`docs/metrics.md`**, generated from the same table the code registers from, with a test that
  fails when they diverge.
- **Flags**: `--metrics`, `--metrics-cache`, `--metrics-cache-heavy`, `--metrics-query-timeout`,
  `--metrics-max-inflight`, `--metrics-max-series`, `--metrics-count-limit`, `--metrics-filter-scan`,
  `--metrics-runtime-collectors`, `--metrics-auth`.

### Out of scope

- The `/metrics` **route** and its `503 not_implemented` placeholder → **#15**. This issue fills the
  injected `Deps.Metrics http.Handler` slot; there is no routing change.
- The event vocabulary, event rows, the fan-out goroutine, slog handlers and sampling → **#19**.

- `/v1/events`, `?follow=1`, `messq trace` → **#20**.
- Emitting the events these counters project — publish/dedup (#7), claim (#9), ack/nak/term/extend

- Bearer tokens and the role middleware → **#16**. This issue declares `/metrics`'s auth requirement

- `messq doctor`'s prose findings and the fsync-latency probe → **#30**; `messq bench` and published

```go
// Proposal. Implemented by internal/store on the read-only pool (#5's ro handle).
type StatsReader interface {
    // Cheap tier (5 s): one pass over `deliveries` + `consumers` + `stream_seq`.
    DeliveryStats(ctx context.Context) ([]ConsumerStat, error)
    // Cheap tier: file sizes from #5's Store.Sizes(), no SQL.
    Sizes(ctx context.Context) (Sizes, error)
    // Heavy tier (60 s): DLQ depths, events-table rows.
    HeavyStats(ctx context.Context, limit int64) (Heavy, error)
    // Bounded scan used for oldest-pending-age of an unfetched consumer (§6.3).
    HeadCandidates(ctx context.Context, stream string, fromSeq uint64, limit int) ([]Candidate, error)
}

type ConsumerStat struct {
    Stream, Consumer  string
    Pending, Inflight int64
    OldestSeq         uint64 // MIN(seq) over unfinished rows; 0 when none

    CursorSeq, LastSeq uint64
    Paused            bool
    Filters           []string
}
```

`store.Stats` is deliberately shared with **#15**'s `/v1/streams`, `/v1/info` and **#24**'s

during an incident. That is the same argument as "one event vocabulary", applied to numbers.

### 2. Registry and handler

```go
type Options struct {
    Version, Commit, Durability string
    Cache        time.Duration // --metrics-cache        (default 5s, PLAN §9.4)
    CacheHeavy   time.Duration // --metrics-cache-heavy  (default 60s)
    QueryTimeout time.Duration // --metrics-query-timeout(default 2s)
    MaxInFlight  int           // --metrics-max-inflight (default 4)
    MaxSeries    int           // --metrics-max-series   (default 10000)
    CountLimit   int64         // --metrics-count-limit  (default 5_000_000)
    FilterScan   int           // --metrics-filter-scan  (default 1000)
    Runtime      bool          // --metrics-runtime-collectors (default true)
    Clock        clock.Clock
    Stats        StatsReader
    Log          *slog.Logger
}

func New(o Options) (*Metrics, error) {
    reg := prometheus.NewRegistry()               // never the default registry
    f   := promauto.With(reg)
    m   := &Metrics{reg: reg, o: o}
    m.published = f.NewCounterVec(prometheus.CounterOpts{
        Name: "messq_published_total",
        Help: "Messages committed to a stream, by stream.",
    }, []string{"stream"})
    // … one construction per catalogue.go row …
    if o.Runtime {
        reg.MustRegister(collectors.NewGoCollector(), collectors.NewProcessCollector(
            collectors.ProcessCollectorOpts{}))
    }
    reg.MustRegister(newCollector(o))             // §6, the scrape-time gauges
    m.buildInfo.WithLabelValues(o.Version, o.Commit, o.Durability).Set(1)
    return m, nil
}

func (m *Metrics) Handler() http.Handler {
    return promhttp.HandlerFor(m.reg, promhttp.HandlerOpts{
        Registry:            m.reg,          // exposes promhttp_metric_handler_errors_total
        MaxRequestsInFlight: m.o.MaxInFlight,
        Timeout:             m.o.QueryTimeout + time.Second,
        ErrorHandling:       promhttp.ContinueOnError, // a partial scrape beats a blind operator
        ErrorLog:            slogAdapter{m.o.Log},
        EnableOpenMetrics:   true,
    })
}
```

`m.Handler()` goes into #15's `Deps.Metrics` slot. `--metrics=false` leaves the slot nil and #15's
honest `503 not_implemented` answers — an operator who turned metrics off gets told so, not a 404.

**Lint gate:** a `forbidigo` rule (#2's config) bans `prometheus.MustRegister`,
`prometheus.Register`, `promauto.New*` (the default-registerer forms), `prometheus.DefaultRegisterer`
and `prometheus.DefaultGatherer` outside this package. A transitive dependency that registers into
the default registry cannot leak into our exposition, because we never gather from it.

### 3. Counters are projections of committed events

**_Decision 1: a counter may only move in response to a committed event._** #19's fan-out delivers
`obs.Event` values *after* the group commit succeeds. Metrics subscribe there and nowhere else.
Consequence: a transaction that rolls back (fsync error, `ErrShuttingDown`, constraint violation)
leaves every counter untouched — and that is a named test (§11), not an aspiration.

```go
// project.go — proposal
type projection struct {
    vec    *prometheus.CounterVec
    labels func(e obs.Event) []string       // ordered label values; nil ⇒ no labels
    obs    func(m *Metrics, e obs.Event)    // optional histogram observation
}

func (m *Metrics) projections() map[obs.Name]projection {
    return map[obs.Name]projection{
        obs.MsgPublish: {vec: m.published, labels: byStream},
        obs.MsgDup:     {vec: m.duplicates, labels: byStream},
        obs.MsgDeliver: {vec: m.delivered, labels: byStreamConsumer, obs: observeRedelivery},
        obs.MsgAck:     {vec: m.acked, labels: byStreamConsumer, obs: observeAckLatency},
        obs.MsgNak:     {vec: m.naked, labels: byStreamConsumer},
        obs.MsgTerm:    {vec: m.termed, labels: byStreamConsumer},
        obs.MsgTimeout: {vec: m.timeouts, labels: byStreamConsumer},
        obs.MsgDead:    {vec: m.dead, labels: byStreamConsumer},
        obs.MsgAckStale:{vec: m.staleAcks, labels: byStreamConsumer},
        obs.MsgExtend:  {vec: m.extends, labels: byStreamConsumer},
        // … see catalogue.go …
    }
}

// Explicit non-projections, so the exhaustiveness test has something to check against.
var noCounter = map[obs.Name]string{
    obs.MsgAckDup:      "idempotent replay; visible in trace, not worth a series",
    obs.ConsumerLag:    "advisory event; the gauge is authoritative",
    obs.ServerStop:     "process_start_time_seconds already encodes restarts",
    // …
}
```

`observeRedelivery` reads `e.Attempt > 1` and increments
`messq_redelivered_total{stream,consumer,cause}` from `e.Detail.Cause` (`timeout` | `nak` |
`broker_restart` — the D6 rule that *every duplicate has a named cause* becomes a PromQL breakdown).
`observeAckLatency` observes `e.Detail.HeldMs / 1000` into `messq_ack_latency_seconds`.

**Exhaustiveness test:** iterate `obs.AllNames()`; every name must appear in `projections()` or in
`noCounter`, else fail with "event %q has no metric decision". Adding an event to §9.2 forces a
one-line decision instead of a silent gap.

### 5. Cardinality policy, stated precisely

PLAN §9.4 says *"labels are only `stream` and `consumer`"* while itself writing
`messq_redelivered_total{stream,consumer,cause}`. The rule that reconciles both, and the one the
test encodes:

> **Identity labels are `stream` and `consumer`, and nothing else.** No label may ever carry a
> subject, a message id, a trace id, a token, a client address, a URL path or an error string.
> Additional labels are permitted only when their value set is a **closed enum defined in Go code**
> (`cause`, `class`, `reason`, `code`, `route`, `tier`, `method`), listed in the catalogue, and
> bounded by a compile-time constant list.

Enforcement, three layers:

1. **Allow-list test.** After a scripted scenario that touches every metric, walk `reg.Gather()`;
   for each `MetricFamily`, its label-name set must equal `catalogue[name].Labels` exactly, and
   every enum label's observed values must be a subset of the declared enum. Forbidden names
   (`subject`, `msg_id`, `id`, `seq`, `trace_id`, `token`, `peer`, `client`, `path`, `url`,
   `error`, `user`, `instance`) fail the test wherever they appear.
2. **Sabotage entry** (#13's `messq_sabotage` build tag): `sabotage_subject_label.go` registers
   `messq_published_total{stream,subject}`. A meta-test asserts the allow-list test *fails* under
   that tag — the acceptance criterion "a subject-labelled metric fails CI" is executed, not
   asserted in prose.
3. **`promlint`** via `testutil.CollectAndLint(reg)` with zero tolerated problems: `_total` suffix
   on counters, `_seconds`/`_bytes` unit suffixes, non-empty help text, no metric name that is also
   a label name.

### 6. The scrape-time collector

**_Decision 2: gauges are computed, never mirrored._** No in-memory counter of pending messages is
maintained anywhere. `Collect` queries the read pool. This is PLAN §9.4's reason verbatim — a
mirrored gauge drifts after a purge, a seek or a restart, and a dashboard that lies once is never
trusted again.

```go
type collector struct {
    o     Options
    mu    sync.Mutex
    cheap snapshot // deliveries, cursors, sizes, disk       — TTL 5s
    heavy snapshot // dlq depths, events rows                — TTL 60s
    descs map[string]*prometheus.Desc
}

func (c *collector) Describe(ch chan<- *prometheus.Desc) { for _, d := range c.descs { ch <- d } }

func (c *collector) Collect(ch chan<- prometheus.Metric) {
    s := c.snapshotCheap()          // single-flight; concurrent scrapes share one refresh
    h := c.snapshotHeavy()
    for _, cs := range s.Consumers {
        ch <- gauge(c.descs["messq_pending"],  float64(cs.Pending),  cs.Stream, cs.Consumer)
        ch <- gauge(c.descs["messq_inflight"], float64(cs.Inflight), cs.Stream, cs.Consumer)
        ch <- gauge(c.descs["messq_backlog"],  float64(cs.Backlog),  cs.Stream, cs.Consumer)
        ch <- gauge(c.descs["messq_oldest_pending_age_seconds"], cs.OldestAgeSec, cs.Stream, cs.Consumer)
        ch <- gauge(c.descs["messq_consumer_paused"], b2f(cs.Paused), cs.Stream, cs.Consumer)
    }
    // … dlq depth, sizes, disk, snapshot age …
}
```

**_Decision 3: a scrape never fails._** On query error or `context` timeout, the previous snapshot
is served, `messq_metrics_scrape_errors_total{tier}` increments,
`messq_metrics_snapshot_age_seconds{tier}` starts climbing, and a WARN is logged at most once a
minute. A blind operator is worse than a slightly stale one; `MessqMetricsStale` (§10) alerts when
the staleness itself becomes the problem.

#### 6.1 Cheap tier (5 s) — one pass, two queries

```sql
-- Q1: the pending set. `deliveries` holds only unfinished work (D5), so this is small by
-- construction; it is a covering scan of the primary key.
SELECT stream, consumer,
       COUNT(*)                    AS pending,
       COALESCE(SUM(state), 0)     AS inflight,   -- state ∈ {0 READY, 1 INFLIGHT}
       MIN(seq)                    AS oldest_seq
FROM deliveries
GROUP BY stream, consumer;

-- Q2: cursors, head sequence, pause state, filters.
SELECT c.stream, c.name, c.cursor_seq, c.paused, c.filters, s.next - 1 AS last_seq
FROM consumers c
JOIN stream_seq s ON s.stream = c.stream;

-- Q3: one indexed lookup per (stream, consumer) that has work: age of the oldest unfinished row.
SELECT published_at FROM messages WHERE stream = ? AND seq = ?;   -- PK lookup
```

`Sizes()` (db/WAL bytes) is `os.Stat`, not SQL. `messq_disk_free_bytes` is one
`unix.Statfs(dataDir)`; when #27 lands, both come from its disk monitor instead.

#### 6.2 Heavy tier (60 s)

`COUNT(*)` over a large table is the one query that can hurt, so it gets its own TTL and a guard:

```sql
-- DLQ depth, labelled with the ORIGIN stream (#12's rule): `<origin>.dlq`.
SELECT COUNT(*) FROM messages WHERE stream = ?;        -- PK range scan
-- Events rows: exact and O(1). The janitor only ever trims the oldest prefix,
-- so ids are contiguous and MAX-MIN+1 is the count, not an estimate.
SELECT COALESCE(MAX(id) - MIN(id) + 1, 0) FROM events;
```

Above `--metrics-count-limit` (5 M) rows the DLQ count falls back to `last_seq - first_seq + 1` and
sets `messq_metrics_estimated{metric="dlq_depth"} 1`, so an operator can see that the number is an
upper bound rather than silently trusting it. When #27's janitor starts maintaining per-stream
counts, the heavy tier reads them and the fallback disappears.

#### 6.3 Definitions that need deciding, not guessing

Delivery rows are created at fetch top-up (**T1**) and deleted on ack (**D5**). Two consequences:

- **A consumer that never fetches has zero delivery rows.** `pending` is 0 while a million messages
  wait. If `oldest_pending_age_seconds` were derived from delivery rows alone it would read 0
  during exactly the outage it exists to detect — a stopped worker.
- Materialised rows always have `seq < cursor_seq`; unscanned messages have `seq ≥ cursor_seq`. The
  two sets are disjoint, so they add without double counting.

Therefore:

| Gauge | Definition |
|---|---|
| `messq_pending` | `COUNT(deliveries)` for the pair — materialised unfinished work (READY + INFLIGHT). |
| `messq_inflight` | `COUNT(deliveries WHERE state = INFLIGHT)`. |
| `messq_backlog` | `pending + max(0, last_seq - cursor_seq + 1)` — **total work owed to this consumer**, the number `messq lag` prints. |
| `messq_oldest_pending_age_seconds` | `now - min(published_at)` over `{oldest delivery row} ∪ {first filter-matching message at seq ≥ cursor_seq}`, clamped at ≥ 0. |

The head-candidate lookup scans forward from `cursor_seq` with the Go subject matcher (#3), bounded
by `--metrics-filter-scan` (1000 rows). For the default filter `[">"]` the first row always matches,
so the cost is one PK lookup. For a narrow filter with no match inside the budget, the collector
falls back to the delivery-row age and increments `messq_metrics_truncated_total`; the gauge is then
an under-estimate for that pair only, and `docs/metrics.md` says so. The other direction is also
possible: cursor advancement is driven by fetches, so an idle consumer's unscanned range may include
messages its filter would skip. Both are documented; **the number is never silently wrong**, and
#24's `messq lag` uses this identical helper so the CLI and the dashboard cannot disagree.

### 7. Histograms

| Metric | Classic buckets | Native |
|---|---|---|
| `messq_ack_latency_seconds` | `ExponentialBuckets(0.005, 2, 14)` → 5 ms … ~40 s | factor 1.1 |
| `messq_commit_duration_seconds` | `ExponentialBuckets(0.0001, 2, 15)` → 100 µs … ~1.6 s | factor 1.1 |
| `messq_commit_batch_size` | `{1,2,4,8,16,32,64,128,256}` (#6's proposal, adopted) | none |
| `messq_fetch_wait_seconds` | `{0.001,0.005,0.025,0.1,0.5,1,5,30,60}` | factor 1.1 |
| `messq_sweep_lateness_seconds` | `{0.05,0.1,0.25,0.5,1,2,5,30}` | none |
| `messq_http_request_duration_seconds` | `DefBuckets` | none |

Native histograms are enabled *alongside* classic buckets (`NativeHistogramBucketFactor: 1.1`,
`NativeHistogramMaxBucketNumber: 100`, `NativeHistogramMinResetDuration: time.Hour`): a scraper that
negotiates protobuf gets high-resolution latency for free, a text-only scraper sees the classic
buckets, and the golden test compares only the text exposition. Nobody is required to upgrade
anything.

### 8. Series lifecycle (I11)

The fan-out is a single goroutine, so the label-value cache is a plain map with no lock:

```go
type seriesKey struct{ stream, consumer string }
type seriesSet struct{ delivered, acked, naked, /* … */ prometheus.Counter }
// bounded by --metrics-max-series; on overflow: WARN once/min + messq_metrics_dropped_series_total
```

- **Bounded**: at `--metrics-max-series` (10 000 pairs) new pairs stop being cached and increment
  `messq_metrics_dropped_series_total`. Refusing is correct; an `{stream="__other__"}` bucket would
  turn a cardinality bug into a silently wrong graph.
- **Reaped**: `stream.delete`/`consumer.delete` call `DeleteLabelValues` on every vec and drop the
  cache entry. Without this, deleted consumers export frozen counters forever — the classic
  broker-metrics leak, and a direct I11 violation.
- Gauges need no reaping: recomputed from live rows, so a deleted consumer simply stops appearing.

permissions (D12) and is unaffected. This issue declares the requirement in #14's route registry;
#16 enforces it.

```yaml
      # ── something is being lost ─────────────────────────────────────────────
      - alert: MessqDlqGrowing

        expr: increase(messq_dead_orphan_total[1h]) > 0
        labels: {severity: critical, runbook: RB-12}

      - alert: MessqRetentionBlocked             # a stuck consumer is about to be a disk problem
        expr: increase(messq_retention_blocked_total[10m]) > 0
        for: 10m
        labels: {severity: warning, runbook: RB-05}

      # ── the broker itself ───────────────────────────────────────────────────
      - alert: MessqReadOnly                     # the fsyncgate latch (D4)
        expr: messq_readonly == 1
        for: 1m
        labels: {severity: critical, runbook: RB-03}

      - alert: MessqDiskWillFill                 # predictive, not reactive
        expr: predict_linear(messq_disk_free_bytes[6h], 24 * 3600) < 0
        for: 30m
        labels: {severity: warning, runbook: RB-03}

      - alert: MessqStaleAcks                    # PLAN §9.4: "alert on any nonzero rate"
        expr: rate(messq_stale_acks_total[10m]) > 0
        for: 15m
        labels: {severity: warning, runbook: RB-07}
        annotations:
          description: "Workers are acking after their lease expired: ack_wait is too short, or handlers should call extend."

      - alert: MessqRedeliveryStorm
        expr: |
          rate(messq_redelivered_total[5m])
            > 0.5 * rate(messq_delivered_total[5m])
        for: 10m
        labels: {severity: warning, runbook: RB-08}

      - alert: MessqSweeperBehind
        expr: messq_sweep_backlog > 0
        for: 5m
        labels: {severity: warning, runbook: RB-13}

      - alert: MessqCommitLatency
        expr: histogram_quantile(0.99, sum by (le) (rate(messq_commit_duration_seconds_bucket[5m]))) > 0.1
        for: 10m
        labels: {severity: warning, runbook: RB-14}

      - alert: MessqMetricsStale                 # the dashboard itself has stopped telling the truth
        expr: messq_metrics_snapshot_age_seconds{tier="cheap"} > 60

        labels: {severity: warning, runbook: RB-15}
```

Validated in CI by a **checksum-pinned `promtool` binary downloaded in the observability job** —
`promtool check rules` plus `promtool test rules contrib/prometheus/alerts_test.yml`, which feeds
synthetic series (a stalled consumer, a paused consumer that must *not* fire, a DLQ that grows once)
and asserts which alerts fire at which minute. `prometheus/prometheus` is deliberately **not** added
to `go.mod`; it would double the module graph for a test tool (§13's ≤ 8 direct dependencies).

### 12. `contrib/grafana/messq.json`

One screen, one datasource variable (`${DS_PROMETHEUS}`), template variables `$job`, `$instance`,
`$stream`, `$consumer` (multi-select, `label_values(messq_backlog, stream)`), schema version pinned,
`refresh: 30s`.

| Row | Question | Panels |
|---|---|---|
| 1. Alive | *is it up and writable?* | `messq_build_info` (version/durability stat), uptime from `process_start_time_seconds`, `messq_readonly` stat with red threshold, disk free + ETA-to-full, `messq_db_bytes`/`messq_wal_bytes` |
| 2. Working | *is traffic flowing?* | publish rate by stream, deliver/ack rate by consumer, ack-latency heatmap, commit-duration p50/p99, mean batch size (`rate(sum)/rate(count)`), waiters |
| 3. Suffering | *is anyone waiting?* | `messq_oldest_pending_age_seconds` top-10 (the hero panel, 15 m threshold line), `messq_backlog` per consumer, `messq_pending` vs `messq_inflight`, paused consumers |
| 4. Losing | *is anything being dropped?* | `messq_dlq_depth` per stream, dead rate by consumer, `messq_redelivered_total` by cause (stacked), stale-ack rate, `messq_expired_total`, `messq_api_errors_total` by code |

**Anti-rot test (both artifacts):** a Go test extracts every `messq_[a-z_0-9]+` token from
`alerts.yml` and `messq.json`, strips `_bucket`/`_sum`/`_count` suffixes, and asserts each is a name
this binary actually exports (from `catalogue.go`). Renaming a metric without updating the shipped
artifacts fails CI. The reverse direction is advisory: a test lists exported metrics that appear in
neither artifact nor `docs/metrics.md`, and `docs/metrics.md` completeness *is* enforced.

### 13. Edge cases

| Case | Handling |
|---|---|
| Consumer exists, has never fetched, 1 M messages waiting | `pending=0`, `inflight=0`, `backlog=1M`, `oldest_pending_age` from the head candidate at `cursor_seq` (§6.3). This is the stopped-worker outage; the SLI must not read 0. |
| Narrow filter, no match inside `--metrics-filter-scan` | Fall back to delivery-row age, increment `messq_metrics_truncated_total`, document the under-estimate. Never block the scrape scanning. |
| `seek`/`purge` moves the cursor backwards or drops rows | Gauges recompute from live rows on the next refresh; nothing to reconcile. Counters keep counting forward (they are event totals, not levels). This is Decision 2's whole point, and it has a named test. |
| Restart | Counters reset to zero; `rate()`/`increase()` handle it and `process_start_time_seconds` makes the reset visible. Gauges are correct on the first scrape after recovery — **no warm-up window**. |
| Writer latched read-only (EIO/ENOSPC) | The collector uses the read pool, so `/metrics` keeps answering; `messq_readonly=1` drives `MessqReadOnly`. #17 keeps the handler alive for `--fatal-drain` so the last scrape before exit is served. |
| Scrape during graceful drain | Reads keep working until the listener closes; `messq_waiters` falling to 0 is the drain progress signal. |
| Read pool times out / returns `SQLITE_BUSY` | Serve the previous snapshot, increment `messq_metrics_scrape_errors_total{tier}`, WARN at most once a minute, never 500. |
| Scrape storm | Single-flight refresh per tier + `MaxRequestsInFlight: 4` → excess scrapes get `503`; SQLite is hit at most once per TTL however many scrapers there are. |
| Clock jumps backwards | Ages are `max(0, now-t)`; a gauge is never negative. Deadline logic is monotonic (#3's Clock seam) and unaffected. |
| Stream or consumer deleted | Counter series are reaped via `DeleteLabelValues` on `stream.delete`/`consumer.delete`; gauge series stop appearing. No frozen zombie series. |
| A `<stream>.dlq` stream also has its own consumers | It is an ordinary stream (D3), so it gets its own `pending`/`backlog` series under `stream="orders.dlq"`, while `messq_dlq_depth{stream="orders"}` reports its depth under the **origin** name. Documented, because the two look like a double count and are not. |
| 10 000+ (stream, consumer) pairs | New pairs stop being cached at `--metrics-max-series`; `messq_metrics_dropped_series_total` rises and `doctor` (#30) reports it. We refuse rather than lie. |
| Scraper cannot negotiate protobuf | Classic buckets are always exported; native histograms are additive. |
| `--metrics=false` | The registry is still built (projection is unconditional and cheap); only the handler slot is nil, so #15 answers `503 not_implemented`. |
| Events table trimmed by the janitor | `messq_events_rows` drops. Expected, not an error; `MAX(id)-MIN(id)+1` stays exact because trimming removes a prefix. |
| A transaction rolls back after events were built | Counters do not move: the fan-out only ever sees committed events (Decision 1). Tested with a fault-injected commit failure. |

- **Exemplars** linking `messq_ack_latency_seconds` buckets to `trace_id` — cardinality-safe and

## Acceptance criteria

- [ ] Every metric in PLAN §9.4 (Table A) is exported with exactly the name, type and label set
      listed there, from a `prometheus.NewRegistry()` — the default registry is never used and a
      `forbidigo` rule fails the build if it is.
- [ ] `/metrics` is served by `promhttp.HandlerFor` with `MaxRequestsInFlight` set, injected into
      #15's existing slot with no routing change; `--metrics=false` leaves #15's `503`.
- [ ] Every counter moves **only** in response to a committed event: a fault-injected commit failure
      after events are built leaves all counters unchanged.
- [ ] Every name in the closed event vocabulary (§9.2) is either projected to a counter or listed in
      `noCounter` with a reason; the exhaustiveness test fails on an unlisted new event.
- [ ] Backlog, pending, inflight, oldest-pending-age and DLQ depth are produced by a custom
      `Collector` from read-pool SQL at scrape time with a 5 s cache; no in-memory mirror of any of
      them exists in the codebase.
- [ ] A consumer that has never fetched, with N unconsumed messages, reports `pending=0`,
      `backlog=N` and a non-zero `oldest_pending_age_seconds`.
- [ ] After `purge`, `seek` and a restart, every gauge equals the value computed independently from
      the database — no drift, no warm-up window.
- [ ] `reg.Gather()` after a full scenario contains no label named `subject`, `msg_id`, `seq`,
      `trace_id`, `token`, `peer`, `client`, `path`, `url` or `error`; every enum label's values are
      a subset of its declared constant list.
- [ ] Under `-tags messq_sabotage` a metric registered with a `subject` label makes the cardinality
      test **fail** (a meta-test asserts the failure), so the guard is proven to work.
- [ ] `testutil.CollectAndLint(reg)` reports zero problems.
- [ ] `testutil.GatherAndCompare` against `testdata/metrics.golden` passes for the scripted
      publish → deliver → timeout → nak → ack → dead scenario, and `ScrapeAndCompare` passes against
      a real `messq serve` on a Unix socket.
- [ ] A read-pool failure or timeout during `Collect` yields a 200 with the previous snapshot, an
      incremented `messq_metrics_scrape_errors_total` and a climbing
      `messq_metrics_snapshot_age_seconds` — never a 500 and never a hang.
- [ ] Deleting a stream or consumer removes its counter series from the next scrape.
- [ ] `promtool check rules contrib/prometheus/alerts.yml` passes and
      `promtool test rules contrib/prometheus/alerts_test.yml` proves `MessqConsumerStalled`,
      `MessqDlqGrowing`, `MessqStaleAcks`, `MessqRetentionBlocked`, `MessqReadOnly` and
      `MessqDiskWillFill` fire on their synthetic series — and that a paused consumer does not page.
- [ ] `contrib/grafana/messq.json` parses, declares its datasource as a variable, and every metric
      name referenced by it or by `alerts.yml` is a metric this binary exports (anti-rot test).
- [ ] `docs/metrics.md` lists every exported metric with type, labels, meaning and the event or
      query it derives from; a test fails if code and doc diverge.
- [ ] A scrape of a database with 100 000 delivery rows and 50 (stream, consumer) pairs completes in
      < 50 ms warm and < 250 ms cold, and running a scrape every 5 s during a 5 000 msg/s bench costs
      < 2 % throughput.

## Test plan

Consistent with PLAN §11. `-race` everywhere, no `time.Sleep` (fake clock / `testing/synctest`),
every failing case lands with a committed artifact.

1. **Unit — projection table** (`internal/obs/metrics`): table-driven, one row per event name;
   asserts the right vec, right label order, right histogram observation. Plus the exhaustiveness
   test over `obs.AllNames()`.
2. **Unit — collector arithmetic** against a fake `StatsReader`: the §6.3 definitions, including
   `backlog = pending + unscanned`, age clamping on a backwards clock jump, the head-candidate scan
   budget, the estimate fallback above `--metrics-count-limit`, and the stale-snapshot path.
3. **Golden exposition** (`TestMetricsGolden`): the shared M5 scenario — the *same* script that
   drives #19's golden log test and #20's golden trace — run on a fake clock against a real SQLite
   file in `t.TempDir()`, compared with `testutil.GatherAndCompare` (`-update` regenerates).
   One scenario, three surfaces: if they disagree, D11 is broken and one of the three tests fails.
4. **Scrape test** (`TestMetricsScrape`): real `messq serve` on a Unix socket,
   `testutil.ScrapeAndCompare` over HTTP, plus a concurrent-scrape test asserting single-flight
   (query count == 1 per TTL for 20 simultaneous scrapes) and `503` above `MaxRequestsInFlight`.
5. **Cardinality suite** (`TestMetricsCardinality`, `TestMetricsLint`): allow-list over
   `reg.Gather()`, enum-value subset check, `CollectAndLint`, and the `messq_sabotage` meta-test
   proving a subject-labelled metric fails CI.
6. **Property test** (`rapid`, reusing #13's reference model — invariant **M1**): after every random
   publish/fetch/ack/nak/term/timeout/seek/purge/**restart** action, gather the registry and assert
   `messq_pending`, `messq_inflight`, `messq_backlog` and `messq_dlq_depth` equal the model's
   independently computed values, and that counter deltas equal the model's transition counts.
   This is the real proof of "recomputed from truth cannot drift"; failfiles committed.
7. **Fault tests**: fault point between event construction and commit (`messq_fault`, #32's grammar)
   → counters unchanged; read pool returning `SQLITE_BUSY`/`context deadline exceeded` → stale
   snapshot served, error counter up, scrape still 200; #6's EIO latch → `messq_readonly=1` while
   `/metrics` keeps answering.
8. **Integration — restart & purge** (`TestGaugesSurviveRestart`): fill, kill -9, restart, scrape;
   gauges match a direct SQL count. Then purge half the stream and scrape again.
9. **Artifact tests**: `promtool check rules` + `promtool test rules` in the observability CI job
   (pinned, checksummed binary); the metric-name anti-rot test over `alerts.yml` and `messq.json`;
   JSON parse + datasource-variable assertion for the dashboard; `docs/metrics.md` ⇄ `catalogue.go`
   equivalence.
10. **testscript** (`metrics.txtar`, into #26's suite): `messq serve` → publish → `curl /metrics` →
    assert the documented names are present — the documentation-cannot-rot rule applied to §9.4.
11. **Benchmarks**: `BenchmarkProjectEvent` (per-event fan-out cost, must stay allocation-free after
    the label cache warms), `BenchmarkCollect` at 10³/10⁵/10⁶ delivery rows, and a bench-run overlay
    measuring throughput with and without a 5 s scrape (< 2 % delta). Numbers feed #31's published
    methodology.
12. **Manual acceptance, recorded in the PR**: the load generator pointed at a local Prometheus +
    Grafana, a screenshot of `contrib/grafana/messq.json` with all four rows populated, and one
    alert deliberately fired by stopping a worker.

**Not tested here**: event emission itself (#19), trace rendering (#20), the disk-pressure state
