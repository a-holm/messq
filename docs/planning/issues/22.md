## Context

By the end of M5 the daemon is complete and honest: a durable store (#5–#8), a delivery engine with
fenced settles and dead-lettering (#9–#13), the full HTTP surface (#14, #15), auth (#16), lifecycle
(#17), the frozen contract (#18), and the event/trace/metrics story (#19–#21). Every one of those is
reachable only with `curl` or Go test code. **M6 is where a human and a program get to use it**, and
this issue is the root of M6's dependency tree: `pkg/client` is what #23 builds the cobra chassis on,
and therefore what #24, #25, #26, #28, #29, #30 and #31 all ultimately speak.

Governing PLAN.md material:

- **D14 — client libraries.** *"One thin Go package, used by the CLI itself… The CLI consumes
  `pkg/client`, which guarantees the client is real without maintaining an SDK surface; it ships a
  `Worker` helper (auto-extend heartbeats — the #1 at-least-once footgun solved in the library)."*
  Both halves are load-bearing and both are testable: **the CLI must not contain a second HTTP
  client** (a lint enforces it), and **the heartbeat must live here**, not in every user's code.
- **§6 Delivery semantics.** At-least-once, consumers must be idempotent, and *"the recommended
  consumer-side dedup key is `stream/seq`… not `msg_id`"*. The client hands that key to the user as
  a method, so the documented right answer is the easy answer.
- **D7 — plain fenced tokens.** `stream/consumer/seq/attempt/generation`. A worker that acks a token
  whose attempt has moved on gets `409 stale_ack`, which is *the* observable symptom of "my job ran
  twice". A `Worker` that produces stale acks under normal operation would be shipping the bug the
  fence exists to reveal.
- **§5.1 T7 (`extend`)** — `visible_at += ack_wait`, attempts unchanged, capped at `--max-ack-wait`
  (1 h). The `Worker`'s lease keeper implements exactly this transition client-side, and T7's cap is
  why it must have a defined give-up behaviour.
- **§5.1 T9 / §4.4 recovery** — a broker restart flips INFLIGHT rows to READY without touching
  `attempts`; the next claim increments. So after a restart, **every token a worker still holds is
  stale by construction**. The acceptance criterion "survives a daemon restart mid-batch with zero
  lost work and zero stale-ack surprises" is a statement about how this package reacts to T9.
- **D2 / §7 API** — HTTP/1.1 + JSON, long-poll pull, one error envelope with a closed machine-code
  enum that is *"part of the 1.0 compatibility contract"*, Unix socket by default.
- **§13 library choices** — `≤ 8 direct non-test deps`. This package adds **zero**: stdlib only.

What it unlocks: **#23** (the cobra root renders this package's typed errors as teaching errors and
maps its error classes to the exit-code contract) and, through #23, the whole of M6, M7's operator
commands and #31's load generator. Python/TypeScript snippets (D14's other half) are docs work in
#35, tested against the daemon rather than against this package.

## Design proposal

> A proposed starting point, not a mandate — **except** the three items marked **_decision_**, which
> are cheap now and expensive after #23–#31 have built on them, and the exported API surface, which
> is public (`pkg/`) and therefore subject to Go compatibility expectations from the day #35 links
> to it.

### 0. Budget and constraints

| Constraint | Value | Why |
|---|---|---|
| Direct dependencies | **0** (stdlib only) | §13's dep budget; a client that pulls `modernc.org/sqlite` into a user's binary is absurd |

### 2. Construction, addresses and transport

```go
func New(addr string, opts ...Option) (*Client, error)

func WithHTTPClient(*http.Client) Option   // caller owns transport, timeouts, TLS (#40)
func WithCredential(Credential) Option     // Bearer msq1_<id>_<secret> (#16)
func WithUserAgent(string) Option          // default "messq-client/<version> (go<ver>)"

func WithRequestTimeout(time.Duration) Option // control plane only; default 30s
func WithClock(Clock) Option               // unexported-interface seam for tests (#3's Clock shape)
```

| Address form | Result |
|---|---|
| `unix:///run/messq/messq.sock` | `DialContext` → `net.Dial("unix", path)`; URL host is the fixed sentinel `messq.invalid`, path from the URL |
| `/run/messq/messq.sock` or `./messq.sock` | Same; a bare path is a Unix socket (what an operator types) |
| `http://127.0.0.1:4390` / `https://…` | Standard transport |
| `tcp://127.0.0.1:4390` | Rewritten to `http://` — `--listen` speaks `tcp://` (#14), so the client accepts it |
| anything else | `ErrBadAddress` naming the four accepted forms |

**Transport defaults when the caller does not supply an `*http.Client`:**

```go
tr := &http.Transport{
    DialContext:           dial,     // unix or tcp
    Proxy:                 nil,      // NEVER ProxyFromEnvironment — see edge cases
    ForceAttemptHTTP2:     false,
    MaxIdleConns:          64,
    MaxIdleConnsPerHost:   64,       // stdlib default of 2 causes a new conn per concurrent fetch
    IdleConnTimeout:       90 * time.Second,
    ResponseHeaderTimeout: 0,        // a long poll's headers arrive at wait_ms
    ExpectContinueTimeout: 1 * time.Second,
}
hc := &http.Client{
    Transport:     tr,
    Timeout:       0,                // per-request context deadlines instead
    CheckRedirect: func(*http.Request, []*http.Request) error { return ErrRedirect },
}
```

Three of those are bug-prevention, not tuning:

- **`Timeout: 0`.** A `http.Client.Timeout` shorter than a long poll turns every idle fetch into a
  spurious error. If a caller passes their own client, `New` **refuses** when
  `hc.Timeout > 0 && hc.Timeout <= defaultFetchWait`, naming the fix; the `Worker` re-checks against
  its configured `Wait` at `Run` time.
- **`Proxy: nil`.** A `HTTP_PROXY` silently routing a localhost broker call through a corporate proxy
  is a classic half-day debugging session, and for `unix://` it is nonsense. Opt in with
  `WithProxy(http.ProxyFromEnvironment)`.
- **No redirects.** Following one would forward the bearer credential to an arbitrary host (#16's
  "the credential never rides a redirect"). `ErrRedirect` is a typed refusal.

### 3. Types — **_decision 1: `pkg/client` owns its own types; the server keeps its own_**

The tempting move is a shared `internal/wire` package (permitted by #1's layer rules) so the server
and client cannot drift. We decline: sharing the structs means every response field `internal/api`
adds appears in the client's **public** API at the same instant, and every rename becomes a breaking
change for external importers. The wire is the contract (#18 froze it); the structs are two
independent readings of it, cross-checked by a test that decodes #18's committed goldens.

```go
type Msg struct {                     // what you publish
    Subject string
    Body    []byte
    Header  map[string]string         // user headers → Messq-Header-*; "Messq-" prefix rejected locally
    MsgID   string                    // → Messq-Msg-Id (publish dedup, §5.1)
    TraceID string                    // → Messq-Trace-Id; empty ⇒ server mints
}

type PublishAck struct {
    Stream      string    `json:"stream"`
    Seq         int64     `json:"seq"`
    ID          string    `json:"id"`          // ULID (D10)
    TraceID     string    `json:"trace_id"`
    Duplicate   bool      `json:"duplicate"`   // dedup hit — not an error
    PublishedAt time.Time `json:"-"`           // from published_at (unix ms)
}

type Delivered struct {                        // what you consume
    Stream, Consumer string
    Seq         int64             `json:"seq"`
    ID          string            `json:"id"`
    Subject     string            `json:"subject"`
    Header      map[string]string `json:"headers,omitempty"`
    Body        []byte            `json:"body_b64"`   // encoding/json base64-decodes []byte for free
    Size        int64             `json:"size"`
    Attempt     int               `json:"attempt"`
    MaxDeliver  int               `json:"max_deliver"` // 0 = unlimited
    AckToken    string            `json:"ack_token"`
    DeadlineMS  int64             `json:"deadline_ms"` // server wall clock — see §7.3
    AckWaitMS   int64             `json:"ack_wait_ms"` // a duration: skew-free, and what we use
    PublishedAt int64             `json:"published_at"`
    TraceID     string            `json:"trace_id"`

    lease *lease // unexported: set by Worker; nil for a raw Fetch
}

// DedupKey is the key PLAN §6 tells consumers to use: stable across every redelivery and redrive.
func (d *Delivered) DedupKey() string { return d.Stream + "/" + strconv.FormatInt(d.Seq, 10) }

// AttemptOf renders "2/5" or "2/∞" for max_deliver = 0.
func (d *Delivered) AttemptOf() string
```

`Body []byte` with the `body_b64` tag is not a shortcut — `encoding/json` marshals `[]byte` as
base64 and unmarshals it back, so the wire's uniform binary-safe shape costs the user nothing and
there is no hand-rolled base64 to fuzz.

### 4. Errors

```go
type Error struct {
    Code      string            // closed enum (#14); UNKNOWN CODES ARE PRESERVED, NOT REJECTED
    Message   string
    Next      []string          // teaching-error "what to type next" (§8) — rendered verbatim by #23
    Detail    map[string]any
    TraceID   string
    Status    int               // HTTP status
    RequestID string            // Messq-Request-Id
    RetryAfter time.Duration    // parsed from Retry-After when present
}
func (e *Error) Error() string
func (e *Error) Is(target error) bool   // maps Code → sentinel

var (
    ErrBadRequest, ErrNotFound, ErrConflict, ErrStaleAck, ErrWrongGeneration,
    ErrUnauthorized, ErrForbidden, ErrTooLarge, ErrReadOnly, ErrShuttingDown,
    ErrBusy, ErrNotReady, ErrCommitUnknown, ErrDiskFull, ErrStreamFull error
    ErrUnreachable error // transport-level: dial refused, socket missing, EOF, timeout
    ErrBadAddress, ErrRedirect, ErrConfig error
)

type Kind uint8 // KindOK KindUsage KindNotFound KindConflict KindPermission
                // KindUnavailable KindTimeout KindEmpty KindInternal
func Classify(err error) Kind
```

**_Decision 2: the client is lenient about server output; the server is strict about client input._**
#14 decodes requests with `DisallowUnknownFields` so a misspelled `wait_ms` is a loud `400`. This
package does the **opposite** on responses: unknown fields are ignored and an unknown `code` yields
an `*Error` with `Code` preserved and matching no sentinel. A minor daemon release must be able to
add a response field or a new error code without breaking every deployed worker; a client that
refuses to parse the future is a client that pins the daemon version. Documented in `doc.go`, and
tested by decoding a golden with three injected unknown fields.

`Classify` exists so #23 owns the exit-code *policy* (0/1/2/3/4/5/6/7) while this package owns the
*classification*. The mapping table lives in #23; a test there asserts every `Kind` has an exit code.

```go

func (c *Client) PublishBatch(ctx context.Context, stream string, msgs []Msg) ([]PublishAck, error)

func (c *Client) Fetch(ctx context.Context, stream, consumer string, req FetchRequest) (FetchResponse, error)

func (c *Client) Ack(ctx context.Context, tokens ...string) (SettleResult, error)
func (c *Client) Nak(ctx context.Context, token string, opts ...SettleOption) (ItemResult, error)
func (c *Client) Term(ctx context.Context, token, reason string) (ItemResult, error)
func (c *Client) Extend(ctx context.Context, tokens ...string) (SettleResult, error)

func WithDelay(time.Duration) SettleOption   // nak only; overrides the backoff schedule (T4)
func WithReason(string) SettleOption         // truncated to 4 KiB client-side (#10's --max-reason-bytes)
```

```go
type FetchRequest struct {
    Batch    int           // 0 ⇒ 1 (the server's default; a naive caller gets one message)
    Wait     time.Duration // 0 ⇒ single-shot
    MaxBytes int64
}
type FetchResponse struct {
    Messages   []Delivered
    Hold       HoldReason    // "" | "no_messages" | "flow_control" | "max_ack_pending" | "backoff" | "paused" | "shutting_down"
    RetryAfter time.Duration
    Pending, Backlog int64
    Batch      int           // EFFECTIVE values echoed by the server after clamping
    MaxBytes   int64
    Wait       time.Duration
}
```

Three rules:

- **`PublishBatch` never silently splits.** Over the server's batch cap it returns `ErrTooLarge`
  naming the limit. The caller asked for one transaction (#14's `messages:batch`); quietly turning
  it into three would break the property they wanted. `MaxBatch(msgs, n) [][]Msg` is provided so
  chunking is explicit and visible in the caller's code.
- **A publish is retried automatically only when `MsgID != ""`.** On `503 commit_unknown` (#6: the
  commit may or may not have succeeded) or a transport error after the request was written, a retry
  without a dedup key can duplicate. With one, the retry is exactly the pattern §5.1 prescribes and
  a duplicate comes back as `Duplicate: true`. Without one, the error is returned with
  `next: ["set Messq-Msg-Id to make this publish retry-safe"]`.
- **Settle calls return per-token results even on a 4xx.** #10 guarantees `results` is present on
  every response including the all-failed `409`. So `SettleResult.Results` is authoritative
  per token and `err` reflects the request-level verdict; the `Worker` reads the results and ignores
  the status. A client that only looked at the status could not tell "3 acked, 1 fenced" from
  "nothing happened".

### 7. The `Worker`

```go
type Handler func(ctx context.Context, m *Delivered) error

type WorkerConfig struct {
    Stream, Consumer string
    Concurrency  int            // default 1
    Batch        int            // default 0 ⇒ min(free slots, server cap)
    Wait         time.Duration  // long-poll wait, default 30s
    Prefetch     bool           // default false — see §7.4
    ExtendAt     float64        // fraction of ack_wait; default 0.5 (PLAN §8: ack_wait/2)
    MaxLease     time.Duration  // stop extending after this much total; default 0 ⇒ server cap (T7, 1h)
    OnLeaseLost  LeasePolicy    // CancelHandler (default) | Continue
    OnPanic      PanicPolicy    // NakAndContinue (default) | Term | Repanic
    AckWindow    time.Duration  // coalesce settles; default 5ms (0 disables)
    Backoff      BackoffConfig  // 100ms → 30s, ×2, ±20% jitter, always jittered
    DrainTimeout time.Duration  // default 30s
    OnEvent      func(WorkerEvent)
    Logger       *slog.Logger   // optional; nil ⇒ silent
}

func (c *Client) NewWorker(cfg WorkerConfig) (*Worker, error)
func (w *Worker) Run(ctx context.Context, h Handler) error  // blocks until ctx done or fatal
func (w *Worker) Drain(ctx context.Context) error           // stop fetching, finish + settle, return
func (w *Worker) Stats() WorkerStats
```

#### 7.1 Goroutine census (complete — the PLAN §3.2 discipline, applied client-side)

```
Run(ctx)
 ├─ fetcher   ×1   long-poll; batch = free slots; honours Hold + Retry-After; jittered reconnect
 ├─ leases    ×1   min-heap of (nextExtendAt, token) → ONE batched POST /v1/extend per 250ms window
 ├─ settler   ×1   coalesces ack/nak/term into batched requests (AckWindow / 256 tokens)
 └─ handlers  ×N   Concurrency slots; each runs handler(ctx, msg) with a per-message cancellable ctx
```

`3 + Concurrency` goroutines, fixed for the lifetime of the worker. **No goroutine per message and
no timer per message** — the same choice D5 made server-side, for the same reason: at concurrency 64
a per-message heartbeat goroutine means 64 goroutines and 64 HTTP requests every `ack_wait/2`, where
one heap and one batched request will do.

#### 7.2 Handler outcome mapping

| Handler returns | Action | Reason field |
|---|---|---|
| `nil` | `Ack(token)` | — |
| `err` where `errors.Is(err, ErrPermanent)` | `Term(token, reason)` → straight to DLQ (T6) | `err.Error()`, ≤ 4 KiB |
| `RetryAfter(d, err)` | `Nak(token, WithDelay(d), WithReason(…))` (T4's explicit delay) | `err.Error()` |
| any other `err` | `Nak(token)` — server backoff schedule applies | `err.Error()` |
| panic | recovered; `OnPanic` policy (default `Nak`) + `OnEvent{PanicRecovered, Stack}` | `"panic: …"` |
| handler still running at `MaxLease` | ctx cancelled, then `Nak` with `reason="lease expired"` | — |
| lease already lost | **nothing is sent** — see §7.5 | — |

```go
var ErrPermanent = errors.New("messq: permanent handler failure")
func Permanent(err error) error                       // wraps, so errors.Is(…, ErrPermanent) is true
func RetryAfter(d time.Duration, err error) error     // carries an explicit nak delay
```

The reason string is the same 4 KiB budget #25's `--exec` gives a child's stderr, and lands in the
same place: `messq trace`, `deliveries.last_reason`, and the DLQ's `Messq-Last-Reason` header. *The
reason a job failed is visible from the queue, not only from the worker's logs* — that property is
established here and reused by #25.

#### 7.3 The lease keeper — the point of the whole helper

Per held message the worker tracks:

```go
type lease struct {
    token     string
    ackWait   time.Duration // from AckWaitMS — a DURATION, therefore skew-free
    localDeadline time.Time // monotonic; anchored at response receipt, NOT at DeadlineMS
    extends   int
    totalHeld time.Duration
    cancel    context.CancelCauseFunc
}
```

1. **Anchor the deadline locally, not from `deadline_ms`.** `deadline_ms` is the *server's* wall
   clock; a worker whose clock is 4 minutes fast would compute a deadline in the past and give up
   immediately, and one that is slow would extend too late. The client sets
   `localDeadline = responseReceivedAt + ackWait − requestElapsed` using `time.Now()`'s monotonic
   reading. `deadline_ms` is kept in `Delivered` for display and used only as a **skew detector**:
   if `|deadline_ms − (localDeadline as wall clock)| > ackWait/2`, fire `OnEvent{ClockSkew}` once
   per worker with both values. (`messq doctor`, #30, gets the same check from the other side.)
2. **Schedule the next extend at** `now + ackWait*ExtendAt`, clamped to
   `localDeadline − margin` where `margin = clamp(ackWait/10, 500ms, 5s)`. The margin covers one
   round trip plus the server's 250 ms sweeper tick; without it, an extend racing the sweeper is a
   coin flip that costs a duplicate delivery.
3. **Batch.** Every lease due within a 250 ms window goes into one `POST /v1/extend` with all its
   tokens. On success each lease's `localDeadline += ackWait` (T7) and it is re-pushed into the heap.
4. **Give up honestly.** When `totalHeld + ackWait > MaxLease` (or the server answers
   `capped: true` / `409 extend_capped`), stop extending, fire `OnEvent{LeaseCapped}`, and apply
   `OnLeaseLost`. Silently continuing to run a handler whose message the server is about to
   redeliver is how you get two workers on one job.
5. **Transport failures are retried inside the margin.** An extend that fails with `ErrUnreachable`
   is retried with the reconnect backoff until `localDeadline − margin`; past that the lease is
   presumed lost.

#### 7.4 Fetching and flow control

**_Decision 3: `batch` is bounded by free handler slots, not by `Concurrency`._** With
`Concurrency: 1` and `Batch: 64`, a naive worker claims 64 messages, works one, and lets 63 leases
expire — 63 redeliveries, 63 burned attempts, and a poison-message-shaped incident that is entirely
self-inflicted. So the fetcher computes `batch = min(cfg.Batch or ∞, freeSlots)` and does not fetch
at all when `freeSlots == 0`. `Prefetch: true` relaxes this (queued messages are heartbeated by the
same lease keeper, which is why it is central) and is off by default.

Hold handling — the difference between a well-behaved worker and a hot loop:

| `Hold` | Worker reaction |
|---|---|
| `""` / messages returned | Immediate next fetch (subject to free slots) |
| `no_messages` | Immediate re-fetch — the long poll already did the waiting |
| `flow_control` / `max_ack_pending` | Sleep `max(RetryAfter, 100ms)`, jittered; `OnEvent{Hold}`. Fire a **one-time warning** if `Concurrency > max_ack_pending` naming `messq consumer edit` |
| `backoff` | Sleep `RetryAfter` (the server knows when the next row becomes visible) |
| `paused` | Sleep `max(RetryAfter, 1s)` capped at 5s; `OnEvent{Hold}` every time — an idle worker whose consumer someone paused must be discoverable |
| `shutting_down` | Reconnect backoff; the daemon is draining and systemd will bring it back (#17) |

At `Run` start the worker issues **one** `GetConsumer` call: it validates that the consumer exists
(a clear `not_found` with `next` beats an infinite 404 loop), reads `ack_wait_ms` and
`max_ack_pending` for the warnings above, and reports them via `OnEvent{Started}`. A failure here is
retried with backoff, not fatal — the daemon may simply not be up yet.

#### 7.5 Restart, fencing and "zero stale-ack surprises"

This is the acceptance criterion, walked through:

1. Worker holds tokens `orders/w/{101..108}/1/1`; handlers are running.
2. `messq serve` is SIGKILLed. In-flight fetches/extends fail with `ErrUnreachable`.
3. The daemon restarts. Recovery (§4.4 step 3, T9) flips those rows to READY with jitter, **leaving
   `attempts` at 1**, and records `recovery.reclaimed`.
4. The lease keeper's next batched extend succeeds at the HTTP level and returns per-token
   `unknown` or `stale_ack` (once the sweeper/another fetch has re-claimed at attempt 2).
5. For each such token the worker: cancels that handler's context with cause `ErrLeaseLost`, fires
   `OnEvent{LeaseLost, Reason}`, and **removes the token from the settle path entirely** — when the
   handler eventually returns, its outcome is dropped with `OnEvent{OutcomeDiscarded}`. **No ack, no
   nak, no term is ever sent for a lost lease.** That is what makes `messq_stale_acks_total` a
   meaningful alert (§9.4: *"alert on any nonzero rate"*) instead of background noise every worker
   generates on every deploy.
6. The message is redelivered exactly once, with `cause=broker_restart` in the events table, so
   `messq trace` shows the duplicate with a named cause (I9). Zero work lost; the handler's partial
   work is redone, which is precisely the at-least-once contract §6 states.

The mirror case — the **ack** is in flight when the daemon dies — is UNKNOWN in #8's three-valued
sense. The worker retries the ack up to `AckRetries` (3, backed off); T3a makes a repeat ack an
idempotent success flagged `stale`, so retrying is always safe. If it still fails, `OnEvent{AckLost}`
fires and the worker moves on: the message redelivers, `messq trace` says `msg.timeout`, and the
handler's idempotency (keyed on `DedupKey()`) absorbs it. Never fatal.

#### 7.6 Drain

`Drain(ctx)` and a cancelled `Run` ctx do the same three things in order: stop fetching; cancel
nothing yet and let handlers finish within `DrainTimeout` (leases keep being extended throughout);
settle everything that completed. Whatever is still held when `DrainTimeout` expires is
**naked with `reason="worker draining"` and `delay=0`** rather than abandoned. Abandoning costs a
full `ack_wait` (30 s by default) of dead time on a rolling deploy; a nak makes the work visible to
the next worker immediately, and both are I9-clean because both have a named cause.

#### 7.7 Observability hook

```go
type WorkerEvent struct {
    Kind      EventKind // Started Fetched Handling Acked Naked Termed Extended
                        // LeaseLost LeaseCapped StaleAck Hold Reconnect
                        // PanicRecovered AckLost HandlerTimeout ClockSkew OutcomeDiscarded Drained
    Msg       *Delivered
    Err       error
    Duration  time.Duration
    Hold      HoldReason
    Attempt   int
    Stack     []byte    // PanicRecovered only
}
```

The names are deliberately §9.2's vocabulary, so a worker's log line and the broker's event row use
one word for one thing. The hook takes no dependency: `Logger` is an optional `*slog.Logger`, and #25
renders the same events as human lines. `Stats()` returns counters
(`Fetched/Acked/Naked/Termed/Extends/LeaseLost/StaleAcks/Reconnects`) for #31 to sample.

### 8. Credentials

```go
type Credential struct{ /* opaque */ }
func TokenCredential(s string) Credential
func CredentialFromFile(path string) (Credential, error)
func TokenFromEnv() (Credential, bool)   // MESSQ_TOKEN; helper, NOT read automatically
func AddrFromEnv() (string, bool)        // MESSQ_ADDR;  helper, NOT read automatically
```

- `Credential` implements `fmt.Stringer`, `fmt.Formatter`, `slog.LogValuer` and `json.Marshaler`,
  all returning `msq1_<id>_***` — the same five-interface redaction #16 requires, and `pkg/client`
  is one of the two packages exempted from the `forbidigo` ban on `.Reveal()`.
- `CredentialFromFile` implements #16's frozen client contract: a 0600 file whose **entire trimmed
  content is one credential**. A file whose first line has four whitespace-separated fields is the
  *server's* `--auth-file`; the error says exactly that, because confusing the two is the predictable
  mistake. A file mode wider than 0600 is a warning through `OnEvent`, not a refusal (CI checkouts).
- **The package reads no environment variables on its own.** A library that silently picks up
  `MESSQ_TOKEN` surprises the one caller who did not want it; #23 calls the helpers explicitly and
  owns the three-layer precedence.

| Setting | Default | Notes |
|---|---|---|
| `Concurrency` / `Wait` / `DrainTimeout` | `1` / `30s` / `30s` | `Wait` must stay under the server's `--max-fetch-wait` (5m) |
| `ExtendAt` | `0.5` | PLAN §8: heartbeat at `ack_wait/2` |

| `AckWindow` | `5ms` (max 256 tokens) | Mirrors the server's group commit (D4) |
| `MaxLease` | server cap (1 h, T7) | An explicit smaller value wins |
| reconnect backoff | `100ms → 30s`, ×2, **±20 % jitter always** | The §5.1 jitter rule, applied client-side |
| `AckRetries` / `MaxResponseBytes` | `3` / `64 MiB` | T3a makes ack repeats idempotent; a rogue proxy must not OOM a worker |
| control-plane request timeout | `30s` | Never applied to `Fetch` |

### 10. Edge cases, decided

| Case | Handling |
|---|---|
| Caller's `http.Client.Timeout` ≤ fetch wait | `New`/`Run` refuse with `ErrConfig` naming the timeout and the wait — never a mysterious `context deadline exceeded` per long poll |
| `HTTP_PROXY` set, `unix://` address | Ignored: `Proxy: nil` by default; opt in with `WithProxy` |
| Server responds with a redirect | `ErrRedirect`; the credential is never re-sent |
| Response body not fully read | Every path drains up to `MaxResponseBytes` then closes, so connections are reused (`bodyclose` lint from #2 covers the rest) |
| Unknown JSON fields / unknown error `code` | Ignored / preserved (Decision 2) |
| `Fetch` ctx cancelled mid-poll | Returns `ctx.Err()`. **Messages may already have been claimed** (#14 §6.6) and will redeliver at `ack_wait` — documented in `doc.go`, and the reason `Drain` exists instead of "just cancel the context" |
| Zero-length body | `Body` is a non-nil empty slice, never `nil`; round-trips exactly |
| User header starting with `Messq-` | Rejected locally with `ErrBadRequest` before the round trip (the server's reserved namespace, §5.1) |
| `Duplicate: true` on publish | Success, not an error; `PublishAck.Seq`/`ID` are the *original* message's |
| `PublishBatch` over the server cap | `ErrTooLarge`; use `MaxBatch` to chunk explicitly |
| `max_deliver = 0` (unlimited) | `AttemptOf()` renders `2/∞`; no client-side attempt logic anywhere |
| Handler ignores its cancelled ctx and blocks forever | After `MaxLease`, the slot is marked lost, a nak is sent, `OnEvent{HandlerTimeout}` fires and `Stats().LeakedHandlers` increments. The goroutine is **not** killed (Go cannot) — the honest report beats a fake guarantee |
| Two `Worker`s on the same consumer | Fully supported (D15: acks are fenced, so multiple workers per consumer already works). Each holds its own leases; `max_ack_pending` is the shared bound |
| `Concurrency > max_ack_pending` | One-time warning at `Run` start naming `messq consumer edit`; the worker still runs (it will just idle on `flow_control`) |
| Consumer deleted while the worker runs | Fetch returns `404 not_found`; the worker retries with backoff and fires `OnEvent{Hold}` — a redeploy that recreates the consumer heals without a restart. `FailFast: true` turns it fatal |
| Daemon latched read-only (#6 fsyncgate) | Publishes and fetches get `503 read_only`; the worker backs off. Acks also fail — the worker keeps retrying because the daemon exits and systemd restarts it into recovery |
| `429 rate_limited` (reserved for #39) | Honoured generically via `Retry-After`; no #39-specific code needed today |
| Clock skew between worker and broker | Detected and reported once (§7.3); never used for scheduling |
| A `nak` returns `dead: true` | The message just entered the DLQ (T5); `OnEvent{Naked, Dead:true}` so a worker can log "this one is dead" without polling the DLQ |

## Acceptance criteria

- [ ] `pkg/client` compiles with **zero non-stdlib imports** and **zero `internal/…` imports**;
      `scripts/layers.sh` (#1) enforces both and fails on a new one.
- [ ] **`internal/cli` does not import `net/http`** (lint-enforced) — D14's "the CLI consumes
      `pkg/client`" is a build gate, not a convention.
- [ ] `New` accepts `unix://`, a bare socket path, `http://`, `https://` and `tcp://`, rejects
      anything else with `ErrBadAddress` naming the accepted forms, and refuses a caller-supplied
      `*http.Client` whose `Timeout` would cut a long poll short.
- [ ] The default client never follows a redirect, never consults proxy environment variables, caps
      response bodies at `MaxResponseBytes`, and drains + closes every response body (asserted by a
      transport that counts unclosed bodies across the whole test suite).
- [ ] Every route in #14/#15 has a method here; a test iterates #15's route registry and fails on an
      unwrapped route or a wrapper whose method/path/query does not match its registry entry.
- [ ] Publish round-trips arbitrary binary bodies including 0 bytes; `Duplicate: true` is returned as
      success; a user header in the `Messq-` namespace is rejected locally with no round trip; a
      `commit_unknown` failure is retried automatically **iff** `MsgID != ""` and the retry returns
      `Duplicate: true` rather than a second `seq`.
- [ ] `Fetch` decodes `body_b64` into `Body` without a hand-rolled base64 path, exposes the
      **effective** (clamped) `Batch`/`MaxBytes`/`Wait` from the response, and surfaces every
      `HoldReason` value as a typed constant.
- [ ] `Delivered.DedupKey()` returns `stream/seq` and is stable across a redelivery **and** across a
      DLQ redrive of the same message (asserted end to end against a real daemon).
- [ ] Settle calls return per-token results on a `409` all-failed response, and `ItemResult.Status`
      distinguishes all five values (`ok`, `stale`, `stale_ack`, `wrong_generation`, `unknown`).
- [ ] Error decoding preserves `Code`, `Message`, `Next`, `Detail`, `TraceID`, `RequestID` and
      `Retry-After`; `errors.Is` works for every sentinel; an **unknown** `code` and unknown response
      fields decode without error (forward compatibility).
- [ ] `Classify` returns a `Kind` for every code in #14's closed enum plus transport errors; a test
      iterates the enum and fails on an unclassified code.
- [ ] **A 10-minute handler under a 30 s `ack_wait` completes with zero timeouts and zero
      redeliveries**, using ~19 extends, proven under `testing/synctest` with no `time.Sleep`.
- [ ] Extends are **batched**: with `Concurrency: 64` and a 60 s handler, the worker issues at most
      one `/v1/extend` request per 250 ms window and total request count is independent of
      concurrency (asserted by counting requests at a fake server).
- [ ] Goroutine count during a `Run` is exactly `3 + Concurrency` regardless of message volume, and
      returns to baseline after `Drain` (asserted, `-race`).
- [ ] `batch` never exceeds free handler slots with `Prefetch: false`: with `Concurrency: 1` and
      `Batch: 64`, no more than one message is ever in flight and no delivery ever times out.
- [ ] Handler-outcome mapping is exhaustive and asserted end to end against a real daemon: `nil`
      deletes the delivery row; `Permanent(err)` puts the message in `<stream>.dlq` with
      `Messq-Cause: terminated`; `RetryAfter(d, err)` produces `visible_at ≈ now + d`; a plain error
      uses the consumer's backoff schedule; a panic is recovered, naks, and **the worker keeps
      running**.
- [ ] Nak/term reasons reach `deliveries.last_reason`, the `msg.nak`/`msg.term` event `detail` and
      the DLQ's `Messq-Last-Reason` header, truncated at 4 KiB.
- [ ] **Zero stale-ack surprises:** a `SIGKILL` of `messq serve` mid-batch with 8 in-flight
      messages, followed by a restart, produces `messq_stale_acks_total == 0`, every message
      redelivered exactly once with `cause=broker_restart`, and every handler's outcome discarded
      via `OnEvent{OutcomeDiscarded}` rather than settled.
- [ ] **Zero lost work:** in the same scenario every message is eventually acked exactly once by a
      handler that ran to completion, verified with #8's three-valued ledger oracle.
- [ ] A lost lease cancels the handler's context with cause `ErrLeaseLost` within one extend window,
      and **no ack/nak/term is ever sent for that token afterwards** (asserted by a request-recording
      server, not by inspecting worker internals).
- [ ] An ack lost to a daemon restart is retried up to `AckRetries` and, if still lost, reported as
      `OnEvent{AckLost}` without failing `Run`.
- [ ] `Drain` stops fetching, lets in-flight handlers finish (extending throughout), settles their
      outcomes, and **naks whatever remains** with `reason="worker draining"` — measured as
      "redelivery begins in < 1 s", not after `ack_wait`.
- [ ] Every `HoldReason` produces the documented backoff instead of a hot loop: a paused consumer
      yields ≤ 1 fetch/second and at least one `OnEvent{Hold}` per attempt (asserted with a request
      counter under `synctest`).
- [ ] `Concurrency > max_ack_pending` emits exactly one warning event naming `messq consumer edit`.
- [ ] Clock skew of ±5 minutes between the worker's fake clock and the daemon changes neither the
      extend schedule nor the outcome; `OnEvent{ClockSkew}` fires once.
- [ ] `Credential` cannot be leaked through `%v`, `%s`, `%#v`, `slog.Any` or `json.Marshal`; a CI
      canary test greps the whole worker log output for the secret and finds nothing.
- [ ] `CredentialFromFile` rejects a server `--auth-file` with an error that says which file it
      needs instead.
- [ ] The exported API surface is snapshotted (`go doc -all` golden); a change to it is a visible
      diff in the PR, and `doc.go` states the compatibility promise for `pkg/`.
- [ ] Godoc examples (`Example_publish`, `Example_worker`, `Example_shellParity`) compile and run in
      CI against a real daemon.
- [ ] Non-test LOC in `pkg/client` is under ~900 (reported by `make ci`, advisory not fatal);
      coverage floors from #2 hold.

## Test plan

Per PLAN §11 / D13: `-race` everywhere, no `time.Sleep` outside soak, all timing via
`testing/synctest` or the Clock seam, every fixed bug landing with a committed reproduction artifact.

**Unit — transport and codec (`httptest` fake broker)**
- Address parsing table: every accepted form plus `ftp://`, `unix://` with an empty path, `http://`
  with a path prefix, IPv6 literals, a bare relative path.
- Transport policy: redirect refused; proxy env ignored; oversized response truncated with
  `ErrTooLarge`; body always closed (a wrapping `RoundTripper` counts opens vs closes and fails on
  any imbalance across the package's whole test run).
- Error decoding table: one case per code in #14's enum + an unknown code + a malformed envelope +
  a non-JSON 502 from a proxy (must become `*Error{Status:502}`, never a JSON parse panic).
- Forward compatibility: #18's goldens with three injected unknown fields decode identically.
- Credential redaction across all five interfaces.

**Unit — worker logic (fake broker, `testing/synctest`)**
- Heartbeat schedule: `ack_wait` ∈ {1 s, 30 s, 1 h} × handler duration ∈ {0, ack_wait/4, 10×ack_wait}
  → assert extend times, counts, the margin clamp and the `MaxLease` give-up, in simulated time.
- Extend batching: 64 concurrent handlers ⇒ one request per window, independent of concurrency.
- Hold matrix: each `HoldReason` × `Retry-After` present/absent → assert sleep and events.
- Reconnect: connection refused → backoff is exponential, capped, and **always jittered** (asserted
  statistically over 1 000 simulated reconnects; §5.1's jitter rule is not optional).
- Outcome mapping table, including the panic policies and the discarded-outcome path.
- Drain: handlers finishing before/after `DrainTimeout`; leftovers naked.

**Property (`pgregory.net/rapid`, test-only dep)**
- A model of the worker driven against a scripted broker returning arbitrary interleavings of
  messages, holds, `stale_ack`, `unknown`, `503`s and hard connection drops. Invariants after every
  action: (a) in-flight ≤ `Concurrency`; (b) never settle a token whose lease was reported lost;
  (c) every fetched token reaches exactly one of {settled, discarded-with-event}; (d) extends only
  for currently held tokens; (e) no goroutine leak; (f) `Stats()` equals the recorded request
  history. Failfiles committed to `pkg/client/testdata/regressions/`.

**Integration — real daemon**
- End-to-end per handler outcome (ack / permanent→DLQ / retry-after / plain error / panic) asserting
  the resulting `deliveries` rows, DLQ contents, and the exact event sequence via `messq trace`.
- The full control-plane surface against #18's contract fixtures; a route in #15's registry without
  a client method fails the test.
- `DedupKey()` stability across a redelivery and a `dlq redrive` (#12/#29 fixtures).
- Two `Worker`s on one consumer, 10 000 messages: conservation holds and no message is
  handled-and-acked twice without a named cause in the events table.

**Crash (extends #8's harness)**
- `SIGKILL` mid-batch at named fault points, restart, and assert the §7.5 walk-through: zero lost
  work, `messq_stale_acks_total == 0`, exactly one redelivery per held message with
  `cause=broker_restart`.
- `SIGKILL` while an ack is in flight (the ledger's UNKNOWN class): the retry must resolve to OK or
  a named redelivery, never a stale ack.
- `systemctl restart`-style graceful drain (#17) under load: the worker sees `shutting_down`, backs
  off, and resumes with zero errors surfaced to the handler.

**Fuzz** (60 s per target in CI, corpus committed)
- Response envelope decoding (arbitrary bytes → never panic, always a typed error).
- Fetch response decoding (arbitrary JSON → never panic; `Body` never aliases decoder memory).
- Address parsing.

**Golden**
- Exported API surface (`go doc -all`) — a public-API change is a reviewable diff.
- The request stream a `Worker` produces for a fixed scenario, normalised (method, path, token
  ordering, body shape) — so a refactor that accidentally doubles the request rate is visible.

**Benchmarks**
- `BenchmarkWorkerThroughput/{1,8,64}` — messages/s end to end, and **HTTP requests per message**
  (target: → 1 as batch grows; extends ≈ 0 for sub-`ack_wait` handlers).
- `BenchmarkPublish/{1KiB,batch=1,64}` — the client-side overhead over #14's `BenchmarkPublishHTTP`.
- `BenchmarkLeaseHeap/10000` — the lease keeper at 10 000 held messages (what `Prefetch` makes
  reachable): allocation-free steady state.

**Not tested here:** CLI rendering, flags and exit codes (#23/#24), `--exec` child semantics (#25),
testscript goldens (#26), daemon-side endpoint behaviour (#14–#21).
