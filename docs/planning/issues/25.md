## Context

PLAN.md calls this **"the widest funnel in the product"** and it is the sentence that appears in
§1.2 *What messq is*:

> **CLI-first.** Every daemon capability is a subcommand. `messq sub jobs worker --exec ./h.sh`
> turns any shell script into a durable, retrying, dead-lettering worker with zero client code.

Everything before this issue built the machine: a durable store (#5–#8), a delivery engine with
fenced tokens, backoff and a DLQ (#9–#13), an HTTP surface (#14–#18), the event journal that makes
`trace` possible (#19–#21), a Go client with a `Worker` helper (#22) and a cobra command tree
(#23, #24). This issue is where a person with a `bash` script and no Go compiler gets all of it.

Governing PLAN.md material:

- **§8 CLI design, the `--exec` bullet** (normative for this issue):
  > `messq sub --exec`: payload on stdin, metadata in `MESSQ_*` env (+ `traceparent`); exit code is
  > the ack — `0` ack, `75` (EX_TEMPFAIL) nak-with-backoff, `65` (EX_DATAERR) term, other non-zero
  > nak; child stderr (first 4 KiB) becomes the nak reason visible in `trace` and the DLQ;
  > automatic `extend` heartbeat at `ack_wait/2` while the child runs.
- **§8 command signature** — `messq sub <stream> <consumer> [--exec CMD --concurrency N]
  [--auto-ack|--manual] [--count N]`. `--exec` is a *mode of `sub`*, not a new command.
- **D14 — one thin Go client, used by the CLI itself.** The `Worker` helper already owns the
  fetch/heartbeat/settle loop and *"auto-extend heartbeats — the #1 at-least-once footgun solved in
  the library"*. This issue must **not** re-implement any of it; `--exec` is a `Worker` handler that
  happens to fork a process.
- **§6 Delivery semantics** — at-least-once. A child that completes work and then loses its lease
  produces a duplicate; §9's design makes that case *named and visible* rather than silent
  (I9: *every duplicate has a named cause*).
- **§10 Security** — *"`--exec` is CLI-side only; the daemon has no exec capability."* The daemon is
  never the thing that forks.
- **§14 M6 exit criterion** — *"`--exec` is a production-viable worker."*
- **#10's `--max-reason-bytes` (4096)** and **#12's DLQ `Messq-Last-Reason` sanitiser (1 KiB)** were
  both sized against this issue's 4 KiB stderr capture. Those contracts are already fixed; this
  issue is the producer on the other end of them.

What it unlocks: **#26** — `messq quickstart` demonstrates a real worker, the README's headline
command becomes a testscript golden, and the `.txtar` suite gets its most valuable subject. It is
also the feature the 1.0 docs (#35) lead with and the one `messq bench` (#31) measures fork/exec
overhead against.

## Scope

### In scope

- The `--exec` branch of `messq sub`: flag surface, validation, mutual-exclusion rules.
- `internal/cli/exec` — the child-process runner: spawn, stdin payload, `MESSQ_*` environment,
  `traceparent`, stderr capture, timeout and kill escalation, process-group cleanup.
- The **exit-code → transition mapping** as a pure, table-tested function, including
  killed-by-signal and spawn-failure cases.
- Wiring the runner into #22's `client.Worker` so heartbeats, settle calls and reconnect are the
  library's job, not the CLI's.
- **Lease-loss handling**: when the heartbeat can no longer hold the message, the child is killed
  and nothing is settled with a dead token.
- `--concurrency` and its clamp against the consumer's `max_ack_pending` (and against `ordered`
  consumers when #38 lands).
- Per-message rendering in all three output modes (#23's contract), the end-of-run summary, and the
  **one-time exit-code hint** on the first non-zero child exit.
- Signal handling for the `messq sub --exec` process itself (drain vs. abort).
- `docs/exit-codes.md` content for the child-side contract (the help topic itself is #26's).
- Tests: unit + fuzz on the pure parts, `testing/synctest` on the timing, a hermetic fake child, a
  live-daemon integration suite, and the first `.txtar` scripts for `--exec`.

- `client.Worker`, its heartbeat scheduler, reconnect/backoff, and the `Retry`/`Terminate` error

- Cobra chassis, `--addr/--output/--token-file`, exit codes, teaching-error rendering, TTY

- Server-side nak/term semantics, backoff maths, reason truncation, `msg.nak`/`msg.term` events →
  **#10**; dead-lettering and `Messq-Last-Reason` sanitisation → **#12**.
- A packaged `messq-worker@.service` systemd template for supervising workers → **#36**.
- Delayed delivery / child-controlled nak delay (`Messq-Deliver-At`) → **#37**.
- Ordered-by-subject concurrency capping is *declared* here and *enforced properly* in **#38**.

## Design proposal

> Sketches are a concrete starting point, not a mandate. Three things **are** contracts because
> other issues and users depend on them: the exit-code table (§3), the `MESSQ_*` environment names
> (§4), and the JSON per-message record (§9).

### 1. Package layout and the one architectural rule

```
internal/cli/
  sub.go              #24's command; gains a `--exec` branch that builds an exec.Runner
  exec/
    runner.go         Runner, Options, Handle(ctx, msg) — the client.Worker handler
    child.go          spawn, stdin pump, stderr pump, WaitDelay, process-group kill
    outcome.go        Classify(*os.ProcessState, cause) → Outcome  (pure, table-tested)
    env.go            BuildEnv(msg, opts) → []string              (pure, fuzzed)
    reason.go         SanitizeStderr(b []byte, cap int) string     (pure, fuzzed)
    words.go          SplitWords(string) ([]string, error)         (pure, fuzzed)
    render.go         human / json / ndjson per-message lines + run summary
    hint.go           the one-time exit-code hint
    testdata/
```

**The rule:** `internal/cli/exec` contains **no** fetch call, **no** ack/nak/term/extend call and
**no** retry loop. It receives a message, runs a process, and returns an error that the `Worker`
translates into a settle. If a reviewer finds an HTTP call in this package, the design has been
violated — everything durable belongs to #22, which is already crash-tested and property-tested.

### 2. Flags

All flags live on `messq sub`; all take `MESSQ_*` env fallbacks through #23's three-layer
precedence (flag > env > default).

| Flag | Env | Default | Meaning |
|---|---|---|---|
| `--exec CMD` | `MESSQ_EXEC` | — | Command to run per message. Split with `SplitWords` (quotes/backslashes honoured; **no** expansion, globbing, pipelines or redirection). Enables exec mode. |
| `--exec-shell` | `MESSQ_EXEC_SHELL` | `false` | Run `CMD` via `$SHELL -c` (fallback `/bin/sh -c`). Opt-in, because "you own the quoting" is a different contract. |
| `--concurrency N` | `MESSQ_CONCURRENCY` | `1` | Max simultaneous children; also the fetch batch size. Clamped (§7). |
| `--exec-timeout D` | `MESSQ_EXEC_TIMEOUT` | `0` | Wall-clock cap per child. **`0` = "as long as the lease can be extended"** (§8). |
| `--exec-kill-grace D` | `MESSQ_EXEC_KILL_GRACE` | `10s` | Time between the stop signal and `SIGKILL`. |
| `--exec-signal SIG` | `MESSQ_EXEC_SIGNAL` | `TERM` | Signal sent to the child's process group when stopping it. |
| `--exec-dir PATH` | `MESSQ_EXEC_DIR` | cwd | Child working directory. |
| `--exec-env K=V` | — | (repeatable) | Extra environment for the child. |
| `--exec-clean-env` | `MESSQ_EXEC_CLEAN_ENV` | `false` | Child gets only `PATH`, `HOME`, `TZ`, `LANG` + messq's own vars. |
| `--exec-stdin body\|envelope` | `MESSQ_EXEC_STDIN` | `body` | `body` = raw payload; `envelope` = one JSON object `{stream,seq,id,subject,attempt,max_deliver,headers,trace_id,deadline,body_b64}` for `jq`-shaped workers. |
| `--exec-stdout inherit\|stderr\|discard` | `MESSQ_EXEC_STDOUT` | `inherit` (table) / `stderr` (json, ndjson) | Where the child's stdout goes. The default flips in machine-output modes so child chatter cannot corrupt the NDJSON stream (§9). |
| `--exec-stderr capture\|mirror\|both` | `MESSQ_EXEC_STDERR` | `both` | `capture` = reason only; `mirror` = messq's stderr only; `both` = default. |
| `--exec-stderr-capture head\|tail` | — | `head` | PLAN §8 says *first* 4 KiB; `tail` exists because the useful line of a stack trace is usually the last one. |
| `--stderr-bytes N` | `MESSQ_STDERR_BYTES` | `4096` | Capture cap; matched to the daemon's `--max-reason-bytes` (#10). Hard ceiling 64 KiB. |
| `--fail-fast` | `MESSQ_FAIL_FAST` | `false` | Stop the worker after the first non-`0` child exit (once that message is settled) and exit `1`. For cron/one-shot use. |
| `--no-hints` | `MESSQ_NO_HINTS` | `false` | Suppress the one-time exit-code hint. |

**Mutual exclusion** (usage error, exit `2`, teaching format):
`--exec` with `--manual` → *"--manual prints ack tokens for you to settle by hand; --exec settles
from the child's exit code. Pick one."*  `--exec` with `--auto-ack` → *"--exec already acks on exit
0; --auto-ack would ack before the child ran."*  `--exec-shell` without `--exec` → usage error.

### 3. The exit-code contract (normative)

| Child result | Transition | Reason recorded | Notes |
|---|---|---|---|
| exit `0` | **ack** | — | stderr is mirrored, never stored |
| exit `75` (`EX_TEMPFAIL`) | **nak** (consumer backoff) | captured stderr | the sysexits convention for "try later" |
| exit `65` (`EX_DATAERR`) | **term** | captured stderr | poison payload → straight to `<stream>.dlq`, remaining attempts skipped (T6) |
| any other non-zero | **nak** (consumer backoff) | `exit N` + captured stderr | ordinary failure |
| killed by signal *S* | **nak** | `killed by SIGTERM` + captured stderr | detected via `WaitStatus.Signaled()` |
| `--exec-timeout` / lease ceiling hit | **nak** | `exec timeout after 1h0m0s` + stderr | after the kill escalation completes |
| lease lost (extend refused / daemon gone) | **nothing** — abandon | logged locally, counted | §8; the token is dead, the sweeper redelivers |
| spawn failed at runtime (`EAGAIN`, `ENOMEM`) | **nak** with a 5 s delay | `could not start ./h.sh: …` | plus the circuit breaker below |

Two deliberate refinements over the persona plans:

1. **plan-01 mapped the whole `64`–`78` sysexits block to `term`.** Rejected: PLAN §8 names exactly
   two special codes, and terminating on `77` (`EX_NOPERM`) or `78` (`EX_CONFIG`) would dead-letter
   messages for an operator's misconfiguration — the worst possible outcome, because the *messages*
   are fine. Only `65` means "this payload is unprocessable". Everything else retries.
2. **`128+N` from a shell is not special-cased.** With `--exec-shell`, a signalled grandchild
   surfaces as exit `137`, which falls into "other non-zero → nak" — the same outcome as a directly
   signalled child, with different reason text. The mapping is defined on the *direct* child only,
   and the docs say so; inventing a `128+N` rule would make `exit 137` from a normal script mean
   something surprising.

**Spawn failures are an operator problem, not a message problem.** `exec.LookPath` runs **once at
startup, before the first fetch**: a typo'd path exits `1` with a teaching error and zero messages
consumed. Burning `max_deliver` on every message in the stream because of a missing binary is the
single worst failure mode this feature can have. At runtime, `--exec-max-spawn-failures`
(default 5) consecutive spawn failures stops the worker with exit `1`.

### 4. Child environment (contract)

Every value below is `MESSQ_`-prefixed, plus the lowercase W3C `traceparent`.

| Variable | Example | Source |
|---|---|---|

| `MESSQ_CONSUMER` | `worker` | fetch |
| `MESSQ_MSG_ID` | `01J8ZQ4K2M9V0X7Y3B5N6C8D1E` | ULID (D10) |
| `MESSQ_SEQ` | `10493` | the recommended consumer-side dedup key is `MESSQ_STREAM/MESSQ_SEQ` (§6) |
| `MESSQ_SUBJECT` | `orders.eu.created` | |
| `MESSQ_ATTEMPT` | `2` | durable attempt counter (D6) |
| `MESSQ_MAX_DELIVER` | `5` | |
| `MESSQ_REDELIVERED` | `1` | `attempt > 1`, for the common `if [ "$MESSQ_REDELIVERED" = 1 ]` check |
| `MESSQ_TRACE_ID` | `4bf92f3577b34da6…` | |
| `MESSQ_DEADLINE` | `2026-10-22T09:14:32.190Z` | current lease deadline (moves on each extend; the child sees the value at spawn) |
| `MESSQ_DEADLINE_MS` | `1761124472190` | epoch ms, for shell arithmetic |
| `MESSQ_PUBLISHED_AT` | `2026-10-22T09:14:02.114Z` | |
| `MESSQ_SIZE` | `1234` | payload bytes |
| `MESSQ_ACK_TOKEN` | `orders/worker/10493/2/1` | D7 tokens are human-readable on purpose; lets an advanced child call `messq extend`/`messq ack` itself |
| `MESSQ_HEADERS_JSON` | `{"Tenant":"acme"}` | lossless; the mangled vars below are the convenience form |
| `MESSQ_HEADER_TENANT` | `acme` | per user header, name mangled |
| `traceparent` | `00-4bf92f35…-1a2b3c4d5e6f7a8b-01` | W3C; span id minted per delivery |

Header-name mangling (`env.go`, pure + fuzzed): uppercase; every byte outside `[A-Z0-9]` → `_`; a
leading digit gets a `_` prefix. Edge cases and their rulings:

| Case | Ruling |
|---|---|
| `x-a` and `X.A` both mangle to `MESSQ_HEADER_X_A` | Sort header names; first wins; the loser is dropped with a **one-time** WARN naming both. `MESSQ_HEADERS_JSON` still has both — nothing is lost. |
| Header value contains a NUL (legal in JSON as ` `) | Cannot be an env value. Skipped, WARN once, present in `MESSQ_HEADERS_JSON`. |
| Header name mangles to the empty string | Skipped. |
| Header named `msg-id` | Becomes `MESSQ_HEADER_MSG_ID`. It structurally cannot collide with `MESSQ_MSG_ID` — the prefix is the namespace. |
| Parent env already contains `MESSQ_HEADER_*`, `MESSQ_SEQ`, … | **Stripped before building the child env.** A stale value inherited from the operator's shell must never masquerade as this message's metadata. `MESSQ_ADDR` / `MESSQ_TOKEN_FILE` are deliberately *kept*, so the child can call `messq` itself. |
| Payload in an env var or argv | **Never.** The body goes to stdin only (§10). A test asserts it. |

`MESSQ_CAUSE` (why this redelivery happened) is deliberately absent: the fetch response (#14) does
not carry it, and adding it is a wire change. It is in the events table; `messq trace` shows it.
Deferred as a possible #14 follow-up.

### 5. The runner (proposal)

```go
// internal/cli/exec — proposal, not mandate.

type Outcome uint8

const (
	OutcomeAck     Outcome = iota // exit 0
	OutcomeNak                    // 75, other non-zero, signal, timeout, spawn failure
	OutcomeTerm                   // 65
	OutcomeAbandon                // lease lost: settle nothing
)

type Result struct {
	Outcome   Outcome
	ExitCode  int            // -1 when the child was signalled
	Signal    syscall.Signal // 0 when it exited normally
	Reason    string         // sanitised stderr, ≤ StderrBytes, UTF-8 safe
	Truncated bool
	Duration  time.Duration
}

// Classify is pure: no clock, no I/O, no globals. One test row per §3 line.
func Classify(st *os.ProcessState, cause StopCause, stderr string) Result

type Runner struct {
	Opts  Options
	Clock clock.Clock // #3's seam — synctest drives every timeout in tests
	Out   Renderer
	Hint  *hint.Once
}

// Handle is the client.Worker handler. One message, one child, one outcome.
func (r *Runner) Handle(ctx context.Context, m *client.Msg) error {
	res := r.run(ctx, m)          // spawn → pump → wait → classify
	r.Out.Message(m, res)         // human line or JSON record
	if res.ExitCode != 0 || res.Signal != 0 {
		r.Hint.Print()            // one-time exit-code explainer
	}
	switch res.Outcome {
	case OutcomeAck:
		return nil
	case OutcomeTerm:
		return client.Terminate(errors.New(res.Reason))
	case OutcomeNak:
		return client.Retry(errors.New(res.Reason))   // server-side backoff, no --delay
	default:
		return client.ErrAbandon                       // Worker settles nothing
	}
}
```

**The one API request to #22:** the handler must be able to say *"do not settle this"*. Two shapes
work — a `client.ErrAbandon` sentinel, or `Worker` treating a handler return of `ctx.Err()` as
abandon when it cancelled the context itself. Prefer the latter (it needs no new API and is the
natural mechanism, see §8) and keep `ErrAbandon` as the explicit escape hatch. If #22 shipped
without either, adding it is part of this issue and is ~15 lines.

### 6. Child lifecycle (`child.go`) — the fiddly part

```go
cmd := exec.CommandContext(ctx, argv[0], argv[1:]...)
cmd.Dir = opts.Dir
cmd.Env = BuildEnv(m, opts)
cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true} // own process group
cmd.Cancel = func() error { return killGroup(cmd.Process.Pid, opts.Signal) }
cmd.WaitDelay = opts.KillGrace                        // Go ≥1.20: bounds Wait after exit
stdin, _ := cmd.StdinPipe()
cmd.Stdout = stdoutSink(opts)                         // inherit | mirror-to-stderr | discard
cmd.Stderr = io.MultiWriter(capture, mirror)          // capture is bounded, never blocks
```

Five failure modes worth naming, because each one is a hang or a leak if handled naively:

1. **The child never reads stdin** (`--exec true`). The stdin pump runs in its own goroutine and
   treats `EPIPE`/`ErrClosed` as success. Payload delivery is best-effort by design: the child's
   exit code is the contract, not whether it read its input.
2. **The child writes 200 MiB to stderr.** The capture writer counts and discards past the cap but
   **keeps draining** — a full pipe buffer would block the child forever. Bounded memory (I11).
3. **A grandchild inherits stderr and outlives the child** (`sh -c 'sleep 999 &'`). `cmd.Wait`
   would block on the still-open pipe. `cmd.WaitDelay` closes the descriptors after the grace
   window, and `killGroup` reaps the whole process group — so `--exec-shell` background jobs do not
   accumulate.
4. **Kill escalation.** `--exec-signal` (default `SIGTERM`) to the *group*, wait `--exec-kill-grace`,
   then `SIGKILL` to the group. Both steps are on the `Clock` seam so `synctest` can drive them.
5. **Zombies.** Every `Start` has exactly one `Wait`, including on every error path. A test asserts
   zero `defunct` children after 1 000 messages, plus flat goroutine and fd counts.

### 7. Concurrency and flow control

- `--concurrency N` sets both the number of in-flight children and the fetch batch (#14 clamps
  `batch` server-side; the effective value is echoed and we use the echo).
- **Clamp at startup** against `GET /v1/streams/{s}/consumers/{c}`: if `N > max_ack_pending`, clamp
  and print once:

  ```
  note: --concurrency 16 exceeds consumer "worker" max_ack_pending=8; running 8 workers.
        raise it with:  messq consumer edit orders worker --max-ack-pending 32
  ```

  The server enforces the bound regardless (`hold_reason=max_ack_pending`); the clamp exists so the
  worker does not spin on held fetches, and so the operator learns the actual knob (I5).
- `ordered=1` consumers (#38): concurrency capped to `1`, reported once with the same note shape.
  PLAN's *"silently capped"* is deliberately not implemented — a silent cap is a support ticket.
- `hold_reason` transitions (`""` → `paused`, `max_ack_pending`, `backoff`) print **once per
  transition**, never per poll. A worker parked against a paused consumer should say so once and
  then be quiet.

### 8. Heartbeats, `--exec-timeout`, and losing the lease

The `Worker` (#22) extends at `ack_wait/2` while the handler runs. This issue adds the part that
makes it honest: **the child's life is bounded by the lease, and the lease is never settled with a
dead token.**

- `--exec-timeout 0` (default) means *"run until the lease can no longer be extended"*. The server
  refuses extension past `--max-ack-wait` (1 h, T7), so the effective ceiling is the server's, not a
  number the CLI invented. When the ceiling is reached: kill escalation → **nak** with reason
  `exec timeout after 1h0m0s (lease could not be extended further)`. A worker never holds a message
  it cannot keep.
- An explicit `--exec-timeout 30s` is a hard local cap and is also validated at startup: if it
  exceeds the consumer's reachable extension ceiling, print a warning naming both numbers.
- **Lease loss** — an extend returns `409 stale_ack` or `wrong_generation` (someone ran
  `messq seek`), or the daemon is unreachable past the deadline. The `Worker` cancels the
  per-message context with a cause; the runner:
  1. kills the child's process group (it is doing work nobody will accept),
  2. returns abandon — **no ack, no nak, no term** with a token that is already dead,
  3. renders a `lease-lost` line and counts it in the run summary.

  The message redelivers via the sweeper (T8) with `msg.timeout`, so `messq trace` explains the
  duplicate — I9 holds. Settling a dead token instead would produce a `msg.ack_stale` WARN and an
  alert on `messq_stale_acks_total` for something that is not the operator's fault.
- Clock discipline: deadlines are derived from `deadline_ms` in the fetch response and re-derived
  after each successful extend, all through #3's `Clock`. No `time.Now()` in this package
  (lint-enforced), no `time.Sleep` in tests (§11).

```
        0    ack    done
        75   nak    EX_TEMPFAIL — retry with the consumer's backoff  [1s 5s 30s 2m 10m]

        else nak    treated like 75 and reported as an unexpected failure
      the child's stderr becomes the failure reason: messq trace <msg-id>
      this hint prints once per run.  messq help exit-codes
```

### 10. Security notes (§10)

- `--exec` lives entirely in `internal/cli`. An import-boundary test asserts that `os/exec` is not
  imported by `internal/api`, `internal/store`, `internal/queue` or `internal/obs` — *"the daemon
  has no exec capability"* becomes an executed test, not a claim.
- **The payload is never in argv or the environment.** A test publishes a canary string and greps
  the child's `/proc/self/environ` and `/proc/self/cmdline`; it must appear only on stdin.
- Headers are publisher-controlled and therefore attacker-influenced. They are namespaced under
  `MESSQ_HEADER_`, mangled to a strict charset, never interpolated into a command line, and
  `--exec-shell` is documented as "the mode where quoting is yours".
- `--exec-clean-env` for workers that should not inherit the operator's environment.
- Reason text is operator-visible (it lands in `trace`, `pending` and a DLQ header) — the docs warn
  that a script must not print secrets to stderr. #12 already sanitises control characters and ANSI
  escapes before the header is built; §11 fuzzes our side of that boundary.

### 11. Considered and deferred

| Idea | Why not now |
|---|---|
| Child-controlled nak delay (a `$MESSQ_RESULT_FILE` or fd 3 convention) | The exit code is the whole contract; a second channel doubles the surface. Revisit with #37's delayed delivery. |
| `--exec-batch N` (one child, N messages) | Partial-failure semantics for a batch child are a real protocol (which of the N failed?). Not worth it before a user asks. |
| Long-lived child with an NDJSON protocol over stdin/stdout (worker pool) | That is a client library with extra steps; it would make `--exec` stop being "any shell script". `docs/non-goals.md`. |
| Supervising `messq sub --exec` (restart on crash) | systemd's job. plan-04 reached the same conclusion. #36 ships an example unit. |
| Per-child cgroup/rlimit sandboxing | systemd unit properties do it better and are already in the hardened-unit story. |

## Acceptance criteria

- [ ] `messq sub <stream> <consumer> --exec CMD` consumes continuously, running `CMD` once per
      message with the payload on stdin, and settles each message from the child's exit code.
- [ ] The §3 exit-code table holds exactly: `0`→ack, `75`→nak, `65`→term, other non-zero→nak,
      killed-by-signal→nak with the signal named in the reason.
- [ ] `internal/cli/exec` contains no HTTP call and no settle call; all durability goes through
      #22's `client.Worker` (enforced by an import/callgraph test).
- [ ] Every `MESSQ_*` variable in §4 is set with the documented value, plus a valid W3C
      `traceparent`; a header named `x-tenant` arrives as `MESSQ_HEADER_X_TENANT` **and** in
      `MESSQ_HEADERS_JSON`.
- [ ] Pre-existing `MESSQ_HEADER_*` / per-message variables in the parent environment are stripped;
      `MESSQ_ADDR` and `MESSQ_TOKEN_FILE` are preserved.
- [ ] The message body appears **only** on stdin — never in the child's argv or environment.
- [ ] The child's stderr (first `--stderr-bytes`, default 4096, UTF-8-safe, control characters
      sanitised) is submitted as the nak/term reason and is visible in `messq trace`,
      `messq pending` and the DLQ message's `Messq-Last-Reason`.
- [ ] A child that writes 200 MiB to stderr does not block, does not grow messq's RSS beyond the
      cap, and still settles correctly.
- [ ] A child that never reads stdin (`--exec true`) acks normally; `EPIPE` is not an error.
- [ ] `extend` heartbeats keep a child running past `ack_wait` without redelivery: with
      `ack_wait=2s` and a 10 s child, the message is delivered exactly once and acked.
- [ ] With `--exec-timeout 0`, a child that outlives the server's extension ceiling is killed
      (TERM → grace → KILL, whole process group) and the message is naked with an `exec timeout`
      reason.
- [ ] When the lease is lost (seek bumps the generation, or the daemon is unreachable), the child is
      killed and **no** ack/nak/term is sent with the dead token; the run summary counts
      `lease-lost` and `messq_stale_acks_total` does not move.
- [ ] `--concurrency N` runs at most N children; N is clamped to the consumer's `max_ack_pending`
      with a printed note naming the `messq consumer edit` fix; `count(deliveries) ≤ max_ack_pending`
      is never violated (I5).
- [ ] A poison message with `--exec 'exit 65'` reaches `<stream>.dlq` after **one** attempt;
      `--exec 'exit 75'` reaches it after exactly `max_deliver` attempts (I4/I8), and
      `messq trace` shows every attempt with the child's stderr as the reason.
- [ ] A missing/non-executable `--exec` target fails at startup with a teaching error and exit `1`,
      **before any message is fetched** (zero attempts burned).
- [ ] The one-time hint prints on the first non-zero child exit, exactly once per run, and is
      suppressed by `--no-hints`.
- [ ] `--exec` with `--manual` or `--auto-ack` is a usage error (exit `2`) naming the conflict.
- [ ] `--output ndjson` emits one frozen-schema record per settled message and child stdout does not
      appear in that stream.
- [ ] SIGINT/SIGTERM to messq: stops fetching, forwards the signal to running children, settles them
      by exit code, prints the summary, exits `0`. A second signal kills children immediately,
      settles nothing, exits `130`.
- [ ] After 1 000 messages: no zombie processes, flat goroutine count, flat fd count.
- [ ] `docs/exit-codes.md` documents the child-side table and is the source the hint text is
      generated from (a test fails if they diverge).

## Test plan

Consistent with PLAN §11: `-race` everywhere, no `time.Sleep` outside soak, every fixed bug lands
with a committed reproduction.

1. **Unit (pure functions)** — `Classify` has one test row per §3 line, including
   `ExitCode() == -1` + `WaitStatus.Signaled()`, `--exec-shell`'s `137`, and each `StopCause`.
   `BuildEnv` table: normal headers, collisions, NUL values, empty-after-mangle names, leading
   digits, parent-env stripping. `SanitizeStderr`: invalid UTF-8, embedded NUL, CR/LF, ANSI escape
   sequences, exactly-at-cap, one byte over, multi-byte rune straddling the cap, `head` vs `tail`.
2. **Fuzz** (§11.6) — `FuzzSplitWords` (never panics; output re-quotes to an equivalent argv),
   `FuzzBuildEnv` (never produces a name containing `=` or NUL, never emits a duplicate name),
   `FuzzSanitizeStderr` (output is always valid UTF-8 and ≤ cap). 60 s/target per PR, corpus
   committed.
3. **Hermetic child** — the standard Go helper-process pattern: tests re-exec the test binary with
   `MESSQ_TEST_CHILD=<behaviour>` (`exit0`, `exit75`, `exit65`, `sleep`, `stderr-flood`,
   `ignore-stdin`, `spawn-grandchild`, `ignore-sigterm`, `echo-env`). **No test depends on
   `/bin/sh`, `bash`, `jq` or `sleep`** — the suite must pass in a scratch container.
4. **`testing/synctest`** — heartbeat cadence at `ack_wait/2`; `--exec-timeout` expiry; the
   TERM→grace→KILL escalation against `ignore-sigterm`; lease-loss cancellation. All against a fake
   `Clock`; a lint rule bans `time.Now`/`time.Sleep` in `internal/cli/exec`.
5. **Integration against a real daemon** (`t.TempDir()`, real socket, real SQLite — never
   `:memory:`): ack path, nak-with-backoff path, term-to-DLQ path, signal path, timeout path;
   `max_deliver` exhaustion producing exactly one DLQ message whose `Messq-Last-Reason` is the
   child's stderr; concurrency ≤ `max_ack_pending`; heartbeat keeping a long child alive.
6. **Lease-loss / restart** — (a) `messq seek` mid-child → generation bump → child killed, nothing
   settled, sweeper redelivers, `trace` names the cause; (b) daemon SIGKILL + restart mid-child →
   `recovery.reclaimed`, at most one duplicate, and `messq_stale_acks_total == 0`. Reuses #8's crash
   harness process control.
7. **testscript `.txtar`** (`test/script/`, §11.5) — `sub_exec_ack`, `sub_exec_nak_backoff`,
   `sub_exec_term_dlq`, `sub_exec_signal`, `sub_exec_timeout`, `sub_exec_concurrency_clamp`,
   `sub_exec_hint_once`, `sub_exec_ndjson`, `sub_exec_bad_command`, `sub_exec_flag_conflicts`.
   Fake clock via env; goldens with `-update`. #26 generalises the harness and adds the README
   blocks; these scripts are its first citizens.
8. **Security tests** — canary-payload grep of the child's `environ`/`cmdline`; the
   `os/exec`-import-boundary test over daemon packages; a `--exec-clean-env` test asserting the
   allow-list.
9. **Leak/robustness** — 1 000-message run asserting zero `defunct` children (`/proc` scan), flat
   goroutine count (`goleak`-style check without the dependency), flat fd count; `stderr-flood`
   child asserting bounded RSS growth.
10. **Bench (`--exec` overhead, published not gated)** — `BenchmarkExecRoundTrip` at concurrency
    1/4/8 with a trivial child vs. the in-process auto-ack path, so the fork/exec cost of the
    feature is a measured number in the docs (§12's honesty rule) rather than a guess. Wired into
    #31's nightly benchstat run.
