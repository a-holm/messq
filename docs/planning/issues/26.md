## Context

After #23 (chassis), #24 (commands) and #25 (`--exec`), messq *has* a CLI. This issue makes it a
**product**: the first five minutes, the surfaces that teach, and the harness that stops all of it
from rotting.

PLAN.md makes three promises that nothing has yet made true:

- **§1.5** — *"Time from download to first acked message: **< 60 s, no config file**
  (`messq quickstart`)."* This is a numbered success criterion for v1.0, not a nicety.
- **§8** — *"dynamic shell completion of live stream/consumer names"*, chosen in **D9** as the
  reason cobra earns its dependency, with 03's justification: *"fewer typos at 3 a.m. is a
  reliability feature."* Plus generated man pages from one source of truth.
- **§11.5** — *"testscript CLI goldens … the README curl transcript and every doc command block
  execute in CI — **documentation cannot rot**."* #18 built that harness for the HTTP surface and
  deliberately left the CLI lane empty, with an `env=MESSQ_OUTPUT=table` seam waiting for M6.

It also closes **M6's exit criterion**: *"Quickstart <60 s on a cold machine."*

Five things ship:

1. **`messq quickstart`** — a guided tour on a throwaway data dir that publishes, acks, naks with
   backoff, deliberately lets a message time out into the DLQ, and then prints — unprompted — the
   `messq trace` of the dead message. That output *is* the pitch (PLAN §8's flagship block); making
   it a subcommand rather than a doc page means it is executable, versioned, and testable.
2. **`messq serve --dev`** — the ephemeral, auto-creating, human-logging mode that `--help` and the
   README can point beginners at without teaching `--data-dir` first. `--dev` is referenced by #16,
   #17 and #19 as PLAN §8 surface; this issue is where it actually becomes a flag.
3. **Dynamic shell completion** for bash/zsh/fish, completing live stream and consumer names inside
   a 200 ms budget with silent failure.
4. **Help topics and man pages** — `messq help concepts|lifecycle|durability|exit-codes|scripting`
   plus generated `messq(1)`/`messq(8)`, both from one embedded source that the docs site (#35) and
   the executable-docs harness also consume.
5. **The testscript (`.txtar`) golden suite** — the CLI's contract, covering every command's human
   and JSON faces on a deterministic clock, with an `-update` flow that cannot launder a JSON shape
   break, wired into CI with a stated budget.

Governing PLAN.md material: **§8 CLI design** (the command tree, the output/exit-code/teaching-error
rules, `--exec`), **§1.5** (the 60 s criterion), **§11** (testing strategy, the 10-minute PR budget,
no `time.Sleep`), **D9** (cobra, dynamic completion, man pages, no viper), **D8** (flags + `MESSQ_*`
only — quickstart must work with **no config file**), **D13** (goldens and executable docs are in;
mutation testing and shipped conformance binaries are not), **§13** (≤ 8 direct non-test deps — the
man-page generator must not spend one), **§14 M6**.

What it unlocks: **#35** writes the 1.0 doc set knowing every block it writes executes; **#29**,
**#30**, **#31** and **#28** drop their commands into an existing suite instead of each inventing a
harness; **#36** installs the completion scripts and man pages this issue generates.

## Design proposal

> Proposal, not mandate — **except** four rules that are cheap now and expensive later: quickstart
> never talks to a pre-existing daemon; completion never blocks a shell; `-update` cannot rewrite a
> JSON golden whose shape digest changed; and every command in the tree is bound to a script.

### 1. `messq quickstart`

**Shape.** A step engine that executes *real argv through the real command tree* against an
ephemeral in-process daemon. It has no private rendering: whatever `messq pub` prints in the tour is
what it prints in production, or the tour is broken.

```go
// internal/cli/quickstart/tour.go — proposal
type Step struct {
    Title string   // one teaching sentence, printed above the command
    Argv  []string // executed verbatim; also what is echoed after the "$ " prompt
    Note  func(*Tour) string // optional post-step narration (e.g. "that took 3 attempts")
}

type Tour struct {
    Dir    string        // ephemeral data dir; removed on exit unless --keep
    Addr   string        // unix://<Dir>/messq.sock
    Out    io.Writer     // stdout: the transcript
    Err    io.Writer     // stderr: narration, banners, warnings
    Pause  bool          // TTY default true
    Vars   map[string]string // captured ids between steps (poison msg id → trace step)
}

func (t *Tour) Run(ctx context.Context, steps []Step) error
```

Each step: print the teaching line → print `$ ` + `strings.Join(Argv, " ")` → run it with a cleared
environment plus `MESSQ_ADDR=<ephemeral>` → stream its stdout/stderr through → optionally pause.
A test asserts *printed command == executed argv* (`TestQuickstartPrintsWhatItRuns`), because a tour
that lies about what it ran is worse than no tour.

**The daemon.** Started in-process (the same `serve` construction path, not a copy), on
`unix://<dir>/messq.sock`, `--durability=full` — the tour shows the honest default. If the socket
path would exceed 100 bytes (long `TMPDIR`), fall back to a dir directly under `/tmp`; if that
fails, `tcp://127.0.0.1:0`. `MESSQ_ADDR`, `MESSQ_TOKEN_FILE` and every other `MESSQ_*` from the
user's environment are **ignored, with one line saying so** — someone with `MESSQ_ADDR=prod`
exported must not be able to point the tour at production.

**The seven steps** (timings are the real thing; the whole tour is ~11 s):

```console
$ messq quickstart

  messq 1.0.0 · quickstart
  throwaway daemon in /tmp/messq-quickstart-01K3QW8… (deleted when we finish)
  durability=full · nothing outside that directory is touched
  ignoring MESSQ_ADDR from your environment — the tour never talks to your real daemon

  1/7  A stream is a durable, append-only sequence of messages.

  $ messq stream add demo --subjects 'demo.>'
  stream "demo" created   subjects demo.>   retention limits (7d)
  next: messq stream info demo

  2/7  Publishing returns only after the write is on disk.

  $ messq pub demo demo.hello -d 'hello world'
  published 01K3QW8F2M9V0X7Y3B5N6C8D1E  seq 1  demo.hello  11 B  durable in 1.9ms

  3/7  A consumer is a durable cursor with retry rules of its own.

  $ messq consumer add demo worker --ack-wait 2s --max-deliver 3 --backoff 500ms
  consumer "demo/worker" created   ack_wait 2s   max_deliver 3   backoff 500ms (±20%)
  retry horizon: a message is dead-lettered ~5s after its first delivery

  4/7  Fetch, work, ack. An ack deletes the delivery — the pending set stays small.

  $ messq sub demo worker --count 1
  01K3QW8F2M…  demo.hello  attempt 1/3  hello world
  acked in 2.4ms   1 message, 0 redeliveries

  5/7  A worker that fails temporarily naks; messq retries it on the backoff schedule.

  $ messq pub demo demo.flaky -d '{"charge":42}'
  published 01K3QW8G4Q…  seq 2  demo.flaky  14 B
  $ messq sub demo worker --count 2 --exec 'messq quickstart-handler'
  01K3QW8G4Q…  demo.flaky  attempt 1/3  -> exit 75  nak  reason="upstream returned 503"  retry in 0.6s
  01K3QW8G4Q…  demo.flaky  attempt 2/3  -> exit 0   ack  (resolved in 0.71s, 2 attempts)

  6/7  A worker that never answers is the interesting case. Nobody acks this one.

  $ messq pub demo demo.poison -d 'bad payload'
  published 01K3QW8H7R…  seq 3  demo.poison  11 B
  $ messq sub demo worker --manual --count 3
  01K3QW8H7R…  demo.poison  attempt 1/3  deadline +2s  token demo/worker/3/1/1
  01K3QW8H7R…  demo.poison  attempt 2/3  deadline +2s  token demo/worker/3/2/1  cause=timeout
  01K3QW8H7R…  demo.poison  attempt 3/3  deadline +2s  token demo/worker/3/3/1  cause=timeout
  3 delivered, 0 settled — this consumer is deliberately not acking

  ... 2s later, attempt 3 times out with no attempts left. Where did the message go?

  7/7  Every transition was written in the same transaction as the change. Replay it:

  $ messq trace 01K3QW8H7R…

  message 01K3QW8H7R4T2K9M0P6S8V1X3Z   stream=demo subject=demo.poison seq=3
  trace 4bf92f3577b34da6a3ce929d0e0e4736  11 B  published 2026-10-23T09:14:02.114Z

    09:14:02.114  publish
    09:14:02.190  deliver   worker  attempt 1/3           deadline 09:14:04.190
    09:14:04.191  timeout   worker  attempt 1/3           waited 2.0s
    09:14:04.702  deliver   worker  attempt 2/3  cause=timeout
    09:14:06.703  timeout   worker  attempt 2/3           waited 2.0s
    09:14:07.298  deliver   worker  attempt 3/3  cause=timeout
    09:14:09.299  timeout   worker  attempt 3/3           waited 2.0s
    09:14:09.299  dead      worker  max_deliver reached   → demo.dlq seq 1

    duplicates: 2 — all accounted for (2× timeout)

  You now know: publish · ack · nak with backoff · redelivery · ack_wait timeout · DLQ · trace.

  Next
    messq help concepts                       the vocabulary, one paragraph each
    messq help lifecycle                      the state machine you just walked through
    messq peek demo.dlq --last 1              the dead message, with its provenance headers
    messq dlq redrive demo --id 01K3QW8H7R…   re-drive it once the bug is fixed
    messq serve --data-dir ./messq-data       a daemon that keeps your data

  removed /tmp/messq-quickstart-01K3QW8… (keep it next time with --keep)   elapsed 11.4s
```

`messq quickstart-handler` is a **hidden** subcommand used as the step-5 worker so the tour needs no
shell, no `sh`, no temp script: it reads #25's `MESSQ_SUBJECT`/`MESSQ_ATTEMPT` env and exits `75`
with a stderr reason on attempt 1, `0` on attempt 2. It is hidden, documented in its own `Long`, and
excluded from the command-coverage binding by name.

| Flag | Default | Meaning |
|---|---|---|
| `--pause` | `true` on a TTY, `false` otherwise | wait for Enter between steps |
| `--keep` | `false` | keep the data dir; print it and the `messq serve --data-dir` line that reopens it |
| `--output` | `text` | `ndjson` emits one record per step (`step`, `title`, `command`, `exit`, `elapsed_ms`) to stdout with all narration on stderr — the machine face #23's contract requires |
| `--no-banner` | `false` | for embedding in asciinema recordings |

**Edge cases.** `TMPDIR` full/noexec → exit 1 naming `TMPDIR`. Ctrl-C → clean up, print the removed
path, exit 130 (signal exits sit outside #23's 0–7 table; documented in `help exit-codes`). A crashed
tour leaves `messq-quickstart-*` dirs; the next run reaps siblings older than 1 h that contain the
`.messq-quickstart` marker file and are owned by the current uid — prefix + marker + ownership, so a
bug cannot turn this into a delete loop. Elapsed > 45 s prints a hint that the disk is slow and
points at `messq doctor` (#30) rather than silently failing the §1.5 criterion.

### 2. `messq serve --dev`

`--dev` is a composite whose parts are already owned elsewhere; this issue wires them and adds two.

| Implication | Owner |
|---|---|
| `--data-dir` = ephemeral temp dir, removed at exit (unless `--data-dir` given explicitly) | this issue |
| auto-create streams on publish and consumers on fetch | this issue |
| `--log-format=human --log-level=debug`, `source` attribute re-enabled | #19 |
| `--drain-timeout=2s` (Ctrl-C is instant) | #17 |
| loopback warning collapsed into one dev banner; **public plaintext bind still fatal** | #16 |

**Precedence rule:** an explicitly-set flag always beats a `--dev` implication (`--dev
--log-level=warn` gives WARN). Implemented by applying `--dev` defaults only where
`cmd.Flags().Changed(name)` is false, and asserted by a table test — this is the "which setting won?"
bug class D8 exists to avoid.

Auto-create, dev only:

```
WARN  stream.create  stream=orders actor=dev-autocreate subjects=[">"]
      auto-created because --dev is set. In production, create it explicitly:
        messq stream add orders --subjects 'orders.>'
```

The created stream accepts `[">"]` (guessing a pattern from one subject would be a worse surprise
than accepting everything in a mode whose data is thrown away). Consumers auto-created on fetch use
schema defaults. Both write their normal `stream.create` / `consumer.create` event with
`actor=dev-autocreate`, so `messq events` shows exactly how the state appeared. Concurrent publishes
to the same new stream collapse to one create (`ON CONFLICT DO NOTHING`, one event). `/v1/info`
gains `"dev": true` — additive under #18's classifier, and the flag `doctor` (#30) keys off.

The banner is unmissable and names what it costs:

```
╭─ DEVELOPMENT MODE ─────────────────────────────────────────────────────────╮
│ data dir /tmp/messq-dev-01K3QW…  is DELETED when this process exits        │
│ streams and consumers are auto-created · logs are human · level DEBUG      │
│ for anything you care about:  messq serve --data-dir /var/lib/messq        │
╰────────────────────────────────────────────────────────────────────────────╯
```

### 3. Dynamic shell completion

```go
// internal/cli/complete — proposal
type Resolver struct {
    Dial   func(ctx context.Context) (*client.Client, error) // built from resolved flags/env (#23)
    Cache  Cache          // $XDG_CACHE_HOME/messq/complete-<addrhash>.json, 0600, 5s TTL
    Budget time.Duration  // 200ms, whole operation including dial
}

func (r *Resolver) Streams(ctx context.Context, prefix string) []cobra.Completion
func (r *Resolver) Consumers(ctx context.Context, stream, prefix string) []cobra.Completion

// wiring helpers used by #24's commands
func StreamArg(r *Resolver) cobra.CompletionFunc                 // positional 0
func ConsumerArg(r *Resolver, streamArg int) cobra.CompletionFunc // positional 1, scoped by argv[streamArg]
func SubjectArg(r *Resolver, streamArg int) cobra.CompletionFunc
func Enum(values ...cobra.Completion) cobra.CompletionFunc        // flag values
```

Descriptions come from the list payload the CLI already fetches — **one request, never N+1**:

```console
$ messq __complete sub demo ''
worker	12 in flight, oldest 4m12s
audit-tap	idle 3d
:4
Completion ended with directive: ShellCompDirectiveNoFileComp
```

```console
$ messq pending or<TAB>
orders     -- 214,882 messages, 2 consumers, 1.2 GiB
orders.dlq -- 41 messages, 0 consumers
```

**Two hard rules, both testable.**

1. **Never hang.** One `context.WithTimeout(200ms)` covers dial + request + decode. On timeout,
   refusal, or any error: return `nil, cobra.ShellCompDirectiveNoFileComp` — no candidates, no
   stderr, exit 0. *Divergence from plan-04, deliberate:* `ShellCompDirectiveError` makes several
   shells fall back to filename completion or beep, so a dead daemon would make the shell look
   broken. "No suggestions" is the honest and quiet answer.
2. **Never expensive for the daemon.** Results cached for 5 s in `$XDG_CACHE_HOME/messq/`, written
   `temp + rename` at 0600, keyed by `sha256(addr + tokenFilePath)`. On a failed refresh a cached
   entry is served up to 60 s stale — completion keeps working across a daemon restart. Requests
   carry `User-Agent: messq-completion/<version>` so an operator can attribute them.

| Completion target | Source |
|---|---|
| `<stream>` positional | `GET /v1/streams?limit=500`, client-side prefix filter (a `?prefix=` query is an additive optimisation for #15 if anyone runs 500+ streams) |
| `<consumer>` positional | `GET /v1/streams/{s}/consumers` scoped to `args[0]`; unknown/absent stream → empty, never an error |
| `<subject>` positional | the stream's configured `subjects`: concrete patterns are offered whole; wildcard patterns are offered as their literal prefix (`orders.` for `orders.>`) with `ShellCompDirectiveNoSpace` — you can't publish to `orders.>`, and suggesting it would teach the wrong thing |
| `--output`, `--durability`, `--log-level`, `--to`, `--reason`, shells, help topics | static enums from the same `const` blocks the commands validate against — a new enum member completes the day it exists |
| `--file`, `--data-dir`, `--auth-file` | `ShellCompDirectiveFilterFileExt` / `…FilterDirs` |

`messq completion bash|zsh|fish` emits the script (cobra's generators); cobra's built-in
`completion` command is disabled and replaced so the shell list is honest about what we test. The
`__complete` hidden command is how the suite tests all of this without installing a shell.

### 4. Help topics and man pages

Topics are embedded markdown, rendered plainly to a terminal, and are **one source of truth** for
the terminal, the docs site (#35) and the executable-docs harness.

```
internal/cli/help/
  help.go            renderer: headings underlined, fences indented 4, no ANSI unless TTY
  topics/concepts.md lifecycle.md durability.md exit-codes.md scripting.md subjects.md output.md
```

Wired as cobra additional-help-topic commands (a `Command` with no `Run` and no children), so they
appear under *Additional help topics* in `messq --help` and answer to `messq help <topic>`.

| Topic | Contents | Bound to code by |
|---|---|---|
| `concepts` | stream, subject, consumer, ack/nak/term/extend, attempt, DLQ, trace — JetStream's vocabulary verbatim (§1.3), one paragraph each, ending in `messq quickstart` | — |
| `lifecycle` | PLAN §5's diagram and the T1–T11 summary; *every duplicate has a named cause* | `TestLifecycleTopicCoversEveryTransition` — the transition table in `internal/queue` ▷ the topic |
| `durability` | §4.3's two modes, what a `201` means, group commit, fsync-failure policy, "check yours: `messq doctor`" | the mode names come from the same enum |
| `exit-codes` | the 0–7 table plus 130 for signals, with a shell snippet that branches on them | **generated** from #23's `const` block at build time; a new code with no description fails the build |
| `scripting` | `--output json\|ndjson`, data-to-stdout/narration-to-stderr, `jq` recipes, the five-line curl worker, #25's sysexits table, `NO_COLOR`, `MESSQ_*` | every fenced block executes in CI |
| `subjects` | `*` / `>` matching rules with a truth table and `messq peek --subject` examples | shares fixtures with #3's matcher tests |
| `output` | the three modes, TTY detection, ULID abbreviation, `--output json` field stability | — |

**Man pages and CLI reference** come from cobra metadata via `tools/gendocs`, a **separate Go module**
(`tools/go.mod`). This matters: `spf13/cobra/doc`'s man generator pulls `cpuguy83/go-md2man`, and
PLAN §13 caps the root module at ≤ 8 direct non-test dependencies with an ADR per addition. A second
module keeps `scripts/dep-budget.sh` (#1/#2) green without an ADR for a build-time tool.

```
make docs   →  docs/cli/messq_stream_add.md …   (GenMarkdownTree)
               man/man1/messq.1, messq-stream-add.1 …   (GenManTree, section 1)
               man/man8/messq.8  →  `.so man1/messq.1`  (roff include; #17's unit says man:messq(8))
```

Reproducible: `GenManHeader.Date` is taken from `SOURCE_DATE_EPOCH` when set, else the build date, so
two builds of one commit produce identical bytes. CI runs `make docs && git diff --exit-code`, so
generated docs are always current and drift shows up as a diff, not as a stale website.

### 5. The testscript golden suite

```
test/script/                    *.txtar — the CLI contract
test/script/script_test.go      RunMain + testscript.Run, two lanes
internal/testutil/scriptenv/    env builder, custom commands, in-process daemon + fake clock
```

**Two lanes, chosen per script.**

| Lane | Daemon | When | Why |
|---|---|---|---|
| `inproc` (default) | constructed **inside the test process** on a `clock.Fake` (#3), listening on `$WORK/messq.sock` | everything about output, JSON shapes, state transitions | The CLI runs in a re-exec'd subprocess (testscript's `RunMain`) and talks over the socket, while the test owns the clock: `clock advance 3s` is deterministic and instantaneous. No `time.Sleep`, per §11. |
| `subproc` | a real `messq serve` via #18's `internal/testutil/daemon` | `quickstart`, `serve --dev` banners, signals, "daemon unreachable" exit 6, `--exec` child handling | Where the process boundary *is* the thing under test. Real clock, durations masked. |

**Custom commands** (`testscript.Params.Cmds`, executed in the test process):

| Command | Behaviour |
|---|---|
| `daemon start [flags…]` | start the lane's daemon, poll `/readyz` (never sleep), export `$MESSQ_ADDR`, `ts.Defer` teardown |
| `daemon stop\|kill\|restart` | graceful stop / SIGKILL / restart — for recovery goldens (`recovery.reclaimed` in `messq events`) |
| `clock advance 3s` \| `clock set <RFC3339>` | move the fake clock, then **quiesce**: force a sweeper tick, drain the writer queue, flush the event fan-out, return only when all three are idle |
| `waitfor pending demo worker == 0 [30s]` | poll a predicate against the daemon with a deadline; the only "waiting" primitive in the suite |
| `capture MSG_ID $.id` | parse the previous command's stdout as JSON and export a field as an env var — how `messq trace $MSG_ID` becomes possible |
| `exitcode 3 messq stream info missing` | run a CLI invocation asserting an **exact** exit status, leaving stdout/stderr in the script buffers for the following `stdout`/`stderr` assertions |
| `mask` | run #18's normaliser over stdout (ULIDs, timestamps, durations, `$WORK`) before comparison |
| `cmpjson stdout want.json` | compare canonicalised JSON (#18's `internal/wirecheck`) — key order and whitespace are not contract |
| `cmpshape stdout StreamInfo` | validate stdout against the committed shape digest for that type; this is what stops `-update` laundering a renamed JSON field into a CLI golden |

A script, end to end:

```
# test/script/lag.txtar
daemon start
messq stream add orders --subjects 'orders.>'
messq consumer add orders billing --ack-wait 30s
messq pub orders orders.created -d '{"id":1}' --count 1284 --output json
messq sub orders billing --count 12 --manual
clock advance 4m12s

messq lag --output table
cmp stdout want-lag.txt

messq lag --output json
cmpshape stdout LagReport
cmpjson stdout want-lag.json

exitcode 3 messq lag --stream nope
stderr 'stream "nope" not found'
stderr 'messq stream ls'

-- want-lag.txt --
CONSUMER  STREAM  FILTER    BACKLOG  INFLIGHT  DLQ  OLDEST UNACKED
billing   orders  orders.>     1,272    12/1000   0  4m12s          (!)

1 consumer needs attention: billing (oldest unacked 4m12s)
next: messq pending orders billing --older-than 1m
```

**Determinism environment**, set for every script: `TZ=UTC`, `LC_ALL=C`, `NO_COLOR=1`, `TERM=dumb`,
`COLUMNS=100`, `HOME=$WORK/home`, `XDG_{CONFIG,CACHE,STATE}_HOME=$WORK/…`, `GOCOVERDIR`, and a
`PATH` containing only the built `messq` plus coreutils. Every `MESSQ_*` variable is cleared unless
the script sets it. Because stdout is not a TTY, the human face must be requested explicitly
(`--output table`) — which is itself the assertion that #23's auto-detection has the right default.

**Coverage bindings** — the part that keeps the suite honest as commands are added:

```go
func TestEveryCommandHasAScript(t *testing.T)  // walk the cobra tree ▷ grep of test/script/*.txtar
func TestEveryExitCodeIsExercised(t *testing.T) // 0–7 each produced by at least one `exitcode` line
func TestNoANSIInGoldens(t *testing.T)          // an escape byte in a golden means colour leaked
func TestNoTrailingSpaceInGoldens(t *testing.T) // renderers must not pad; editors would churn these
```

Opt-outs live in `test/script/testdata/no-script.txt` as `command<TAB>reason` and are reviewed like
code (`serve` — covered by the `subproc` lane; `quickstart-handler` — hidden helper).

**`-update`.** `go test ./test/script -update` rewrites the golden sections inside each `.txtar`.
It refuses when a `cmpshape` assertion changed, printing #18's classifier verdict — a renamed
`--output json` field is a compatibility decision, not a golden refresh.

### 8. Edge cases, decided

| Case | Handling |
|---|---|
| `MESSQ_ADDR` points at production when `quickstart` runs | Ignored with one printed line; the tour's child invocations get a cleared env. Asserted by a test that sets `MESSQ_ADDR` to a socket that fails the test if dialled |
| Quickstart's socket path > 100 bytes (long `TMPDIR`) | Fall back to `/tmp`, then `tcp://127.0.0.1:0`; the banner prints whichever was used |
| Quickstart interrupted | Signal handler removes the dir, prints it, exits 130; a `subproc` script sends SIGINT and asserts the dir is gone |
| Quickstart on a slow disk | Runs to completion; > 45 s prints a slow-fsync hint and `messq doctor` (#30). Never silently fails the 60 s criterion |
| Leftover `messq-quickstart-*` dirs after SIGKILL | Reaped on the next run: name prefix **and** `.messq-quickstart` marker **and** current-uid ownership **and** age > 1 h. Three guards on a delete loop |
| `--dev` with an explicit `--data-dir` | Directory is kept, not deleted; banner says so; auto-create still on |
| `--dev` on a public bind | Still fatal (#16); a test asserts `--dev` cannot weaken it |
| `--dev` auto-create races | `ON CONFLICT DO NOTHING`; exactly one `stream.create` event (#8's ledger discipline applies) |
| Completion against a dead daemon | Empty list, `:4`, exit 0, nothing on stderr; asserted with a socket path that does not exist |
| Completion against a daemon that answers slowly | A fixture daemon delaying 5 s: `__complete` must return within ~200 ms; asserted with a fake clock in the `inproc` lane |
| Completion without permission (403) | Same as failure: silent empty. A completion must not tell you what you cannot see |
| Completion cache corrupt / truncated / from another user | Ignored and refetched; never an error path the user sees |
| Two shells completing simultaneously | `temp + rename` is atomic; last writer wins; both read a valid file |
| 10 000 streams | One request with `limit=500`, client-side prefix filter, descriptions from the same payload; truncation drops candidates silently rather than hanging |
| `messq help nosuchtopic` | Exit 2, cobra's suggestion (`did you mean "concepts"?`), then the full topic list |
| A topic that documents a flag that was renamed | The topic-binding tests (`exit-codes` generated, `lifecycle` bound to the transition table, all fences executed) catch the classes that matter; prose drift beyond that is #35's review surface |
| Relative times in goldens (`4m12s ago`) | `inproc` lane pins them via the fake clock; `subproc` lane masks them. Never both |
| ULIDs in goldens | Masked, **except** ack tokens (`demo/worker/3/2/1`), `seq`, `attempt` and counts — #18's never-mask list applies unchanged, because a token in a golden is a free assertion about fencing arithmetic |
| A golden containing `$WORK` | `cmpenv`, or the normaliser's `$WORK → /work` rule; a raw temp path in a committed golden fails the golden lint |
| `testscript` coverage of the in-process CLI | `RunMain` + `GOCOVERDIR` keeps the CLI in #2's coverage numbers; if it proves flaky, fall back to a built binary on `$PATH` and record the coverage loss in `CONTRIBUTING.md` rather than silently dropping the floor |
| Man page date churn | `SOURCE_DATE_EPOCH`; two builds of one commit are byte-identical |
| `man:messq(8)` in #17's systemd unit | `man/man8/messq.8` is a one-line roff `.so man1/messq.1`, not a duplicated page |
| Shell completion scripts changing between cobra versions | The generated scripts are **not** golden-tested byte-for-byte (that would pin a dependency's internals); the `__complete` protocol output is |

## Acceptance criteria

- [ ] `messq quickstart` runs on a machine with no config file, no `--data-dir`, and no running
      daemon, creating and deleting its own data directory, and exits 0.
- [ ] The tour publishes, acks, naks with backoff, produces a genuine `ack_wait` timeout ×3 into
      `demo.dlq`, and ends by printing a `messq trace` of the dead message **without being asked**,
      plus the `dlq redrive` next-command.
- [ ] Every command the tour prints is the argv it executes (`TestQuickstartPrintsWhatItRuns`), and
      every step's output comes from the real command tree — no private renderer.
- [ ] Quickstart ignores `MESSQ_ADDR`/`MESSQ_TOKEN_FILE` from the environment, says so, and a test
      proves it never dials the pre-existing address.
- [ ] Ctrl-C during the tour removes the data directory, prints the removed path, and exits 130.
- [ ] The nightly `quickstart-cold` job fetches the artifact into a clean container and completes the
      tour in **under 60 seconds** wall clock, failing loudly and naming PLAN §1.5 when it does not.
- [ ] `messq serve --dev` starts with no arguments, prints the dev banner, auto-creates streams on
      publish and consumers on fetch with `actor=dev-autocreate` events, and deletes its data dir on
      exit; with an explicit `--data-dir` it keeps the directory and says so.
- [ ] An explicitly-set flag always overrides a `--dev` implication (table test over every implied
      flag), and `--dev` cannot make a non-loopback plaintext bind succeed.
- [ ] `messq __complete <cmd> <args> ''` returns live stream names, and consumer names scoped to the
      stream already typed, with descriptions, and the `NoFileComp` directive.
- [ ] Completion against a dead, slow (5 s), or unauthorised daemon returns **empty, silently, exit
      0, within ~200 ms** — asserted for all three, the slow case on a fake clock.
- [ ] Completion issues at most one request per invocation, caches for 5 s at 0600 under
      `$XDG_CACHE_HOME`, serves a stale cache for up to 60 s when refresh fails, and tolerates a
      corrupt cache file.
- [ ] Wildcard subject patterns complete as their literal prefix with `NoSpace`; concrete patterns
      complete whole.
- [ ] `messq completion bash|zsh|fish` emits a script that sources without error in the corresponding
      shell (nightly, skipped locally when the shell is absent); cobra's default `completion` command
      is not exposed.
- [ ] `messq help concepts|lifecycle|durability|exit-codes|scripting|subjects|output` each print a
      rendered topic; `messq help nosuchtopic` exits 2 with a suggestion and the topic list; topics
      appear under *Additional help topics* in root help.
- [ ] The `exit-codes` topic is generated from #23's `const` block — adding a code without a
      description fails the build; the `lifecycle` topic is bound to the transition table, so an
      unmentioned transition fails a test.
- [ ] Every fenced command block in every help topic, in `README.md`, in `docs/quickstart.md` and in
      generated `docs/cli/*.md` executes in CI, and every cobra `Example` line runs or carries a
      non-empty `# noexec:` reason.
- [ ] `make docs` generates `docs/cli/*.md`, `man/man1/*.1` and the `man/man8/messq.8` roff include
      reproducibly (identical bytes for one commit); CI fails if the tree is not up to date; the root
      module's direct-dependency budget (§13) is unchanged.
- [ ] `test/script` covers every command family with both faces where applicable;
      `TestEveryCommandHasAScript` fails on a new command without a script or a reasoned opt-out.
- [ ] Each exit code 0–7 is produced by at least one script via `exitcode`, asserting the exact status.
- [ ] The suite uses no `time.Sleep`: the `inproc` lane advances a fake clock and quiesces; the
      `subproc` lane polls with `waitfor`.
- [ ] `go test ./test/script -update` refreshes goldens, and **refuses** when a `cmpshape` assertion
      changed, printing #18's classifier verdict.
- [ ] Goldens contain no ANSI escapes, no trailing whitespace and no raw `$WORK` paths (lint tests);
      ack tokens, `seq`, `attempt` and counts are never masked.
- [ ] `verify.txtar` (#8), `metrics.txtar` (#21) and #25's `--exec` scripts run under the shared
      environment with no private harness left behind.
- [ ] The `script` job stays ≤ 180 s and the whole PR lane stays under PLAN §11's 10 minutes; the
      three sabotage self-tests each fail as designed.

## Test plan

Per PLAN §11 / D13. `-race` everywhere, no `time.Sleep`, every fixed bug lands with a committed
script reproducing it.

**Unit**
- Quickstart step planner: step list is data; argv/echo equality; `--keep` vs cleanup; env
  sanitisation (a poisoned `MESSQ_*` environment is fully cleared); socket-path-length fallback
  ladder; stale-dir reaper (marker present/absent, wrong owner, too young, wrong prefix — each
  asserted *not* to delete).
- `--dev` flag composition: table over every implied flag × explicitly-set/unset, asserting
  precedence; explicit `--data-dir` retention; banner content.
- Completion resolver: prefix filtering, description truncation (≤ 60 chars, no tabs, no ANSI),
  scoping by `args[0]`, wildcard→prefix subject rule, empty results on error, budget enforcement
  under a `clock.Fake`, cache read/write/atomicity/staleness/corruption.
- Help renderer: heading underlining, fence indentation, width wrapping at `COLUMNS`, no ANSI when
  not a TTY, unknown-topic path.
- `gendocs`: deterministic output with a fixed `SOURCE_DATE_EPOCH`; the `.so` include is emitted.

**Golden / binding**
- `TestEveryCommandHasAScript`, `TestEveryExitCodeIsExercised`, `TestNoANSIInGoldens`,
  `TestNoTrailingSpaceInGoldens`, `TestExitCodeTopicMatchesCode`,
  `TestLifecycleTopicCoversEveryTransition`, `TestExamplesExecute`.

**testscript — `inproc` lane** (fake clock, deterministic, the bulk of the suite)
- One script per command family (list in §5), each asserting the `--output table` face against a
  golden, the `--output json` face against a shape digest and a canonical-JSON golden, and at least
  one error path with its exact exit code and its teaching-error `next:` line.
- `completion.txtar`: `__complete` for streams, consumers, subjects and enum flags; dead-daemon,
  slow-daemon and forbidden cases.
- `help_topics.txtar`: every topic renders; unknown topic exits 2; root help lists them.
- `dev_mode.txtar` (partly `subproc`): auto-create events appear in `messq events`; explicit
  `--data-dir` retention.
- Restart golden: `daemon restart` then `messq events --stream demo` shows `recovery.reclaimed`, and
  `messq trace` explains the redelivery — the "every duplicate has a named cause" promise, seen
  through the CLI.

**testscript — `subproc` lane** (real binary, real clock, masked durations)
- `quickstart.txtar`: full tour with `--pause=false`, output masked and compared; asserts the DLQ
  message exists, the trace contains `dead`, the data dir is gone afterwards, and wall clock < 20 s.
- SIGINT during the tour → dir removed, exit 130.
- `messq lag` with no daemon → exit 6 and a message naming `messq serve`.
- `serve --dev` banner and Ctrl-C responsiveness (2 s drain, #17).
- `--exec` paths adopted from #25 (ack/nak/term/signal) re-run under the shared env.

**Executable documentation** (#18's harness, extended set)
- README CLI blocks, `docs/quickstart.md`, help topics, generated `docs/cli/*.md`, all cobra
  `Example` blocks; `-update` writes back into the markdown and is idempotent.

**Property (`pgregory.net/rapid`)**
- Completion candidate filtering: for random stream-name sets and prefixes, the result is exactly the
  prefix-matching subset, sorted, deduplicated, capped — never a panic, never a candidate containing
  a tab or newline (which would corrupt the `__complete` protocol). Failfiles committed.

**Timing / budget**
- The `script` job records its own wall clock and fails over 180 s, so the PR lane degrades visibly
  instead of quietly eating the 10-minute allowance.
- `quickstart-cold` records download and run times separately into the nightly summary, so a
  regression is attributable.

**Gate self-tests** (extends #2's sabotage matrix)
- Mutate one character of a table golden → `script` fails naming file and line.
- Rename a JSON field on a CLI response type → `cmpshape` fails, and still fails under `-update`.
- Add a command with no script → `TestEveryCommandHasAScript` fails naming it.

**Not tested here:** delivery semantics and invariants (#13), crash behaviour (#8/#32), wire shapes
themselves (#18), metric names (#21), log field schema (#19), DLQ operations (#29), doctor/backup
(#30), bench numbers (#31), packaging install paths (#36).
