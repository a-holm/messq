## Context

D12 drew the 1.0 security line precisely: *"No TLS in core at 1.0: terminate TLS in
nginx/caddy/Envoy **into the Unix socket**, or use WireGuard/Tailscale — one documented paragraph
instead of a certificate subsystem. Native TLS (stdlib `crypto/tls`) is phase 2."* D15 lists native
TLS among the demand-ordered phase-2 features. This is that issue, and it lands **after** v1.0 is
tagged (#36) on purpose: nothing here may perturb the frozen 1.0 surfaces.

The gap it closes is narrow and real. The 1.0 story assumes an operator who can run a proxy. Some
cannot: a single VM with no sidecar discipline, a two-host deployment where a proxy is a second
thing to keep alive, or a shop whose policy is "mTLS everywhere, no shared bearer tokens". For them
#16's listener policy currently ends in a WARN banner — *"bearer tokens travel in cleartext"* — and
that banner is the honest description of a bad deployment. After this issue there is a first-party
answer, and the banner turns into a refusal.

Governing PLAN.md material:

- **D12 — Security model: secure-by-default minimalism.** Unix socket remains the default and the
  whole story for local use. TCP still requires a credential. TLS is *added*, never *required for
  the default path*, and it brings no new dependency: `crypto/tls`, `crypto/x509` and `net/http`
  only (§13's budget is untouched — this issue adds **zero** modules).
- **§10 Security model.** *"A non-loopback bind without auth is a fatal startup error."* This issue
  tightens the same startup function: a non-loopback bind without **transport confidentiality** is
  now fatal too, with a message that names either the TLS flags or the proxy-into-the-socket
  recipe.
- **D8 — flags + `MESSQ_*` env only.** Every knob below is a flag. The certificate is *data* behind
  a path-valued flag, which is exactly the category #17 says SIGHUP re-reads.
- **D11 / §9.2–9.4 — three surfaces, one vocabulary.** TLS gets durable events, log lines and
  metrics with the same names, and the cardinality rule (`stream`/`consumer` labels only, closed
  small enums like `reason` permitted by #16's precedent) applies unchanged.
- **§14 M9 exit criterion.** *"Each feature ships with a new invariant, events, metrics, docs — or
  it does not ship."*

What it builds on: **#16** left `Principal.Kind` open for `KindCert`, kept address classification in
one function, and put every grant in one file — this issue fills all three holes. **#17** built the
two-phase `Reloader` registry and already prints `reload.skip reloader=tls reason="no --tls-cert
configured"`; this issue is the reloader that line is waiting for.

The bar is not "we support TLS". It is: **a rotation is a `systemctl reload` that drops zero
requests**, and **an identity check cannot be skipped by session resumption** — both proven by
committed tests, not by review.

## Scope

### In scope

- **`internal/tlsconf`** (~450 lines incl. comments): certificate/key loading and validation, the
  atomic snapshot, `GetConfigForClient` / `GetCertificate` / `VerifyConnection`, client-identity
  extraction, and the `lifecycle.Reloader` implementation #17 registers.
- **TLS on TCP listeners**: `--tls-cert` / `--tls-key`, `MinVersion` 1.2 (TLS 1.3 preferred by
  negotiation), Go's default cipher selection, ALPN `http/1.1` by default with an opt-in `h2`.
- **Hot reload**: SIGHUP re-reads both files; new handshakes get the new leaf, in-flight
  connections and parked long polls are untouched; a bad pair leaves the previous certificate live.
- **mTLS**: `--tls-client-ca`, `--tls-client-auth=off|optional|require`, identity derived from a URI
  SAN / DNS SAN / subject CN, mapped to a **`KindCert` principal whose grants live in #16's auth
  file**, with `Actor() == "cert:<id>"` landing in `events.actor` and therefore in `messq trace`.
- **Identity and chain checks inside `VerifyConnection`** — never `VerifyPeerCertificate` — plus the
  resumption regression test that proves it (the CVE-2025-68121 class).
- **Listener policy tightening** in #16's single policy table: a public listener now needs TLS *and*
  a credential source; `--tls-*` on a Unix-only daemon is a configuration error, not a no-op.
- **Preflight**: key-file mode/ownership, cert/key pair agreement, expiry, CA pool sanity — fatal
  rows exit **78 (`EX_CONFIG`)** exactly like #16's.
- **Observability**: two new event kinds (`tls.handshake_failed`, `tls.cert_expiring`), TLS facts in
  `server.start.detail` and `/v1/info`, four metrics, two shipped alert rules, `doctor` findings.
- **Client side**: `https://` addresses for `--addr` / `MESSQ_ADDR`, `--tls-ca-file`,
  `--tls-client-cert`, `--tls-client-key`, `--tls-server-name`, `--tls-insecure` (loud), wired
  through `pkg/client`'s existing `WithHTTPClient` seam.
- **Docs**: the deployment matrix in `docs/OPERATIONS.md` and `SECURITY.md` gains the native-TLS
  row, a certbot/cert-manager rotation recipe, and the written revocation story.

### Out of scope

- CRL and OCSP checking. Go verifies neither by itself; the supported revocation story is
  short-lived certificates plus deleting the principal's line and reloading (instant, because
  grants are resolved per request). Deferred with a revisit trigger below — no issue owns it.
- SNI-based multi-certificate serving, per-listener certificates, ACME/autocert. One cert per
  process; deferred, revisit trigger below.
- Automatic file-watching reload (fsnotify or a poll loop). SIGHUP is the contract #17 defined;
  deferred, revisit trigger below.
- Cipher-suite, curve and session-ticket-key configuration. Go's defaults, unmodified.
- The SIGHUP signal path, the reload registry, the two-phase ordering and `server.reload` →
  **#17**; this issue only implements a `Reloader` and is tested by calling it directly.
- Bearer tokens, roles, the token-file grammar, the permission matrix, `auth.denied` and its
  coalescing machinery → **#16**; this issue extends the grammar by one credential form and reuses
  the coalescer verbatim.
- Event-kind machinery, `docs/log-schema.md` generation and the fold model → **#19**/**#13**;
  metric registration and the cardinality golden → **#21**; `doctor`'s prose renderer → **#30**;
  the contract/curl golden harness → **#18**; the 1.0 documentation set → **#35**. This issue adds
  rows to each of their tables and ships plain Go tests so it blocks on none of them.
- HTTP/2 as a supported transport. `--tls-alpn-h2` exists, is off by default, and is documented as
  experimental with its `--max-conns` caveat (§9). Making h2 first-class is not on the roadmap.
- Encrypting the SQLite file, signing artifacts, hash-chained audit trails → rejected by D12 or
  owned by #36.

## Design proposal

> Proposal and starting point, not mandate — **except** the four **_decisions_** below, each of
> which is a security property rather than a style choice, and the flag names, which become an
> operator-visible surface the moment anyone writes a systemd drop-in.

### 1. Package layout

```
internal/tlsconf/
  config.go     Config (flags → struct), Mode, Source, validation of the combination
  snapshot.go   snapshot: leaf + chain + parsed cert + CA pool + fingerprint; atomic.Pointer
  load.go       LoadPair(certFile, keyFile) — X509KeyPair + all the checks of §4
  server.go     ServerConfig(), GetConfigForClient, GetCertificate, VerifyConnection
  identity.go   Identity(*x509.Certificate, Source) (string, error)
  reload.go     Manager implements lifecycle.Reloader (#17): Name/Validate/Apply
  preflight.go  file modes, ownership, expiry; shared with doctor (#30)
internal/auth/
  file.go       + the `cert:` credential form (§5)
  principal.go  + KindCert, Actor() == "cert:<id>"
internal/api/
  authn.go      + step 2 of the credential ladder (§6)
internal/testutil/pki/
  pki.go        in-memory test CA: server certs, client certs, wrong-CA certs, expired,
                no-EKU, no-SAN — used by every test below; never a fixture file on disk
```

`internal/tlsconf` imports `crypto/tls`, `crypto/x509`, `internal/clock`, `internal/obs` and
`internal/errs`. It does not import `internal/api`, `internal/auth` or `internal/store`: identity
extraction is a pure function from a certificate to a string, which is what makes it table-testable
and fuzzable.

### 2. Types

```go
package tlsconf

type Mode uint8   // client-certificate policy
const (ModeOff Mode = iota; ModeOptional; ModeRequire)

type Source uint8 // where the client identity comes from
const (SourceAuto Source = iota; SourceURI; SourceDNS; SourceSubjectCN)

type Config struct {
    CertFile, KeyFile string
    ClientCAFile      string
    ClientAuth        Mode          // ModeRequire is the default *when* ClientCAFile is set
    MinVersion        uint16        // tls.VersionTLS12 | tls.VersionTLS13 — nothing else parses
    Identity          Source
    ALPNH2            bool
    ExpiryWarning     time.Duration // 336h
}

// snapshot is immutable once published. Everything mutable lives behind one atomic pointer.
type snapshot struct {
    cert        *tls.Certificate
    leaf        *x509.Certificate // cert.Leaf, always populated (we parse it ourselves)
    clientCAs   *x509.CertPool
    caSubjects  []string          // for the startup banner and doctor
    fingerprint string            // sha256 over cert+key+CA bytes: drives reload.skip
    loadedAt    time.Time
}

type Manager struct {
    cfg  Config
    cur  atomic.Pointer[snapshot]
    next atomic.Pointer[snapshot] // staged by Validate, published by Apply (#17's two phases)
    clk  clock.Clock
    emit obs.Emitter
}

func New(cfg Config, clk clock.Clock, emit obs.Emitter) (*Manager, error) // loads once, eagerly
func (m *Manager) ServerConfig() *tls.Config
func (m *Manager) Identity(cs *tls.ConnectionState) (string, bool)
func (m *Manager) Snapshot() Info            // for /v1/info, doctor, the expiry gauge

// lifecycle.Reloader (#17 §7)
func (m *Manager) Name() string { return "tls" }
func (m *Manager) Validate() (lifecycle.Change, error)
func (m *Manager) Apply()
```

### 3. The `tls.Config`, and the two things that are easy to get wrong

```go
func (m *Manager) ServerConfig() *tls.Config {
    return &tls.Config{
        MinVersion:           m.cfg.MinVersion,          // 1.2 floor; 1.3 wins by negotiation
        GetCertificate:       m.getCertificate,          // reads m.cur — hot reload, no restart
        GetConfigForClient:   m.getConfigForClient,      // fresh CA pool per NEW handshake
        VerifyConnection:     m.verifyConnection,        // ← runs for resumed handshakes too
        VerifyPeerCertificate: nil,                      // ← deliberately, permanently nil
        ClientAuth:           m.clientAuthType(),
        NextProtos:           m.alpn(),                  // ["http/1.1"], or ["h2","http/1.1"]
    }
}
```

**_Decision 1: every identity and trust check lives in `VerifyConnection`._** `VerifyPeerCertificate`
is documented as *not* invoked on resumed connections — including connections resumed across
configs returned by `GetConfigForClient` — while `VerifyConnection` *"will run for all connections,
including resumptions"*. CVE-2025-68121 is precisely the case where narrowing `ClientCAs` between
handshakes still admits a resumed session. So:

- `ClientCAs` is never mutated in place. `GetConfigForClient` returns a config built from the
  *current* snapshot; a snapshot is immutable.
- `verifyConnection` re-verifies the presented chain against `m.cur.Load().clientCAs` **itself**, so
  a resumed session established under the old CA is rejected the moment the pool changes.
- A `forbidigo` rule (#2) forbids assigning `VerifyPeerCertificate` anywhere in the tree, with the
  CVE named in the rule's message. A grep-level test asserts the field stays nil.

```go
func (m *Manager) verifyConnection(cs tls.ConnectionState) error {
    s := m.cur.Load()
    if m.cfg.ClientAuth == ModeOff || (m.cfg.ClientAuth == ModeOptional && len(cs.PeerCertificates) == 0) {
        return nil
    }
    if len(cs.PeerCertificates) == 0 {
        return m.reject(cs, "no_client_cert")
    }
    opts := x509.VerifyOptions{
        Roots:         s.clientCAs,                 // the LIVE pool, re-read every handshake
        Intermediates: intermediatePool(cs.PeerCertificates[1:]),
        KeyUsages:     []x509.ExtKeyUsage{x509.ExtKeyUsageClientAuth},
        CurrentTime:   m.clk.Wall(),                // wall clock: certificates are wall-clock objects
    }
    if _, err := cs.PeerCertificates[0].Verify(opts); err != nil {
        return m.reject(cs, classify(err))          // untrusted_ca | expired | not_yet_valid | no_client_eku
    }
    if _, err := Identity(cs.PeerCertificates[0], m.cfg.Identity); err != nil {
        return m.reject(cs, "no_identity")          // a cert we cannot name is a cert we cannot audit
    }
    return nil
}
```

**_Decision 2: the handshake proves the certificate; the request proves the authority._**
`verifyConnection` stops at "this is a trusted certificate carrying an extractable identity". It
does **not** look up grants. Grants are resolved per request from #16's live registry, so deleting
a principal's line and sending SIGHUP revokes it **on the next request of an existing, already
established connection** — no connection teardown, no session-ticket problem, no revocation
latency. It also means an unmapped-but-trusted client gets a readable `403` instead of an opaque
TLS alert.

### 4. Loading and validating a pair (the checks are the feature)

```go
func LoadPair(certFile, keyFile string) (*tls.Certificate, *x509.Certificate, error)
```

| Check | Startup | SIGHUP reload |
|---|---|---|
| files readable | fatal 78 | `Validate` error, previous stays live |
| `tls.X509KeyPair` agrees (key matches leaf) | fatal 78 | error — this is the non-atomic-write case |
| key file mode ⊄ 0600, or not owned by euid/root | fatal 78, prints the `chmod`/`chown` | error |
| leaf `NotAfter` in the past | **fatal 78** | error (a rotation that installs an expired cert is a typo) |
| leaf `NotBefore` more than 5 min in the future | fatal 78 | error |
| leaf has no `serverAuth` EKU | fatal 78 | error |
| leaf has no SAN (CN-only) | **WARN**, starts — modern clients will reject it, and saying so beats failing to connect | WARN |
| `--tls-client-ca` parses to zero certificates | fatal 78 | error |
| leaf expires within `--tls-expiry-warning` | WARN banner + `tls.cert_expiring` | same |

The leaf is parsed once and stored in `cert.Leaf` so no handshake re-parses it. Both paths are
re-read through the filesystem on every load and **never held open as a file descriptor**: k8s and
cert-manager rotate by swapping a `..data` symlink, and a cached fd would pin the old file forever.

### 5. Where a certificate identity gets its grants

**_Decision 3: grants have exactly one home — #16's auth file._** A certificate authenticates; it
never authorizes. The token file's credential column already distinguishes forms by shape, so mTLS
costs one grammar rule and no second file, no second reloader, no second permission model:

```
# /etc/messq/tokens   mode 0600, owned by the messq user
# id             credential                                    roles          streams
ci-publisher     3f786850e387550fdab836ed7e6dc881de23001b…     publish        orders,payments
billing-worker   cert:messq://principal/billing-worker         consume        orders*
audit-bot        cert:spiffe://corp/ns/ops/sa/audit-bot        admin,consume  *
```

- 64 hex characters ⇒ a bearer-token principal (#16, unchanged).
- `cert:` prefix ⇒ a certificate principal; the remainder is matched **exactly** against the
  extracted identity string. No patterns, no prefixes — a wildcard here would be a silent
  authority grant to anyone the CA ever signs.
- Duplicate identities are fatal, like duplicate ids and duplicate hashes.
- `messq auth add billing-worker --cert 'messq://principal/billing-worker' --role consume --streams
  'orders*'` writes such a line and prints no secret (there is none). `messq auth ls` grows a `kind`
  column (`token` / `cert`).

**Identity extraction** (`identity.go`, pure, fuzzed):

| `--tls-identity-source` | Rule |
|---|---|
| `auto` (default) | first URI SAN; else, if exactly one DNS SAN, that; else subject CN if non-empty |
| `uri` | exactly one URI SAN required |
| `dns` | exactly one DNS SAN required |
| `subject-cn` | subject CN, non-empty |

More than one URI SAN is an error in every mode (`ambiguous_identity`) — picking "the first of
several" is how a confused-deputy bug is born. The extracted string must be printable UTF-8, ≤ 253
bytes, and free of whitespace and control characters; it is compared byte-for-byte and never
case-folded (URIs and DNS names disagree about case, and folding is where a mismatch hides).

### 6. The credential ladder (extends #16's `authn` middleware)

```
1. Authorization: Bearer …      → KindToken   (explicit credential always wins — #16's precedent)
2. r.TLS.PeerCertificates       → KindCert    (identity re-extracted per request; grants looked up live)
3. SO_PEERCRED on the socket    → KindLocal
4. nothing                      → anonymous
```

Identity is re-derived per request from `r.TLS` rather than cached on the connection: it is a field
read plus a bounded string extraction, it keeps the connection layer stateless, and it means a
`GetConfigForClient` change can never leave a stale principal attached to a live connection.

| Situation | Result |
|---|---|
| Cert principal present in the auth file | Normal principal; `Actor() == "cert:billing-worker"` on every mutating event |
| Trusted cert, identity **not** in the auth file | `403 forbidden` naming the identity and the exact `messq auth add --cert …` line. **Deliberate exception to #16's "never name the identity in a 403"**: this identity is the caller's own, it is in their certificate, and withholding it makes the error unactionable. |
| Bearer token **and** a client certificate naming a *different* principal | `403 forbidden`, `auth.denied reason=identity_conflict`, zero store commands. Ambiguous authority is refused, never silently resolved. |
| Bearer token and a certificate naming the *same* id | Allowed; `detail.auth_method="token+cert"` on the log line |
| `--tls-client-auth=optional`, no certificate presented | Falls through to the token path; the mixed fleet is the point of `optional` |

### 7. Listener policy, tightened (one edit to #16's table)

| Listener | TLS | Credential source | Result |
|---|---|---|---|
| `unix://…` | n/a | peercred / token | ✅ default, unchanged |
| `unix://…` | `--tls-cert` set | — | ❌ **fatal 78** — TLS on a Unix socket is a misconfiguration; the message names `--listen tcp://` |
| loopback `tcp://` | none | token or none | ⚠️ allowed, WARN banner (unchanged) |
| loopback `tcp://` | TLS | any | ✅ |
| non-loopback | **none** | any | ❌ **fatal 78** — was fatal only without `--auth-file`; now fatal without TLS as well |
| non-loopback | TLS | `--auth-file` (± `--tls-client-ca`) | ✅ no banner |
| non-loopback | TLS | no `--auth-file` | ❌ fatal 78 — grants live in the auth file (§5), so mTLS without it is a daemon nobody can use |
| any | `--tls-client-ca` without `--tls-cert` | — | ❌ fatal 78 — mTLS requires TLS |

**_Decision 4: the cleartext public listener is gone, and there is no flag to bring it back._** #16
shipped it with a WARN because there was no alternative; now there is. The refusal message is the
whole user experience of this change:

```
messq: refusing to serve tcp://0.0.0.0:4390 in cleartext.
       Bearer tokens on this listener would travel unencrypted over the network.
  fix: messq serve --listen tcp://0.0.0.0:4390 --tls-cert /etc/messq/tls/server.crt \
                   --tls-key /etc/messq/tls/server.key --auth-file /etc/messq/tokens
   or: keep --listen unix:///run/messq/messq.sock and terminate TLS in a reverse proxy
       into that socket (docs/OPERATIONS.md#tls-termination)
exit 78
```

Note the compatibility shape: a 1.0 deployment that binds `0.0.0.0` in cleartext was already living
on a documented warning, and the phase-2 release notes must say plainly that it now refuses to
start. That is a deliberate, announced break of a discouraged configuration — §14's M9 is the right
place for it and `docs/UPGRADING.md` gets the paragraph.

### 8. Reload

```go
func (m *Manager) Validate() (lifecycle.Change, error) {
    cert, leaf, err := LoadPair(m.cfg.CertFile, m.cfg.KeyFile)   // all §4 checks
    if err != nil { return lifecycle.Change{}, err }             // nothing staged, old stays live
    pool, subjects, err := loadCAs(m.cfg.ClientCAFile)
    if err != nil { return lifecycle.Change{}, err }
    s := &snapshot{cert: cert, leaf: leaf, clientCAs: pool, caSubjects: subjects,
                   fingerprint: fingerprint(...), loadedAt: m.clk.Wall()}
    if cur := m.cur.Load(); cur != nil && cur.fingerprint == s.fingerprint {
        return lifecycle.Change{}, lifecycle.ErrUnchanged      // → reload.skip reason="unchanged"
    }
    m.next.Store(s)
    return lifecycle.Change{Field: "tls.cert",
        From: fmt.Sprintf("%s exp %s", short(cur.leaf), cur.leaf.NotAfter.Format(time.RFC3339)),
        To:   fmt.Sprintf("%s exp %s", short(leaf), leaf.NotAfter.Format(time.RFC3339))}, nil
}

func (m *Manager) Apply() { m.cur.Store(m.next.Load()) }        // one pointer store; cannot fail
```

```console
$ sudo certbot renew && sudo systemctl reload messq
INFO  server.reload  trigger=SIGHUP applied=1 unchanged=1 failed=0 duration_ms=4
INFO  reload.diff    reloader=tls  cert=CN=messq-1.internal/serial=0a3f… exp 2026-12-27T09:00:00Z
                                     → CN=messq-1.internal/serial=0b71… exp 2027-03-27T09:00:00Z
```

Established connections keep the certificate they handshook with (that is how TLS works, and it is
why rotation drops nothing); every new handshake gets the new leaf. Parked long polls are
unaffected. A failed `Validate` leaves the previous certificate serving and logs
`reload.diff reloader=tls failed=1 error="…"` — a mistyped path at 3 a.m. must not take the
listener down, exactly as #17 requires for the token file.

### 9. Flags

| Flag | Env | Default | Meaning |
|---|---|---|---|
| `--tls-cert` | `MESSQ_TLS_CERT` | *(none)* | PEM leaf + intermediates. Presence enables TLS on **all** `tcp://` listeners. |
| `--tls-key` | `MESSQ_TLS_KEY` | *(none)* | PEM private key; mode ≤ 0600 enforced. |
| `--tls-client-ca` | `MESSQ_TLS_CLIENT_CA` | *(none)* | PEM bundle of client CAs. Presence enables mTLS. |
| `--tls-client-auth` | `MESSQ_TLS_CLIENT_AUTH` | `auto` | `off` \| `optional` \| `require`. `auto` = `require` when a CA is set, `off` otherwise. |
| `--tls-identity-source` | `MESSQ_TLS_IDENTITY_SOURCE` | `auto` | `auto` \| `uri` \| `dns` \| `subject-cn` (§5). |
| `--tls-min-version` | `MESSQ_TLS_MIN_VERSION` | `1.2` | Only `1.2` and `1.3` parse; `1.0`/`1.1`/`ssl3` are a startup error naming the reason. |
| `--tls-expiry-warning` | `MESSQ_TLS_EXPIRY_WARNING` | `336h` (14 d) | When the banner, the event and `doctor` start warning. |
| `--tls-alpn-h2` | `MESSQ_TLS_ALPN_H2` | `false` | Advertise `h2` in ALPN. **Experimental**: `--max-conns` (#14) counts connections, and one h2 connection carries many streams, so the accept-side limit stops bounding concurrent requests. Documented, not gated. |

Client side (persistent flags on #23's cobra root, honoured by `pkg/client` through
`WithHTTPClient`): `--tls-ca-file`, `--tls-client-cert`, `--tls-client-key`, `--tls-server-name`,
`--tls-insecure`. `--addr https://host:4390` selects TLS; `--tls-insecure` prints a one-line WARN to
stderr on **every** invocation — a debugging aid that is never quiet enough to become a habit.

No cipher-suite, curve or session-ticket flags. Go's defaults are the policy; TLS 1.3 suites are
not configurable in Go at all, and a suite list in a systemd drop-in is a 2031 vulnerability report.

### 10. Observability

Two new event kinds for #19's table (its rules apply: WARN ⇒ never sampled; both are
repeat-limited; both need an explicit no-op rule in #13's fold model since neither touches queue
state):

| Event | Level | Smpl | Rpt | Fold | Key `detail` |
|---|---|---|---|---|---|
| `tls.handshake_failed` | WARN | no | **yes** | no-op | `reason`, `remote`, `tls_version`, `sni`, `client_subject` |
| `tls.cert_expiring` | WARN | no | **yes** | no-op | `not_after`, `days_left`, `subject`, `serial` |

`reason` is a closed enum: `no_client_cert`, `untrusted_ca`, `expired`, `not_yet_valid`,
`no_client_eku`, `no_identity`, `ambiguous_identity`, `version_too_low`, `plaintext_client`, `eof`.
Handshake failures are an **unauthenticated flood vector**, so durable rows reuse #16's Decision-4
coalescer verbatim: always log + metric, one durable row per `(reason, remote-host)` per
`--auth-event-window`, capped at 1024 LRU keys, written on the janitor tick (I11 applies).
`plaintext_client` exists because "someone curled `http://` at the TLS port" is the single most
common support question, and the log line should answer it:

```
WARN  tls.handshake_failed  reason=plaintext_client remote=10.2.0.9:51544
      hint="the client spoke cleartext HTTP to a TLS listener — use https:// or --tls-ca-file"
```

No new kind for rotation (`server.reload` + `reload.diff` already say it) and none for startup:
`server.start.detail` gains `tls_min_version`, `tls_mtls`, `tls_alpn`, `tls_not_after`,
`tls_leaf_sha256`, and the human handler renders one extra banner line:

```
INFO  server.start  version=1.1.0 durability=full listen=unix:///run/messq/messq.sock,tcp://0.0.0.0:4390
      tls  min=1.2 alpn=[http/1.1] mtls=require ca_subjects=1
           leaf CN=messq-1.internal sans=[messq-1.internal 10.2.0.7] expires 2026-12-27 (in 30d)
```

Metrics (#21's registry; labels are closed enums only — no ids, no subjects, no remote addresses):

```
messq_tls_handshakes_total{version}              # "1.2" | "1.3"
messq_tls_handshake_failures_total{reason}       # the closed enum above
messq_tls_cert_not_after_seconds{usage}          # "server"; unix seconds — the standard shape
messq_tls_cert_reloads_total{result}             # "applied" | "unchanged" | "failed"
```

Shipped alert rules in `contrib/prometheus/alerts.yml`: `MessqTLSCertExpiringSoon`
(`messq_tls_cert_not_after_seconds - time() < 14d`, warning at 14 d, critical at 3 d) and
`MessqTLSHandshakeFailures` (`rate(messq_tls_handshake_failures_total[10m]) > 0` excluding `eof`).

`GET /v1/info` (admin-scoped) gains an additive `tls` block — never a key, never a fingerprint of
the key:

{"tls":{"enabled":true,"min_version":"1.2","alpn":["http/1.1"],"mtls":"require",

### 11. Edge cases, decided

| Case | Handling |
|---|---|
| Cert written before key (non-atomic rotation) | `X509KeyPair` mismatch → `Validate` error, previous cert stays live. The rotation recipe in the docs writes to a temp dir and renames, and says why. |
| Cert/key are symlinks into a k8s `..data` directory | Paths are re-read every load; no fd is held. Tested by swapping a symlinked directory between reloads. |
| SIGHUP with byte-identical files | `reload.skip reloader=tls reason="unchanged"`; no snapshot churn, `messq_tls_cert_reloads_total{result="unchanged"}`. |
| Certificate expires *while running* | Nothing is torn down (that is the client's judgement); the metric goes negative-ward, the alert fires, `tls.cert_expiring` repeats at the limiter's interval. |
| Wall clock jumps backwards past `NotBefore` | Handshakes fail with `not_yet_valid`; certificates are wall-clock objects, so the `Clock` seam's `Wall()` is used deliberately and the monotonic deadline machinery elsewhere is untouched. Documented in the runbook. |
| Health-check prober opens a TCP connection and closes it | `reason=eof`, coalesced, excluded from the alert rule — an LB probe must not page anyone. |
| Client presents a cert signed by the **server** CA | `untrusted_ca` unless that CA is also in `--tls-client-ca`. The docs recommend separate CAs so they rotate independently; a test covers the confusion. |
| Client cert valid but lacking `clientAuth` EKU | Rejected (`no_client_eku`). Go's `VerifyOptions.KeyUsages` does this; we set it explicitly rather than inheriting a default. |
| CA rotated to exclude an issuer, client resumes an old session | Rejected — `verifyConnection` re-verifies against the live pool. **This is the regression test.** |
| Principal's line deleted, SIGHUP, existing connection sends a request | `403` on the next request; the parked long poll it already had completes (#16's rule, unchanged). |
| `--tls-client-auth=require` and a browser hits the port | Handshake fails with a client-cert alert; the log line names the reason; documented, because "the browser shows nothing useful" otherwise. |
| Two `--listen tcp://` addresses | Both get the same certificate. Per-listener certs are out of scope; the startup banner prints the cert once and names both listeners. |
| SNI naming a host the certificate does not cover | Served anyway — we do not select on SNI. Documented, and `doctor` warns when the leaf's SANs do not include any `--listen` host. |
| TLS 1.2 renegotiation attempt | Disabled by Go's default (`RenegotiationNever`); asserted in a test so a future config edit cannot enable it silently. |
| `--tls-min-version=1.3` with a 1.2-only client | Handshake rejected, `reason=version_too_low`, and the hint names the flag so an operator can tell a policy refusal from a broken cert. |
| Payload of a rejected handshake | Nothing is read; no handler runs; `--max-conns` still bounds the accept path (#14). |

### 12. Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| CRL / OCSP checking | Go verifies neither by itself; a CRL file is a freshness problem plus a fetcher plus a failure mode. Short-lived certs + `auth-file` revocation covers the ICP and revokes *faster*. | A user with a compliance requirement that names CRLs |
| SNI multi-certificate, per-listener certificates | One process, one identity is the whole deployment shape (§3.1). `GetCertificate` already has the signature that would support it. | Someone runs two DNS names into one daemon |
| ACME / autocert | A network dependency and a state directory inside a broker whose selling point is one file. certbot's post-renew hook is `systemctl reload messq`, which is one line of docs. | Never, for core |
| File-watch (fsnotify) or polled reload | A dependency (§13's budget) or a poll loop, versus SIGHUP, which #17 already ships and which certbot and cert-manager both support via hooks. | A k8s user shows that neither a hook nor a sidecar `kill -HUP` is available |
| First-class HTTP/2 | The `--max-conns` semantics (§9) and h2-specific timeout behaviour are a separate piece of work with no measured benefit at ≤ 5k msg/s. | A measured latency win at the ICP's scale |
| TLS on the Unix socket | Encryption over a filesystem path whose ACL is the security model. | Never |
| Encrypted private keys (passphrase) | A passphrase prompt in a `Type=notify` unit is an availability hazard; file mode 0600 plus systemd credentials is the answer. | A `LoadCredentialEncrypted=` recipe request |

## Acceptance criteria

- [ ] `messq serve --listen tcp://0.0.0.0:4390 --auth-file …` **without** `--tls-cert` exits **78**
      before binding, with the §7 message naming both fixes, and emits
      `server.start outcome=refused`; the same command with `--tls-cert`/`--tls-key` starts and
      serves HTTPS with no cleartext banner.
- [ ] Every fatal row of §7 is table-tested against a real `messq serve` subprocess: TLS on a Unix
      socket, `--tls-client-ca` without `--tls-cert`, public + TLS without `--auth-file`,
      `--tls-min-version=1.1` — each exits 78 with a message naming the flag that fixes it, and
      nothing ever listens.
- [ ] Every §4 preflight check is enforced: a world-readable key, a mismatched cert/key pair, an
      expired leaf, a `NotBefore` in the future, a missing `serverAuth` EKU and an empty CA bundle
      each refuse startup with exit 78 and an exact `chmod`/`chown`/re-issue instruction; a CN-only
      leaf warns and starts.
- [ ] **TLS conformance suite green**: a TLS 1.0 and a TLS 1.1 client are rejected; TLS 1.2 and
      TLS 1.3 clients succeed; with `--tls-client-auth=require` a client with no certificate is
      rejected; a certificate from the wrong CA is rejected; an expired client certificate is
      rejected; a certificate without the `clientAuth` EKU is rejected — each with the correct
      `reason` on all three surfaces.
- [ ] **Resumption regression test passes**: a client completes a handshake, obtains a session
      ticket, the CA pool is reloaded to exclude its issuer, and the *resumed* handshake is
      **rejected**; the same test asserts `tls.Config.VerifyPeerCertificate == nil` and the
      `forbidigo` rule that keeps it nil fails a fixture that sets it.
- [ ] **Rotation under load drops zero requests**: with a sustained publish+fetch+ack load over
      TLS, the certificate is rotated and SIGHUP sent twice; every request succeeds (zero non-2xx,
      zero transport errors), the ledger oracle stays clean, and connections established after each
      reload present the new leaf's SHA-256 while pre-existing connections keep serving.
- [ ] A failed reload (unreadable file, mismatched pair, expired leaf) leaves the previous
      certificate live and the listener serving — asserted with a successful request before, during
      and after — and reports `failed=1` on `server.reload`; an unchanged pair yields
      `reload.skip reason="unchanged"`.
- [ ] A client certificate whose identity has a `cert:` line in the auth file is authorized by
      those grants, and a mutating request through it records `events.actor == "cert:<id>"`,
      visible in `messq trace`.
- [ ] A trusted client certificate whose identity is **not** in the auth file receives `403` naming
      the identity and the exact `messq auth add --cert …` line; deleting that line and reloading
      makes the very next request on the **same connection** return `403` (per-request grant
      resolution, Decision 2).
- [ ] Presenting a bearer token and a client certificate that name different principals returns
      `403` with `auth.denied reason=identity_conflict` and performs zero store mutations; naming
      the same principal succeeds with `detail.auth_method="token+cert"`.
- [ ] Identity extraction is table-tested over: one URI SAN, two URI SANs (rejected), a SPIFFE URI,
      one DNS SAN, several DNS SANs (rejected in `dns`/`auto`), CN-only, empty subject with no SANs,
      a non-UTF-8 SAN and a SAN containing whitespace or control characters (all rejected), for
      each of the four `--tls-identity-source` values.
- [ ] The auth-file grammar accepts `cert:<identity>` in the credential column, rejects a duplicate
      identity and a `cert:` value containing `*`, and `messq auth add --cert` / `messq auth ls`
      round-trip it with a `kind` column and print no secret.
- [ ] `tls.handshake_failed` appears on all three surfaces with the closed `reason` enum, is
      repeat-limited in logs, and its durable rows are coalesced per `(reason, remote-host)` per
      `--auth-event-window` with `detail.suppressed=N`, capped at 1024 keys; a cleartext client to
      the TLS port produces `reason=plaintext_client` with the `https://` hint.
- [ ] `tls.cert_expiring` fires from the janitor when the leaf is inside `--tls-expiry-warning`,
      is repeat-limited, and both new kinds have a `Kind` entry, a `docs/log-schema.md` row and an
      explicit fold rule (#13's `TestFoldCoverage` passes).
- [ ] The four metrics exist with exactly the labels in §10, pass #21's cardinality golden (no
      remote address, no identity, no serial as a label), and `messq_tls_cert_not_after_seconds`
      equals the leaf's `NotAfter` before and after a rotation.
- [ ] `GET /v1/info` returns the additive `tls` block; a byte-level test asserts no private-key
      material, and no `tls` block at all when TLS is disabled (1.0 shape unchanged).
- [ ] `messq --addr https://… --tls-ca-file …` publishes and fetches end to end; with
      `--tls-client-cert/--tls-client-key` it authenticates as the certificate principal; a
      hostname mismatch and an untrusted CA both map to CLI exit code **6** with a message naming
      `--tls-ca-file`/`--tls-server-name`; `--tls-insecure` works and prints a WARN every run.
- [ ] `messq doctor` renders the §10 TLS section including days-to-expiry, key-mode, mTLS state and
      the SAN-vs-listener-host warning, and exits non-zero only on the documented fatal findings;
      `docs/OPERATIONS.md`'s deployment matrix, `SECURITY.md`'s revocation story and
      `docs/UPGRADING.md`'s note about the now-refused cleartext public bind are executable or
      golden-tested where they contain commands.

## Test plan

Consistent with PLAN §11: `-race` everywhere, no `time.Sleep` (the expiry-warning tick and the
coalescing window run under `testing/synctest` with the `Clock` seam), every fixed bug lands with
its reproduction artifact. All certificates are minted in-process by `internal/testutil/pki` —
**no PEM fixture files on disk**, so nothing in this repo can expire and no test key can be
mistaken for a real one.

**Unit — `internal/tlsconf` (pure, fast, the coverage centre)**
- `LoadPair` table: valid RSA / ECDSA / Ed25519 pairs; mismatched pair; key-only; cert-only;
  garbage PEM; empty file; DER-not-PEM; chain with an intermediate in the wrong order; expired;
  not-yet-valid; no `serverAuth` EKU; no SAN; 0644 key (mode check skipped when running as root).
- `Identity` table: the full matrix from the acceptance criteria × four sources, asserting the exact
  extracted string or the exact error class.
- `Config` validation table: every §7 row, plus `--tls-min-version` parsing (`1.2`, `1.3`, `1.1`,
  `TLSv1.2`, empty, garbage) and `--tls-client-auth` parsing including `auto` resolution.
- `Validate`/`Apply`: staged-but-not-applied semantics; `ErrUnchanged` on identical bytes; a failing
  `Validate` never mutates `cur`; 1 000 concurrent `getCertificate` calls during a reload under
  `-race` never observe a torn snapshot.

**Property / fuzz (`pgregory.net/rapid`, `go test -fuzz`; corpus committed — #33 adopts)**
- `FuzzIdentity`: random SAN sets and subject fields through `Identity` — never panics, and any
  returned identity satisfies the printable/length/no-whitespace contract.
- `FuzzCertCredentialLine`: random `cert:` lines through #16's parser — never panics; anything that
  parses re-renders and re-parses identically; nothing containing `*` ever parses.
- Rapid round trip: random principal sets (mixed token and cert forms) → render → parse → compare
  with `go-cmp`, asserting a cert identity authorizes iff it matches exactly.

**Integration — real listeners, real handshakes (`net.Listen` + `crypto/tls` clients)**
- The conformance suite of §11 and the acceptance criteria, one subtest per row, asserting the HTTP
  outcome *and* the emitted event/metric.
- **The resumption regression test** (the flagship): `tls.Config.ClientSessionCache` on the client,
  handshake #1 succeeds, `Validate`/`Apply` a CA pool without the issuer, handshake #2 resumes and
  must fail; a control run without the CA change must resume successfully, so the test proves
  resumption actually happened rather than passing vacuously.
- Credential-ladder matrix: {no credential, token, cert, token+cert same, token+cert different} ×
  {`off`, `optional`, `require`} × {mapped, unmapped identity}, asserting status, `actor`, and that
  every denial submits zero writer commands (#16's counter assertion, reused).
- Revocation latency: delete the `cert:` line, `Validate`+`Apply` the auth registry, assert the next
  request on the **same** keep-alive connection is `403`.
- Symlink rotation: cert/key behind a `..data`-style symlinked directory, swapped between reloads.

**Crash / load**
- Rotation-under-load, the M9 acceptance gate: `messq bench` (#31) driving publish+fetch+ack over
  TLS for 60 s while a helper rotates the certificate and sends SIGHUP twice; assert zero failed
  requests, the ledger oracle clean, `messq_tls_cert_reloads_total{result="applied"} == 2`, and the
  post-reload leaf fingerprint on a fresh connection. Nightly variant: 10 min with `kill -9` and
  restart interleaved, asserting recovery still holds (#8's harness, TLS transport swapped in).
- `TestNoGoroutineLeak` around 1 000 failed handshakes (an unauthenticated client can be made to
  fail cheaply; we must not accumulate anything — I11).

**Golden**
- `server.start` detail and the human banner line with TLS on/off; the `tls.handshake_failed` and
  `tls.cert_expiring` JSON log lines and event rows (serials and fingerprints normalised);
  `/v1/info`'s `tls` block; the `/metrics` name+label set (#21's cardinality golden); the two new
  rows in `docs/log-schema.md`.

**testscript (#26's suite)**
- `messq doctor` TLS section against a daemon with a near-expiry certificate (minted 9 days out at
  test time, so the transcript is stable); the `--tls-insecure` warning; the CLI exit-code-6
  transcripts for hostname mismatch and untrusted CA; the `docs/OPERATIONS.md` TLS command blocks
  executed as documentation.

**Bench** — `BenchmarkPublishTLS` vs `BenchmarkPublishPlaintext` on loopback with keep-alive, plus a
handshake-rate benchmark with and without mTLS. Reported, not gated: with connection reuse TLS must
be invisible against the group-commit fsync of PLAN §12, and a number in the PR is how we know.

**Not tested here:** the SIGHUP signal path and drain (#17), token verification and the permission
matrix (#16), event-kind machinery (#19), metric registration (#21), doctor's renderer (#30).
