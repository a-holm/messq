## Context

#14 gave messq a wire. It did not give it a **life**. Today `messq serve` is a `main()` that opens a
store, starts a writer, binds a listener and blocks forever; `Ctrl-C` kills it wherever it happens to
be, `clean_shutdown` is never written, so every single start runs `quick_check` and logs
`recovery.unclean`, and nothing tells systemd when the daemon is actually usable.

This issue builds the missing goroutine — the last row of PLAN.md **§3.2's goroutine census**:

> | signal/lifecycle | 1 | SIGTERM → graceful drain; SIGHUP → reload log level + tokens; sd_notify |

and the operating-system contract around it: the process state machine, the ordered start-up and
reverse-ordered shutdown of every component, and the hardened systemd unit that runs it.

Governing PLAN.md material:

- **§4.4 Crash recovery** — the normative shutdown sequence: *"stop accepting → release long-polls →
  drain handlers (10 s) → final commit → `wal_checkpoint(TRUNCATE)` → set `clean_shutdown` → exit
  0"*, and the sentence this whole issue is built around: **"Drain is an optimization, never a
  correctness requirement — `kill -9` is always safe, and the crash suite asserts it."** Nothing here
  may become load-bearing for correctness. If it does, the design is wrong.
- **§4.4 startup** — recovery runs *"before listeners open"*, and `server.start` + `sd_notify READY`
  are emitted only after it completes. This issue owns that ordering.
- **D8 — flags + `MESSQ_*` env only.** *"Runtime-mutable settings (log level, auth tokens) reload on
  SIGHUP."* There is no config file to re-read, which makes "what exactly does SIGHUP reload?" a real
  design question rather than a one-liner (§7 below answers it).
- **D4 / §4.3 fsyncgate** — on `EIO`/`ENOSPC` the writer latches read-only and *"exits non-zero after
  a short drain"*. #6 built the latch and the `Fatal()` channel; **this issue is the supervisor that
  selects on it** and turns it into an exit code systemd understands.
- **§10 Security model** — *"Hardened systemd unit (`Type=notify`, `ProtectSystem=strict`,
  `NoNewPrivileges`, `StateDirectory=messq`, syscall filter, empty capability set)"*.
- **§13 dependency budget** — ≤ 8 direct non-test modules, *"every addition needs an ADR"*.
  `coreos/go-systemd` is not one of the eight; §6 replaces it with ~60 lines of stdlib.
- **§14 M4 exit criterion** — *"`systemctl restart` mid-load loses nothing"*. That sentence is this
  issue's acceptance test.

What it unlocks: **#36** installs the unit this issue writes and ships the `systemd-analyze security`
gate; **#30**'s `doctor` reads the lifecycle state and the restart history; **#32** kills the daemon
*during* drain and asserts the ledger still holds; **#40** registers a TLS-certificate reloader into
the SIGHUP registry built here; **#16** registers the auth-token reloader into it. No issue lists #17
in `blockedBy`, but four of them assume it exists.

## Scope

### In scope

- **`internal/lifecycle`**: the process state machine, the component `Manager` (ordered start,
  reverse-ordered stop), the signal loop, the drain orchestration, the reload registry, and the
  `sd_notify` client.
- **The composition root** — `internal/cli/serve.go`'s `runServe()`: the one place that wires
  store (#5) → writer (#6) → event fan-out → sweeper (#11) → janitor (#27 seam) → API server (#14)
  → lifecycle, and tears them down in reverse.
- **Signals**: `SIGTERM`/`SIGINT` → drain; `SIGHUP` → reload; second termination signal → escalate;
  `SIGQUIT` deliberately **not** intercepted (the Go runtime's stack dump is the best debugging tool
  we have for a wedged daemon).
- **Graceful drain** exactly as §4.4 specifies, bounded by `--drain-timeout`, with a progress log
  line, a `server.stop` event carrying drain statistics, and the `clean_shutdown` marker.
- **SIGHUP reload**: the two-phase `Reloader` interface (validate-all-then-apply-all), the logged
  diff, the `server.reload` event, and the explicit, documented answer to *"which knobs need a
  restart?"*.
- **sd_notify**, hand-rolled: `READY=1`, `STATUS=…`, `RELOADING=1` + `MONOTONIC_USEC`, `STOPPING=1`,
  `EXTEND_TIMEOUT_USEC`, and the `WATCHDOG=1` ping loop driven off `WATCHDOG_USEC`.
- **The fatal supervisor**: select on #6's `Fatal()`, keep serving reads for `--fatal-drain`, exit
  **74**.
- **Daemon exit codes** as a documented contract, and the `RestartPreventExitStatus` policy that
  keeps a misconfigured daemon from restart-looping.
- **`packaging/systemd/messq.service`** (hardened, `Type=notify`), `messq.sysusers.conf`, and
  `messq.env.example`, plus the offline `systemd-analyze security` + `systemd-analyze verify` CI
  gate.
- `server.start` / `server.stop` / `server.reload` event emission (against #19's vocabulary
  constants, stubbed locally until #19 lands).

### Out of scope

- Parsing the auth-token file, hashing, roles, listener policy → **#16**. This issue defines
  `lifecycle.Reloader` and the SIGHUP orchestration; #16 registers `authfile` into the registry and
  owns its `Validate`/`Apply`.
- The `slog.LevelVar`, handlers, sampling and `--trace-subjects` → **#19**. This issue drives #15's
  `LevelSetter` seam and registers a `loglevel` reloader against it.
- The janitor's actual jobs (retention, dedup trim, event trim, checkpoint policy, disk safety) →
  **#27**. This issue starts and stops the janitor goroutine and nothing else.
- `.deb`/`.rpm`/container/goreleaser packaging that *installs* the unit → **#36**. The unit file and
  its CI gate live here so M4 can test them; #36 puts them in a package.
- Fault-injection points, the kill-during-drain sweep, ENOSPC/EIO scenarios → **#32**. This issue
  ships the drain-under-load integration test; #32 industrialises it.
- TLS certificate hot reload on SIGHUP → **#40** (it registers a reloader).
- `messq doctor`'s lifecycle findings (restart-loop detection, "last shutdown was unclean") →
  **#30**.
- Socket activation (`LISTEN_FDS`), `messq drain` as a CLI verb / admin endpoint, and a supervisor
  heartbeat beyond the watchdog: **not planned for 1.0** — see *Considered and deferred*.

## Design proposal

> Concrete enough to argue with, not a mandate — **except** the shutdown ordering in §5 and the
> "drain is never load-bearing" rule, which are normative.

### 1. Package layout

```
internal/lifecycle/
  manager.go     State, Manager, Component, ordered start / reverse stop
  signals.go     the signal loop (injectable channel; no real signals in unit tests)
  drain.go       the §4.4 sequence, budgets, progress reporting
  reload.go      Reloader, Registry, two-phase apply, diff rendering
  sdnotify.go    NOTIFY_SOCKET client + watchdog loop (~60 lines, stdlib + x/sys/unix)
  health.go      implements api.HealthState (#15) from atomics
internal/cli/
  serve.go       the composition root: flags → components → Manager.Run(ctx)
packaging/systemd/
  messq.service  messq.sysusers.conf  messq.env.example
```

`internal/lifecycle` imports `internal/clock`, `internal/obs`, `internal/errs` and the component
interfaces — never `internal/api` or `internal/store` concretely. Components are injected, so the
whole manager is testable with fakes and a `clock.Fake`.

### 2. The state machine

```
                 ┌──────────┐
                 │ STARTING │  flags parsed, nothing open
                 └────┬─────┘
                      ▼
              ┌──────────────┐   no listener exists yet (§4.4: recovery precedes bind)
              │  RECOVERING  │   store.Open: WAL replay, quick_check, migrate,
              └────┬─────────┘   reclaim leases, clean_shutdown='0'
                   ▼
              ┌──────────┐   listeners bound · sd_notify READY=1 · server.start
       ┌─────▶│  READY   │◀────────────┐
       │      └────┬─────┘             │
       │           │ SIGTERM/SIGINT    │ reload finished (SIGHUP: READY→RELOADING→READY)
       │           ▼                   │
       │      ┌──────────┐             │
       │      │ DRAINING │─────────────┘   /readyz 503 draining · STOPPING=1
       │      └────┬─────┘                 mutations 503 shutting_down
       │           ▼
       │      ┌──────────┐
       │      │ STOPPED  │  clean_shutdown='1' · exit 0
       │      └──────────┘
       │
       │  writer.Fatal() (EIO/ENOSPC, D4)
       └────────────▶ ┌────────┐  read-only, reads keep answering for --fatal-drain
                      │ FATAL  │  storage.fatal · /readyz 503 read_only · exit 74
                      └────────┘
```

```go
type State uint8
const (Starting State = iota; Recovering; Ready; Draining; Stopped; Fatal)

// Transitions are one-way and monotone except Ready↔Ready (reload). A CompareAndSwap
// guards every move, so a SIGHUP racing a SIGTERM cannot resurrect a draining process.
func (m *Manager) advance(from, to State) bool
```

| State | `/healthz` | `/readyz` (#15) | sd_notify | Writes accepted |
|---|---|---|---|---|
| `RECOVERING` | *(not bound)* | *(not bound)* | `STATUS="recovering: …"` | no |
| `READY` | 200 | 200 | `READY=1`, periodic `STATUS=` | yes |
| `DRAINING` | 200 | 503 `draining` | `STOPPING=1`, `STATUS="draining: …"` | no — `503 shutting_down` |
| `FATAL` | 200 | 503 `read_only` | `STATUS="read-only: …"` | no — `503 read_only` |

`/healthz` stays `200` in every bound state (#15's rule): a draining node must not be declared *dead*
by its supervisor while it is draining itself.

### 3. Components and the composition root

```go
type Component interface {
	Name() string                       // "store", "writer", "api", "sweeper", …
	Start(ctx context.Context) error    // returns when started, not when finished
	Stop(ctx context.Context) error     // idempotent; must respect ctx
}

type Manager struct {
	clock   clock.Clock
	comps   []Component                 // start order; stop is exactly the reverse
	reload  *reload.Registry
	notify  Notifier                    // sd_notify; Nop when NOTIFY_SOCKET is unset
	state   atomic.Uint32
	sigC    chan os.Signal              // injectable
	cfg     Config
}

func (m *Manager) Run(ctx context.Context) (exitCode int)
```

Start order (each one's failure aborts the start and stops everything already started, in reverse):

| # | Component | Start does | Stop does |
|---|---|---|---|
| 1 | `store` (#5) | flock, pragmas, migrate, recovery, reclaim, `clean_shutdown='0'` | `optimize` → `wal_checkpoint(TRUNCATE)` → `server.stop` + `clean_shutdown='1'` **in one tx** → close `ro`, `rw` → release flock |
| 2 | `writer` (#6) | spawn the single writer goroutine | drain `cmdCh`, commit the remainder, publish its events, stop |
| 3 | `fanout` (#19 seam) | committed events → slog/metrics/followers | flush the queued events, then stop |
| 4 | `sweeper` (#11) | 250 ms tick | stop ticking, wait for the in-flight tick |
| 5 | `janitor` (#27 seam) | 60 s tick | stop ticking; a running sweep is cancelled, never awaited |
| 6 | `api` (#14) | bind listeners, serve | `ReleaseAll()` → `http.Server.Shutdown` → `Close` on timeout |

**Proposed one-parameter amendment to #5**, mirroring how #14 amended #3: `Store.Close(ctx,
final *obs.Event) error`. The `server.stop` event row and the `clean_shutdown='1'` marker then commit
in the **same transaction** — which is exactly D11's rule ("the audit trail cannot disagree with
reality") applied to the daemon's own death. If that transaction fails, the marker is not written,
the next start runs `quick_check`, and we exit **1**. Fail-safe by construction.

### 4. Signals

| Signal | State | Action |
|---|---|---|
| `SIGTERM`, `SIGINT` | `READY`/`RECOVERING` | begin drain (§5) |
| `SIGTERM`, `SIGINT` | `DRAINING` | **escalate**: cancel the drain budget, force-close the API, still run the store's final commit. `lifecycle.drain_aborted` at WARN. |
| `SIGTERM`, `SIGINT` (3rd) | `DRAINING` | `os.Exit(1)` immediately. The operator has asked twice; `kill -9` is safe anyway. |
| `SIGHUP` | `READY` | reload (§7) |
| `SIGHUP` | `DRAINING`/`FATAL` | ignored, WARN with the reason |
| `SIGQUIT` | any | **not intercepted** — the runtime's goroutine dump is deliberately preserved |
| `SIGPIPE` | any | Go handles it; never intercepted |

`signal.Notify(sigC, …)` with `cap(sigC) == 2`. Signals are coalesced by the state machine, not by
the channel: a SIGHUP storm produces at most one reload after the current one finishes, and a signal
arriving during recovery is honoured as soon as recovery returns (recovery's context is cancelled by
it, so `store.Open` aborts promptly).

### 5. Drain — the exact sequence (normative)

```go
func (m *Manager) drain(cause string) {
	if !m.advance(Ready, Draining) { return }
	deadline := m.clock.Now().Add(m.cfg.DrainTimeout)     // monotonic via clock.Since
	m.notify.Set("STOPPING=1", "STATUS=draining: …")
	m.health.SetDraining()                                // /readyz 503, degraded[draining]

	// 1. stop accepting, release parked long polls (they get 200 + hold_reason:"shutting_down")
	m.api.ReleaseAll()                                    // #14's Registry
	// 2. drain handlers: Shutdown closes listeners immediately, waits for active requests
	ctx, cancel := context.WithDeadline(context.Background(), deadline)
	if err := m.api.Shutdown(ctx); err != nil { m.api.Close(); forced = true }
	cancel()
	// 3–5. reverse-order Stop of sweeper, janitor, fanout, writer, store
	m.stopAll(context.WithTimeout(…, m.cfg.DrainTimeout+m.cfg.CheckpointTimeout))
}
```

1. **Flip readiness first.** A load balancer or a sibling worker must learn we are going away
   *before* we stop accepting, not after.
2. **Release long polls before `Shutdown`.** `http.Server.Shutdown` waits for active handlers; a
   parked 5-minute long poll would hold it for 5 minutes. `Registry.ReleaseAll()` (built in #14)
   closes every waiter channel, and each parked fetch returns `200` with an empty `messages[]` and
   `hold_reason:"shutting_down"` — the shell worker in §7 of PLAN.md loops and reconnects rather
   than seeing a reset connection.
3. **New requests during drain**: mutations get `503 shutting_down` + `Retry-After: 1`; inspection
   endpoints keep answering until the listener closes, because forensics during a restart are the
   product.
4. **In-flight publishes complete.** A publish already handed to the writer commits and gets its
   `201`. This is what "loses nothing" means: we never accept a command we do not finish.
5. **In-flight *deliveries* are not waited for.** A worker holding a message for 30 s does not delay
   the restart. Its lease is voided at restart by #5's reclaim (T9) — `attempts` untouched,
   `recovery.reclaimed` recorded, jittered redelivery. One named duplicate, invariant **I9**
   satisfied.
6. **`--drain-timeout` expiry is not an error path, it is a budget.** Handlers still running are
   force-closed, `forced=true` goes into `server.stop`, and the store's final commit runs regardless.

```console
$ systemctl stop messq     # or: kill -TERM $(pidof messq)
WARN  lifecycle.draining   cause=SIGTERM in_flight=37 waiters=412 budget_ms=10000
INFO  lifecycle.progress   in_flight=12 waiters=0 elapsed_ms=2005
INFO  lifecycle.progress   in_flight=0  waiters=0 elapsed_ms=3140
INFO  writer.closed        drained=88 commits=3 last_batch=41
INFO  store.checkpoint     mode=TRUNCATE pages=2048 wal_bytes=0 duration_ms=61
INFO  server.stop          reason=signal signal=SIGTERM uptime_ms=86400123 \
                           drained_requests=88 forced=0 pending_deliveries=412 \
                           clean_shutdown=1 duration_ms=3260 exit=0
```

`pending_deliveries=412` is deliberate: the operator is told, at shutdown, how many messages will be
redelivered on the next start. Nobody should have to infer that from a metric.

### 6. sd_notify without a dependency

`coreos/go-systemd/v22/daemon` is the obvious choice and is **rejected**: PLAN.md §13 caps direct
non-test modules at eight and requires an ADR for each addition. The protocol is a newline-separated
datagram on an `AF_UNIX`/`SOCK_DGRAM` socket. Sixty lines is cheaper than an ADR and a supply-chain
entry.

```go
type Notifier interface {
	Set(fields ...string) error  // "READY=1", "STATUS=…", "STOPPING=1", "WATCHDOG=1"
	Watchdog() (interval time.Duration, ok bool)
}

func NewNotifier() Notifier {
	addr := os.Getenv("NOTIFY_SOCKET")
	if addr == "" { return NopNotifier{} }          // foreground, docker, supervisord: all fine
	if addr[0] == '@' { addr = "\x00" + addr[1:] }  // abstract namespace
	c, err := net.DialUnix("unixgram", nil, &net.UnixAddr{Name: addr, Net: "unixgram"})
	if err != nil { log.Warn("sdnotify.unavailable", "err", err); return NopNotifier{} }
	os.Unsetenv("NOTIFY_SOCKET")                    // never inherited by anything we spawn
	return &sock{c: c}
}
```

Rules that matter:

- **`NOTIFY_SOCKET` unset is never an error.** `messq serve` in a terminal, in Docker, under
  supervisord and under systemd are the same code path with a `NopNotifier`.
- **A failed notify is never fatal.** It is a WARN and the daemon carries on. Telling systemd is not
  a durability property.
- **`RELOADING=1` requires `MONOTONIC_USEC=`** (systemd ≥ 253 drops the message otherwise). Read it
  with `unix.ClockGettime(unix.CLOCK_MONOTONIC)` — `golang.org/x/sys/unix` is already a dependency.
  `READY=1` is re-sent when the reload finishes.
- **Watchdog**: `WATCHDOG_USEC` gives the interval; ping at half of it; if `WATCHDOG_PID` is set it
  must equal `os.Getpid()`. `--watchdog=auto|off`; `auto` follows the environment.
- **The ping must prove more than "the lifecycle goroutine is scheduled."** Proposal: before each
  ping, `writer.Ping(ctx)` enqueues a no-op command with a timeout of `interval/4`. It joins the next
  batch; a read-write transaction that changes nothing commits **without writing the WAL**, so an
  idle broker pays no fsync for its watchdog, and a batch that already carries real work rides that
  commit. If the ping times out, we **skip** the `WATCHDOG=1` and log `lifecycle.watchdog_missed` at
  WARN — a wedged writer is exactly the condition the watchdog exists to catch, and the correct
  response is the restart systemd will perform. *(Requires a `CmdPing` no-op in #6; trivially small,
  flagged there as an amendment.)*
- **`EXTEND_TIMEOUT_USEC=`** is sent once at the start of a drain that is expected to exceed
  `TimeoutStopSec/2`, so a large `wal_checkpoint(TRUNCATE)` is not `SIGKILL`ed mid-flight. Harmless
  when it is not needed.

`STATUS=` is refreshed every `--status-interval` (10 s, `0` disables) from #15's cached info — never
a fresh SQLite query, or a busy broker would answer `systemctl status` slowly exactly when someone
needs it:

```
$ systemctl status messq
 Active: active (running) since Mon 2026-10-05 09:14:02 UTC; 1 day ago
 Status: "ready · 4 streams · 11 consumers · pending 32 · oldest 4.1s · dlq 0"
```

### 7. SIGHUP reload — and an honest answer to "reload what?"

D8 removed the config file, so there is nothing for SIGHUP to re-parse. The rule this issue adopts is
one sentence:

> **SIGHUP re-reads every file the daemon was pointed at by a path-valued flag. Nothing else.**

Flags and environment are frozen for the process's life, and pretending otherwise is the "which
setting won?" support category D8 deleted.

| Reloader | Source | Owner | Effect |
|---|---|---|---|
| `authfile` | `--auth-file` | **#16** | new token set swapped atomically; existing connections keep serving |
| `loglevel` | `--log-level-file` *(proposed, default empty)* | this issue → #15's `LevelSetter`, backed by #19's `slog.LevelVar` | one line, e.g. `debug` |
| `trace-subjects` | `--trace-subjects-file` *(proposed)* | **#19** | targeted verbosity during an incident |
| `tls` | `--tls-cert` / `--tls-key` | **#40** | certificate rotation without a restart |

**Not reloadable, by design:** `--data-dir`, `--listen`, `--durability`, `--commit-*`, `--max-waiters`,
`--socket-mode`, `--drain-timeout`. A SIGHUP names them in its log line so nobody files a bug:

```
INFO  server.reload  trigger=SIGHUP applied=2 unchanged=1 failed=0 duration_ms=3
INFO  reload.diff    reloader=authfile  tokens=7→8 added=[ci-runner] removed=[] roles_changed=[deploy]
INFO  reload.diff    reloader=loglevel  level=info→debug
INFO  reload.skip    reloader=tls       reason="no --tls-cert configured"
WARN  reload.note    restart_required_for="--listen --durability --data-dir --commit-window"
```

The primary way to change the log level stays `POST /v1/admin/log-level` (#15) / `messq admin
log-level debug` — it is authenticated, audited with an actor in `admin.action`, and instant. The
level *file* exists so `echo debug > /etc/messq/log-level && systemctl reload messq` works for
operators who live in systemd. Whichever wrote last wins; both log the transition.

**Two-phase, all-or-nothing:**

```go
type Reloader interface {
	Name() string
	Validate() (Change, error)   // parse and build the new state; MUST NOT mutate anything
	Apply()                      // swap it in; cannot fail — Validate did all the fallible work
}
type Change struct{ Field, From, To string } // To/From are redacted for secrets (slog.LogValuer)
```

If **any** `Validate` fails, **nothing** is applied, the old configuration keeps running, and the
failure is a WARN plus an `api.error`-style detail on the `server.reload` event. A typo in the token
file at 3 a.m. must not lock every worker out of a working broker. This is the single most important
behaviour in §7 and it gets its own test.

### 8. The fatal path (D4)

```go
case fe := <-m.writer.Fatal():           // #6's buffered channel
	m.advance(Ready, Fatal)              // or Draining → Fatal
	m.health.SetReadOnly(fe)             // /readyz 503 read_only; /healthz stays 200
	m.notify.Set("STATUS=read-only: " + fe.Class + " — see storage.fatal")
	m.clock.Sleep(ctx, m.cfg.FatalDrain) // --fatal-drain (2s): reads/metrics/trace keep working
	m.stopAll(shortCtx)                  // NO clean_shutdown marker: we are not clean
	return 74                            // EX_IOERR
```

The read window is the point: `messq trace`, `/metrics` and `peek` answer for two more seconds so a
human or a scrape can capture *why*. The `clean_shutdown` marker is **not** written, so the next
start runs `quick_check` — the disk that produced an `EIO` has not earned our trust.

### 9. Exit codes (`messq serve`)

PLAN.md §8's table (`0 ok · 1 error · 2 usage · 3 not found · 4 conflict · 5 empty · 6 unreachable ·
7 permission`) is the **client** contract. `serve` uses `0`, `1`, `2` from it and two sysexits values
that do not collide with `3–7`:

| Code | Meaning | systemd behaviour |
|---|---|---|
| `0` | clean drain (or `--help`) | `Restart=on-failure` → stays stopped |
| `1` | unexpected error, incl. a failed final commit | restart |
| `2` | usage / bad flag combination | restart *prevented* |
| `74` `EX_IOERR` | `storage.fatal` latch (D4) | restart into recovery, capped by `StartLimitBurst` |
| `75` `EX_TEMPFAIL` | data dir locked by another instance (#5) | restart (the other one may be exiting) |
| `78` `EX_CONFIG` | schema newer than binary, pragma mismatch, non-loopback bind without auth (#16), bad permissions | restart *prevented* — it will never succeed |

`RestartPreventExitStatus=2 78` is the operational payoff: a mistyped flag or a rolled-back binary
against a migrated data dir **fails loudly and stays failed** instead of hammering the disk five
times a second while the journal fills with identical stack traces.

### 10. Flags added by this issue

All also read `MESSQ_<UPPER_SNAKE>` (D8).

| Flag | Env | Default | Meaning |
|---|---|---|---|
| `--drain-timeout` | `MESSQ_DRAIN_TIMEOUT` | `10s` | budget for in-flight handlers (PLAN §4.4) |
| `--checkpoint-timeout` | `MESSQ_CHECKPOINT_TIMEOUT` | `5s` | bound on the exit `wal_checkpoint(TRUNCATE)`; on expiry, skip it (it is an optimisation) and log |
| `--fatal-drain` | `MESSQ_FATAL_DRAIN` | `2s` | read-only forensics window before exit 74 (defined in #6, consumed here) |
| `--watchdog` | `MESSQ_WATCHDOG` | `auto` | `auto` (follow `WATCHDOG_USEC`) \| `off` |
| `--status-interval` | `MESSQ_STATUS_INTERVAL` | `10s` | `sd_notify STATUS=` refresh; `0` disables |
| `--log-level-file` | `MESSQ_LOG_LEVEL_FILE` | *(empty)* | *proposed*: single-line file re-read on SIGHUP |

`--dev` (PLAN §8) additionally implies `--drain-timeout=2s` and human log format, so `Ctrl-C` in a
terminal is instant.

Notes an operator should not have to discover:

- **`TimeoutStopSec` (30 s) > `--drain-timeout` (10 s) + `--checkpoint-timeout` (5 s) + slack.** If
  those flags are raised, the unit must be raised too — `doctor` (#30) will check the relationship
  and say so.
- **`StartLimitBurst=5 / 300s`** is the "dying disk doesn't grind the evidence away" rule from the
  issue brief: five `EX_IOERR` exits in five minutes and the unit enters `failed`, leaving the data
  dir, the journal and the events table intact for a human.
- **No `AF_NETLINK`** in `RestrictAddressFamilies`, therefore `--listen` accepts **IP literals only**,
  never hostnames. Documented in `OPERATIONS.md` and validated at startup with a typed error.
- `${STATE_DIRECTORY}` is `/var/lib/messq`, created `0700` by systemd; the socket lives in
  `/run/messq` (`0750`), mode `0660`, group `messq` — clients join the group (D12).
- `CapabilityBoundingSet=` empty means privileged ports are impossible; the default listener is a
  Unix socket and the documented TCP port is 4390.
- `messq.sysusers.conf`: `u messq - "messq queue daemon" /var/lib/messq /usr/sbin/nologin`.

### 12. Edge cases, decided

| Case | Handling |
|---|---|
| `SIGTERM` during `RECOVERING` | recovery's context is cancelled; `store.Open` aborts, no `clean_shutdown` marker, exit 0. Recovery is idempotent (#5), so the next start simply redoes it. |
| `SIGTERM` before any listener is bound | same path; nothing to drain; exit 0 in milliseconds. |
| Second `SIGTERM` while draining | abort the wait, force-close the API, still run the store's final commit. Third → `os.Exit(1)`. |
| `SIGHUP` while draining or latched | ignored, WARN naming the state. A reload cannot help a process that is leaving. |
| `SIGHUP` with a corrupt auth file | nothing applied; old tokens keep working; WARN + `server.reload failed=1`. **Tested.** |
| Concurrent `SIGHUP`s | serialized by the lifecycle goroutine; extra ones collapse into one queued reload. |
| `NOTIFY_SOCKET` unset | `NopNotifier`; identical behaviour otherwise. |
| `sd_notify` write fails (socket gone) | WARN once per minute, never fatal. |
| Watchdog enabled but the writer is wedged | ping is skipped, `lifecycle.watchdog_missed` WARN, systemd restarts us. That is the intended outcome. |
| `wal_checkpoint(TRUNCATE)` blocked by a live reader | bounded by `--checkpoint-timeout`; on expiry, log `store.checkpoint_skipped` and continue. The next start checkpoints anyway (#5 step 10). |
| Final commit fails (disk full at the last moment) | marker **not** written, `server.stop` not recorded, exit **1**. The next start treats the dir as unclean and runs `quick_check`. Never claim clean. |
| `kill -9` at any point | Nothing above is load-bearing. #8's crash harness + #32's kill-during-drain sweep assert the ledger holds. |
| Unix socket file left behind | Go's `UnixListener` unlinks the socket it created on `Close`; systemd removes `/run/messq` with `RuntimeDirectory`. A socket we did not create is never unlinked (#14's rule; the flock is the authority on "another instance"). |
| Clock steps −1 h mid-drain | every budget uses `clock.Since` (monotonic, #3), so the drain neither shortens nor hangs. |
| Panic in the lifecycle goroutine | recovered, logged with the stack, best-effort `stopAll` with a 2 s context, exit 1. |
| A component's `Stop` hangs | each `Stop` gets its own sub-context; on expiry the manager logs `lifecycle.stop_timeout component=…` and moves on. The process always reaches `os.Exit`. |
| `systemctl reload` on a stopped unit | systemd's problem, not ours. |
| Restart while 10 000 deliveries are in flight | reclaim is one indexed `UPDATE` with jitter (#5); recovery budget stays ≤ 2 s (§12) and is benchmarked. |

### Considered and deferred

| Idea | Why not now | Revisit trigger |
|---|---|---|
| Socket activation (`LISTEN_FDS`, `messq.socket`) | Would make the listener exist during `RECOVERING`, so #15's `recovering` readiness state becomes routinely visible and clients see typed 503s instead of a connect error. Genuinely nice; it is also a second listener-construction path and a second unit to harden, for a daemon that starts in < 2 s | An operator asks for zero-connect-error restarts, or containers need readiness before recovery |
| `coreos/go-systemd` | §13 budget + ADR requirement; the protocol is 60 lines | Never for `sd_notify`; reconsider if we ever need journal-native logging |
| `messq drain` CLI verb / `POST /v1/admin/drain` | plan-03 had it; PLAN §8's CLI does not. `systemctl stop` and `kill -TERM` already do it, and an authenticated remote "please die" endpoint is a footgun | Rolling restarts across many nodes — which implies clustering, a permanent non-goal |
| A supervisor heartbeat beyond the watchdog | `WatchdogSec` + `messq_oldest_pending_age_seconds` cover the real failure | #30 finds a wedge class the watchdog misses |
| Draining *deliveries* (waiting for workers to ack) | Unbounded by construction (`ack_wait` can be an hour) and it would make drain load-bearing. Redelivery with a named cause is the correct answer | Never |
| `systemd-notify --reloading` via ExecReload | Requires `NotifyAccess=all` and a second process in the sandbox | Never |
| `Type=exec` instead of `notify` | Loses the "ready means *recovered*" signal, which is the entire point of `Type=notify` here | Never |

## Acceptance criteria

- [ ] `messq serve` runs recovery **before** binding any listener, then binds, then emits
      `server.start` (version, durability mode read back from a live connection, listeners, db/wal
      bytes, per-stream counts) and only then `sd_notify READY=1`. Asserted by ordering the captured
      datagram against the captured log stream.
- [ ] `SIGTERM` produces exactly PLAN §4.4's sequence — readiness flips → long polls released →
      handlers drained → components stopped in reverse start order → final commit →
      `wal_checkpoint(TRUNCATE)` → `clean_shutdown='1'` → **exit 0** — and the following start logs
      neither `recovery.unclean` nor a `quick_check`.
- [ ] **`systemctl restart messq` (or a real `SIGTERM`/restart) under sustained publish+fetch+ack
      load loses nothing**: every `2xx`-acknowledged publish is present afterwards, no
      committed-and-acked message is redelivered, in-flight deliveries are redelivered exactly once,
      and `recovery.reclaimed count=N` appears with `N` equal to the in-flight count at shutdown.
- [ ] Every parked long poll returns `200` with `hold_reason:"shutting_down"` during a drain — zero
      connection resets, zero 5xx, measured over ≥ 500 parked fetches.
- [ ] Requests arriving during `DRAINING` get `503 shutting_down` with `Retry-After` for mutations,
      while `/healthz` stays `200` and `/readyz` returns `503` with `status:"draining"`.
- [ ] A publish accepted (queued to the writer) before the drain started is committed and answered
      `201`; a publish arriving after gets `503 shutting_down`. No request is ever answered after its
      connection is closed by us.
- [ ] `--drain-timeout` expiry force-closes remaining handlers, records `forced` in `server.stop`,
      and **still** performs the final commit and marker write; exit code is still 0.
- [ ] `SIGHUP` reloads every configured file-backed input, emits one `server.reload` event plus one
      `reload.diff` line per changed reloader, and logs the restart-required flag list.
- [ ] **A SIGHUP whose auth file is invalid changes nothing**: the previous token set still
      authorizes, `server.reload` reports `failed=1`, and the process keeps serving.
- [ ] `SIGHUP` during `DRAINING` or `FATAL` is ignored with a WARN; a burst of 100 SIGHUPs produces
      at most 2 reloads.
- [ ] With `NOTIFY_SOCKET` set to a test-owned `unixgram` socket, the exact datagram sequence is
      observed: `READY=1` + `STATUS=` at start, `WATCHDOG=1` at `WATCHDOG_USEC/2` cadence,
      `RELOADING=1` + `MONOTONIC_USEC=` then `READY=1` on SIGHUP, `STOPPING=1` on SIGTERM.
- [ ] With `NOTIFY_SOCKET` unset, or pointing at a dead socket, the daemon behaves identically and
      logs at most a WARN.
- [ ] A wedged writer (fault-injected stall) causes the watchdog ping to be **skipped** and
      `lifecycle.watchdog_missed` to be logged, rather than a ping that lies.
- [ ] A `storage.fatal` latch (#6) keeps `/metrics`, `peek` and `trace` answering for
      `--fatal-drain`, writes **no** `clean_shutdown` marker, and exits **74**.
- [ ] The daemon exit-code table in §9 is exercised end to end: `0`, `2`, `74`, `75` (second instance
      on a locked data dir), `78` (schema newer than binary).
- [ ] `packaging/systemd/messq.service` passes `systemd-analyze verify` and scores **≤ 2.0** on
      `systemd-analyze security --offline=true`; the score is printed in CI and a regression fails
      the build.
- [ ] `TimeoutStopSec` in the shipped unit is ≥ `--drain-timeout` + `--checkpoint-timeout` + 10 s —
      asserted by a test that parses both the unit and the flag defaults.
- [ ] After `Manager.Run` returns in-process, goroutine count returns to the pre-start baseline and
      no `clock` timer remains armed (no leaks).
- [ ] `kill -9` at 20 random points during a drain never violates the three-valued ledger, and the
      subsequent start is `quick_check`-clean.
- [ ] No new module appears in `go.mod` (the §13 budget test from #2 still passes).

## Test plan

Per PLAN §11 / D13: `-race` everywhere, real SQLite files in `t.TempDir()`, no `time.Sleep` outside
soak, all timing through the `Clock` seam or `testing/synctest`, every fix landing with a committed
reproduction artifact.

**Unit — state machine and manager (`internal/lifecycle`)**
- Transition table: every legal move, and every illegal one rejected by the `CompareAndSwap` guard
  (`Draining → Ready` must fail; `Fatal` is absorbing).
- `Manager` start/stop ordering with recording fakes: start order is declaration order, stop order is
  its exact reverse, a mid-start failure stops only what started, `Stop` is called exactly once per
  component even on a doubled signal.
- Per-component `Stop` timeout: a hanging fake is abandoned, logged, and the manager still returns.
- Signal mapping driven through the injected channel — no real signals, so the test is hermetic and
  parallel-safe.

**Unit — reload (`reload_test.go`)**
- Two-phase semantics: a failing `Validate` in reloader 2 of 3 leaves **all three** unapplied
  (asserted on the fakes' apply counters).
- Diff rendering golden, including redaction: a secret's value never appears in `Change.To`
  (extends #16's canary-leak test).
- SIGHUP coalescing under `synctest`; SIGHUP ignored in `Draining`/`Fatal`.

**Unit — sd_notify (`sdnotify_test.go`)**
- A real `unixgram` socket in `t.TempDir()`; assert exact datagram bytes for each message.
- Abstract-namespace (`@`) address translation.
- Missing / unreadable / dead socket → `NopNotifier` or a single WARN, never an error return.
- `WATCHDOG_USEC` parsing, half-interval cadence under `synctest` (hours of simulated time),
  `WATCHDOG_PID` mismatch disables pinging.
- `MONOTONIC_USEC` is present and monotonically increasing across two reloads.

**Deterministic timing (`testing/synctest`)**
- Drain budget: handlers finishing at `budget−1ms` are awaited; at `budget+1ms` they are forced.
- `--status-interval` cadence; `--fatal-drain` window; `--checkpoint-timeout` expiry path.
- A −1 h clock step mid-drain changes neither the budget nor the cadence.

**Integration — a real subprocess (`internal/lifecycle/integration_test.go`)**
- Spawn a real `messq serve` on a real data dir, send real `SIGTERM`/`SIGINT`/`SIGHUP` via
  `os.Process.Signal`, assert exit code, `meta.clean_shutdown`, WAL size after exit, socket removal,
  and the `server.stop` / `server.reload` event rows.
- **Drain under load** (the M4 exit criterion): the #8 ledger driven over HTTP by a load generator
  (publishers, fetchers, ackers) while the daemon is `SIGTERM`ed and restarted 10×. Assert: no `OK`
  publish missing, no acked delivery redelivered, every redelivery attributable to
  `recovery.reclaimed` in the events table (invariant **I9**), zero untyped 5xx.
- `SIGTERM` during recovery (fault point `store.recovery.mid_reclaim` from #32's grammar, stubbed
  here): exit 0, marker absent, next start clean.
- Second-instance start on a locked data dir → exit 75 with the holder's pid in the message.
- Schema-newer-than-binary fixture (#34's shape) → exit 78.

**systemd (hermetic + nightly)**
- Hermetic: the `NOTIFY_SOCKET` faker above — 90 % of the value with zero systemd dependency, runs on
  every PR.
- Static: `systemd-analyze verify` and `systemd-analyze security --offline=true` on the shipped unit,
  score recorded as a CI artifact and gated at ≤ 2.0.
- Nightly (container with a systemd PID 1, or `systemd-run --user` when available): real
  `systemctl start/reload/restart/stop`, `systemctl show -p NRestarts`, watchdog kill verified by
  stalling the writer, and `RestartPreventExitStatus` verified with a deliberately bad flag.

**Crash (extends #8, feeds #32)**
- `SIGKILL` at 20 named points across the drain: after readiness flip, after `ReleaseAll`, mid
  `Shutdown`, after writer close, mid checkpoint, between the final commit and `os.Exit`. Ledger
  holds, `integrity_check` clean, `messq verify` clean. The marker is `1` only when the process
  actually reached `Exit(0)`.

**Golden**
- `server.start` / `server.stop` / `server.reload` event rows and log lines: exact field sets,
  normalized ids and durations (the schema #19 later owns).
- The `packaging/systemd/messq.service` file itself is a golden — an unreviewed hardening change
  fails CI.

**Benchmarks**
- `BenchmarkRestartRecovery/{1k,10k,100k}` pending deliveries: asserts PLAN §12's *"crash recovery
  ≤ 2 s typical"* and reports the reclaim `UPDATE` cost.
- `BenchmarkDrain/{100,1000}` parked long polls + 200 in-flight requests: total drain wall time,
  which is what sets `TimeoutStopSec`.

**Not tested here:** token-file parsing and the role matrix (#16), metric names (#21), the
ENOSPC/EIO/clock fault matrix (#32), packaging installation (#36).
