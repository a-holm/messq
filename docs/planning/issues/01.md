## Context

This is the first commit of real repository structure. Today `messq` is a `README.md`, a
`.gitignore` and `docs/`; there is no Go module, no build, no CI. Every other issue in the
backlog assumes a module path, a package layout, a `make ci` entry point and a green pipeline,
so this issue is on the critical path for all 41 remaining issues (it directly unblocks #2, #3
and #4).

The work is deliberately *skeleton only*. No queue logic, no SQLite, no HTTP. What it must
deliver is the shape the rest of the plan is written against:

- **PLAN.md §3.3 (Package layout)** — the directory tree is normative. `internal/queue` must be
  a pure state machine with no I/O; that property is only cheap to keep if the layout enforces
  it from commit one rather than being untangled at M3.
- **PLAN.md §13 + §1.5 (Library choices / success criteria)** — "≤ 8 direct non-test deps; every
  addition needs an ADR", `CGO_ENABLED=0`, one static binary, Go pinned at ≥ 1.25 for
  `testing/synctest`. A dependency budget that is only a sentence in a plan is a dependency
  budget that will be violated; this issue makes it a CI check while the count is still zero,
  and builds the static binary before there is any code to put in it.
- **PLAN.md §13 (License)** — Apache-2.0, DCO, no CLA. Getting the legal surface right on the
  first commit costs an hour; retrofitting a licence across contributed code costs a
  relicensing exercise.
- **PLAN.md §14 (M1: Foundations)** — milestone exit is "CI green ... spec merged before feature
  code". This issue provides the "CI green" half of that on an empty binary.

The quality *gates* themselves (full linter set, `-race` in CI, coverage floors, `govulncheck`,
nightly lane) are #2. This issue provides the scaffolding those gates bolt onto: a `Makefile`
whose targets already exist, and a workflow whose jobs already run.

## Design proposal

Everything below is a proposed starting point, not a mandate — except the two items marked
**decision**, which are expensive to change later.

### 1. Module identity and Go version (**decision**)

The module path is the one thing in this issue that is genuinely hard to reverse: it appears in
every import, in `pkg/client`'s public import path, and in the `-ldflags -X` symbol names.

**Proposed:** `go.messq.dev/messq` — a vanity import path, so the code can move between hosting
providers without breaking anyone's `go get` (plan-11 §9/M0 argues this; PLAN.md does not
adjudicate it). It requires exactly one static page served at `https://go.messq.dev/messq`:

```html
<meta name="go-import" content="go.messq.dev/messq git https://github.com/<org>/messq">
```

**Fallback, if the domain is not in hand on day 1:** `github.com/<org>/messq`. Do not "decide
later" — pick one in this issue, record it in `docs/adr/0006-module-path.md` (body written with
the other ADRs in #4), and move on. Switching after `pkg/client` has external importers is a
breaking change for them.

```
module go.messq.dev/messq

go 1.25.0          // minimum language version: testing/synctest is GA in 1.25 (PLAN.md §13)
toolchain go1.26.5 // pinned; CI uses `go-version-file: go.mod` so local == CI

require ()         // stays empty until #5 adds modernc.org/sqlite
```

Rationale for the split: `go 1.25.0` keeps the *minimum* at the version PLAN.md §13 requires;
`toolchain` pins what actually builds, so a contributor on 1.25 gets the pinned toolchain
fetched automatically instead of a subtly different build.

### 3. `cmd/messq` and `internal/buildinfo`

```go
// cmd/messq/main.go
package main

import (
	"os"

	"go.messq.dev/messq/internal/cli"
)

func main() { os.Exit(cli.Run(os.Args[1:], os.Stdin, os.Stdout, os.Stderr)) }
```

`cli.Run` returning an `int` (not `error`) is what makes the exit-code contract of PLAN.md §8
testable without spawning a process. For this issue it is a placeholder dispatcher; #23 replaces
its body with the cobra root while keeping the signature.

```go
// internal/cli/run.go  — PLACEHOLDER, replaced by the cobra root in #23.
func Run(args []string, stdin io.Reader, stdout, stderr io.Writer) int {
	switch {
	case len(args) == 0, args[0] == "-h", args[0] == "--help", args[0] == "help":
		fmt.Fprint(stdout, usage)
		return 0 // exit 0 when help was asked for; exit 2 when help is printed *because of* misuse
	case args[0] == "version" || args[0] == "--version":
		return version(args[1:], stdout, stderr)
	default:
		fmt.Fprintf(stderr, "messq: unknown command %q\nrun 'messq help'\n", args[0])
		return 2 // usage — PLAN.md §8 exit-code table
	}
}
```

Only two of the eight exit codes are exercised here (`0` ok, `2` usage), but they must already
match PLAN.md §8 so #23 inherits rather than corrects them.

```go
// internal/buildinfo/buildinfo.go
package buildinfo

// Injected with -ldflags -X. Unset in `go install` / `go test` builds; Get() falls back
// to runtime/debug.ReadBuildInfo.
var version, commit, date string

type Info struct {
	Version   string `json:"version"`    // "v0.3.1" | "v0.3.1-4-gabc1234" | "dev"
	Commit    string `json:"commit"`     // 12-char hex, or "" when unavailable
	Date      string `json:"date"`       // RFC3339 UTC, derived from SOURCE_DATE_EPOCH
	Dirty     bool   `json:"dirty"`      // built from a modified worktree
	GoVersion string `json:"go_version"` // runtime.Version()
	Platform  string `json:"platform"`   // "linux/amd64"
}

func Get() Info      // ldflags first, then BuildInfo vcs.* settings, then zero values
func Short() string  // "messq v0.3.1 (abc123456789, 2026-08-24T00:00:00Z, go1.26.5, linux/amd64)"
```

`Get()` is deliberately allocation-free-ish and never panics: a binary built by
`go build ./cmd/messq` with no flags at all must still print something useful.

`messq version` output:

```console
$ messq version
messq v0.1.0 (a1b2c3d4e5f6, 2026-08-24T09:00:00Z, go1.26.5, linux/amd64)

$ messq version --output json
{"version":"v0.1.0","commit":"a1b2c3d4e5f6","date":"2026-08-24T09:00:00Z","dirty":false,"go_version":"go1.26.5","platform":"linux/amd64"}

$ go run ./cmd/messq version          # no ldflags at all
messq (devel) (a1b2c3d4e5f6+dirty, unknown, go1.26.5, linux/amd64)
```

The JSON key set is frozen from here (PLAN.md §8: "JSON field names are frozen at 1.0 and
schema-tested") — a golden test in this issue pins it.

### 4. Makefile

`make ci` is the single entry point used identically by a developer and by GitHub Actions; CI
must never contain a build step that cannot be run locally.

```make
SHELL       := /usr/bin/env bash
.SHELLFLAGS := -euo pipefail -c
.DEFAULT_GOAL := help
.DELETE_ON_ERROR:
MAKEFLAGS   += --warn-undefined-variables --no-builtin-rules

MODULE  := go.messq.dev/messq
VERSION ?= $(shell git describe --tags --always --dirty 2>/dev/null || echo dev)
COMMIT  ?= $(shell git rev-parse --short=12 HEAD 2>/dev/null || echo unknown)
SOURCE_DATE_EPOCH ?= $(shell git log -1 --format=%ct 2>/dev/null || date -u +%s)
DATE    := $(shell date -u -d @$(SOURCE_DATE_EPOCH) +%Y-%m-%dT%H:%M:%SZ)

LDFLAGS := -s -w \
  -X '$(MODULE)/internal/buildinfo.version=$(VERSION)' \
  -X '$(MODULE)/internal/buildinfo.commit=$(COMMIT)'  \
  -X '$(MODULE)/internal/buildinfo.date=$(DATE)'
GOBUILD := CGO_ENABLED=0 go build -trimpath -ldflags "$(LDFLAGS)"

GOLANGCI_VERSION := v2.<pin at bootstrap>   # go run, never a go.mod entry (PLAN.md §13)

build:      ## static binary for the host arch → dist/messq
	$(GOBUILD) -o dist/messq ./cmd/messq

build-all:  ## static linux/amd64 + linux/arm64 → dist/messq-linux-<arch>
	GOOS=linux GOARCH=amd64 $(GOBUILD) -o dist/messq-linux-amd64 ./cmd/messq
	GOOS=linux GOARCH=arm64 $(GOBUILD) -o dist/messq-linux-arm64 ./cmd/messq

ci: fmt-check vet tidy-check dep-budget layers test build-all  ## what CI runs
```

Remaining targets, one line each: `test` (`go test ./...`), `race` (`go test -race ./...`,
required gate in #2), `cover` (`-coverprofile` + `go tool cover -func`), `lint`
(`go run …/golangci-lint@$(GOLANGCI_VERSION) run`), `fmt` / `fmt-check` (`gofmt -l -w .` /
fail if `gofmt -l .` prints anything), `vet`, `tidy-check` (`go mod tidy -diff`), `dep-budget`,
`layers`, `repro` (build twice on a clean tree, compare sha256), `clean`, and a self-documenting
`help` that awks the `## ` comments.

`lint` deliberately stays out of the `ci` chain until #2 lands `.golangci.yml`; the target exists
now so #2 only has to add a config file and one word to `ci`.

### 5. CI workflow skeleton

```yaml
name: ci
on:
  push: { branches: [main] }
  pull_request:
permissions:
  contents: read                       # least privilege; jobs opt in to more
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  check:
    runs-on: ubuntu-latest
    timeout-minutes: 10                # PLAN.md §11: PR CI ≤ 10 minutes wall clock
    steps:
      - uses: actions/checkout@<sha>   # actions pinned by commit SHA, not tag
        with: { fetch-depth: 0 }       # git describe needs tags
      - uses: actions/setup-go@<sha>
        with: { go-version-file: go.mod, check-latest: false }
      - run: make ci
  build:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      # same checkout (fetch-depth: 0) + setup-go steps as `check`, then:
      - run: make build-all                       # both arches; no cgo ⇒ no cross toolchain
      - run: scripts/assert-static.sh dist/messq-linux-amd64
      - run: scripts/assert-static.sh dist/messq-linux-arm64
      - uses: actions/upload-artifact@<sha>
        with: { name: messq-binaries, path: dist/messq-linux-* }
```

A build *matrix* over `GOARCH` would be the obvious shape, but with `CGO_ENABLED=0` both
binaries come out of one `go build` invocation pair on one runner in seconds — a matrix would
spend two runner startups to save nothing. Revisit only if `build-all` grows beyond ~1 minute.

Actions pinned by SHA and a workflow-level read-only `permissions:` block are cheap now and are
the supply-chain posture PLAN.md §10/§12 expects; #2 adds `govulncheck` and the nightly lane.

### 6. Static-binary assertion (`scripts/assert-static.sh`)

Naive `ldd` checks break in two ways that will bite on the first arm64 run:

1. `ldd` on a static binary **exits 1** and prints `not a dynamic executable` — under
   `set -euo pipefail` that fails the build for the *correct* outcome.
2. `ldd` cannot inspect a foreign-architecture binary at all on an amd64 runner.

So the assertion is architecture-independent and uses the toolchain's own record:

```bash
#!/usr/bin/env bash
set -euo pipefail
bin="$1"
go version -m "$bin" | grep -qE '^\s+build\s+CGO_ENABLED=0$' \
  || { echo "$bin: not built with CGO_ENABLED=0"; exit 1; }
go version -m "$bin" | grep -qE '^\s+build\s+-trimpath=true$' \
  || { echo "$bin: not built with -trimpath"; exit 1; }
file "$bin" | grep -q 'statically linked' \
  || { echo "$bin: file(1) does not report a statically linked executable"; exit 1; }
```

### 7. Dependency budget and layering guards

`scripts/dep-budget.sh` — an **allow-list**, not a count, so an accidental transitive promotion
to a direct require fails loudly with a pointer to the ADR requirement (PLAN.md §13):

```
allowed direct modules (PLAN.md §13):
  modernc.org/sqlite            spf13/cobra          prometheus/client_golang
  oklog/ulid/v2                 pgregory.net/rapid   rogpeppe/go-internal
  google/go-cmp                 golang.org/x/sys
```

Implementation: `go list -m -f '{{if not .Indirect}}{{.Path}}{{end}}' all` (excluding the main
module) diffed against the list; any addition fails with
`new direct dependency <path>: add an ADR under docs/adr/ and extend scripts/dep-budget.sh`.
At this issue the observed set is empty, which is the easiest possible baseline to defend.

`scripts/layers.sh` — protects the single decision PLAN.md §3.3 calls load-bearing ("the state
machine in `internal/queue` is a pure function"):

| Package | Must not (transitively) import |
|---|---|
| `internal/queue` | `database/sql`, `net/http`, `os`, `internal/store`, `internal/api`, `internal/cli`, `internal/obs` |
| `internal/store` | `net/http`, `internal/api`, `internal/cli` |
| `internal/model` | `internal/queue`, `internal/store` (it is an *independent* oracle) |
| `pkg/client` | any `internal/…` except a shared wire-types package |

Implemented with `go list -deps <pkg>` and a grep; ~25 lines. It passes trivially today and
stops being trivial the moment #3, #5 and #9 land.

### 9. Edge cases and how to handle them

| Case | Handling |
|---|---|
| Built by `go install go.messq.dev/messq/cmd/messq@latest` — no `-ldflags` | `buildinfo.Get()` falls back to `debug.ReadBuildInfo()`: `Main.Version` for version, `vcs.revision`/`vcs.time`/`vcs.modified` settings for commit/date/dirty. Never print an empty version string. |
| `go test` binaries and `go run` | `ReadBuildInfo` reports `(devel)` and usually no `vcs.*`; `Get()` must return `Version: "(devel)"` rather than `""`. Unit-tested. |
| No git (tarball export) | `git describe`/`git rev-parse` fail → `VERSION=dev`, `COMMIT=unknown`, `SOURCE_DATE_EPOCH=$(date -u +%s)`. `make build` must still succeed; guarded by `2>/dev/null || echo`. |
| Shallow CI checkout | `git describe --tags` returns nothing useful without tags → `actions/checkout` with `fetch-depth: 0`. |
| `-buildvcs` and dirty trees | Leave `-buildvcs=true` (default) so the fallback path works, and accept that dirty builds are not reproducible: the `repro` check refuses to run on a dirty worktree with a clear message rather than failing mysteriously. |
| `ldd` semantics | See §6 — never use `ldd` exit status as the oracle. |
| Empty package directories | Git will not track them and `go vet` errors with `no Go files`; every package gets a `doc.go` in this commit. |
| `go mod tidy` drift | `go mod tidy -diff` in `make ci` — deterministic and does not mutate the tree in CI. |
| Toolchain drift local vs CI | `go-version-file: go.mod` + `check-latest: false`; `toolchain` line in `go.mod` is the single source. |
| `make lint` offline | `go run …@version` needs the module cache warm; document `make lint` as network-touching on first use. Not in `make ci` yet, so an offline `make ci` still works. |
| Line endings | `.gitattributes` `* text=auto eol=lf` — the testscript and `messq trace` goldens in #26/#20 are byte-compared. |
| Reserved name collision | `dist/` and `cover.out` already partly covered by `.gitignore`; extend rather than replace so the existing `*.db`/`*.db-wal` entries survive. |

## Acceptance criteria

- [ ] GitHub Actions `ci` workflow is green on a pull request; all `uses:` are pinned to commit

- [ ] `LICENSE` (Apache-2.0), `NOTICE`, `CONTRIBUTING.md` (DCO, explicitly no CLA),

- [ ] `docs/adr/0000-template.md` exists and the module-path decision is recorded as an ADR

- [ ] README has a build-from-source section whose commands actually work on a clean clone, and

## Test plan

Consistent with PLAN.md §11 — this issue's testable surface is small, but the harness habits
start here (no `time.Sleep`, table-driven, `t.TempDir()`, no assertion DSL).

**Unit (`go test ./...`)**

- `internal/buildinfo`:
  - `TestGet_LdflagsWin` — package vars set via a test-only setter (or an `_test.go` in the same
    package) take precedence over `ReadBuildInfo`.
  - `TestGet_BuildInfoFallback` — with empty ldflag vars, `Get()` returns a non-empty `Version`
    and populates `Dirty` from `vcs.modified`; the case where `ReadBuildInfo` returns `ok=false`
    yields the documented zero-ish values and does not panic.
  - `TestInfoJSONKeys` — marshal `Info{}` and compare the sorted key set against a golden
    slice; this is the frozen-field-name guard PLAN.md §8 requires.
- `internal/cli`:
  - `TestRun_Table` — table of `{args, wantExit, wantStdoutContains, wantStderrContains}` over
    `Run` with `bytes.Buffer` writers: `[]`→0, `["help"]`→0, `["version"]`→0,
    `["version","--output","json"]`→0 with parseable JSON, `["bogus"]`→2 with empty stdout,
    `["version","--output","yaml"]`→2. Asserts the data-to-stdout / narration-to-stderr rule
    from PLAN.md §8 at the smallest possible scale.
- `cmd/messq`: no test — `main` is three lines by construction; the logic lives in `cli.Run`.

**Script/CI-level (the real gates for a chore issue)**

- `make ci` on a clean checkout is the primary test; a PR that breaks any sub-target must go
  red. Verify by deliberately introducing, on a scratch branch, each of: an unformatted file, an
  untidy `go.mod`, a bogus direct dependency, and an `internal/queue` → `internal/store` import,
  and confirming four distinct, readable failures.
- `scripts/assert-static.sh` is exercised by the build matrix for both architectures; verify it
  *fails* by temporarily building with `CGO_ENABLED=1` locally.
- Reproducibility: `make repro` (build → sha256 → `go clean -cache` → build → sha256 → compare).
  Run manually as part of review; wired as a nightly job in #2 rather than a per-PR cost.
- Timing: record the wall-clock of the `check` job in the PR description as the baseline for
  PLAN.md §11's ≤ 10-minute budget, which everything after this issue spends against.
