## Context

#22 gave the project a real Go client. Everything after this issue — the command surface (#24),
`--exec` workers (#25), quickstart/completions/testscript (#26), the operations verbs (#28, #29,
#30, #31) — is a *command*, and every one of them has to answer the same four questions the same
way:

1. **Where is the daemon, and who am I?** (`--addr`, `--token-file`, `--timeout`, and their env
   fallbacks.)
2. **Who is reading this output — a person or a program?** (table vs JSON/NDJSON, colour, relative
   times, abbreviated ULIDs, stdout vs stderr.)
3. **What do I say when it goes wrong?** (the teaching-error format: what happened / why / what to
   type next.)
4. **What number do I exit with?** (the exit-code contract that makes `messq` usable in cron and
   `until` loops without grepping prose.)

Answering those four questions **once**, in a chassis every command inherits, is the difference
between a CLI that feels designed and thirty commands that each invented their own conventions.
Answered thirty times, the answers diverge — and PLAN.md's CLI rules become aspirations rather than
mechanisms.

Governing PLAN.md material:

- **§8 CLI design** — the rules this issue turns into code: *"Built with cobra (D9): `RunE`
  everywhere, `SilenceUsage`, persistent `--addr/--output/--token-file` flags"*; *"Human output on a
  TTY, machine output otherwise (`--output table|json|ndjson`), **never a third mode**. JSON field
  names are frozen at 1.0 and schema-tested"*; *"**Data to stdout, narration to stderr.** Exit codes
  are a documented contract (0 ok · 1 error · 2 usage · 3 not found · 4 conflict/stale · 5
  empty/timeout · 6 daemon unreachable · 7 permission)"*; *"Every inspect command ends with the next
  useful command; every error names the fix (what happened / why / what to type next)."*
- **D9 — cobra** — chosen for `RunE` error propagation, persistent flags, dynamic completions and
  man pages. *"No viper, no cobra-cli scaffolding."*
- **D8 — flags + `MESSQ_*` env only** — no config file, no contexts file, no precedence engine.
  *"This kills a parser, a precedence bug class, and a 'which setting won?' support category."*
- **§13 dependency budget** — cobra + pflag are already on the list; this issue adds **zero** new
  direct dependencies. TTY detection, colour and column layout are stdlib.
- **§12 / §10** — a token never reaches `/proc/<pid>/cmdline`; server-supplied strings never reach a
  terminal unsanitised.

What it unlocks: #24 writes commands, not plumbing; #25 inherits the exit-code contract that its
`sysexits` mapping is a mirror of; #26 has a stable byte-level surface to freeze into `.txtar`
goldens; #28/#29 hang `--dry-run`/`--confirm` off the TTY and renderer seams built here; #35
documents a contract instead of a habit.

It also **re-homes the four commands that exist before the chassis** — `version` (#1), `serve`
(#17), `verify` (#8), `trace`/`events` (#20) — onto the cobra root without changing a byte of their
output.

## Scope

### In scope

- **`internal/cli` root**: the cobra root command built per-invocation from an injected `Env`
  (writers, `Getenv`, clock, TTY predicate), keeping #1's `cli.Run(args, stdin, stdout, stderr) int`
  signature so the exit contract is testable in-process.
- **Execution-chain configuration**: `SilenceUsage`/`SilenceErrors`, `RunE` everywhere,
  `EnableTraverseRunHooks`, `SetFlagErrorFunc`, suggestion engine, command groups, `Args` validators,
  a single error/exit funnel.
- **Configuration resolution** (`internal/cli/conf`): three layers — flag > `MESSQ_<UPPER_SNAKE>`
  env > built-in default — applied uniformly to *every* flag, persistent or local; ~100 lines, no
  viper, no file.
- **The persistent flag set**: `--addr`, `--output`, `--token-file`, `--timeout`, plus the chassis
  flags `--color`, `--quiet`, `--verbose`, `--full-ids`.
- **`internal/cli/render`**: the output contract — mode selection (auto/table/json/ndjson), the
  `Renderable` seam, `text/tabwriter` layout, relative times, byte and duration humanisation, ULID
  abbreviation, colour profile + `NO_COLOR`, control-sequence sanitisation, streaming/flush rules,
  the stdout-is-data invariant, and the "next command" footer.
- **`internal/cli/uierr`**: the teaching-error type and its two renderings (human, and the server
  envelope re-emitted verbatim in machine mode), including the **no-invented-text** rule.
- **`internal/cli/exit`**: the exit-code constants, the wire-`code` → exit map, the `errs` sentinel →
  exit map, transport-failure classification, and both exhaustiveness tests.
- **`internal/cli/clitest`**: the in-process golden harness (fake daemon over a unix socket, frozen
  clock, forced TTY, `-update`) that #24/#25/#26 build on.
- **The DX linter test** walking the command tree (Long/Example/flag-usage/Args/naming/alias rules).
- **Generated `docs/generated/exit-codes.md`** from the exit table, in #3's generated-artifact style.
- **Re-homing** `version` (+ opt-in `--remote` server-version skew check), `serve`, `verify`,
  `trace`, `events` under the root, output-byte-identical.

- Any new command with queue semantics — `stream`/`consumer`/`pub`/`sub`/`peek`/`pending`/`lag`/

- The wire error envelope, the closed machine-code enum and their status mapping → **#14**; the JSON

## Design proposal

> Proposal, not mandate — **except** the exit-code table, the stdout/stderr split, the
> three-output-modes rule and the no-invented-text rule. Those four are compatibility surface from
> the moment #24 lands, and cheap only right now.

### 1. Package layout

```
internal/cli/
  run.go        cli.Run / cli.RunEnv — replaces #1's placeholder, same signature
  root.go       newRoot(env) *cobra.Command — the tree, groups, persistent flags
  conf/         flag > MESSQ_* env > default resolution; Config; source tracking for -vv
  render/       Format, Renderable, Table, humanisers, colour profile, sanitiser
  uierr/        UserError, human + machine rendering, did-you-mean helper
  exit/         codes, code/sentinel → exit maps, Of(err) int
  clitest/      in-process harness: fake daemon, frozen clock, forced TTY, goldens
  cmd*.go       one file per command (this issue: version + the four migrations)
```

`internal/cli` may import `pkg/client`, `internal/errs`, `internal/buildinfo`, `internal/clock`.
It may **not** import `internal/store`, `internal/queue` or `internal/api` (enforced by #1's import
matrix) — except `cmdserve.go`, which is the composition root #17 already owns.

### 2. Entry point and the `Env` seam

```go
// internal/cli/run.go
type Env struct {
	Stdin          io.Reader
	Stdout, Stderr io.Writer
	Getenv         func(string) string
	Now            func() time.Time              // #3's clock seam; only affects rendering
	IsTerminal     func(io.Writer) bool          // default: *os.File + os.ModeCharDevice
	Width          func() int                    // terminal columns; 0 = unlimited
}

func Run(args []string, stdin io.Reader, stdout, stderr io.Writer) int   // #1's signature, kept
func RunEnv(ctx context.Context, env Env, args []string) int             // the real entry point
```

`RunEnv` builds a **fresh command tree per invocation** (`newRoot(env)`); a package-level tree keeps
parsed flag state between calls and makes parallel in-process tests wrong in ways that look like
flakes. Nothing in `internal/cli` reads package-level `os` state, so every CLI test is an in-process
table test with no subprocess and no `t.Setenv` race.

Signals: `RunEnv` installs `signal.NotifyContext(ctx, SIGINT, SIGTERM)`; the first signal cancels the
command context (long-polls unwind, in-flight work is settled where the command can), a second
signal exits immediately. **SIGPIPE is deliberately not handled** — Go's default (die on write to a
closed stdout) is the correct Unix behaviour for `messq events --follow | head -3`, and installing a
handler would break it.

### 3. Root command configuration

| Setting | Value | Why |
|---|---|---|
| `SilenceUsage` | `true` | A runtime failure must print an error, not a wall of usage. |
| `SilenceErrors` | `true` | Errors are rendered by `uierr`, once, in the right format on the right stream. |
| `RunE` (never `Run`) | all commands | Every failure reaches the single exit funnel. Linted. |
| `cobra.EnableTraverseRunHooks` | `true` | Otherwise a child's own `PersistentPreRunE` (e.g. `serve`) silently skips the root's config resolution. This is the single nastiest cobra footgun in this design. |
| `SetFlagErrorFunc` | wraps into `uierr.Usage(...)` | One format for flag errors → exit 2 with usage on **stderr**. |
| `Args` | non-nil on every command | A nil `Args` accepts anything; `cobra.ExactArgs`/`RangeArgs` + a teaching message. Linted. |
| `SuggestionsMinimumDistance` | `2` | `messq consumers` → *Did you mean `consumer`?* |
| `CompletionOptions.DisableDefaultCmd` | `true` | #26 ships a real one; cobra's default has no `Long`/`Example` and would fail the DX linter. |
| `AddGroup` | `hot`, `inspect`, `manage`, `operate`, `server` | A 30-command `--help` needs sections. |
| `SetOut`/`SetErr` | `env.Stdout` / `env.Stderr` | Help goes to stdout (exit 0); usage-on-error goes to stderr (exit 2). |

The whole funnel:

```go
func RunEnv(ctx context.Context, env Env, args []string) int {
	root := newRoot(&env)
	root.SetArgs(args)
	err := root.ExecuteContext(ctx)
	if err == nil {
		return exit.OK
	}
	code := exit.Of(err)
	uierr.Render(&env, err, code)     // stderr, human or machine shape
	return code
}
```

### 4. Configuration: three layers, ~100 lines, no viper

Precedence is exactly **flag > `MESSQ_*` env > built-in default**. There is no config file, no
context file and no profile (D8). The env name is *derived*, never registered by hand:
`--commit-window` → `MESSQ_COMMIT_WINDOW` (this generalises the convention #17 already uses for
`serve`).

```go
// internal/cli/conf/env.go
func ApplyEnv(cmd *cobra.Command, getenv func(string) string) error {
	var errs []error
	cmd.Flags().VisitAll(func(f *pflag.Flag) {
		if f.Changed { return }                              // layer 1 wins
		name := "MESSQ_" + strings.ToUpper(strings.ReplaceAll(f.Name, "-", "_"))
		v, ok := lookup(getenv, name)
		if !ok || v == "" { return }                         // empty env = unset, never "false"
		if sv, ok := f.Value.(pflag.SliceValue); ok {
			errs = append(errs, sv.Replace(splitCSV(v)))
		} else if err := f.Value.Set(v); err != nil {
			errs = append(errs, fmt.Errorf("%s=%q: %w", name, v, err))   // names the ENV VAR, not the flag
		}
		f.Changed = false                                    // still "not set by flag" for -vv source reporting
	})
	return errors.Join(errs...)
}
```

Run from the root's `PersistentPreRunE`, over `cmd.Flags()` of the *executing* command, so local
flags get env fallback too. A malformed env value is a **usage error (exit 2)** whose message names
the environment variable and the value, never the flag — the "which setting won?" bug class D8 was
meant to delete.

Persistent flags:

| Flag | Env | Default | Notes |
|---|---|---|---|
| `-a, --addr` | `MESSQ_ADDR` | `unix:///run/messq/messq.sock` | `unix://`, `http://`, `https://`. One default, no probing of alternative paths — the unreachable-error lists candidates instead of guessing. |
| `-o, --output` | `MESSQ_OUTPUT` | `auto` | `auto\|table\|json\|ndjson`. Never a fifth value; an unknown value is exit 2 listing the four. |
| `--token-file` | `MESSQ_TOKEN_FILE` | *(unset)* | File must be mode `0600` or narrower, or exit 7. **There is no `--token` flag** — `/proc/<pid>/cmdline` is world-readable (§10). `MESSQ_TOKEN` (raw secret) is accepted as the container-friendly path, lower precedence. |
| `--timeout` | `MESSQ_TIMEOUT` | `30s` | Client-side per-request deadline. `0` = none. Long-poll requests use `max(timeout, wait+slack)`; `--follow` sets no deadline. |
| `--color` | `MESSQ_COLOR` | `auto` | `auto\|always\|never`. |
| `-q, --quiet` | `MESSQ_QUIET` | `false` | Suppresses all narration; data and errors unaffected. |
| `-v, --verbose` | `MESSQ_VERBOSE` | `0` | Repeatable. `-v` narrates; `-vv` dumps each HTTP request/response line **with `Authorization` redacted** and prints the resolved config with its source. |
| `--full-ids` | `MESSQ_FULL_IDS` | `false` | Print 26-char ULIDs instead of `01J8Z…KQ7` in table mode. |

Hidden test hooks (documented, rendering-only, never affecting protocol or auth): `MESSQ_NOW`
(RFC3339, freezes relative-time rendering) and `COLUMNS` (pins table width). They exist so #26's
testscript goldens are stable against a real binary.

`-vv` config dump — the answer to "which setting won?", available without a `context` subcommand:

```
addr        unix:///run/messq/messq.sock   (default)
output      json                           (env MESSQ_OUTPUT)
timeout     5s                             (flag --timeout)
token-file  /etc/messq/token               (env MESSQ_TOKEN_FILE)
```

### 5. The output contract

**Mode selection** (`auto` resolves once, in `PersistentPreRunE`, and is then a plain value):

| `--output` | stdout is a TTY | stdout is a pipe/file |
|---|---|---|
| `auto` (default), non-streaming command | `table` | `json` |
| `auto`, command annotated `messq.stream=true` (`sub`, `events --follow`) | `table` (line by line) | `ndjson` |
| explicit `table` / `json` / `ndjson` | as asked | as asked |

`--output json` combined with `--follow` is a **usage error (exit 2)**: *"a followed stream has no
final document; use `--output ndjson`"*. That is the one case where the two machine modes are not
interchangeable, and silently buffering forever would be worse.

**The seam every command implements** — small on purpose, so #24 writes data structures, not
printers:

```go
// internal/cli/render
type Format int; const ( Table Format = iota; JSON; NDJSON )

type Renderable interface {
	Table(*render.T)   // headers + rows, via tabwriter
	Data() any         // the frozen JSON shape (struct with json tags)
}

type Streamer interface{ Each(func(Renderable) error) error } // ndjson / incremental table

func Emit(env *Env, v Renderable) error     // dispatch on the resolved Format
func Hint(env *Env, lines ...string)        // "next command" footer → stderr, TTY-only
```

**Rules, all mechanically checked:**

1. **stdout is data only.** Tables, JSON, NDJSON, raw message bodies. Nothing else — ever. Test:
   every command run in `json` mode produces stdout that is either empty or parses as one JSON
   document (`TestStdoutIsPureData`).
2. **stderr is narration**: progress, warnings, confirmations, teaching errors, and the
   next-command footer. `messq peek orders --seq 1042 --raw > body.bin` is byte-exact, always.
3. **Hints are TTY-only.** `Hint` writes only when stderr is a terminal and `--quiet` is unset, so
   pipes and CI logs stay clean while PLAN §8's *"every inspect command ends with the next useful
   command"* still holds where a human is watching.
4. **The CLI never renames a server field.** Where a command is a thin wrapper, its JSON *is* the
   server's JSON (#18's shape digests then cover it for free). Where a command joins several
   endpoints (`lag`), the CLI-only shape is digested the same way. Removing or retyping a field is a
   `messq.v2` decision, not a refactor.
5. **Times**: JSON/NDJSON always RFC3339 UTC with milliseconds; table mode relative (`4m12s`,
   `2h07m`, `-` for absent) computed from `env.Now()`.
6. **Numbers**: right-aligned, thousands separators in table mode (`1,284`), plain integers in JSON.
   Bytes are humanised in table mode only (`1.2 KiB`), raw in JSON.
7. **IDs**: table mode prints `01J8Z…KQ7` (first 5 + last 3, U+2026); `--full-ids` and every machine
   mode print all 26 characters, and **any ULID inside a hint or an error is always full**, because
   an abbreviated id in a suggested command is a copy-paste trap.
8. **Sanitisation** (security, not cosmetics): every server-provided string — subject, header value,
   consumer name, error message — passes `render.Safe()` before touching a terminal, which escapes
   C0/C1 controls and `ESC` as `\xNN`. A subject containing `\x1b]0;…\x07` must not retitle the
   operator's window. Fuzzed.
9. **Width**: `tabwriter` with 2-space padding, no borders, uppercase headers. Only the *last*
   column is truncated to fit `env.Width()`; ID and count columns never are. When stdout is not a
   TTY and `table` was asked for explicitly, width is unlimited unless `COLUMNS` is set — so goldens
   are stable.
10. **Buffering**: block-buffered normally (one `Flush` at the end), **line-buffered when the
    command is streaming**, so `messq events --follow | grep dead` is live rather than stalled.
11. **Empty results are not errors.** A list with zero rows exits 0, prints `[]` (JSON) / nothing
    (NDJSON), and in table mode prints *nothing to stdout* plus a stderr line: `no consumers on
    "orders"` + a hint. Exit 5 is reserved for a *wait* that expired — see §7.

Colour resolution order (first match wins), with the palette limited to four roles — attention
(red), warning (yellow), dim (secondary), bold (headers):

`--color` flag → `MESSQ_COLOR` → `NO_COLOR` non-empty ⇒ off → `CLICOLOR_FORCE` non-empty and ≠ `0`
⇒ on → `TERM=dumb` ⇒ off → stdout is a character device ⇒ on → off.

Machine modes never emit an escape sequence, whatever the colour setting says.

### 6. Teaching errors

```go
// internal/cli/uierr
type UserError struct {
	Code    string            // wire code from the envelope, or a CLI-local code
	Summary string            // one line: what happened
	Because string            // optional: why / the concept, 1–3 lines
	Suggest []string          // "did you mean" candidates, computed locally
	Next    []string          // commands to type; server-supplied entries are verbatim
	Help    string            // "messq help concepts" (topic pages land in #26)
	Detail  map[string]any    // machine-readable specifics, from envelope.detail
	TraceID string
	Exit    int               // 0 = "ask the table"
	Cause   error
}
```

**The no-invented-text rule (from the issue brief, and the reason this is a type and not a
`fmt.Errorf`):** when the daemon returned an envelope, `Summary` is `client.Error.Message`, `Next`
is `client.Error.Next`, `Detail` is `client.Error.Detail` — **byte-for-byte**. The CLI adds only what the
daemon cannot know: the address it dialled, the flag the user typed, locally computed did-you-mean
candidates, and the help topic. A test asserts a canary string from a fake daemon appears unaltered
in rendered output. The teaching quality of an error is therefore #14's job on the wire and this
issue's job in the rendering — never a second, drifting copy of the same sentence.

Human rendering (stderr), directly from PLAN §8's *what happened / why / what to type next*:

```console
$ messq sub orders bilingg
Error: consumer "bilingg" not found in stream "orders"

  A consumer holds the cursor and the ack state; messages are delivered through it.

  Did you mean:  billing

  Create it:   messq consumer add orders bilingg --ack-wait 30s
  Learn more:  messq help concepts

exit status 3
```

```console
$ messq pub orders orders.created -f big.bin
Error: message is 4.1 MiB, stream "orders" allows at most 1.0 MiB

  Large bodies make the database and every backup larger, and slow every redelivery.
  Consider storing the payload elsewhere and publishing a reference.

  Raise the limit:  messq stream edit orders --max-msg-size 8MiB
  Check current:    messq stream info orders

exit status 4
```

```console
$ messq lag
Error: cannot reach messq at unix:///run/messq/messq.sock

  connect: no such file or directory — the daemon does not appear to be running.

  Start it:      messq serve --data-dir /var/lib/messq
  Or as a unit:  systemctl start messq
  Elsewhere:     messq --addr http://queue-1:4390 lag   (or MESSQ_ADDR=…)

exit status 6
```

Machine rendering: in `json`/`ndjson` mode the error is written to **stderr** as the server envelope
re-emitted (`{"error":{"code":…,"message":…,"next":[…],"detail":{…},"trace_id":…}}`), so
`messq lag -o json | jq` never receives an error object where it expected data. CLI-local failures
synthesise the same envelope with a CLI-local code (`unreachable`, `usage`, `wait_expired`,
`token_file_perms`, `interrupted`).

When `--addr` is not the default, a final dim stderr line is appended: *"(these commands assume
`--addr unix:///…`)"* — the CLI never rewrites a server-authored suggestion.

Enforced by review and by the DX linter: no `UserError` without at least one `Next` entry; no error
text containing a Go type name, a stack trace, or the word "unexpected" without a bug-report URL.

### 7. Exit codes — the contract

```go
// internal/cli/exit — the single source of truth; docs/generated/exit-codes.md is generated from it
const (
	OK          = 0 // success
	Error       = 1 // generic runtime failure, incl. a bug in the daemon
	Usage       = 2 // bad flag, bad argument, request the daemon rejected as malformed
	NotFound    = 3 // stream / consumer / message / seq does not exist
	Conflict    = 4 // conflict, stale fence, precondition or limit refused the request
	Empty       = 5 // the wait expired before the request was satisfied
	Unreachable = 6 // no answer obtainable from the daemon
	Denied      = 7 // authentication or authorization refused
)
```

#22 deliberately stops one step short of this: it owns *classification* (`client.Error` with `Code`,
`Status`, `Next`, `Detail`, `RetryAfter`, plus `client.Classify(err) Kind`) and hands the **policy**
here. So the primary map is `client.Kind` → exit, with a finer wire-`code` → exit table underneath
it for the cases where one `Kind` splits (the table's other half lives in #14; a test asserts both
halves cover the same closed enum):

| `client.Kind` | Exit | Note |
|---|---|---|
| `KindOK` | `0` | |
| `KindUsage` | `2` | |
| `KindNotFound` | `3` | |
| `KindConflict` | `4` | |
| `KindEmpty` | `5` | |
| `KindUnavailable` | `6` | includes `ErrUnreachable`, `ErrBusy`, `ErrNotReady`, `ErrShuttingDown` |
| `KindTimeout` | `5` **or** `6` | the split below: a *wait* that expired is 5; a request that got no answer is 6 |
| `KindPermission` | `7` | |
| `KindInternal` | `1` | includes `ErrReadOnly` and `ErrCommitUnknown` |


| Exit | Wire codes | Why this bucket |
|---|---|---|
| `2` | `bad_request`, `bad_subject`, `subject_mismatch`, `reserved_header`, `reserved_name`, `invalid_token`, `unsupported_media_type` | The fix is to retype the command. Usage errors are usage errors wherever they were detected. |
| `3` | `not_found` | |
| `4` | `conflict`, `stream_exists`, `stale_ack`, `extend_capped`, `would_lose_data`, `paused`, `too_large`, `disk_full`, `stream_full`, `rate_limited`, `flow_control` | "The request was well-formed; a limit, a fence or a precondition refused it." Retyping will not help; changing a config or waiting will. #39 revisits the two 429 rows. |
| `6` | dial/connect failure, TLS failure, socket missing, EOF, deadline before any response, **and** `busy`, `too_many_waiters`, `shutting_down` | A retry loop must treat "no daemon" and "daemon cannot serve you now" identically. `client.Error.RetryAfter` is surfaced in the message (*"the daemon asked for 3 s"*). |
| `7` | `unauthorized`, `forbidden` | |
| `1` | `internal`, `method_not_allowed`, `read_only`, `commit_unknown`, **any unrecognised code** | `read_only` is the fsyncgate latch (D4) — retrying never works, an operator must act. `commit_unknown` is deliberately **not** 6: it is #8's UNKNOWN class, and a naive `until` loop must not retry it blindly; the message says *"the publish may or may not have been stored — retry with the same `--msg-id`"*. An unknown code from a newer daemon never crashes and is never mis-bucketed as usage: it falls back to `client.Classify` (which buckets by HTTP status), and to `1` if that yields nothing. |
| `5` | *(no wire code)* — produced locally | See the table below. |

When "empty" means 5 and when it means 0:

| Situation | Exit |
|---|---|
| `messq consumer ls orders` returns zero rows | `0` — zero is a successful answer |
| `messq pending orders w` with an empty pending set | `0` |
| `messq sub orders w --count 1` and the long-poll expired with nothing | `5` |
| `messq sub orders w --count 3` and only 2 arrived before the deadline | `5` (the 2 records are still on stdout) |
| `messq peek orders --seq 99999` where seq does not exist | `3` |
| a `--dry-run` that would change nothing | `0` |

Exceptions, documented in the same table so they cannot be discovered by surprise: `messq serve`
keeps #17's sysexits values `74` (storage latch), `75` (data dir locked) and `78` (config will never
work), because `RestartPreventExitStatus=2 78` is an operational contract with systemd; and
`interrupted by signal` exits `130` (128+SIGINT) per shell convention. Both are outside the 0–7
semantic table by design; commands opt into them by returning `exit.Code(n)`.

Classification is one function, ordered:

```go
func Of(err error) int {
	var ec *exit.Err;      if errors.As(err, &ec)  { return ec.Code }        // explicit override (serve, 130)
	var ue *uierr.UserError; if errors.As(err, &ue) && ue.Exit != 0 { return ue.Exit }
	var ae *client.Error
	if errors.As(err, &ae) {
		if c, ok := byWireCode[ae.Code]; ok { return c }                     // finer than Kind
		return byKind[client.Classify(err)]                                  // unknown code ⇒ Kind ⇒ Error
	}
	if errors.Is(err, context.DeadlineExceeded) || isTransport(err) { return Unreachable }
	if code, ok := bySentinel(err); ok { return code }                       // errs.All(), errors.Is
	return Error
}
```

Two exhaustiveness tests, mirroring #14's pair: `TestEverySentinelHasAnExitCode` iterates
`errs.All()` and fails on any sentinel that is neither mapped nor listed as never-CLI-visible with a
reason; `TestEveryWireCodeHasAnExitCode` reads #18's frozen code list and fails on a gap;
`TestEveryExitCodeIsProduced` drives a scenario per code 0–7 against the fake daemon and fails on an
exit code the CLI can document but never return.

### 8. The command chassis and the DX linter

Every command is built by a constructor taking `*Env`, and `newRoot` assembles them. The DX linter
(`TestCommandTreeIsWellFormed`) walks `root.Commands()` recursively and fails when:

| Rule | Rationale |
|---|---|
| `Short` empty, capitalised, or ending in `.` | one-line, verb-first, lowercase |
| `Long` shorter than 120 characters | help must teach the concept, not restate the name |
| `Example` empty on a runnable command | PLAN §8's teaching rule, mechanised |
| a flag has an empty `Usage`, or `Usage` ends in `.` | |
| `Run` used instead of `RunE`, or `PersistentPreRun` instead of `PersistentPreRunE` | breaks the exit funnel / the traverse hooks |
| `Args == nil` on a runnable command | silently accepts typos as arguments |
| command name not lowercase kebab, or longer than 12 characters | typing cost at 03:00 |
| aliases collide among siblings, or with a sibling's name | |
| `Annotations["messq.exits"]` names a code outside the table | keeps the contract honest per command |

Exempt: cobra's generated `help` command. Cobra's `completion` command is disabled until #26.

### 9. Migrating the pre-chassis commands

| Command | Owner | What changes | What must not change |
|---|---|---|---|
| `version` (#1) | this issue | gains `--remote` (queries `/v1/info`, prints the server line and warns on skew, 2 s budget); default stays **offline-only** so `messq version` in a Dockerfile can never hang | the frozen JSON key set from #1's golden |

### 10. Decisions taken here (alternatives considered and refused)

| Decision | Refused alternative | Reason |
|---|---|---|
| Three output modes only | `-o wide`, `-o yaml`, `-o template=`, embedded jq/jsonpath | PLAN §8: *"never a third mode"*. `messq … -o json \| jq` is the composition story, and `--output`'s help says so with a jq example. |
| Hand-rolled 100-line precedence | viper | D8/D13, unanimous. |
| No config or context file | kubectl-style contexts (plan-04) | D8 kills the file; `MESSQ_ADDR` plus shell aliases cover the same ground with no precedence surface. |
| Plain cobra + stdlib rendering | `charmbracelet/fang` for styled help/errors | §13's ≤ 8-dependency budget lists cobra, not fang; styling is ~40 lines of `tabwriter` and four SGR codes. |
| `--token-file` / `MESSQ_TOKEN` only | a `--token VALUE` flag | `/proc/<pid>/cmdline` is world-readable (§10). |
| Errors to stderr in every mode | error JSON on stdout | keeps stdout a single parseable document; a `jq` pipeline never has to distinguish. |
| Per-invocation command tree | package-level `rootCmd` (cobra-cli default) | leaked flag state across in-process tests. |

### 11. Edge cases

- **`messq` with no arguments**: help to stdout, exit 0. **`messq bogus`**: suggestion + usage to
  stderr, exit 2. **`messq --help`**: stdout, exit 0. (Inherited from #1 and preserved.)
- **`-o json` on a command that writes a raw body** (`peek --raw`): the raw bytes go to stdout
  untouched; `--output` is a usage error for that flag combination, named explicitly.
- **A daemon newer than the CLI** returns an unknown `code` or an unknown field: the message is
  printed verbatim, the exit code comes from `client.Classify`'s status bucket, and unknown JSON
  fields are ignored by the client (#22's "lenient about server output") — never fatal, never a
  parse error in the operator's face.
- **`--timeout` shorter than a long-poll `--wait`**: the effective deadline is
  `max(timeout, wait+2s)`, and `-v` narrates the adjustment once. Killing a 30 s long-poll with a
  30 s default timeout would otherwise be a permanent, mystifying flake.
- **Token file with mode `0644`**: exit 7 before any network call, message names the file and
  `chmod 600`.
- **`NO_COLOR=""`** (present but empty): per the NO_COLOR spec, colour stays enabled.
- **A subject containing terminal escapes**: sanitised (§5.8); the fuzz target proves no ESC survives
  to stdout or stderr.
- **stdout closed early** (`| head -1`): Go's default SIGPIPE death; no handler, no error message.
- **`MESSQ_OUTPUT=table` in a CI environment** (non-TTY): honoured — an explicit setting always
  beats detection; only `auto` looks at the terminal.

      a table test covers all three layers plus empty-string-is-unset, slice flags, bool flags, and

- [ ] `--addr`, `--output`, `--token-file`, `--timeout`, `--color`, `--quiet`, `--verbose`,

## Test plan

Consistent with PLAN §11: `-race` everywhere, no `time.Sleep`, goldens with `-update`, coverage that
follows the risk rather than a vanity number.

1. **Unit — configuration** (`conf`): a precedence table (flag / env / default × string, duration,
   bool, count, string-slice), empty-env-is-unset, invalid values, name derivation
   (`--commit-window` → `MESSQ_COMMIT_WINDOW`), and source attribution for `-vv`.
2. **Unit — render**: humanisers (durations, bytes, counts, relative times against a frozen
   `env.Now`), ULID abbreviation and its full-form guarantee inside hints, column alignment and
   truncation, empty-result behaviour per mode, streaming flush behaviour (a `Streamer` writing
   three records into a pipe yields three lines before the command returns).
3. **Unit — exit**: `Of(err)` classification table over wrapped sentinels, `*client.Error` values
   (known and unknown codes), every `client.Kind`, transport errors, `context.DeadlineExceeded` and
   `exit.Err` overrides; plus the four exhaustiveness tests.
4. **Golden — human faces**: `--help` for root and each migrated command, the three teaching-error
   transcripts in §6, the `-vv` config dump, the "no rows" narration. Rendered through `clitest`
   with a forced TTY and a frozen clock, `-update` to refresh.
5. **Golden — machine faces**: `version -o json`, the error envelope re-emission, NDJSON framing.
   Shapes are digested with #18's `internal/wirecheck` so a renamed CLI JSON field fails the build
   with a message demanding a version decision.
6. **Integration — fake daemon**: an `httptest` server on a `t.TempDir()` unix socket returning
   scripted envelopes; drives the exit-code matrix, the token-file path (including a `0644` file),
   the unreachable path (socket absent, socket present but not listening, refused connection), the
   `Retry-After` surfacing, and the long-poll timeout adjustment. Timing uses `testing/synctest`,
   never sleeps.
7. **Property/fuzz**: `FuzzSafe` (no ESC/C0/C1 byte ever reaches the writer, output stays valid
   UTF-8, length is bounded); `FuzzEnvValue` (no panic, and any accepted value round-trips through
   the flag's `String()`); both seeded into #33's nightly corpus.
8. **Contract self-tests** (#2's gate-self-test style): sabotage each gate and assert it bites —
   delete a `Long`, add a `Run` instead of `RunE`, add a wire code with no exit mapping, print a hint
   to stdout, rename a JSON field. Five deliberate breakages, five failing gates.
9. **testscript smoke**: one `.txtar` proving the real binary honours `MESSQ_*`, `NO_COLOR`,
   `--output` and the exit codes outside the in-process harness. The full suite is #26's.
10. **Regression guard**: re-run #8's `verify` goldens and #20's `trace` golden through the new root
    and diff — the migration must be byte-neutral.

Coverage: `internal/cli/exit` and `internal/cli/conf` ≥ 95 % (they are pure tables), `internal/cli/
render` ≥ 90 %, `internal/cli/uierr` ≥ 90 %. Budget: the whole package's tests run in < 20 s.
